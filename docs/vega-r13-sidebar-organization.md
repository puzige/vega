# R13 — 侧栏视图、排序与任务分组

2026-09-06 · 主 Agent 规格 · 基线 `301ebec` · 对应 ZCode 矩阵 N09–N11/N15。用户已授权继续按 ZCode 的功能和使用体验实现，Astra medium 执行，主 Agent 审查、集成与真实客户端验收。性能专项延期，R12 Git 时序残留不在本卡修复范围。

## 参考端证据

本轮通过原生 CUA 实际点验本机 ZCode：侧栏「分组 / 项目」切换；项目筛选菜单为视图「按项目 / 时间线」及排序「更新时间 / 创建时间」；时间线跨项目显示任务及所属项目。项目视图按项目嵌套任务，初始5行及「显示更多」，有「收起全部」及项目/分区拖动入口。

分组是任务集合，可以跨项目，不是磁盘目录。新建分组会直接建立空分组并进入标题编辑；颜色为灰/红/橙/黄/绿/蓝/紫。分组右键菜单为新建任务、重命名、更改颜色、取消分组并删除；空组可接收拖拽。检查建立的空白组已清理，参考端恢复原来的项目/按项目/更新时间视图。没有移动、删除参考端现有任务，没有发送消息或访问凭据。分组拖动与任务拖入的入口已展示，未移动参考端真实任务；Vega 必须以 owned fixtures 实测。

## 用户行为契约

1. 在搜索下方提供紧凑的「分组 / 项目」切换、收起全部、筛选排序和归档入口，保留330px默认侧栏及R12标题栏避让。不得显示空实现按钮。
2. 项目视图提供「按项目 / 时间线」，排序提供「更新时间 / 创建时间」（新→旧，稳定ID打破同时间平局）。切换只改变侧栏投影，不打开任务、不清未读、不丢 composer 草稿、不写任务时间。
3. 按项目显示所有注册项目及各自活动任务；项目标题可单独折叠，初始显示5任务，显示更多每次增加5。置顶任务在所属项目优先。选择项目/任务继续使用真实访问、历史导航和权限/取消生命周期，跨项目任务点击必须同步正确项目。项目顺序支持拖动，未手排项目按既有最近打开顺序追加；旧名称/最近打开排序能力可保留为项目菜单，不与任务时间排序混淆。
4. 时间线显示跨项目活动任务及项目名称，按所选时间字段分为今天、昨天、近7天、近30天、更早；今天/昨天以系统本地日历边界为准，未来时间归今天。置顶可独立置顶区。归档不混进活动结果，空列表有真实空态。
5. 分组视图：新建、重命名、7种token颜色、独立折叠、拖动分组顺序；任务拖入/移出组及组内顺序；同时提供菜单「移入分组 / 移出分组」作为键盘和非拖拽入口。组按手动顺序，未分组任务在后；任务至多属于一组，不改变project_id。分组手动排序优先，置顶标记及操作保留。新建任务仍需要真实选中项目，可在该项目创建并原子加入指定组；无选中项目给出添加项目入口，不能制造无项目任务。
6. 删除分组仅解除分组并保留所有任务及内容；动作标签必须明确「取消分组并删除」，不得调用删除任务。任务真正删除时分组关联自然清理；归档保留组关联，恢复回原组。新建/重命名支持Enter确认、Escape取消；名称trim后1–64个Unicode字符，空白/超长有可见提示；取消新建不产生无名持久行。
7. 收起全部作用于当前组织视图的项目/组和相关分区，不改变任务选择；各标题可重新展开。视图、任务排序、项目/分组/任务手排及折叠状态跨重启保留，更多行数可以窗口内保留。任务分组和显示偏好完全通过产品UI完成。
8. 保留R12全部真实任务菜单、240px弹层遮挡/鼠标事件隔离、rename/unread准确目标、访问信息原子更新、草稿和前后导航。筛选切换/拖放/排序不得误开背后任务或发送文字。新增菜单须可鼠标、Tab/箭头/Enter/Escape操作，960×600与1280×750浅/深色可用；溢出滚动、选中/拖动反馈与错误提示使用主题token。

## 数据与异步约束

- 新增 `0004_sidebar_organization.sql` 递增迁移；只新增组织元数据表，不改现有任务/消息列。原有数据默认未分组、项目视图、更新时间；不写凭据或项目文件。
- Store只处理SQL/primitive rows，conversation输出共享类型于 `types/sidebar_organization.rs`。独立 `sidebar_organization` service 负责一致快照、校验、事务；UI不直接读写SQL。
- 组织快照包含所有注册项目、任务metadata（含归档供恢复）、组、关联/顺序、折叠及偏好、组织revision。事务保证快照一致；可设10000任务/128组上限，超限明确报错，不能静默遗漏/抹掉已有状态。不加载消息正文。无额外依赖。
- 组织动作以expected revision提交并在单事务内校验、应用、增加revision；冲突返回可区分错误并要求刷新，不能覆盖更新状态。验证任务/项目/目标组存在、相邻锚点归属、重复/自移动合法性。优先单项move-before，未涉及行保持顺序；新任务加入组必须与创建同事务。
- 事务结果为 `SidebarOrganizationOutcome { snapshot, created_thread: Option<Thread> }`；组内新建直接携带本次真实创建的任务，其他动作返回None。UI不得用前后快照差集猜创建身份，因为另一窗口可能在操作前创建其他任务。`snapshot()`仍只返回一致快照。（主Agent接口审查补充）
- 所有新查询和写入在后台执行。界面使用cached snapshot，单一在途组织请求，重复刷新合并；completion核对generation/owner，不在render做IO。成功持久确认后更新组织状态，失败保留表单/当前草稿并显示原因。任务元数据写入继续使用R12的mutation fence，组织写入不得覆盖Thread快照；旧metadata刷新不能倒退手排/分组revision。task create/delete/archive后刷新组织数据，导航访问不能写组织revision。
- 不改runtime、Git runner/超时、Keychain、provider、费用显示；不运行真实provider请求或性能bench/soak。旧Git全量失败原样留存，不能删断言/放宽期限或重复求绿。
