# Issue 59 · Markdown 表格渲染修复

关联：https://github.com/puzige/vega/issues/59 。用户于 2026-09-18 授权与 #58、#61 同时修复。

## 问题与任务契约

Issue 截图展示 Markdown 表格退化为带 `|` 的文本：表头被拆成多行，列无法对齐，长中文内容与代码挤在一起。先核查 GFM parser、流式提交和真实 GPUI renderer 的路径，依据实际根因作最小修复。

- I59-R1：合法 GFM 表格展示真实行列；同一列在表头/表体对齐，不显示作为语法分隔符的原始竖线。单元格内中文、粗体、inline code 正常显示，不把表头变成代码块。
- I59-R2：长内容按单元格可用宽度换行；较多列可有表格局部水平滚动，不把整个会话撑宽或裁掉内容。复用 theme/token、既有字体和可访问滚动机制，不新增硬编码颜色字号。
- I59-R3：流式分片完成后的结构与历史重开一致。保持 fenced code、列表、正文和转义竖线的语义；不凭截图猜造缺失的源文本。
- I59-R4：优先修现有 table rendering 路径，不替换整套 Markdown 库，不引新依赖，不修改 #58 权限功能或 #61 thinking 事件接线。
- I59-R5：表头/表体共享等宽列；最小列宽为 `8 × Typography::MESSAGE = 8 × 15 = 120` 逻辑 px，作为派生 Layout token。N 列表格最小宽为 N×120（如 4 列为 480）；容器更宽时列平分可用宽度，更窄时仅表格水平滚动。单元格复用既有 8px 内边距，两侧共 16px，最小内容宽为 104px；不设固定行高。
- I59-R6：同一 Markdown block 内嵌于引用或列表的多个表格，使用 block id 加表格顺序号作为稳定滚动身份；横向滚动其中一个不能移动另一个，尾部追加内容不能重置已存在表格的身份。

## 验收

以自主编写的截图同类 fixture 覆盖四列表格、长中文/inline code、左右对齐、窄会话和流式分片/最终历史输入。必须包含真实 renderer 布局断言（表头/正文列边界一致、无零宽/越界）以及 parser 的内容/结构断言，不能仅证明 helper 返回了预设数字。运行相关测试及 workspace 格式、Clippy、test/build 门禁。主 agent 审核修复并在真实应用中查看历史表格，记录自动化与原生外观验证的区别。
