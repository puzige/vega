# 长任务基于证据的非终止纠偏

## 授权与边界

2026-10-18 用户要求按汇报、收敛、上下文三个方向完善方案并直接实现，明确不能靠硬限制轮数，必须保证长任务持续推进。本规格更新 #411：旧 Issue 的“三次后禁止路径并强制无工具收尾”不再实施。此卡给模型证据和重新评估提示，不替模型宣布任务停滞或完成，不增加总轮数、总时长、思考大小限制。

根因：普通工具执行成功只说明工具完成，无法保证任务接近目标；模型可反复读取、调整失败参数或不断扩展调查。连续失败计数又会被夹杂的成功读取掩盖。应区分可确定的重复证据与模型需要判断的任务进度。

依赖已合并的统一工具合同 #300；与 #452 共用固定运行时 guidance 的安全出站边界。分支 `feat/411-progress-aware-recovery`。实现可独立落地同等最小 guidance 接入；集成时必须复用 #452 已审查类型，不引入第二套投影/源比较规则。两卡 loop 范围单一写入者串行实施。

## 实现契约

1. 新建私有 `agent/progress_recovery.rs`。每个完整工具批次记录至多64个键，滚动保留最近32个批次的有界证据。键为规范化工具名与参数 JSON 的 SHA-256，不含 call ID；嵌套对象键递归稳定排序，数组顺序和数值含义不能改。无效参数使用已有审计摘要，不重新暴露原输入。不能以 shell 子串（如 sleep/gh）猜测任务类型或安全性。
2. 结果证据基于脱敏后完整 runtime 输出摘要、实际 status、exit_code、truncated。只存摘要/类别，不能复制大输出或敏感正文。不要基于已省略中间内容的预览判断相同。相同键出现不同结果即重置该键重复链；无关成功不能消除未解决键的重复证据。同批次相同证据最多计一次。
3. 三个独立批次有同样证据时提示一次：失败要求检查工具合同和当前状态、实质性修改输入/方法；成功结果重复要求判断等待/退避或该查询是否仍有价值。文案不能断言整个任务“没有进展”，不能鼓励跳过权限或盲重放未知副作用。
4. 每16个完整工具批次允许一次简短策略复核提示，以覆盖参数都不同的无边界研究：归纳已确认事项、关键未知、下一步与成功判据的关系；已有足够证据则转实现/结论，仍需工作则继续。16只决定提示节奏，不限制允许的请求或工具数量。
5. 同一批次最多附一个复合 guidance，优先具体重复失败/结果提示；周期复核同时到期时合并或消费该次节奏，不产生多条系统/用户/助手消息。#452 汇报提醒同时存在时保留其含义。guidance 仅附到最后新工具结果的出站投影，第一次出站前冻结。正常 Tool 使用固定后缀；无效参数等已经转换成历史观察的结果，沿用 #452 的既有 JSON advisory 字段，保留 authority:none、转义后的原 output 和不可执行语义。不得新增 User、恢复失效调用或把建议当作新授权；原结果伪造字段不能生成私有元数据。
6. 有效 steering、新上下文压缩安装清空观察窗口；新run/重开重新开始，不新增持久化计数。保留固定已发送提示的历史投影，不重写旧缓存前缀。不改变工具调度、同ID幂等、授权、审批、Goal/Loop预算或用户指定上限。
7. 所有错误仍走原有分类。无需自动新增“收尾请求”，不设置 tools=[]，不取消root token。原有权限/未知副作用/CUA等安全终止语义保持。

## 修改与集成

`agent/loop_.rs` 在每个结果分支收集真实结果、完整批次结束后生成决定；无效参数、重用结果、普通读写/bash路径须覆盖，不能只覆盖主成功分支。新模块经 `agent/mod.rs` 接入。固定提示走 `provider.rs` 的类型化 guidance；不直接改 ChatMessage.content 或增加伪造 User。

基础策略提示可在 `agent_context.rs` 明确调查结束条件、以阶段结论推进及同类失败需换方法；保持简洁，不把工具元数据复制一遍。不修改与本卡无关的 skills/默认配置。

测试须通过真实 `run_agent` 与 MockProvider 捕获下一请求，配合进程内工具替身和可控时钟；不能仅用提示字符串包含断言代替执行语义。已有错误、权限、工具幂等和压缩负例保持。

## 交付与回滚

本地仅diff/格式/静态检查；Actions：`cargo fmt --all -- --check`、`cargo clippy --workspace --all-targets -- -D warnings`、`cargo nextest run --workspace`。最新head required check通过后合并In review，用户手测长研究、轮询、纠错、停止继续和重开。

回滚代码即可；无迁移、配置修改或历史删改。提示机制不能保证模型永远收敛或提升固定百分比，报告区分自动机制测试与真实任务效果。用户已授权Ready后Codex直接组织实现，单一卡片执行者记录明确。
