# Vega 设计守则

**版本：v2.0 已批准实施基线 · 2026-10-11。适用：macOS / Rust + GPUI。**

本文件统一今后的设计方向，不宣称这些方向已经实现。已交付基线为 #298 / 0.1.67；本次 18 点改造已获批准、正在实施，尚未验收。先看[方案总览](vega-issue-296-ui-redesign-review.md)，精确行为、数值提案、依赖和验收见[改造 spec](vega-issue-296-ui-redesign-v3.md)。旧版完整保存在[历史快照](vega-design-guidelines-legacy-2026-10-11.md)。

## 1. 权威边界

### 1.1 设计来源

- 用户本轮 18 点反馈是产品方向；Codex / WorkBuddy 截图仅作可见交互参考，不复制私有资产，不在公开文档附原始会话或截图。
- [Apple HIG：macOS](https://developer.apple.com/design/human-interface-guidelines/designing-for-macos/)、[Layout](https://developer.apple.com/design/human-interface-guidelines/layout)、[Offering help](https://developer.apple.com/design/human-interface-guidelines/offering-help)、[Motion](https://developer.apple.com/design/human-interface-guidelines/motion)提供平台交互依据：窗口可调整、帮助贴近操作、动效服务反馈。
- [GPUI Kit Design Guides](https://gpui-kit.com/docs/design-guides/)用于检查组件组合、对齐和状态一致性。它不替 Vega 决定消息阶段、模型身份或计费语义。
- 查阅日期为 2026-10-11。指南站点显示 v0.7.1，Vega 依赖仍锁定 `gpui-kit = "=0.6.0"`。本轮不升级依赖，不把指南中的 API 当成仓库已经可用。
- 禁止以第三方 bundle 解包、反编译所得的 CSS、内部 token、组件树或图标作为输入。旧研究记录不构成实现依据。

### 1.2 一个规则只有一个当前入口

1. 用户最新明确裁决优先；产品安全、数据真实性与持久化契约继续有效。
2. 本次详细方案已获用户批准实施；v3 spec 的冲突清单只替代列明的旧展示规则，不推翻无关功能契约。
3. 本文件管跨页面设计语言；v3 spec 管本轮精确行为；业务规格管底层行为。冲突必须显式登记，不能靠文件日期猜优先级。
4. [`vega_theme`](../crates/vega_theme/src/lib.rs) 与实际 controller 是当前实现事实。新数值未进入共享 token、行为未验证前，不得称为已落地。
5. 旧任务的“允许重启”“自动合并”“验收通过”等记录不延续为本轮授权。当前按用户最新“按照spec执行”授权推进。

> 最新信息流视觉契约见[Codex截图对齐](vega-issue-296-codex-stream-parity.md)，行为契约见[工具时间线与最终收起](vega-issue-296-process-timeline.md)：运行时说明与阶段/工具按序，Final后统一收起。顶部纯计时与细分隔线，阶段箭头紧跟标题且仅hover/focus出现；不显示Vega角色行。取代上一版顶部集中工具与箭头整行靠右规则，正文、安全项与阅读保护保留。

## 2. 设计原则

Vega 要成为清楚、安静、容易操作的桌面工作台。以下是结合用户反馈形成的 Vega 自有规则，不是平台规定的像素模板。

- **内容优先**：最终答案是阅读主体；过程中展示有用进展，思考和工具详情按需展开。
- **对象归属清楚**：模型能力、思考、定价在同一模型配置内；动作放在它操作的对象附近。
- **关系先于装饰**：用字体、间距、缩进和展开关系组织过程，撤掉整块常驻灰底。
- **几何稳定**：hover、运行、选中、禁用不改变标题起点或挤动邻居；辅助时长紧贴其标题。
- **状态可信**：不知道最终答案归属、上下文分类或模型价格时明确缺失，不用外观填补数据。
- **少写解释**：控件标签应足以操作；可选说明进入帮助，真实错误和待用户处理事项保持可见。

## 3. Token 架构

颜色经 `ThemeColors`，排版经 `Typography`，几何经 `Layout`，动效经共享 `Motion`。新规则先在 spec 标注意图与影响范围，获准实施后进入类型化入口；不在各页面复制数值。

沿用 4px 间距梯度 `4 / 8 / 12 / 16 / 20 / 24 / 32`。线宽、图标绘制、锚点刻度等例外需说明理由。逻辑像素是设计基准，不是每个控件调用 `px` 的授权；缩放须协调文字、槽位、控件和虚拟列表测量。本轮不新增全局缩放功能。

## 4. 颜色

沿用当前浅深两套语义色，不在规范复制第二份十六进制表；颜色事实以 `ThemeColors` 为准。

| 语义 | 用途与边界 |
|---|---|
| `bg_base` / `bg_sidebar` | 主阅读面 / 导航面 |
| `bg_elevated` | Composer、浮层等真实容器，不等于每个消息都加卡片 |
| `bg_subtle` | 低强调设置分组等；**新目标不再用于思考/工具/过程整组常驻灰底** |
| `bg_hover` / `bg_active` | 局部反馈 / 当前导航选择；hover 不扩大为整组背景 |
| `border_subtle` | 必要边界；相邻区域不重复画线 |
| `text_primary / secondary / tertiary` | 正文、辅助信息、弱提示；主要可读内容不降为占位灰 |
| `accent` / 品牌色 | 主操作和焦点；不把所有导航、工具图标染蓝 |
| `warning / danger / success` | 实际状态，配文字或形状，不仅靠颜色 |
| `code_bg` | 代码内容的语法识别面，不受“去过程灰底”一概删除 |

浅深模式分别验收。正常过程无卡片底色；错误、危险确认、代码和设置分组仍可有必要表面。正文默认不加渐变或阴影。

用户追加的 Codex 展示参考进一步明确：活动概览、阶段摘要、单条工具记录保持页面同底；只有展开后的命令/输出才使用独立的浅底细边框容器。容器从详情开始，到该条详情结束，不能重新包住整组过程。详情内可有低强调的工具类型、等宽内容及真实结果状态，见 v3 §3.3a。

## 5. 排版

使用平台系统字体，代码使用等宽字体；CJK、Latin、数字、标点共同验收。控件标签按基线，图标按槽位中心对齐，不能把文字包围框中心当成字形视觉中心。

| 区域 | v3 提案 | 当前基线 / 变化 |
|---|---|---|
| 会话正文、展开思考正文 | 15px，行高 1.65 | 会话保留15；展开思考由13提升15是新提案，需重测高度与锚点 |
| 导航、控件、过程摘要 | 13px | 保留；导航行 32px、过程摘要行 28px |
| 时间、来源等元信息 | 12px | 保留；不用于主要操作标签 |
| 设置页 / 区块标题 | 20px / 14px，600 | 采用已交付 v2，废除旧 24px 设置标题 |
| 代码 | 12.5px，等宽 | 保留；块内行高提案 1.6 |

Markdown 使用独立阅读节奏：段间 12px、标题前 24/后 12px、列表项间 6px、块间 16px。禁止为降密度简单放大全应用字号。表格、列表、代码规则见 v3 §5。

2026-10-13 行内代码与表格的细化契约见[阅读排版](vega-issue-296-inline-code-layout.md)：代码底在实际行盒内垂直内缩并绘制小圆角；表格按共享内容权重分配列宽。沿用当前 conversation 字号/行高、源文及选择复制规则，不以改写文本改善视觉换行。

## 6. 几何与布局

| 区域 | 保留的逻辑像素基线 |
|---|---|
| 主 Sidebar | 默认 304，范围 240–365；宽度持久化；行高 32、圆角 8 |
| 主 Header / 顶部前导按钮 | 46 / 28×28，16 图标，组内间隔 4 |
| 正文与 Composer | 同轴、同宽，最大 768；Composer 最小高 100、圆角 20 |
| 设置导航 / 页面内容 | 224 / 最大 720；不随主 Sidebar 拖拽宽度改变 |
| 设置表单 | 标签列 208、列间距 16、分组内距 16、行上下内距 12 |
| 思考/工具详情 / 工具组子列表 | 最大高 240 / 320，短内容自然高度 |
| 阅读导航区 | 高 40，稳定占位；v3 只改为纯箭头按钮 |
| 最小窗口 / 验收窗口 | 960×600 / 1403×860 与 1400×900 |

精准新几何只在 v3 §2 维护，包括 footer 外层、状态槽、锚点刻度、Provider 响应式。GPUI 圆角裁剪、浮层绘制顺序仍遵守 [AGENTS](../AGENTS.md) 的已知约束。

壳层紧凑、正文舒适、设置适中，不强制同密度。页面已有内距时，子容器不自动再叠页面内距。浮层可以有轻阴影，常驻 Composer 与普通过程区不加阴影。

## 7. 图标与品牌形态

继续使用共享 `vega_ui::icons` 和同一套 GPUI Kit / Lucide 线性图标，统一圆端点、圆连接与光学重量。16×16 槽位、24 viewBox / 2 源描边是已有基线，**仅重申这些值不能算解决“偏、不圆润、不表意”**。

逐个验收实际轮廓、相邻字形与居中效果，覆盖侧栏、标题栏、Composer、过程、设置和弹层。光学校正需有记录，不用散落偏移补救布局。Provider 用连接类、MCP 用插头类、Agents 用机器人类、Skills 用能力/积木类、用量用图表类；具体名称须核对当前库可用图标。禁止 Unicode/emoji 代替控件图标，本轮不生成装饰资产。

## 8. 组件状态

| 状态 | 统一要求 |
|---|---|
| 默认 / hover / pressed | 默认可识别，hover 局部反馈，pressed 即时；尺寸、基线、命中框不变 |
| 选中 / 焦点 / 弹层打开 | 三种不同状态；键盘焦点可见；弹层打开时触发器保持对应状态 |
| 禁用 | 保留必要槽位、阻止动作，无误导 hover；必要原因通过帮助查看 |
| 运行 | 真实任务绑定的 spinner 或文字 shimmer，不堆叠多种装饰 |
| 错误 / 权限 / 待回答 | 就近显示可操作信息；不得藏进过程折叠或 help |

hover 不是唯一操作路径；focus、菜单打开和上下文菜单提供等价入口。图标按钮有可访问名称及 tooltip，弹层支持 Esc、外部点击及合理回焦。

用户气泡保留右对齐、最大列宽 80%、圆角 16、内距 12/8 与源文换行。[消息复制](vega-issue-78-hover-copy.md)当前禁用的常驻动作行不因本轮重新启用；选择、复制原文和历史定位完整保留。

## 9. Composer

- 保留一个输入主表面、一行操作区域，以及发送/停止、输入法、快捷键、浮层键位和提交 guard。
- **#294/#295：底栏不出现分支图标、名称、入口、焦点目标或占位。** 新任务上方 utility bar 保留项目入口和有效 Git 项目的分支入口；已有消息的会话不渲染 utility bar。见 [#294](vega-issue-294-composer-footer-no-branch.md) 与 [A8-01](vega-a8-composer-project-entry.md)。
- utility bar 的 37 高、19 内缩、零重叠关系，以及项目/分支切换的权限、焦点、pending 语义不变；见 [utility chip states](vega-utility-chip-states.md)。
- 保留只读、确认、自动、完全访问四种权限及危险确认；外观不改变 sandbox 与授权语义，见 [#58](vega-issue-58-full-access.md)。
- 上下文环进入模型选择器前的紧凑槽位；点击展示模型配置输入上限的使用比例，不等于本轮runtime预算、账单或已验证模型总容量。真实数据、估算标记与降级见 v3 §6。

## 10. App Shell

主窗口、Settings、Workspace、Terminal、Environment 共享图标、状态、排版和动作密度；本轮不新增无关功能。

- Sidebar 保留项目/置顶/最近任务的唯一投影、渐进展开和已有任务操作。静止任务行不增加常驻相对时间；尾部状态与操作按 v3 固定槽位替换。
- Settings footer 收紧外层，按钮本体圆角与内距不变。顶部搜索、前进后退、原生 traffic lights 与拖拽区保留。
- 全局尾部三个窗口控制仍由窗口管理；保留 [R46](vega-r46-window-anchored-shell-slots.md) 的 104px 预留与动作语义。
- Environment 默认折叠，宽窄切换、Workspace Dock/最大化、终端焦点与 PTY 身份保持 [#141](vega-issue-141-environment-default-collapsed.md)、[R44](vega-r44-terminal-panel-logic.md) 的契约。
- 2026-10-13 用户追加的[图片右侧预览](vega-issue-296-image-preview.md)统一现有图片入口：点击进入Workspace，文件名、打开方式、保存操作就近呈现；替代截图居中模态，保留原图与来源生命周期。
- 空间不足时先收起次级文案、用溢出菜单或垂直表单；不能截掉主操作或让整窗口承担局部内容滚动。

## 11. Settings

目标一级导航：**通用 → 服务提供方 → MCP → Agents → Skills → 用量**。思考、定价成为具体模型配置分区，不保留重复一级入口。旧链接/快捷入口转到对应模型分区；找不到对象则进入模型选择，不跳到无关模型。

Provider 使用“列表 → 提供方详情 → 模型配置”层次，宽屏主从展示，窄屏逐层进入并保留返回位置。模型配置含基本信息、思考、定价；所有原有字段和动作语义保留。MCP 授权、Agents 参数、Skills 路径、用量长文本及各页独立滚动的既有修复继续有效。

普通帮助不常驻占行；关键警告、授权步骤、错误、保存冲突和待重启动作保持可见。设置可以有低强调分组，避免卡片套卡片。详细布局和能力保全见 v3 §4。

## 12. 动效与滚动

hover 沿用 120ms，按下即时反馈。新增 Thinking/摘要 shimmer 仅表示实际思考或等待，不是所有文案的常驻特效；终态、待用户操作、隐藏页面与 Reduce Motion 下停止。

折叠、摘要更新和时长变化不抢用户阅读位置。长思考提供内部滚动条，尊重系统始终显示设置；只有内部能消费滚动时才截获事件，到边界交给外层。同一次运行，用户手动展开/回看优先于默认自动折叠。阶段规则见 v3 §3。

## 13. 验收与证据

本轮已进入实施；尚未取得证据的 UI、性能和真实集成项目不得声称通过。后续分行为测试、几何/视觉检查、用户真实手测，不能互相替代。GPUI 焦点以生产测试状态为证，不能仅用截图推断。

覆盖默认、hover、focus、打开、禁用、运行、失败、窄窗口与浅深主题中的适用状态；反馈对应 v3 的 U01–U18。公开证据只用合成任务和脱敏数据。

## 14. 变更方式

方案通过评审后先冻结阶段与数据契约，再由专职 agent 分批实现；主 agent 协调、审查和集成。每批更新共享 token、组件和规格，保留范围外功能、安全断言及已接受限制，不重开 #291。
