# #768: 审计当前会话历史读取

基线：`faf14b302d28d17f24afe3398db527f744cf15a5`。`read_conversation` 在 #667 提供的范围、来源绑定和低信任合同继续有效。本卡只接通该工具的审计生命周期，不修改压缩、来源查询、权限或历史重放边界。

## 根因与证据

运行时对具备读取器和合法参数的提议准备 `ConversationHistory`，持久化事件处理却将非空参数按未知工具拒绝。即使仅放行该处，只读审批来源和终态／重开校验也缺少对应分支。非法或不可用调用被运行时转换为不含原参数的 `{}`，随后以不可用工具拒绝。故障记录没有保存被拒绝工具的名称，不能从调用 ID 证明某次事故的具体工具。

## 验收用例（先于实现计划）

1. 真实线程和消息存在时，对 `messages`、`tools`、`skill_resources`、`delegated_results` 分别发起合法提议：持久化 pending、只读一次性审批、running、真实有界 observation 和终态；后续模型请求得到结果并继续。重新加载终态与下一轮验证接受同一记录。验证精确来源、序号分页、Unicode 字符偏移和空来源结果。
2. 非法 JSON、未知字段、超限的 ID／游标／页大小或工具不可用时，运行时不得保存原始非法参数，不执行读取；保存的安全拒绝可被重开和下一轮恢复，不遗留 pending，也不因参数错误终止整轮。混合普通工具可继续；与要求独占批次的工具混用时沿用既有安全拒绝。
3. 真实读取失败、凭据检查失败、执行中取消、审批前取消、启动恢复 pending／running 均保留对应失败或取消状态，重开校验通过且不交付被取消的数据。
4. 伪造的请求形状、非只读审批、成功结果的信任包装、异常元数据、错误状态或超限输出均不得通过安全校验。线程隔离由绑定当前线程的只读查询保证；历史内容和路径不被执行或升级为权限，凭据先过滤再按字符分页。静态结果验证不能独立证明任意伪造的、形状完全相同的历史正文来源，来源真实性交由绑定读取器和既有持久化边界保证。
5. 审计失败提示只陈述安全校验失败与重试，不假设已有工具记录或旧记录损坏。运行期错误分类沿用现有投影；历史错误分类问题由 #770 单独处理。

## 实现计划与验证

- 复用运行时唯一的 `ConversationReadRequest` 解析契约，在提议、混合批次、审批和终态／恢复校验中显式处理该工具；仅认可合法请求或运行时的 `{}` 安全拒绝投影。成功只认可受限大小、`authority:none` 的历史 observation 结构；失败、取消和恢复只认可真实输出与审批组合。
- 保持读取器、查询、凭据过滤、字符分页、只读权限和数据模型不变；修正读取失败输出的重复前缀，统一使用不含敏感内容的文案。调整中英文审计错误提示。
- 开发分支添加针对真实持久化边界的必要 Rust 回归以及运行时实际执行覆盖；仅在 GitHub Actions 执行。固定测试提交和云端结果后，按仓库政策从最终 head 移除 Rust 测试及独占接线，最终 head 需完整 required CI 并确认 0 发现／0 执行。非写入者独立审查，合并后由用户手测。
- 本地仅静态／格式／diff 检查，不运行 Vega、构建或测试。涉及来源版本变化的 `summary_source_changed` 属于独立问题，不纳入此卡实现。
