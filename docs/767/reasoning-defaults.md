# #767 新对话记住模型思考档位

## 问题、范围与基线

用户报告打开新对话时，之前选择的模型思考档位未被记住。基线 `faf14b302d28d17f24afe3398db527f744cf15a5` 静态追踪：`persist_composer_thinking` 只保存目标 thread 快照；新草稿从 `NewTaskDefaults` / `reasoning-preferences.toml` 的全局模板初始化，因而不会继承 Composer 选择。没有运行时复现证据。本规格修订 [#743](../743/session-reasoning.md) 的「Composer 不反写默认模板」规则，不撤销会话隔离。

## 验收用例

| 前置与操作 | 可观察结果及证据层级 |
|---|---|
| 在已有会话 A 为模型 P/M 选择合法档位，保存确认后新建 C | C 的选择和下一次冻结请求使用该档位；B 已存在的快照、选择、后续请求不变。需云端行为验证及用户 UI/真实请求手测 |
| 在未发送草稿 A 选择档位，新建 C；重启再新建 D | 保存确认后 C、D 均使用该档位；A 的快照在物化后保留。需云端行为验证及用户重启手测 |
| P/M、P/N 或不同供应商分别设置不同档位，切换模型；选择 provider default、Off 或合法 effort | 每个精确 provider/model 独立保留最新合法选择；只更新该键，其他键和现有会话不变。需云端验证 |
| 已有运行中改变档位 | 当前运行的 FrozenReasoning 不变，仅下一轮及未来新会话使用新选择。需云端行为验证 |
| 保存期间快速拖动、切会话或刷新目录 | 合并最新意图，旧回执只更新原会话；过时的目录快照不能覆盖新默认；已完成保存后新建会话继承确认值。需云端验证 |
| 全局文件损坏、冲突或写失败；会话事务失败；写入后读回失败 | 不覆盖其他键，不报告全成功；会话和默认值分别按实际确认状态投影，部分成功仍提示错误，保留可重试路径。需云端验证 |
| 更新 Settings 默认、无记录模型、旧会话首次初始化、能力变更 | Settings 的默认只影响未来及尚未初始化的会话；空快照不回退，能力不支持的选择依旧拒绝发送；旧行为不回归。需云端验证 |

## 用户确认：保留原草稿并新建

**已被后续用户裁决取代**：[#785](../785/single-draft-ui.md) 要求恢复旧版单草稿及 UI，不再保留多份未发送内容；下述多草稿要求与实施计划第 5 项仅保留为历史记录，思考档位记忆与默认保存规则继续有效。验收中的草稿 A 不再承诺新建 C 后仍可恢复；已确认的默认仍应由 C、D 继承。

点击“新对话”时，若存在未发送草稿，保留原草稿的独立身份、输入文字、附件及进行中的导入、模型、权限、思考档位和技能选择；创建不同身份的新草稿，并以创建时最近**已确认**的按供应商和模型默认档位初始化。原草稿必须仍可通过明确、支持键盘的入口恢复：浏览历史可前进/后退，但历史截断或容量淘汰不得使草稿不可达。不可用项目必须保留草稿并提供可恢复路径，不能静默转移或删除。

此用户裁决取代 [R69](../vega-r69-home-lazy-draft-composer.md) R4「每窗口至多一个草稿 ID」的数量限制，以及 [R12](../vega-r12-task-navigation.md) 不缓存非活动会话的规则中对**未物化草稿**的部分；每个草稿仍有稳定身份、在首次提交前仅存在内存、不为导航写入数据库。重启后的草稿持久性不超出现行规则。后台保存、模型和权限回执必须按来源草稿身份与版本隔离；物化、自动化、Codex 和权限重置只更新各自真实目标。草稿保留容量、附件及待导入资源必须有界；不能安全容纳时，创建或离开前保留当前草稿并给出可操作的恢复路径，不能静默丢弃。

云端行为验证至少覆盖：多个草稿的文本、附件、技能、各自模型权限和档位；新建、返回/前进、历史分支截断后的恢复；项目重绑与删除；迟到保存回执、权限重置、普通/Codex/自动化物化；资源上限与键盘操作。UI 与重启行为仍须用户手测。

## 行为与失败语义

Composer 对受支持的精确 provider/model 选择新值时，保存原会话快照并对既有默认配置做单键 patch。两个持久化位置并非单一事务：会话保存成功而默认保存失败时，保留已确认会话值并显示保存错误；默认写入可能已发生但读回失败时不得推断结果，重新加载权威文件。会话保存失败不得更新默认值。草稿会话值在内存中确认，默认值独立持久化；不为新对话而改写其他现有快照。未保存或保存中的选择不承诺已成为默认，新会话在确认保存后继承。

对默认文件复用现有进程内协调、按键合并、冲突检测、原子替换和权威读回；不改文件格式或 provider 能力。目录后台读取与保存并发时，不允许先前快照覆盖默认模板；确认后及时同步新任务默认、配置缓存及 Settings 投影。线程回执维持身份/revision 隔离和当前运行冻结。默认写失败后允许用户重新选择当前档位重试。

## 最小实现计划

1. `window/reasoning.rs`：复用 reasoning profile patch，为 Composer 保存携带会话结果与默认文件的实际结果；按两部分确认结果更新原会话、新任务默认、配置权威和错误状态，保留串行协调与身份围栏。
2. `window/session.rs`：catalog 完成期间已有默认保存时，禁止陈旧快照覆盖新任务默认；完成后按需重新载入。
3. `window/permission_reset/projection.rs`：权限刷新仅替换权限默认，保留无关的思考默认。
4. 为部分保存失败提供跨导航保留、可键盘访问的明确重试入口；重试只针对未确认的新会话默认，不覆盖较新的会话选择。
5. 根据用户裁决重构未物化草稿的身份、完整 composer 所有权与可恢复导航，并协调各物化、权限和迟到回执路径；该架构工作未完成，不以重置旧草稿代替。
6. 按风险在云端验证以上回归；本地只做低 CPU 静态检查，遵守 Rust 开发测试及最终清零、独立审查、最终 required CI 和用户手测门禁。不得将未运行验证称为通过。

## 非目标与回滚

不修改模型能力声明、上下文预算、权限规则、已有已初始化会话的思考设置、历史消息及正在运行的请求。不读取或修改用户实际配置。回滚本修复后恢复 #743 原有行为，先前默认文件中保存的有效档位仍可作为新会话默认读取。
