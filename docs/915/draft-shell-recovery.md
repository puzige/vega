# 新对话草稿的 shell 恢复检查

## 范围与用户裁决

基线：34555cec9c0c4c4c1f7a528d739752f414e53edf（0.1.410）。

新对话草稿未入库，不得按持久对话强查而误报恢复不可用。用户确认：新对话页始终不放整块恢复面板；正常状态无提示，真实阻塞或读取失败时在发送位置提供简短原因和可发现的详情入口，详情以主动打开的独立浮层展示。既有对话的恢复行为不改。

不得升级、重启或修改远端机器与用户数据库；不调整 shell 执行、清理、恢复确认和权限规则。

## 验收用例

| 前置 / 操作 | 可观察结果 | 验证 |
|---|---|---|
| 有效项目下未保存草稿读取恢复状态，无 shell 操作 | 成功返回真实规范工作区与空阻塞，不创建对话 | SQLite 服务回归 |
| 同工作区另一持久对话存在未解决 shell 阻塞，草稿读取 | 返回该阻塞；存储与运行时写门禁保持有效 | SQLite 服务回归 |
| 父子路径重叠工作区存在阻塞 | 仍使用既有恢复查询的路径重叠规则 | SQLite 服务回归 |
| 项目不存在、目录消失或读取失败 | 不返回伪造空结果；失败保持可见与可重试 | 服务回归 |
| 草稿 ID 实际已持久化、或身份不是有效 native 顶层草稿 | 拒绝草稿查询，不降级为普通成功 | 服务回归 |
| 已保存对话读取、身份 revision 变化 | 保持现有严格读取与 Changed 校验 | 服务回归 |
| 正常新对话页面 | 无恢复文案、无常驻面板，无额外成功反馈 | UI 状态回归 + 用户手测 |
| 新对话真实阻塞 / 检查失败 | 输入区仅短原因和详情入口；主动打开浮层查看并处理，关闭 / Escape 不解除阻塞 | UI 状态回归 + 独立审查 + 用户手测 |
| 草稿项目改变、草稿持久化、异步旧回执到达 | 清空旧投影、重新检查；陈旧回执不得覆盖新状态 | 状态回归 + 静态审查 |

## 实现计划

1. 恢复服务增加显式草稿来源，不把任何 NotFound 自动当作草稿。窗口以真实 draft route 选择来源。验证草稿未入库、native 活跃顶层身份及有效项目，再读取数据库登记项目的规范路径。
2. 草稿和持久对话共用真实 recovery / generation reconciliation / runtime block 接线；恢复动作仍保留工作区版本、资源与 authority epoch 校验。
3. 新对话页只提供短状态与按需入口，详细面板移至独立浮层；沿用现有确认、重试、关闭、Escape 与焦点行为。不把未知状态写成安全。
4. 补开发期 Rust 回归，优先本地执行；固定可恢复源码与实际结果，合并前按仓库规则清理测试及独占接线。独立审查与最终 required CI 分别确认。

## 非目标

不改 Fork、不做数据修复、不新增 schema / 依赖、不执行远端升级或重启、不扩展 shell 生命周期重构。
