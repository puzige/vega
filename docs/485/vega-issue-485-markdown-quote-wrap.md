# Markdown 引用随正文宽度折行

Issue：[#485](https://github.com/puzige/vega/issues/485)。版本：v1，2026-10-20。

## 范围与基线

用户要求阅读并修复「Markdown 引用没有折行」，且明确禁止使用 CUA。Issue 正文只有图片，没有文字复现步骤或评论；以下判断来自标题和当前源码，不声称完成原生视觉复现。

初始生产基线：`e93518cf76a24df921a1af2c2663ebce75f614fd`；测试先行提交前安全快进至 `3a2ef8e9795d609f022b7b81011360db102e3de6`（上游仅调整思考滑块档位命名及 #506 文档，引用布局未变），以此为 RED 生产基线。分支：`fix/485-markdown-quote-wrap`。独立 worktree：`vega-485-markdown-quote-wrap`。主仓库原有改动保留，不进入本卡。

目标是让普通 Markdown 引用在当前消息正文的可用宽度内自然折行，保留引用左侧竖线、现有文字样式、链接与选择复制。仅修复布局，不修改 Markdown 解析、源文、流式状态、字体、主题、全局尺寸或消息交互。不新增依赖、提示文字、公共生产 API 或 CI 设施。

## 根因与涉及路径

- `crates/vega_ui/src/conversation_stream/render_rows.rs::render_line_selectable` 的 `LineKind::Quote` 分支：引用竖线和 `SelectableStyledText` 直接作为横向 flex 的子元素。文本没有像列表正文一样放入可收缩、最小宽度为零的容器，因而无法可靠获得扣除竖线和间距后的宽度来测量折行。
- 同文件 `render_line` 的 `LineKind::Quote` 分支存在相同组合，普通 `markdown_text` 也直接进入横向 flex 行。两个分支必须一起修复，避免只修复当前选择路径。
- 同文件 `LineKind::ListItem` 已采用 `div().flex_1().min_w_0().child(content)`，是可复用的布局模式。
- 不带行内代码/链接的选择文本经 `selection.rs::SelectableStyledText::request_layout` 委托给真实 `StyledText`；带行内代码或链接的文本改走 `InlineFlow`，根据可用宽度生成多个定位片段。两者都必须取得确定的剩余宽度，不在源文里添加换行或手工拆行。默认 flex-shrink 已经为 1，问题是自动内在最小尺寸阻碍有限宽度传递，而非完全没有收缩属性。
- `thinking_body.rs` 在排版引用时已传入扣除引用装饰后的 `style.width - x`；该自定义布局不属于本次修改范围。

## 冻结验收矩阵

测试先于生产修改，使用合成内容；不能以源码字符串、样式字段存在或镜像排版算法作为行为证据。

| ID | 输入与操作 | 可观察结果 | 自动验证边界 |
|---|---|---|---|
| Q1 | 含常规断词位置的长英文与中文引用，在窄正文列绘制；对普通和可选择两条渲染路径分别验证 | 引用高度超过一行，文本布局不超出可用正文右边界；竖线和文本不重叠 | GPUI 测试平台实际布局/绘制结果 |
| Q2 | 将同一长引用放在较宽正文列；再次缩窄 | 宽列所需高度低于窄列；根据可用宽度重新折行，而不是固定高度、截断或手工插入换行 | 同一生产渲染路径的布局高度与边界 |
| Q3 | 短引用在足够宽的正文列中绘制 | 保持自然单行高度，竖线保留；不会因为修复而把引用强制拉高 | GPUI 实际布局/绘制结果 |
| Q4 | 带粗体、行内代码和链接的可选择引用自然折行 | 显示正文完整，逻辑选择复制内容不增加软换行；链接、行内样式仍由原有生产文本构建器处理 | 实际生产文档投影与布局；真实交互交用户手测 |
| Q5 | 思考区长引用与普通代码块在窄/宽容器中绘制 | 思考引用继续按宽度折行；代码保持既有不软折行的语义 | 原有生产排版入口的布局与文本投影保护用例 |

不承诺对没有任何可断点的任意长 token 新增断词策略；不改变 Markdown 软换行/硬换行语义或引用嵌套语义。

几何观测必须来自生产排版的文本/片段：行容器有界或变高本身不足以证明没有溢出。纯文本检查实际视觉折行，富文本检查片段的多个纵向位置、有界几何和完整逻辑内容；不要求每个已定位的富文本片段再次折行。引用竖线应保留宽度，与文字分离并覆盖文本高度。窄→宽→窄在同一渲染上下文中验证重新排版，最后一次窄布局应恢复。

允许最小私有 `cfg(test)` 只读布局观察，不改变生产宽度或决策，不新增生产公共 API。绘制场景数据必须在完成帧后读取；若用 `VisualTestContext::draw` 的 prepaint 测量，则不把未交换的 rendered-frame quad 当作本次结果。默认 GPUI 测试字体为合成度量，自动测试只证明布局约束与完整内容，不能宣称原生字形/字体外观通过。

## 实现计划

1. 专职子 agent 先添加仅开发阶段保留的回归测试和必要的 dev-only GPUI test-support 接线；生产布局保持基线不变。测试覆盖 Q1–Q5，主控审查冻结内容与预期。
2. 通过现有 draft PR 的 `pr-check` 获取目标布局缺失导致的有效 RED。编译/依赖/runner 失败不是行为 RED；没有有效 RED 不进入实现。
3. 在两个引用分支中为横向行约束可用宽度，并将文本放入可收缩、最小宽度为零的 flex 子容器；保持竖线宽度、间距与文本构造不变。必要时复用私有容器构造，避免扩展公共 API。
4. 用同一冻结测试在 Actions 确认 GREEN；不在实现后追加或放宽断言。固定完整测试提交、原始补丁、RED/GREEN run/job 和准确计数。
5. GREEN 后独立删除本卡 Rust 测试及独占接线，审查生产差异不变，并对最新 head 执行完整现有 PR gate，确认 `no Rust tests`（0 发现/0 执行）。空集不代表回归测试通过。

引用装饰现有数值不变：竖线为 2px，间距使用 `Layout::MARKDOWN_CODE_PADDING`（当前 12px）。算术关系为 `文本可用宽度 = 正文列宽 - 2 - 12`，例如 240px 列得到 226px，480px 列得到 466px；测试应从共享 token 取值，不在生产中新增硬编码。
