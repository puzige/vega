# Issue #500 · 运行中选择模型，下一轮生效

## 1. 目标与依据

用户明确：运行中选择模型不应因运行态报错，但实际从下一轮生效。不能禁用运行中的选择器，也不能热切换当前轮。

接手基线：origin/master `9a90ef74`，任务分支 `feat/500-runtime-model-selection`。此前 `410758d3` 上的半成品保留于接手检查点，未交付。

根因：UI 允许选择，app 的运行态 guard 及 conversation 的独占 admission 却拒绝保存。直接改写 `threads.model` 也不安全：自动压缩、checkpoint、replay 使用该值作为当前运行身份。

## 2. 行为契约

1. 运行中允许鼠标及键盘选择模型，包括等待权限/回答时。配置与存储验证成功后，选择器显示新选择并关闭列表，不弹虚假保存错误。配置歧义、无效模型、存储失败仍报真实错误。
2. `threads.model` 保持当前运行身份；下一轮选择独立持久化。当前 provider、推理、工具续轮、压缩、checkpoint、计费与已启动子 agent 不变。不得放宽任何原有模型/source/CAS/权限围栏。
3. 当前运行及自动标题释放 admission 后，获取新的独占 admission 才可把待生效选择写入 `threads.model`。完成、失败、取消均执行相同收尾；切换前禁止下一轮读取旧模型启动。
4. 同一线程多次选择最后一次成功保存获胜。异步回执必须核对请求与模型身份，旧回执不得清除新选择。选择原模型可撤销之前的下一轮选择。
5. 普通发送、排队消息、计划恢复及自动启动都不能越过待生效状态。成功后同步权威线程、推理档位、上下文和 replay 投影，再允许下一轮启动。
6. 路由切换与 Settings 不使成功保存丢失或污染其他线程。重启后恢复持久化选择。draft 没有运行时仍沿用原有内存保存及物化路径。
7. 发送准备、独立可信操作、手动压缩的互斥不变。模式与权限更改不借此放开。保留提供商分组、键盘导航、Esc、真实失败可重试，不新增常驻解释文案。

## 3. 验收矩阵

| 场景 | 必须满足 |
|---|---|
| A 运行中选择 B | 成功显示 B；本轮身份仍 A；无运行态保存错误 |
| 工具续轮/自动压缩/标题 | 继续使用 A，现有身份围栏不变；标题释放后才切换 |
| 完成/失败/取消后的下一轮 | B 生效，推理档位与 B 一致 |
| 排队消息/计划恢复/自动启动 | 不抢在待生效保存前以 A 启动 |
| 连续 B、C 或回选 A | 最后成功选择获胜，迟到回执不能覆盖 |
| 配置错误/存储失败 | 不伪报成功；保留真实错误和可恢复路径 |
| A→其他会话→A、Settings | 不污染其他路由；原线程恢复最新选择 |
| 退出或崩溃后重启 | 已确认的下一轮选择不丢失 |
| 空闲与 draft | 原保存流程不退化 |
| 鼠标/键盘/Esc、提供商分组 | 保留现有交互，不禁用运行中的模型列表 |

## 4. 实现边界与计划

- store 增加独立待生效模型持久化及原子提升操作；保持当前模型列语义，恢复阶段处理前一进程遗留选择。
- conversation 在验证 admission 后提升选择，不改 runtime、压缩或 checkpoint 校验。
- UI 将选择器显示与当前运行身份分开；app 异步保存选择并在准入释放后生效，严格隔离保存回执及路由投影。
- 下一轮启动和队列续跑必须等待提升完成，成功后重投影推理及上下文。
- 移除未接通/重复的内存状态，只保留实际使用的状态。

## 5. 验证与交付

本地仅快速差异、格式和静态检查，不运行 Vega、不编译或执行测试。云端 required check 必须验证最终 head；空集写 `no Rust tests`，不是行为测试通过。非实现者独立审查后方可合并。真实 provider、UI、重启及工具运行由用户手测，未取得结果不标通过。合并后 Issue 开放、Project 为 In review，等待用户验收。

## 6. 修订记录

接手修订：废弃旧稿“运行中直接改 threads.model 并放宽压缩围栏”的实现计划。仅内存暂存不能满足已确认选择的重启恢复要求，因此采用独立持久选择与准入保护下的延迟生效；不修改用户要求的本轮/下一轮语义。
