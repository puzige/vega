## 设计冻结

### H1 表面与节奏

使用既有palette与原生SVG，不更换品牌、不引入Web框架。新增`ThemeColors.bg_subtle`语义，值与现有code_bg相同（Light #F6F6F6 / Dark #262626），专用于内嵌过程和低强调分组；普通阅读平面仍bg_base，表单/输入仍bg_elevated。不改全局正文15px/1.65、控件13px或主侧栏用户持久化宽度。Settings页标题由24改为20px/semibold；区块标题14px/semibold，字段标签13px，说明12px secondary。

新增共享Layout token：SETTINGS_NAV_WIDTH=224，SETTINGS_CONTENT_MAX_WIDTH=720（修改既有值），SETTINGS_LABEL_WIDTH=208，SETTINGS_FIELD_GAP=16，SETTINGS_GROUP_PADDING=16，SETTINGS_ROW_PADDING_Y=12，SETTINGS_NOTES_MAX_HEIGHT=240，PROCESS_PADDING_X=12，PROCESS_ITEM_GAP=4，ASSISTANT_ROLE_HEIGHT=20。数值由唯一theme owner实现，不在组件硬编码。

### H2 设置导航与页面

八路由及顺序不变；Settings独立224px导航，不再继承主任务SidebarWidth；主侧栏本身仍保留拖拽与持久化。导航保留32px行高、16px图标槽、13px标签；八项使用现有语义图标，返回入口保留。主内容水平居中max720、左右最少24px，顶部24px；标题与内容间16px、组间24px。

分组用一层中性细边界或bg_subtle底色，radius12、内距16；不要在同一组中再次嵌套装饰卡片。紧密相关的设置放在同组内，以1px细分隔/12px纵内距分行。标题、说明、动作各自有稳定区域，长中文/CJK/无空格模型名完整可达，不能靠裁切假装适配。

### H3 八页表单与动作

共同字段行：标签/说明区宽208px，随后16px间隔，控件区域紧邻、min-width=0；不使用justify_between把控件推到内容列最右。控件按实际内容收缩或占用本区，普通按钮min28高、横内距12。可用行宽不足容纳标签+间隔+220px控件时改上下排列，8px上下间距；Provider详情窄列允许字段上下排。保持原输入Entity/FocusHandle/action与guard。

- 通用：外观与布局、默认项、更新分组。主题选项保持真实三态；Sidebar开关使用原32×20开关。默认模型与权限控件邻近标签，保留完整可访问名称与原菜单。
- Skills：来源/触发四项、单目录启用/自动触发均用相同32×20开关，沿用原handle_skills_action与禁用原因。说明和路径以secondary表示；名称、可用性与动作先于技术详情；安全状态/授权说明始终完整可见。检查/导入/移除操作不拉伸占满一行。
- 思考：每个profile保留独立分组，以名称+次级协议信息开头，字段按统一列对齐。effort多选使用紧凑28px选项组，选中使用已有中性/品牌软色及check；未选项不叠加重边框。原cycle_*动作保留，显示真实当前值与“更改”轻量动作及准确aria/tooltip，不能伪装成会打开菜单的下拉。
- 提供方、MCP、Agents：名称、地址/可执行文件、参数等编辑字段持续可见标签；保留提供方180px列表和详情两个滚动区、遮罩和并发保存语义。MCP确认/授权步骤及危险说明不折叠、不省略；字段行在窄详情中可上下堆叠。
- 定价：保留计价模型与完整编辑字段，编辑区按字段行/标签层级对齐；普通编辑动作轻量，保存主色，删除danger文字与中性边界。
- 用量：筛选与刷新形成紧凑页头操作区，统计与图表保留真实数据与既有算法，使用共同分组/状态层级。

开关是已有布尔设置的同一入口，不增设状态；保留mouse/Enter/Space恰好一次、disabled不触发和真实焦点环。错误、授权、忙碌状态仍来自原typed state。普通说明不画成报错框。

Settings独立挂载，不经过会话Workspace的Tab代理；未被子控件或专属KeyContext消费的Tab/Shift-Tab由Settings根转交现有focus_next/focus_prev。验证原生产路径上的焦点可达和恰好移动一次，不给测试壳额外注入生产界面没有的委托。

### H3a 原生候选验收补正（2026-10-11）

首个候选在真实已填充页面暴露以下五处可读性问题，本轮只补正这些表现，不改变保存、加载或业务语义：

- 用量指标：长费用字符串必须完整留在所属指标列内，与该指标标签左对齐；允许该值换行、指标自动换行或取得更宽列，禁止溢入前后指标、裁切或删减真实数字。使用合成长费用与未计价计数在宽/窄两尺寸证明真实文本布局受约束，不能只断言父级bounds不重叠。
- 定价编辑：表单顶部显示当前编辑模型的完整名称；新增自定义仍保留可编辑模型ID。模型标题与字段保持12px以上分隔，打开/取消/保存仍沿用原逻辑，不新增自动提交或更改业务导航。
- Agents参数：多行argv输入增加与相邻输入一致的中性边界、背景及内距，保留原Input Entity和FocusHandle，不增设说明或占位业务状态。
- Skills操作区：最后一条设置字段与操作组至少12px间隔；同组操作横向与换行纵向至少8px；来源卡的移除操作与前后说明也保持可辨间距。禁止通过改动触发器、权限或导入行为处理排版。
- 设置页面滚动：各路由内容区有独立滚动身份。首次进入某页从顶部展示，不继承上一页的滚动偏移；返回已读页面可保留该页自身偏移。不在每次render强制复位，不改变Provider双滚动区或发行说明内滚动。用真实路由切换及滚动事件证明首次进入和返回行为。

复验这五处实际原生页面，并在现有受影响测试中保留防重叠/完整内容/操作一次与禁用断言。其余冻结布局不随意改动。

### H4 更新区

当前版本、是否有更新、检查/下载/安装主动作始终可见，并在紧凑区域呈现；自动检查使用共同布尔开关。发行说明默认折叠，仅为UI状态，标题“发行说明”，可鼠标/键盘展开；展开使用已有MarkdownStream/StreamModel/native Markdown renderer，最大240px内部滚动，完整内容可读且不改下载/签名/安装语义。解析只在notes内容改变时更新缓存，不在每次render重新解析。不将未经验证的外链内容作为指令或自动打开链接。

内部滚动复用已有disclosure归属规则：说明区域实际消耗滚动时不带动外层；短说明或到达边缘后允许外层继续滚动。不得通过无条件吞掉wheel事件制造滚动陷阱。

### H5 会话角色、过程与Composer

用户气泡保持右对齐、80%宽与无“你”标签。每个用户轮次内第一条助手正文前显示一次“Vega”次级角色行（20px高、12px、已有16pxAgent语义图标若有；无合适图标则只文字），位于选择/复制文档之外。后续助手正文保持原15px、原Markdown与源内容，不逐段重复角色标记；历史开头缺用户消息时按可见历史边界显示一次。不能将最后一条助手消息或MessageFinished视为最终答案。保持原虚拟条目索引，禁止为此跨条目建立新可折叠整轮容器；计算角色边界沿用真实User/Assistant条目，不扫描文案。

已有RunActivity/RunActivitySegment按原位置呈现统一bg_subtle过程表面、1px border_subtle左边界、横内距12、内部间距4；保留28px标题与13px过程字、16px图标及真实状态。被助手正文隔开的过程段不可搬家合并。Thinking/Tool/ToolGroup内部不重复叠卡片背景；旧独立过程路径也使用同一语法。240/320高度上限、内部滚动与最新展开/完成折叠行为保持。权限审批仍独立可见，不并入过程折叠内容。

云端验收算术澄清（2026-10-11）：ToolGroup的320px是可滚动内容体上限，子工具详情上限仍240px。展开组总高度上限为28px标题＋本轮4px间距＋320px内容体＝352px；旧总高公式348px缺少本轮已冻结的间距。回归须同时精确检查这三部分、内容体≤320和详情≤240，并保留原嵌套/外层滚动断言，不能只扩大一个总高容差。此澄清不修改生产尺寸或滚动行为。

正文/Composer宽度、36px安全内缩、40px回到底部固定行不变。Composer移除常驻阴影，仅保留1px细边界、原20圆角和min100高；send/stop/权限/model全部可达，不恢复底栏分支。

### H6 导航降噪与壳层一致性

消息rail保留20px命中、每个锚点、预览、键盘及历史定位。静态普通4px标记使用border_subtle；hover或focus时普通标记恢复text_tertiary，当前位置/选中6px accent不变。轨道保留1px细线，不额外动画、不改变命中位置。角色行/过程内距新增高度必须纳入现有估算与实测路径，不能以像素改动破坏滚动定位。

高度估算遵循真实展开状态：RunActivity标题28px，已折叠的RunActivitySegment为0px（既有renderer本来返回h0），正文仍为正高度。旧“所有条目估值都大于0”断言按这些精确条件更新，锚点数量、顺序、身份与定位断言保持。

主Sidebar只统一内置栏目文案：“项目”“最近任务”“已固定”“展开更多”“收起”，不改用户自定义名字、宽度、折叠或排序语义。标题栏、Environment、终端/Review停靠与搜索结构继续保留；验收其共享控件与主题一致性，不扩展新功能。

## 算术与验收矩阵

- 960px窗口：导航224px包含其1px尾边界，960−224−2×24=688px设置内容；带1px边界的组内688−2×(16+1)=654px；208+16+220=444px，两列可容纳。
- 1403px窗口：1403−224−48=1131px可用，内容钳制720；带1px边界的组内686px，字段控件起点=组左+1+16+208+16=组左241px。仅底色无边界分组对应688px与240px；测量依据实际是否绘制边界，不额外补空白。
- Provider内部列表180px加间隔后，详情不足444px时字段上下排列；不能强保两列。
- 32×20开关在28px控制槽的上下余量为(28−20)/2=4px；16px图标在28px控制槽的上下余量为(28−16)/2=6px；20px角色行的16px图标上下余量为(20−16)/2=2px。

实施期算术校正（2026-10-11）：上式显式计入可选1px组边界；不改变冻结的padding、标签宽度或控件间隔。32×20开关本体放在28px控制槽居中，与字段标签首行对齐；焦点环不得改变其几何。

## 分工、交付与循环

Settings owner只改settings及直接测试；stream owner改conversation_stream、Thinking/Tool相关表现及直接测试；shared owner独占theme token、Sidebar内置文案与直接测试，并承担组合构建验证。主agent准备规格、集成、代码审查、原生操作、Issue/PR/合并。无新增代码注释，unsafe最小SAFETY例外。

使用原隔离集成worktree的新feature分支，从最新origin/master起步；旧本地分支和所有旧worktree保留。子片使用新的隔离worktree、默认独立target，不覆盖旧脏副本。每轮PR最多3个提交，后续修正折叠到本轮提交；不重开#291、不覆盖#294工作树。

先实现与定向检查，再打包候选。核验签名、bundle、架构、来源/源码hash；仅正常停止必要的真实任务、正常退出并确认进程结束，zip备份旧安装，原位替换/失败回滚，明确路径启动。当前应用ad-hoc，无TeamID；同方式候选不冒充正式发行签名。候选使用三段版本号并单独记录commit与binary SHA，避免updater不支持后缀版本影响验收。主agent查看实际界面，不达V8就修复后再build/install/review。真实秘密不用于自动测试，不修改用户配置来伪造通过。

云端绿→squash合并→正式发布安装身份再确认→原生复查。用户要求的修复验收循环优先于旧的立即停止规则；不得以测试全绿代替视觉判断。Issue保持开放直至用户认可主观视觉效果，本地工作树保留；最终报告明确自动/原生已验证及仍需用户主观确认的边界。回滚为整体revert与恢复已验证安装zip，无数据迁移。
