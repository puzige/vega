# Issue #64 — 上下文占用指示

## 用户场景

在已有会话中，用户希望不离开 Composer 就能查看当前输入上下文大约占用了多少，以及当前配置的容量还有多少。Issue #64 的参考图展示模型选择器旁的圆环指示器；悬停提示为 `52% full` 和 `135k / 258k tokens used`。

## 现状与事实

- 会话加载时，Conversation 服务已有包括系统提示与当前运行模式工具定义的输入 token 估算；运行期间也会更新预测输入量。
- 可用容量只有会话 `ContextSettings.context_limit` 中明确配置的值。未配置时为未知；模型策略中的未编辑默认值是 Vega 的估算假设，不是供应商验证过的容量。
- 估算输入 token 与供应商报告的实际 token usage 不等价。
- 当前 Composer 没有可见的上下文占用指示器。

## 行为约定

1. 在现有 Composer 模型选择器左侧显示紧凑的圆环指示器，不新增常驻文字行或改变 Composer 整体高度。
2. 已有输入估算时显示指示器；新任务没有估算时不显示。容量未知时圆环保持中性、无填充，但仍可查看估算值。
3. 鼠标悬停或键盘焦点展示同一个提示。提示包含“上下文窗口”标题与估算输入 token 数。仅当当前会话容量已配置且大于零时，显示使用百分比和估算值/配置容量；否则清楚写明“容量未配置”，不展示百分比。
4. 百分比由 `estimated_tokens / context_limit` 计算，四舍五入到整数。使用量超过配置容量时显示真实的超限百分比，圆环视觉填充最多到 100%；不可因渲染上限而改写文本数值。
5. 标签明确称为“估算”。分子按现有会话投影的输入 token 估算，包括系统提示和实际工具定义。分母称为“当前设置上限”，不得声称是供应商验证容量。
6. UI 使用紧凑格式（如 `135k / 258k`）；辅助技术文本提供完整数字和估算/配置来源。
7. 会话、模型或 route 切换时不能短暂展示上一会话的数值；新投影或运行中估算到达后更新指示器与提示。无估算时不伪造 `0`。
8. 指示器只读，不启动请求、不改变模型选择、发送状态或自动压缩策略。颜色、文字和尺寸沿用 Vega theme token；浅色、深色均可辨识。

## 范围与非目标

- 范围：Composer 模型选择器附近的上下文占用圆环、hover/focus 提示、紧凑数字格式、对应单元与 GPUI 测试。
- 复用现有会话输入估算与 `ContextSettings.context_limit`；本卡不新增 provider 请求、容量发现、数据库 schema 或自动压缩行为。
- 不把产品默认假设当作验证容量；不保存或展示 prompt、回复、凭据或其他会话正文。
- 不复制参考产品的内部实现或私有资产；只实现 Vega 自有的状态与视觉。

## 实现计划

1. 在 `vega_ui` 内为指示器提取纯显示模型，单独覆盖百分比、超限填充与紧凑数字格式。
2. 从当前 `ConversationStream` 的估算与配置上限派生显示模型；不添加跨 crate 类型或依赖。
3. 将圆环挂到现有 Composer 模型选择器旁，复用 theme token，并让 hover、键盘 focus 与可访问文本共用同一显示模型。
4. 先写 C64 对应纯函数和 GPUI 回归，再实现并运行 `cargo nextest run -p vega_ui issue64_context_usage_`；不跑本地 workspace 全量测试。
5. 主 Agent 审查变更、更新交付记录、开 PR 并等待云端门禁。合并后在真实 Vega 桌面端用 Computer Use 检查已知容量、未知容量、hover/focus 与主题显示。

## 真实桌面验收

- 打开已有会话并确认圆环位于模型选择器左侧，不改变 Composer 高度。
- 将鼠标悬停后核对估算输入量、配置上限与百分比；用键盘焦点重复确认提示内容相同。
- 检查容量未配置时没有百分比/猜测上限，切换会话后不显示旧值。
- 若本机没有可控的已知/未知容量会话，分别使用符合上述数据状态的 GPUI 测试；桌面记录里标清未能覆盖的场景，不伪称通过。
