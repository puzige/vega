# Issue #64 — 上下文占用指示

## 用户场景

在已有会话中，用户希望不离开 Composer 就能查看当前输入上下文大约占用了多少，以及当前配置的容量还有多少。Issue #64 的参考图展示模型选择器旁的圆环指示器；悬停提示为 `52% full` 和 `135k / 258k tokens used`。

## 现状与事实

- 会话加载时，Conversation 服务已有包括系统提示与当前运行模式工具定义的输入 token 估算；运行期间也会更新预测输入量。
- 对 #64 圆环而言，可显示容量来自当前已启用且唯一匹配的 provider/model 对中显式保存的模型输入上限。没有唯一 provider、没有已保存策略或输入上限为 unknown 时，圆环不显示容量分母。
- 每会话 `ContextSettings.context_limit` 是旧数据，不是此指示器的容量来源；模型策略中未编辑的默认假设也不显示为圆环容量。此展示规则不改变 #76 的运行时契约：运行时仍可把无策略行解释为默认预算，而圆环在无显式保存行时不显示百分比。两种来源都不得被称为供应商验证容量。
- 估算输入 token 与供应商报告的实际 token usage 不等价。
- 当前 Composer 已有此前交付的输入估算圆环；本次修复的是容量来源，使其使用精确 provider/model 策略中显式保存的输入上限。

## 行为约定

1. 在现有 Composer 模型选择器左侧显示紧凑的圆环指示器，不新增常驻文字行或改变 Composer 整体高度。
2. 已有输入估算时显示指示器；新任务没有估算时不显示。容量未知时圆环保持中性、无填充，但仍可查看估算值。
3. 鼠标悬停或键盘焦点展示同一个提示。提示包含“上下文窗口”标题与估算输入 token 数。仅当当前 provider/model 的模型策略中存在大于零的显式保存输入上限时，显示使用百分比和估算值/模型设置输入上限；否则清楚写明“容量未配置”，不展示百分比。此条件只控制指示器呈现，不改变 #76 运行时对缺少策略行采用可编辑默认预算的语义。
4. 百分比由 `estimated_tokens / model_input_limit` 计算，四舍五入到整数。使用量超过配置容量时显示真实的超限百分比，圆环视觉填充最多到 100%；不可因渲染上限而改写文本数值。
5. 标签明确称为“估算”。分子按现有会话投影的输入 token 估算，包括系统提示和实际工具定义。分母只取精确 provider/model 对的显式保存输入上限，不使用输出预留；称为“当前模型设置上限”，不得声称是供应商验证容量。模型策略必须由既有唯一启用 provider 规则解析；仅凭 model ID 或 legacy per-thread setting 不得推断 provider。
6. UI 使用紧凑格式（如 `135k / 258k`）；辅助技术文本提供完整数字和估算/配置来源。
7. 会话、模型或 route 切换时不能短暂展示上一会话的数值；新投影或运行中估算到达后更新指示器与提示。无估算时不伪造 `0`。
8. 指示器只读，不启动请求、不改变模型选择、发送状态或自动压缩策略。颜色、文字和尺寸沿用 Vega theme token；浅色、深色均可辨识。

## 范围与非目标

- 范围：Composer 模型选择器附近的上下文占用圆环、hover/focus 提示、紧凑数字格式、对应单元与 GPUI 测试。
- 复用现有会话输入估算与精确 provider/model 对的显式保存输入上限；不把旧 `ContextSettings.context_limit` 或未编辑的 assumed default 用作圆环分母。本卡不新增 provider 请求、容量发现、数据库 schema 或自动压缩行为。
- 不把产品默认假设当作验证容量；不保存或展示 prompt、回复、凭据或其他会话正文。
- 不复制参考产品的内部实现或私有资产；只实现 Vega 自有的状态与视觉。

## 实现计划

1. 在 `vega_ui` 内为指示器提取纯显示模型，单独覆盖百分比、超限填充与紧凑数字格式。
2. 从当前 `ConversationStream` 的估算与模型策略显式保存输入上限派生显示模型；读取策略前用配置中的唯一 provider resolver 得到精确 provider/model key，不增加 provider 请求或配置持久化。
3. 将圆环挂到现有 Composer 模型选择器旁，复用 theme token，并让 hover、键盘 focus 与可访问文本共用同一显示模型。
4. 先写 C64 的 provider/model 隔离、legacy 行为、stale owner 与 GPUI 回归，再实现并运行变更 crate 的定向 Nextest；不跑本地 workspace 全量测试。
5. 主 Agent 审查变更、更新交付记录、开 PR 并等待云端门禁。合并后在真实 Vega 桌面端用 Computer Use 检查已知模型设置容量、未知容量、hover/focus 与主题显示。

## 2026-10-05 修订：容量归属与读取来源

- 原生复验发现：设置中当前选中模型已有显式模型上下文策略，而 Composer 指示器仍显示“容量未配置”。该缺陷说明原 #64 的会话级容量来源已过时。
- 按 [Issue #76 模型归属更正](vega-issue-76-model-context-correction.md)，模型容量归属精确 provider/model 对；本指示器只展示显式保存的模型输入上限，不展示输出预留、legacy per-thread 上限或未编辑默认假设。该展示选择不更改 #76 运行时对缺失策略行使用默认预算的规则。
- provider 必须通过当前唯一启用 provider 规则解析。缺配置、provider 不唯一、策略不存在或输入上限为 unknown 都保持“容量未配置”。估算、百分比/超限呈现、交互和只读约束不变。
