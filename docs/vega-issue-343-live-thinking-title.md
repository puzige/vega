# Issue #343 · 运行中的思考标题跟随后续可读内容

来源：[Issue #343](https://github.com/puzige/vega/issues/343)。用户看到思考详情仍持续追加，但阶段标题停在较早的短语。当前 #71 提取器一旦遇到 Markdown 小标题或整行加粗，就拒绝后续普通段落；同时已有 summary 永远优先于后来到达的 thinking。这两条规则都能造成该现象，仅凭截图不能确认实际命中哪一条。

本规格仅修正实时标题的更新选择。它取代 [#71 规格](vega-issue-71-reasoning-summary.md) R1–R3 中“小标题保持到下一小标题”和“非空 summary 永远优先于后续 thinking”的规则。#329 的[前缀回退](vega-issue-329-prefix-rollback.md)继续适用：不添加固定 `Thinking ·`。其余 #71 的提取安全、资源上限及 #296 的阶段布局、展开、工具/正文归属规则不变。

## 行为契约

- 同一来源内，新的可读 Markdown 小标题或普通段落都能更新标题。未完成的 Markdown 标记、空白、代码围栏内部内容不清除已有可读标题，也不抢占另一来源。
- summary 与 thinking content 各自增量提取预览；最近一次**产生新可读预览**的来源决定显示标题。后来的有效 summary 可再次接管；后来的有效 thinking 也可替换旧 summary。无可读预览时沿用「思考过程」占位，不制造思考块。
- 标题最多 96 个 Unicode 标量；长小标题保留开头，长普通段落保留最新尾部。增量处理和 UTF-8 分片规则沿用 #71，不扫描整个思考原文，不增加新的模型请求。
- 会话阶段行与独立思考行的运行中标题使用同一当前预览；可访问名称与可见标题一致。终止后保留最后一次有效标题；展开原文、复制内容、折叠/键盘行为和 shimmer 样式不变。
- 不改 provider 协议、事件、存储、思考原文、工具、正文或安装方式；公开证据只用合成文本。

## 验收矩阵

| ID | 输入与状态 | 预期 | 验证 |
|---|---|---|---|
| T1 | content 先有 `## 旧小标题`，随后普通段落分片继续 | 标题逐步转为最新可读段落，不停在小标题 | 进程内预览与 GPUI 回归；云端 PR Check |
| T2 | content → summary → content → summary | 标题依次跟随四次有效预览；无固定前缀 | 进程内 GPUI 回归；云端 PR Check |
| T3 | 某来源追加空白、未完成标记或围栏代码 | 既有可读标题保留，另一来源不被无效内容抢占 | 单元与 GPUI 回归；云端 PR Check |
| T4 | 超长中英文段落、跨 UTF-8 delta、标题行 | 不超过 96 标量，长普通段落显示最新尾部，标题行保留开头 | 单元与现有界限回归；云端 PR Check |
| T5 | 阶段/独立思考行在运行、终止、展开、收起时 | 可见标题与可访问名称一致，原文/交互不变 | 进程内 GPUI 回归；云端 PR Check |
| T6 | 合并后真实模型持续输出思考 | 上方阶段标题随下方新可读内容更新 | 用户原生手测 |

本地仅进行快速静态检查，不编译、构建或运行耗时测试。云端 PR Check 执行格式、Clippy、nextest；不把未运行的本地测试标为通过。回滚为回退本卡 PR。
