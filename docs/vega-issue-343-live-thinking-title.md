# Issue #343 · 思考过程的信息层级与实时反馈

来源：[Issue #343](https://github.com/puzige/vega/issues/343)。用户看到思考详情仍持续追加，但阶段标题停在较早的短语。当前 #71 提取器一旦遇到 Markdown 小标题或整行加粗，就拒绝后续普通段落；同时已有 summary 永远优先于后来到达的 thinking。这两条规则都能造成该现象，仅凭截图不能确认实际命中哪一条。

2026-10-13 用户手测修订：PR #346 的“最近可读来源优先”会让后续原始 thinking 覆盖已收到的 summary，与期望不符。本规格改为 summary 替换模式：出现可读 summary 后，标题只由 summary 更新；常规展开内容也只展示 summary。原始 thinking 仍可接收并保存在当前块，但不主动展示。该修订取代本文旧版“较晚来源优先”及 [#71 规格](vega-issue-71-reasoning-summary.md) R1–R3 中“小标题保持到下一小标题”的规则；#71 的 summary 优先原则继续适用。#329 的[前缀回退](vega-issue-329-prefix-rollback.md)继续适用：不添加固定 `Thinking ·`。其余 #71 的提取安全、资源上限及 #296 的阶段布局、折叠、工具/正文归属规则不变。

2026-10-14 用户手测修订：阶段展开时外层与内层重复同一条预览。DeepSeek 流可能只有详细 thinking，GPT 流可能只有 summary；按收到的事件决定展示，不根据模型名称推断。summary 适合替换外层标题，详细 thinking 不应被截成不断跳动的外层标题。该修订取代前一日“常规展开区展示 summary”的要求；工具进度独立于思考 disclosure 保持可见，不让用户长期等待。[#296 信息流契约](vega-desktop-ui-unification.md)中相冲突的嵌套标题与折叠默认值以此为准，其余布局和交互继续适用。

2026-10-14 用户再次手测：连续的思考与命令循环出现多组重复的 `Thinking` 和单条“已运行命令”，没有收成一个可扫读的过程。默认视图应让无可见正文隔开的循环共用一个外层阶段，并把多条命令收成一个可展开的工具组；运行、审批与错误反馈仍需及时可见。纯空白的正文增量不能单独制造视觉阶段，真正的正文仍是边界。这项修订细化下文的阶段和工具归属规则，不改变用户可见的真实正文或工具事件。

2026-10-14 用户继续手测 GPT 6：外层已有 `Thinking`，其后的查找、读取、命令、编辑和搜索失败仍逐条露在外面。用户要求这些工具记录收进同一个 `Thinking` 展开区。本次修订取代上文及 T9–T12 中“外层折叠时工具行仍可见”的展示规则：默认只显示阶段标题与简洁、真实的运行或待处理状态；打开阶段才显示按原事件顺序排列的思考和工具记录。真正需要处理的审批、阻塞及错误不能被静默掩盖，但状态提示不应把整列工具记录重新铺在外面。产物和正式正文仍保持独立可见。

2026-10-14 第四轮用户手测：`Thinking · 正在运行命令`、`Thinking · 失败 2 · 拒绝 4` 等尾缀仍然太吵；连接中断后的“正在重新连接”也不能被思考 disclosure 收起。本轮裁决取代上段“折叠标题附近显示工具状态”的设计：外层标题只表达 `Thinking` 或真实 summary，不附加工具动作、计数、失败或拒绝文案。工具级失败／拒绝是模型可能自行恢复的过程记录，仍在用户主动展开的详情中；不得把它们逐条搬到 feed 制造新噪音。需要用户处理的权限请求、连接重试、整轮失败及其他真正阻塞事项是独立 feed 记录，不能依赖 Thinking 展开状态才能看到。重试恢复后移除临时状态，终态错误保持可见或可再次访问。

## 行为契约

- 同一来源内，新的可读 Markdown 小标题或普通段落都能更新预览。未完成的 Markdown 标记、空白、代码围栏内部内容不清除已有可读预览，也不抢占另一来源。
- summary 与 thinking content 各自增量提取预览。尚无可读 summary 时，thinking 的最新可读片段只用于内层思考行；一旦 summary 产生可读预览，本块进入 summary 替换模式，后续 thinking 不能再抢占。后续 summary 继续更新预览。空白、未完成标记或代码围栏不触发模式切换；没有可读 summary 的外层始终显示 `Thinking`，不把详细思考截成跳动的标题。
- 有可读 summary 时，阶段展开区不再渲染该思考行；思考块内部保留 #351 的 summary 优先来源与复制数据，后续 thinking 增量不会把原文重新放回展示。summary 尚无可读预览时外层保持 `Thinking`，避免流式标记造成标题闪空。没有 summary 时，展开内容仍为原始 thinking。当前块保留真实收到的两种文本，不虚构摘要，也不改变事件归属和存储边界。
- 标题最多 96 个 Unicode 标量；长小标题保留开头，长普通段落保留最新尾部。增量处理和 UTF-8 分片规则沿用 #71，不扫描整个思考原文，不增加新的模型请求。
- 外层阶段始终存在于有 thinking 或 summary 的阶段。尚无可读 summary 时，外层只显示 `Thinking`；一旦出现可读 summary，外层改为最新的可读 summary 预览，后续 summary 增量持续替换它，展开状态不改变标题。summary 已在外层表达，展开区不再生成重复的 summary 思考行；用户打开外层后，工具与原始思考按真实事件顺序显示，产物继续独立可见。只有详细 thinking 的阶段，外层不使用原文预览；用户展开外层后保留实时更新的内层思考预览行，原文仍由内层 disclosure 控制。只有 summary 且没有工具等可展开内容时，外层仅作状态行，不提供点开后空白的展开操作；有工具时，summary 标题仍可点开查看工具。
- 没有用户操作时，只有思考内容流式更新不会自动展开外层或详细思考；现有运行时钟和动态状态说明仍在工作。用户主动展开外层后，内层思考预览随 delta 实时更新，但内层详细正文保持折叠，只有再次主动展开内层才可查看。用户手动收起外层或内层后，后续 delta 不得反复替用户打开。用户手动打开的外层不会因思考结束而自动收起。
- thinking 与工具继续按事件顺序进入当前消息的活动阶段。工具先到且当前阶段没有 thinking 时，工具行直接显示，不创建空外层；同一阶段后来出现 thinking 时，已有工具也归入该阶段的展开内容，保留原始顺序。没有可见正文隔开的多轮 thinking／工具事件共用该阶段；纯空白正文增量不单独切段，后续确有正文时仍按原内容呈现。只要阶段含 thinking，折叠时不渲染单条工具行或工具组，展开时逐条显示真实工具记录与思考行。纯工具阶段沿用现有相邻工具合并。只有实质正文开启后，后续活动才进入新阶段；不把跨正文的整轮过程改成一个长期折叠的总块。
- 折叠阶段只显示 `Thinking` 或当前可读 summary，不在标题后追加运行命令、工具数量、失败或拒绝状态；可访问名称也不朗读隐藏的工具计数。运行计时与真实的流式变化提供等待反馈。工具级失败、无效调用、拒绝和成功一样保留在展开详情及原始复制数据中，不额外生成 feed 噪音；若运行整体失败，则由已有运行错误机制在 feed 独立提示，不能只藏在阶段详情。用户手动展开后，后续事件实时加入展开区；手动收起后不会被新事件强行展开。只有 summary 的流不制造空的内层思考行；详细 thinking 的运行指示由后续工具、正文、运行终止等实际事件结束，不靠无依据的时间阈值。外层和内层 disclosure 的可访问名称与可见内容一致，键盘与焦点行为保持可用。
- 需要用户处理的权限请求在 feed 保持独立可操作入口，不依赖展开阶段。连接重试使用独立的 feed 状态行，阶段无论展开、收起或因重试回滚，重连信息均可见且位于阶段之外；尝试次数原位更新，恢复后消失。重试耗尽或其他整轮错误以独立的 feed 错误行展示，不在 Thinking 标题上拼接错误计数，也不因活动阶段折叠、Final 归档或虚拟列表复用而消失。纯工具阶段、产物与正式正文维持原有边界。
- 不改 provider 协议、事件、存储、思考原文、工具、正文或安装方式；公开证据只用合成文本。

## 实现计划

调整 `RunActivityGroup` 的阶段标题、可见子项投影与高度估算；保留 `ThinkingBlock` 的内层手动展开行为，以及 #351 的来源优先、文本存储与复制逻辑，不改 provider 协议。先建立 T8–T10 的合成流 UI 断言，再实现两种来源的展示。运行中工具、审批、错误和跨正文分段必须进入回归范围。本地只做快速差异、格式/静态检查，完整编译和测试由云端 PR Check 执行。回滚为回退本次修订 PR。

本地仅进行快速静态检查，不编译、构建或运行耗时测试。云端 PR Check 执行格式、Clippy、nextest；不把未运行的本地测试标为通过。回滚为回退本卡 PR。
