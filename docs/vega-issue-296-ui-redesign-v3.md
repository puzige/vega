## 2. 壳层、侧栏与阅读导航

### 2.1 几何提案

下表是评审用逻辑像素，批准后进入共享 token；不是 Apple/GPUI Kit 强制数值。未列出的主壳层数值沿用设计守则 §6。

| 项目 | 提案 | 理由及约束 |
|---|---|---|
| Settings footer | 按钮高 32，左右/底部 inset 12，外层顶部间距 4，总占高 48 | `4+32+12=48`；取消额外 min-height/flex 撑高，保留按钮内距与圆角 8 |
| 侧栏任务尾部 | 52 宽动作槽，槽外至行右边缘留8；两个动作各24，间距4 | `24+4+24=52`；尾部总预留`52+8=60`；spinner16居中于最后24槽，标题在动作槽前截断 |
| 阅读安全边距 | 阅读面板左右各至少 32 | 正文/Composer 仍同轴、最大宽 768；左边距内安放导航，不侵入正文 |
| 锚点 rail | 宽 24，距面板左缘 4；每项命中高 16，线段默认 8×2、hover/当前项 16×2 | 独立于正文块高度；线段与命中框分离，是密集导航的明确尺寸例外 |
| 刻度窗口 | 最多同时显示 9 项，144 高；位于消息视口垂直中央 | `9×16=144`，不是铺满长文高度的点线；项少时自然收缩 |
| 回到底部 | 按钮 32×32，箭头 16，外层导航带 40 | 上下各 4；继续保位，无常驻文字、无消失后的高度跳变 |
| Provider 主从 | 总宽最多 720；列表 180，间距 24，详情 516 | `180+24+516=720`；详情不足 440 时切为列表/详情逐层页 |

侧栏短标题不会因为 spinner 消失或 Pin/Archive 出现而改变宽度。默认 spinner 占最后一槽；hover / focus / menu-open 时该 52 区域切为操作，不同时挤进第三个状态图标。任务的运行语义仍保留在可访问名称和状态提示中；菜单关闭、指针移开且无焦点后恢复状态。选中态始终独立存在。已结束/未读等状态也消费同一槽位规则，禁止另堆徽标。

### 2.2 锚点与滚动

- 不再画贯穿正文的常驻竖线/小方点。rail 位于消息面板的左侧 gutter，刻度映射稳定消息/轮次身份，不把其 y 坐标当成实际文档高度。
- 保留全部已有导航目标；超过 9 项使用 rail 自身的可滚动窗口，指针在 rail 内滚动切换刻度窗口。当前目标默认进入刻度窗口，但用户正在浏览/hover 时不抢窗口。不得用抽样丢弃旧目标。
- hover / 键盘 focus 时刻度加长、加深，并显示邻近预览：消息角色、简短正文摘要；无可预览内容则用类型/状态名称。最多三行，不展示隐藏凭据或工具原始参数。预览不自动发起总结请求。
- 点击定位到目标开头；被折叠的目标先按需展开所属过程，再定位。历史水合完成后按稳定 ID 重定位，不按过期索引或当前总高度猜位置。流式追加不改变既有目标身份。
- 当前阅读目标与 hover 目标分开；上下键移动刻度焦点、Enter 定位、Esc 关闭预览。键盘能访问所有目标，不能只给微小刻度鼠标命中路径。
- 正文滚动、rail 滚动、展开详情滚动有明确归属，不同时移动两处。点击锚点退出跟随底部；点击向下按钮调用原有 `resume_tail` 恢复跟随。
- 40 高阅读导航带保留在消息区与 Composer 之间；按钮按真实“未贴底”状态显示，保留 tooltip/可访问名称“回到底部”。不浮在最后一行正文上。

### 2.3 窄窗口、面板与设置

正文宽度公式为 `min(768, 消息面板可用宽 - 64)`，Composer 使用同一公式。以 960 窗口、304 Sidebar、暂不计分隔线为例，可读宽 `960-304-64=592`；实际实现需从测得 content bounds 扣除边框，不凭窗口外尺寸硬算。

设置内容宽为 `min(720, 设置主区域可用宽 - 48)`，左右至少 24。主从所需最小宽 `180+24+440=644`，低于该宽使用单列逐层页面。1403 宽窗口在 224 导航、两边24边距后有 `1403-224-48=1131`，取720；960 时为688，详情484，仍能容纳主从。高缩放或面板更窄时按实际内容宽退化。

主 Header、Workspace、Terminal、Environment 本轮接受同一图标/控件状态巡检；保留既有可见性、拖拽、焦点和响应式行为。Composer 底栏分支保持移除，不重做 #294/#295。

## 3. 单次请求的信息流契约

### 3.1 展示单位与可信阶段

“本轮”指一次用户提交至其执行终态的 run，包含多次模型响应和工具循环；不是列表里的最后一条 message，也不是每次流式片段。

目标展示投影需要明确区分：用户消息、过程说明、思考摘要、思考详情、工具调用、最终答案、错误/权限/待用户输入。原始事件与顺序不变；折叠只是投影，不删除、不改写、不跨 run 合并历史。

| 阶段 | 默认可见内容 | 折叠与时长 |
|---|---|---|
| 已开始，尚无有用内容 | Working for …；Thinking | 思考/工具详情默认收起；低强度文字 shimmer |
| 持续思考 / 中间说明 | 已到达的助手过程说明按序展示；当前可信摘要替换 Thinking | 说明正文可读；思考和工具仍默认折叠；时间持续 |
| 工具执行 | 真实操作摘要，如“正在运行命令” | 工具详情默认折叠；单操作时长贴近标题，不冒充 Thinking |
| 等待权限或用户回答 | 具体问题/权限操作常驻可见 | shimmer 停止；状态改“等待确认/等待回答”，不得收进隐藏过程 |
| 可信最终答案开始 | 先前过程归入一条可展开过程摘要；最终答案流式可读 | 默认收起过程一次，之后尊重手动展开；时间继续 |
| 完成且有可信最终答案 | Worked for … 与过程展开入口；最终答案 | 停止时钟/动效，保留全过程可检索可展开 |
| 失败、取消或无 final | 错误/终止状态及已经产生的有效正文 | 不伪造最终答案，不隐藏唯一结果；思考/工具可折叠 |

默认布局示意（均无整块过程灰底）：

```text
运行中                            完成后（具有可信 final）
Working for 22s                    › Worked for 1m 18s
────────────────────             ────────────────────
中间进展说明……                    最终答案正文……
› 正在核查配置  [文字 shimmer]
› 运行命令 · 5s
另一段进展说明……
```

### 3.2 必须先解决的阶段信号

当前代码核查结果：

- Native 的 `assistant_message_id` 被用作 run ID；工具循环结束才产生 `RuntimeEvent::Finished` 并映射 `MessageFinished`，不是每个模型 response 都结束 run。但 `TextDelta/ThinkingDelta/SummaryDelta` 没有足够的 final-start/正文归属信号，不能在首 token 确定是否还会继续调用工具。
- ACP 当前把 `agent_message_chunk` 追加到同一 assistant buffer，并处理工具事件；未消费足够的 thought/summary/channel 阶段信息。prompt 非取消结果被映射成 End，不能据此推断每段文本都是最终答案。
- 后续需要在既有事件模型上冻结 run、segment 的稳定身份与类别、final 的可信来源、终态和历史持久化映射。不得只加 UI 布尔值或以“最后一段/文案关键词/暂时没有工具/空闲超时”猜最终答案。
- 若后端只能在终态确认正文类别，则只在确认后收起有归属的过程。若连终态也无法分辨过程/最终正文，**保留全部助手正文，仅折叠已知工具与思考**。这属于明确降级，不算完成“final 首 token 收起”的完整目标。
- Native 与 ACP 分别验收，不用一条线路的成功替代另一条。历史没有阶段元数据时采用上述保守降级，不以新的启发式改写旧记录。

证据位置：[native entry](../crates/vega_conversation/src/agent/entry.rs)、[runtime events](../crates/vega_runtime/src/agent/mod.rs)、[loop](../crates/vega_runtime/src/agent/loop_.rs)、[ACP adapter](../crates/vega/src/codex_agent.rs)。

### 3.3 摘要、操作和动效

- 使用正确拼写 **Thinking**；有真实可用摘要时直接以摘要替换。摘要默认单行并保持28高标题，长摘要省略，完整文本可展开查看；不每个 token 重启动效或跳变行高。
- shimmer 只作用于当前一条思考/等待摘要文字，提案周期 1.8s、单向柔和扫过，不改变位置、字重、字号；普通正文、工具输出、时长不 shimmer。无需为了动画新增一条模型总结请求。
- 默认 hover 为 120ms 颜色过渡；pressed 即时；展开/收起优先 120ms 的局部淡入，不对长虚拟列表做高度弹簧。Reduce Motion 静态切换；隐藏视图不调度动画。
- 思考、工具、过程的折叠与展开外层都与页面同底。必要的细缩进线只出现在展开详情内；hover 只作用于可点击标题区，不铺满整个组。工具输出/代码面板可保留其内容背景。
- 操作行结构为 `[类别图标] 标题 · 时长 [展开箭头]`，间距依次8/8/8；短标题自然宽，时长紧邻；整行最大不越正文列。长标题先省略，时长和展开箭头不被挤没。取消旧的标题左、时间贴最右 `space-between` 布局。
- 单操作时长仅在底层有可靠起止/持续时长时显示。继续保留现有 Bash 时长能力；其他工具可在提供同等可靠数据后接入。聚合工具组不累加并发子项时长；无真实组时钟时不显示合计。
- 脱敏错误、拒绝与取消语义保持，不通过换成绿色对勾掩盖失败。权限卡、危险确认、提交 guard 和重试机制不受过程降噪影响。

### 3.3a 追加参考：轻量活动行与独立工具详情

2026-10-11 用户追加 Codex 正常界面截图，作为 U11/U12/U16/U18 的结构参考，不新增第19项，也不扩大到新建子agent运行能力。只记录可见层级，不收录原始截图或会话内容；静态图不作为默认折叠、动效或自动收起时机的证据，这些行为仍按本spec单独定义。

| 层级 | Vega采用的表达 | 约束 |
|---|---|---|
| 活动概览 | 小类别图标 + 简短事实，如“已读取文件、搜索资料” | 来自真实已发生事件；无卡片背景，无每条都重复的品牌标识 |
| 阶段摘要 | 简短阶段描述 + 就近展开箭头，如“正在整理结果” | 沿用已有可信摘要；没有摘要才用Thinking；不另发总结请求 |
| 单条工具 | 类别图标 + 动作/对象 + 已知时长 + 展开箭头 | 固定前导槽，名称与元信息相邻；已有文件打开能力可将文件名作为链接 |
| 展开详情 | 独立命令/输出容器 | 低强调类型标签、等宽命令与输出、真实结果状态；只覆盖该条详情 |

这些是可组合的表现，不要求每个工具都套四层容器。相邻可归并事件才生成活动概览，不跨用户消息、助手说明或待确认事件吞并内容；原始顺序和逐项详情仍可追溯。已有子agent状态若进入当前信息流，按普通活动行表达名称和真实状态，不复制参考中的头像资产或新增无数据的状态行。

```text
[读取图标] 已读取文件、搜索资料
[助手图标] 配置审查已完成

正在整理结果  ∨
  [读取图标] 读取 example.rs
  [终端图标] 运行命令 · 2.4 秒  ∨
  ┌──────────────────────────────┐
  │ Shell                        │
  │ $ example-command            │
  │ 无输出                       │
  │                       ✓ 成功 │
  └──────────────────────────────┘
  [终端图标] 下一条操作…  ›
```

- 概览、阶段摘要与工具行使用辅助文字层级，仍须清晰可读；不能用低透明度把实际信息做成禁用态。每一层重复行共享文本起点，只有真实包含关系产生一级缩进，不叠加多层卡片padding。
- 工具详情复用`code_bg`、`border_subtle`、12内距与12圆角提案；类型标签和结果是次级信息。输出正文可选择、复制，仍按§3.5限高滚动。展开箭头跟随标题，不甩到整行最右。
- “无输出”只在该工具已经结束且没有可显示输出时出现；运行尚未返回不能提前写“无输出/成功”。成功状态可低强调并靠详情尾部，失败/拒绝/权限状态仍在收起后可见，不能只藏进详情footer。
- 折叠行只显示易读动作摘要和短对象名；长命令/脚本单行省略，完整且已脱敏的内容进入详情，不把原始多行脚本铺满过程列表。路径沿用已有安全投影，不能借文件链接暴露私有绝对路径或不可打开的假链接。
- “不想要灰底”指过程外层的常驻大色块；此次参考中独立代码/输出详情保留轻背景作为内容边界已随spec获准；不恢复整组灰底或叠加多层阴影。

### 3.4 请求级时长

- 起点为该请求被接受并实际开始执行的时间，不含用户编辑草稿；终点是完成/失败/取消的可靠终态。界面概念为**本轮经过时间**，包括网络、工具及待确认的等待，不宣称是纯模型计算时间。
- 执行中显示 `Working for 22s`，成功完成显示 `Worked for 1m 18s`；待确认时“等待确认 · 已用 …”，失败/取消用对应状态加时长。中英文状态文案集中管理，不散落拼接。
- 阶段切换、工具返回、重绘、切换页面不重置计时；重试属于同一 run 则继续，新用户提交创建新 run。运行刷新不超过每秒一次，时长数字使用稳定宽度布局。
- 终态采用同一起止定义的持久化 duration；若现有字段计时口径不同，先归一或明确区别，不在终态突然换成另一种时长。
- 前台以单调时钟计算，后台恢复和重启需可靠持久化起止/恢复状态；未知历史只显示完成状态，不补造时长。ACP 目前没有持久化 execution duration，须补契约后才承诺历史一致性。

### 3.5 长思考、折叠与阅读位置

- 默认折叠；展开正文最大 240 高、工具组列表最大320，标题留在内部滚动区域之外。短内容自然高度，不空留240。
- 滚动条位于实际滚动区域尾缘：滚动/hover 时可见，系统设置“始终显示”时常显；需要保留文字与滚动条间距。内容确实能滚动，不能只是裁剪显示一部分。
- 流式追加仅在用户仍位于该详情底部时跟随；用户上翻立即停止该区域跟随。内部到边界后交给外层；不要一轮滚动同时驱动内外。
- 最终答案出现时只执行一次默认收起。用户已主动展开并正在阅读、选择文字或 focus 在过程内时，保留该展开与滚动，直到用户离开/主动收起；后续 token 不反复强制关闭。
- 折叠前后以用户当前阅读的稳定对象和局部 offset 保持视口；被收起的目标落到对应过程标题，不突跳到底部。搜索/锚点进入隐藏项可展开它，恢复原文选择与复制能力。

- 提供方列表上方是一组列表动作：“添加提供方”和重新读取图标；重新读取有名称/tooltip，涉及未保存草稿时按现有冲突机制处理。上移/下移若仍为既有能力，收进提供方对象菜单，不能因降噪删除。

- 模型区标题与“发现模型 / 添加模型”同一局部工具栏。发现模型的 loading、失败、重试属于这一区域，不散落到整页。
- 模型行左侧名称及简短能力概览，右侧“配置”与更多菜单；测试在行内次级操作/菜单中，删除收进更多菜单并保留原确认，不让每行红色按钮成为视觉主体。
- 模型测试不自动执行；配置页面进入、hover 或目录刷新不能触发计费模型请求。
- 各区域只有自己的滚动 owner；切换模型/返回保留选择和滚动，表单错误贴近字段。窄屏逐层页返回恢复提供方列表原位置。

### 4.3 模型配置能力保全

| 分区 | 必须保留的内容 | 表示方式 |
|---|---|---|
| 基本信息 | 现有名称/标识、协议或能力字段、输入输出限制等当前可编辑项 | 明确标签与控件；来源可查；不添加后端不支持的伪字段 |

每个分区沿用对应服务的保存/取消与错误反馈；没有跨服务原子事务前，不造一个会部分成功却宣称全部保存的总按钮。切换脏表单有一致的保存/放弃/留在本页处理。

**当前定价是 model 全局键，思考是 (provider, model) 双键。** 第一批入口迁移必须在定价分区清楚标明“此模型的共享价格”，避免用户误以为仅修改当前提供方。若要支持不同中转商独立价格，需在数据批次先冻结身份迁移、价格优先级、run 快照和历史费用不重算；不可把它藏在 UI 重排中顺手实现。

旧思考/定价入口、快捷路径和配置文件继续可达或按语义重定向。没有 provider 归属的全局定价条目仍须有入口管理：放在服务提供方页的“模型价格库”次级管理入口，展示其共享作用域，而不是丢掉这些条目或恢复一级“定价”页。

## 5. Markdown 与阅读节奏

此处是对正文渲染的规格，不改用户/模型原文。主会话保留15px；展开思考从旧过程体13px提升为15px阅读样式，这是新提案，需重测240px限高、虚拟行高度和锚点；折叠摘要维持紧凑13px。

| 元素 | v3 提案 |
|---|---|
| 段落 | 15px / 1.65，段间12；不以每个软换行额外生成段距 |
| 标题 | H1 22、H2 19、H3 17、H4–6 15并用字重区分；前24后12，块首不重复加前距 |
| 列表 | 层级缩进24，项间6；列表内多段间8；列表块外16 |
| 引用 | 左侧细线和12内距，正常可读文字；不做整块灰卡 |
| 代码块 | 12.5 / 1.6，内距12，块外16；保留换行/缩进；长行局部横向滚动 |
| 行内代码 | 与正文基线协调，不把整行行高撑高；保留轻语法底色 |

本轮先保持 15px 正文，修复实际行高和块节奏，避免字号变大但表格/行内代码仍拥挤。若评审要调成16px，统一修改 token、列宽容量和几何预期，不能各页临时调字。

## 6. 模型目录与上下文数据

### 6.1 models.dev 补齐流程

仓库目前没有 models.dev 获取/缓存管线，这是新增数据能力。外部资料只补充 metadata，**Provider 的可用模型列表和实际接口能力不由目录替代**。[models.dev 官方接口说明](https://github.com/anomalyco/models.dev#api)提供目录结构；实现前须按固定 schema 样本核验字段，不以文档名猜 payload。

拟定流程：读取 Provider 可用模型 → 精确匹配 provider/model 或用户确认的 canonical 映射 → 展示补齐预览与来源 → 写入可追溯默认层 → 用户按需覆盖。

- 匹配不靠模糊短名静默套用；别名/中转模型无法唯一匹配时手动选择或保持未知。
- 字段来源优先级：明确用户覆盖 > 经过匹配的 provider 专属目录值 > 明确适用的 canonical 能力默认 > 原有安全默认。**canonical 价格不自动当中转商价格**；Provider 运行限制与实际错误仍有最终约束。
- 价格按现有模型作用域接入，不让某 provider 的一次刷新静默改掉所有共享该模型的费用；provider 独立定价需先通过 §4.3 身份迁移门槛。
- 目录字段须区分总上下文、输入上限、最大输出，按明确类型映射；仅有总容量时先冻结转换规则，禁止把它直接存为输入上限或重复扣除输出预留。
- 思考支持/允许档位可以补齐，用户默认档位保留。外部 reasoning 标识不能自动推导 wire protocol 字段、关闭方式或回传策略，更不能重置已冻结的 run selection。
- 缓存保留来源、获取时间、schema 版本/内容摘要。提案缓存24小时；仅进入相关设置且缓存过期时后台更新，提供手动刷新，不阻塞聊天，不每次渲染联网。
- 失败使用最后一次有效缓存，保留未保存输入；无缓存时显示未知并允许手填。字段缺失不是0/不支持，不删除用户旧配置。数据更新采用校验后原子替换；坏数据不污染已有缓存。
- 获取公开目录不携带 API key、私有 Base URL、任务内容或会话信息；不因拉取目录自动添加、启用、测试模型。
- 展示来源和手动覆盖状态；恢复目录默认是明确操作，refresh 本身绝不覆盖用户值。

### 6.2 上下文环与浮层

Composer 模型控件前放一枚28×28触发器，内环16；它表示当前模型配置输入上限的使用比例，和侧栏运行 spinner 使用不同含义及可访问名称。静态弧段不能做持续旋转。

浮层提案宽320、内距16：标题“上下文用量”，主数字百分比，其旁为“估算 已用 / 配置输入上限”；下方总量条。缺分母不画百分比；缺分子显示尚无数据，不画0%。超过上限的数字保留真实值，图形饱和并显示状态。估算标签常显，不能仅放进help。

三种容量必须分别建模，不能只替换文案：

| 数值 | 来源与语义 | 本轮显示用途 |
|---|---|---|
| 模型配置输入上限 | 当前 `ContextUsageProjection.model_input_limit` 来自保存的 `ModelPolicy.input_limit`；不是供应商验证容量 | **环与主百分比固定使用此分母**，直显“配置输入上限”；help可解释来源及是否为目录补齐/用户覆盖 |
| 本轮输入预算 | 真实runtime/accounting同版本的budget；`ContextBudget.input_budget()`由其自身total_limit减output_reserve | 若拿到可信当前值可在详情另示“本轮可用输入”；未接通则省略，不冒充环的旧字段 |
| 目录上下文总容量 | models.dev或明确模型资料的metadata，有来源和时间 | 属于模型资料；不能代替当前上限或本轮预算，不把未知供应商容量称为验证通过 |

**禁止从模型配置输入上限再减一次输出预留。** 当前管线把配置输入上限B与输出预留O相加，以`total=checked(B+O)`、`reserve=O`构造ContextBudget，故runtime输入预算`(B+O)-O=B`；这个派生total也不是供应商验证的总容量。上限已经是输入限制，和runtime总容量不是同一字段。环的分母不因后台拿到另一种值静默换口径；模型/配置切换需要新的完整版本投影。后续如要改用本轮预算作主分母，需明确改变产品标签、计算与迁移规则，并接入同一run/revision的predicted_input和input_budget，不属于本次纯布局默认。保存配置缺失、显式未知与runtime默认假设分别处理；不能拿默认假设冒充已保存上限。

现有pipeline有总估算及部分provider baseline/增量记录，但UI尚无系统/工具/消息/MCP/Skills的token分类。分两级交付：

1. **总量级**：沿用真实模型配置输入上限及当前总估算，用紧凑浮层表达来源，不把旧字段重新命名为“已验证容量/输入预算”。provider实际input计数若展示，需明确它属于哪次请求；不与当前估算混成精确当前总量。
2. **分类级**：共享accounting获得互斥、无重复分类后再显示分段条和列表。目标分类为系统、工具、对话、MCP、Skills；不全时保留“其他/未分类”并严格对账，不能由message/tool count推算占比。

所有分类百分比使用与主环相同的模型配置输入上限为分母；各项总和对应主百分比。当前上下文、runtime输入预算与累计账单tokens/费用分开，不能借用累计量填图。分类合计仍为估算时，分类同样保留估算语义。

浮层点击保持、Esc/外部点击关闭、焦点回触发器；显示最新上下文 revision，模型切换/压缩后以同一版本重新计算，不能拼旧分子和新分母。配色用可区分的语义分类并配标签，不仅靠颜色。

证据位置：[ContextUsageProjection](../crates/vega_ui/src/conversation_stream/context_control.rs)、[输入上限投影来源](../crates/vega_conversation/src/agent/compaction.rs)、[预算构造](../crates/vega_conversation/src/agent/pipeline.rs)、[现有用量口径](../crates/vega_ui/src/conversation_stream/context_usage.rs)、[ContextAccountingRecord](../crates/vega_conversation/src/types/context.rs)、[ContextEstimate](../crates/vega_runtime/src/context.rs)、[ReasoningProfile](../crates/vega_conversation/src/types/reasoning.rs)、[PricingSettingsService](../crates/vega_conversation/src/pricing.rs)、[ModelPricingSpec](../crates/vega_token/src/catalog.rs)。

文档归档不废除旧测试中的业务断言。后续实现只更新被上述规则替代的几何/展示预期，不删除功能与安全测试以求通过。

## 9. 分批实施提案与验收门槛

本节工作切分已获用户批准。每批按仓库流程明确范围，由专职子 agent 实现，主 agent审查。不要再次做“仅改几个控件但称全 App 已统一”的交付。

| 批次 | 边界 | 通过条件 |
|---|---|---|
| A 共享视觉与阅读 | U01/02/03/05/10/13/14/16/17/18 + 全区域共享状态巡检 | 新布局/样本/阅读与锚点行为可见；保留现有运行状态语义 |
| B 设置对象结构 | U04/06/07 | 六导航、Provider重排、全部字段/旧入口兼容，价格共享作用域明确 |
| C 运行阶段 | U11/12/15 | Native/ACP可信阶段、持久化与降级契约先通过，再接投影与时钟/动效 |
| D 模型与上下文数据 | U08/09 | 目录缓存/匹配/覆盖、定价身份契约、上下文总量；分类有数据才显示 |

可以先完成 A/B 的视觉改善，C/D 的依赖不应阻塞所有 UI；但只有18项各自达到目标或用户接受明确降级，才能声称本轮完整交付。分类图和 final首token折叠不能用样例数据提前冒充完成。

### 9.2 评审时需冻结的设计选择

本草案给出的默认建议为：保持15px正文先修Markdown节奏；保留40px阅读导航带但按钮纯箭头；主设置六项、模型三级分区；第一批价格先明确现有共享作用域；最终阶段与分类用量不足时采用保守降级。上述数值和分批方式现已获用户批准；接口前提按本轮交付记录补充冻结，不能借实现困难静默削减18项目标。
