# 会话导航刻度按中间栏宽度显隐

## 需求与范围

用户要求三栏或中间会话栏空间不足时隐藏消息左侧的导航刻度。本修订覆盖旧版 [阅读导航规则](../296/vega-issue-296-ui-redesign-v3.md#22-锚点与滚动) 在窄栏下仍展示 rail 的行为；宽栏的消息身份、定位、预览和键盘交互保持不变。

## 显示契约

- 以 `ConversationStream.workspace_width`（宿主已扣除侧栏及右侧 Workspace 的会话栏宽度）为准，不以整个窗口宽度或是否三栏为准。
- 宽度达到 `Layout::CONVERSATION_MAX_WIDTH + 2 * Layout::CONVERSATION_PADDING` 时才允许显示 rail，并继续满足已有内容长度条件。当前值为 `736 + 2 × 32 = 800` 逻辑像素；小于 800 隐藏，等于或大于 800 可显示。
- 尚未获得会话栏宽度时不显示，不回退到整个窗口宽度。
- 隐藏时不渲染 rail、预览、命中框或 Tab 目标，清除 rail hover、预览 hover、键盘选中等临时状态。焦点若原在 rail 则释放，不主动聚焦 Composer 或触发滚动。
- 恢复宽度时由当前阅读位置重新选择刻度窗口，不复活旧预览。
- 不改正文留白、正文宽度、Composer、滚动锚点、历史定位或跟随底部。不新增设置、按钮或产品文案。

## 实现与验证

最小改动限定在 `conversation_stream/message_anchors.rs` 的 rail 显示决策和隐藏分支。复用现有布局 token、宿主宽度传播以及布局 observer，无新依赖、后台任务或持久状态。

此为低风险显示条件变更，不临时新增 Rust 测试。本地只执行差异/格式/静态检查；编译、Clippy 和现有检查由最终 head 的 required Actions 验证。独立审查核对宽度来源、边界及隐藏后的焦点/预览状态。真实 UI 由用户手测，CI 不代替验收。

### 用户验收矩阵

| 场景 | 预期 |
|---|---|
| 长会话，会话栏 799 / 800 / 801 | 隐藏 / 按原条件显示 / 按原条件显示 |
| 三栏拖窄或双栏缩窗 | 均按会话栏实际宽度显隐 |
| 全窗口很宽但中间栏不足 800 | 仍隐藏 |
| 宽栏但内容不足原显示条件 | 仍隐藏 |
| hover 或键盘选中时缩窄，再放宽 | 预览关闭、无隐藏 Tab 目标、无旧预览复活 |
| 上滚阅读或跟随底部时切换宽度 | 只沿用既有重排保位，不主动跳到底部 |
