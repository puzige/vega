# 凭据安全检查错误分类与诊断

Issue: https://github.com/puzige/vega/issues/862

## 目标与范围

运行时安全检查失败不能再等同于 API key 无效。凭据读取器将返回内容安全的结构化错误，贯穿主运行、子任务、最终 Provider 边界和摘要。区分凭据缺失/权限/格式/限制、数据库、配置协调、运行授权和工作线程失败；未知原因不得引导换 key。

不修改凭据匹配、隐私例外、授权验证、工具调度、自动重试或 continuation 的消费规则。所有错误仍 fail-closed；继续使用既有恢复收据和上下文恢复，不重放已完成工具。历史无分类记录显示中性的安全检查不可用，不追溯猜测根因。

## 最小实现

1. runtime 新增无文本载荷的凭据读取错误类型，保留阶段、分类和可取得的 SQLite/I/O 元数据；读取器不再返回 `()`。保留旧错误兼容历史。
2. app、MCP、隐私刷新、运行 fence 校验在来源处分类，消费者不再抹除原因。安全错误 Display/Debug 不包含配置、路径、凭据、底层任意消息。
3. 诊断 schema 仅增量添加凭据阶段和原因字段；已有 SQLite 和 I/O 字段沿用。严格白名单验证并同步诊断导出与重开会话映射。
4. 本地化提示区分凭据存储、内部存储/配置暂不可用、运行状态不可用；所有新分类仍走安全 continuation。只有凭据类故障显示凭据设置入口；旧未知错误不做凭据诊断。
5. 快速静态扫查其他模糊错误，单独记录，不自动实现范围外修改。

## 验收与风险验证

- 缺失、权限、格式错误仅凭据提示；数据库 busy/locked、配置协调失败不提示 key 无效。
- 错误在模型请求之前、之后以及准备摘要时均保留阶段/分类；SQLite/I/O 元数据存在时写入诊断，重开与即时提示一致。
- 所有失败仍停止安全边界；不吞错误、返回空凭据或添加隐式重试。
- 已完成工具回执和恢复操作身份不变；新错误与原安全错误一样创建 continuation 收据。
- 中英文键一致，最终无新增 Rust 测试。按项目规则本地只做格式/差异/静态检查；云端 required CI 和非实现者独立审查完成后合并；真实 UI 恢复由用户手测。

## 已有证据与限制

本次历史事件只保留 `runtime / credential_check`，重试成功不能证明数据库锁。不得把候选原因写成已确认根因。本次不读取用户密钥、不修改用户配置或数据库。
