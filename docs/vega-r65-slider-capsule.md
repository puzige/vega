# R65 · 滑块填充左端不是胶囊半圆（规格冻结）

> 状态：**SPEC FROZEN**
> 基线：`master @ 5a0c023`
> 发现：2026-09-15，用户实机截图
> 影响：滑块轨道的填充层左端

---

## §1 现象

用户描述：*"它应该像一个胶囊一样左侧应该是半圆形，右侧应该也是半圆形，现在右侧的正确做出的，但是左侧它是半圆形边缘不对，变成一个矩形，所以现在看一下左右根本就不对称。"*

滑块填充的**右端是半圆帽，左端是方角**，左右不对称。

## §2 证据（像素测量，非目测）

## §3 关键判定：这是既有缺陷，不是 R64 引入的

在同一位置的 R64 前帧（`L1.png`，`master @ 3739586`）上采样，填充同样是 y=1510 起整行蓝、左端垂直直边——**与 R64 后逐像素一致**。

R64 之前这个缺陷被那条横穿卡片的 `border_subtle` 线掩盖；R64 修掉那条线后它才显出来。**不要把它当成 R64 回归。**

## §4 根因（GPUI 源码确证）

**`overflow_hidden` 只做矩形裁剪，GPUI 没有圆角裁剪机制。**

`gpui-pre-0.3.4/src/window.rs:2081` 的 `ContentMask` 定义：

```rust
pub struct ContentMask<P: Clone + Debug + Default + PartialEq> {
    /// The bounds
    pub bounds: Bounds<P>,      // ← 只有矩形边界，没有任何圆角字段
}
```

`style.rs:638` 的 `overflow_mask` 据此构造遮罩：它把 `bounds` 收进边框宽度，然后 `Some(ContentMask { bounds })` —— **纯矩形**。

因此轨道的 `.rounded(12).overflow_hidden()` **无法**把子元素裁成胶囊：`rounded` 只作用于**轨道自己的背景**，对子元素毫无影响。

后果：

- **填充左端**与轨道左端重合（都在逻辑 x=790），正落在矩形裁剪边界上 → **从未被裁剪，方角**。
- **右端看似是半圆**，那是**轨道自身背景**的 `rounded`，不是裁剪效果。

**这不是"左端坏了"，而是"从来没有圆角裁剪"**——R64 之前那条横穿卡片的 `border_subtle` 线掩盖了它。

**实现者须知**：不要试图加强 `overflow_hidden`、再加一层裁剪、或调整轨道的 `rounded` 来修复——那条路在 GPUI 里不存在。填充层必须**自己**呈现胶囊形状。

## §4b 修复手段（已确定，无需再研究 GPUI）

**做法：给填充层左侧两个角加半径 `THINKING_TRACK_HEIGHT / 2.0`（= 12.0）。**

GPUI 的圆角是**按 quad 尺寸钳制**的，行为完全确定（`gpui-pre-0.3.4/src/geometry.rs:2467`）：

```rust
pub fn clamp_radii_for_quad_size(self, size: Size<T>) -> Corners<T> {
    let max = cmp::min(size.width, size.height) / 2.;
    Corners {
        top_left:     cmp::min(self.top_left, max.clone()),
        top_right:    cmp::min(self.top_right, max.clone()),
        bottom_right: cmp::min(self.bottom_right, max.clone()),
        bottom_left:  cmp::min(self.bottom_left, max),
    }
}
```

即每个角的实际半径 = `min(设定值, min(宽, 高) / 2)`。

### ⚠️ 本规格初版在此处算错（2026-09-15 实机复验后修正）

初版断言：*"fill = 12.0 时半径钳到 6.0，在 12px 宽的方块上视觉上就是左半圆"*。**这是错的。**

真半圆需要半径 = `H/2 = 12`，而钳制把 12px 宽的 quad 压到 6。半径 6 的圆角在 y=0 处左界是 x=6，而轨道的左半圆帽在 y=0 处左界是 x=12 —— **填充比轨道多出 6px，戳到胶囊外面**。这正是用户复验截图里那道蓝色月牙。

算术（填充宽 `w`，高 24，左角半径 `r`，轨道/knob 左界 `kx`）：

| 行 y | 半径 6 时填充左界 | knob 左界 | 露出 |
|---|---|---|---|
| 0 | 6.00 | 12.00 | **6.00** |
| 1 | 2.68 | 7.20 | **4.52** |
| 2 | 1.53 | 5.37 | **3.84** |
| 6 | 0.00 | 1.61 | **1.61** |
| 12 | 0.00 | 0.00 | 0.00 |

半径 12 时每一行露出均为 0。

### 修正后的做法

**根因**：任何宽度 < `2 × (H/2) = 24` 的 quad 都装不下半径 12 的端帽——钳制必然把半径压小，于是端帽退化成"小圆角 + 直边"，戳出轨道。

**所以填充宽度必须先撑到 `THINKING_TRACK_HEIGHT`（24），再上半径：**

```
w_effective = max(dot_center_offset(selected, count), THINKING_TRACK_HEIGHT)
```

- 撑宽的部分最多 12px，而 knob（直径 24、白色、**在填充之后绘制**）恰好覆盖 `[中心-12, 中心+12]`，所以多出来的宽度全部落在 knob 下面。
- 撑到 24 后钳制上限 = `min(24, 24)/2 = 12`，端帽是**真半圆**。

**窄填充（`w < 24`，即最低档 / Off）两端都要加半径**：此时填充就是那个端帽本身——`w_effective = 24` 且左右各半径 12，画出来是一个直径 24 的**圆盘**，与 knob 完全重合。

> 视觉后果（预期且正确）：最低档 / Off 选中时，knob 之外**看不到蓝色**——因为该档位的填充在几何上就是端帽，而端帽整个被 knob 盖住。这不是"填充消失"，是"填充恰好等于端帽"。**不要**为了让它显蓝而把填充加宽到 24 以上。

**宽填充（`w >= 24`）只加左侧两角**，右端保持方角（右端在 knob 中心，被 knob 覆盖）。

### 另一处遗漏：渐变分支的右端帽

初版只处理了左端，**漏了最强档渐变的右端**。用户复验第二张图（`high`/最强档）显示：渐变填充右端是方角，戳出轨道右半圆帽。

实测（`/tmp/u-high.png`，轨道行 y=236..283）：渐变填充**每一行都结束于 x=613**（垂直直边），而轨道右帽在 y=236 处应止于 613−12=601。

原因：`TRACK_GRADIENT` 铺满整条轨道 `0..203`，最后一段 `0.64..1.0` 结束于 203 = 轨道右缘；它没有圆角，于是在上下行戳出 12px。

**做法**：最后一段（`index == TRACK_GRADIENT.len() - 2`）加右侧两角半径 `FILL_LEFT_CAP_RADIUS`。第一段加左侧两角（已实现），中间段不动。

**不要**研究 quad shader、content mask 对绝对定位后代的裁剪等 GPUI 内部实现——钳制行为已由上面这段源码确定。

## §5 契约

**R1（必须）** 填充层左端与右端**形状对称**：两端都是半径 = `THINKING_TRACK_HEIGHT / 2` 的半圆帽。

验收判据（可量化）：在选中**最低档**（含 Off，位置 0）时，测量填充左端逐行的起始 x：

- 中线（y 居中）的起始 x 必须**显著小于**上下边缘的起始 x；
- 差值应与右端的对应差值（实测 9 物理像素 @2×）**同量级**；
- 即左端不再是"每一行同一 x"的垂直直边。

**R2（必须）** 不得为了让左端变圆而改变轨道尺寸、knob 直径、档位间距、颜色或 `dot_center_offset` 的既有契约（§4 表格中的常量与 `M5` 未测量项保持原样）。

**R3（必须）** `dot_center_offset` 的语义（两端各内缩半个 knob，使 203px 成为硬边界）不得回退。

**R4（必须）** 修复对**所有档位**生效，不只是最低档。

**R4b（必须，修正版新增）** 填充宽度在绘制时取 `max(dot_center_offset(...), THINKING_TRACK_HEIGHT)`，使端帽半径不被钳制。多出的宽度必须全部落在 knob（直径 24、白色、后绘）覆盖范围内。

**R4c（必须，修正版新增）** 窄填充（`w < THINKING_TRACK_HEIGHT`，即最低档 / Off）**两端都加半径**。

> **几何结论（用户 2026-09-15 复验后确定）**：位置 0 的圆点圆心在 x=12、直径 24，而轨道左帽（半径 12）与它**完全重合**。因此"左端做成真半圆"与"该档不填充"**是同一个形状**——两条路收敛。实现上**不要**加 `is_off` 特判分支，统一按 `w_effective = max(fill, 24)` + 两端半径 12 渲染即可，画出来是直径 24 的圆盘，恰好压在圆点下面。
>
> 预期视觉：**最低档 / Off 的圆点之外看不到蓝色**。这是正确结果，不是"蓝色丢了"——该档位的填充在几何上就等于端帽本身。

**R4d（必须，修正版新增）** 渐变分支的**最后一段**加右侧两角半径（初版遗漏，用户第二张图暴露）。中间段不动。第一段的左侧两角已实现，保留。

**R5（不得）** 不得删除轨道的 `overflow_hidden` 或 `rounded` 来"统一"成方角——目标是胶囊，不是矩形。

**R6（不得）** 不得为了在最低档"看到蓝色"而把填充加宽到 `THINKING_TRACK_HEIGHT` 以上——那会重新戳出轨道。最低档看不到蓝色是正确结果。

### 判据的量化形式（供实机复验直接套用）

对每一行 y，令 `fillLeft(y)` / `fillRight(y)` 为填充（饱和色）的左右边界，`knobLeft(y)` / `knobRight(y)` 为白色 knob 的左右边界：

- **A1（最低档）**：不存在 `fillLeft(y) < knobLeft(y) - 1` 的行。
- **A2（中间档）**：`fillLeft` 在中线处最小、在上下边缘处最大（弧形），且 `fillLeft(y) >= trackLeft(y) - 1` 处处成立。
- **A3（最强档）**：不存在 `fillRight(y) > trackRight(y) + 1` 的行。**初版实现下 y=236 行会 `fillRight=613 > trackRight=601`，差值 12 —— 这条判据正是为了抓住它。**
