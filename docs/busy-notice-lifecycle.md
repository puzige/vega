# 会话忙碌提示生命周期

## 范围

修复运行结束后输入区残留忙碌提示。忙碌提示使用独立类型，不按翻译后的文本匹配；终态仅清除该类型，不清除存储、权限、凭据、运行失败等其他错误。重复发送不覆盖既有真实错误或其运行错误关联。原有运行/准备准入及终态身份围栏不放宽，不从数据库 done 状态推断 worker 已退出。

不操作远端应用、数据、部署或任务，不涉及压缩诊断及 QA 流水线。交付新 PR，保持开放等待用户决定合并。

## 验收与必要回归

- 正常运行期间重复发送可显示忙碌提示，不能启动重复任务。
- 对应 worker 终态释放运行状态时，仅清除忙碌提示；成功、取消、断连共用终态路径。
- 存储、权限、凭据和运行错误在忙碌提示尝试及终态处理中保持原值；同文案普通错误不按文本被删除。
- 旧 generation、其他 thread 或其他 stream 的终态不得通过所有权围栏，不清新运行状态或提示。
- 运行期间追加用户消息不释放运行所有权；最终结束仍清理该轮忙碌提示。
- 不增加可见文案、依赖、数据库字段，不改变输入、焦点或恢复权限。

## 验证计划

本地运行相关 Rust 开发回归、格式检查及受影响 crate 严格 Clippy。独立审查绑定冻结提交。开发测试保存到可访问提交后移除测试及专用接线；最终 PR head 执行 required CI，Rust 空集明确标记 no Rust tests。原生用户现场状态及键盘交互仍需用户手测，不以纯状态回归冒充端到端验证。
