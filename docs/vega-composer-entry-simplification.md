# Vega Composer 入口精简规格

版本：v0.2 · 2026-10-26。状态：**产品提案，待确认，未实施**。

调研基线：`9a90ef74cd8e17793341c6a7b46e0a383332f223`。本轮只产出规格，不改功能、不迁移数据、不宣称界面或运行验证通过。后续实施须先确认本提案，尤其是 §10 列出的旧产品约定调整。

## 1. 目标与取舍

**「＋」添加上下文，「/」选择动作；模型和权限各留独立控件，安全控制随真实任务状态出现。**

Vega 不需要完整的通用命令面板或内容连接平台。本期减少默认选项和概念混用，不删除已有目标、定时任务、凭据保护或电脑控制能力。

- 默认「＋」最多两项：项目文件引用、添加图片。
- `/` 分两层：空查询只放少量高频项；其余命令通过搜索出现。
- 本期把 A 类"会真正执行动作"的命令接进 `/`：`/compact`、`/goal`、`/fork`（`/fork` 依赖既有数据层 UI 落地，见 §7.3）。
- 不新增常驻技能按钮、命令按钮或第二行工具栏。不用常驻说明条解释入口划分。
- 先让新的安全入口可用，再删除旧入口；不能用"精简"换取不可发现的接管或凭据检查。
- **命令层按可扩展设计**：新增一条命令是"表里加一行 + 一个派发分支 + i18n"，不改浮层、键盘索引和可见行投影。见 §4.4。

**本规格不采用"一个动作只能有一个入口"作为产品约束。** 同一动作可以同时有专用控件和斜线命令，但必须共用同一状态源、同一前置守卫和同一真实回执；不得形成两套状态或两条绕过门禁的路径。

本规格的设计依据是 Vega 自身的能力、现有业务契约、[设计守则](vega-design-guidelines.md)及平台交互原则。不采用第三方解包代码中的组件结构、样式、内部 token 或资产。

### 3.1 可用性矩阵

"支持"沿用既有 backend 能力，不因为菜单重排而新增支持。

| 会话 | 「＋」 | 本地 `/` 候选 |
|---|---|---|
| Native，有项目 | 项目文件引用、添加图片 | 按 §4 展示 |
| Native，独立会话 | 仅添加图片 | 按 §4 展示；技能只读取该会话适用的授权来源 |
| Native，新任务草稿（未持久化） | 项目文件引用、添加图片 | 模式与 `/skills`；`/compact` 不出现（不为压缩创建会话） |
| Codex，有项目 | 仅项目文件引用 | 本期不挂载 Native 的模式、技能、压缩、自动任务、分叉候选 |
| Codex，无项目（如该路由可达） | 无可用项目，隐藏「＋」及其焦点目标 | 不新增本地候选 |

- 无项目时隐藏"项目文件引用"，不保留点击后无反应的项。
- 永久不支持的项不展示；暂时忙碌的项可禁用，但原因必须在相关位置可通过键盘获取，不能只靠 hover。
- 不更改 Codex 自身的命令文本处理、发送限制或权限边界，也不把未知命令吞成本地操作。

## 4. 「＋」与斜线交互

### 4.1 「＋」只添加上下文

顺序固定为"项目文件引用""添加图片"，仅投影可用项；没有分组标题、"更多"子菜单或重复解释。按钮的可访问名称和必要提示改为"添加上下文"，不再宣称可切换模式。

**项目文件引用**：复用当前行为，在草稿末尾按需添加空白分隔及 `@`，聚焦现有项目索引选择器。选择、取消、无结果、加载失败与重试保持既有语义；索引结果仍受项目、路由和 generation 约束。关闭或切换会话后，旧异步结果不能重开菜单或写入另一份草稿。

这里不是通用文件上传：不承诺任意本机文件、PDF、Office、目录、整仓打包或外部应用内容导入，不新增文件附件格式和上传存储链路。

**添加图片**：调用现有原生图片选择和导入流程，沿用 PNG/JPEG/WebP、现有数量/单图/单回合限制以及凭据与提交 guard。取消选择不改变草稿和已有图片；失败保留原有输入，显示真实错误及可行恢复操作。导入未完成时不得伪装成已添加或放开原有发送门禁。

### 4.2 `/` 的默认与搜索列表

仅 Native 使用以下集合，顺序固定，不按使用频率漂移。

| 命令 | 行标签 | 空查询 `/` | 搜索别名 | 前置 |
|---|---|---|---|---|
| `/ask` | 询问 | 显示 | `ask`、询问、问答 | 无 |
| `/plan` | 计划 | 显示 | `plan`、计划 | 无 |
| `/execute` | 执行 | 显示 | `execute`、执行 | 无 |
| `/compact` | 压缩上下文 | 显示（仅已持久化会话） | `compact`、压缩 | 见 §7.1 前置 |
| `/skills` | 选择技能 | 批准技能调整后显示 | `skills`、技能 | 见 §5 |
| `/goal` | 目标 | 不显示 | `goal`、目标 | 无 |
| `/loop` | 定时任务 | 不显示 | `loop`、定时、周期 | 无 |
| `/fork` | 分叉会话 | 不显示（#519 落地后显示） | `fork`、分叉 | 见 §7.3 |

移除开头 `/` 后，对命令名和表中固定词做不区分英文字母大小写的前缀匹配，不引入模糊搜索、远程搜索或拼音检索。例如 `/g`、`/目标` 可找到目标，`/l`、`/定时` 可找到定时任务，`/c`、`/压缩` 可找到压缩。中文词只是候选检索别名，不新增自动任务解析器语法，也不新增命令参数语法。

技能名称不直接铺进首层候选；先选"选择技能"，再在技能列表内查找。未批准 §10 的技能调整前，首层不含该行，不展示不可用的占位项。

### 4.3 触发、选择与草稿保护

- 仅在草稿首字符是 `/` 时启用本地候选，以第一个 token 为查询；正文中间、前有空白、普通路径或不匹配的 token 不触发。不得全局扫描用户正文寻找命令。
- 非模式命令的首 token 后一旦出现空白，即结束首层候选；完整 `/goal …`、`/loop …` 进入既有解析路径，`/compact 文本` 按普通消息提交。模式命令仍支持 `/plan 正文` 等旧行为。
- IME 组合期间不打开、不选择、不执行命令，方向键、Enter、Tab、Escape 优先服务组合输入。
- 方向键移动有效候选；Enter/Tab 只接受当前候选，不同时发送消息。无候选时关闭列表并停止拦截普通键位。鼠标与键盘使用同一份可见行投影，不能把分隔线或隐藏项计为可选行。
- Escape 或点外关闭保留草稿、光标语义和附件；同一未改变草稿不立即自动重开。关闭后不遗留隐藏焦点目标。
- 一次只开一个 Composer 浮层；从命令进入技能或从「＋」进入文件选择时正确转移焦点，关闭后回到合理的输入或触发位置。保留现有发送、换行与 Tab/Shift-Tab 控件遍历约定。
- 空输入的既有 placeholder 提供简短发现提示即可：Native 项目会话可用"描述任务，输入 / 使用命令、@ 引用文件"；独立会话省略 `@` 部分。不新增常驻教程、说明条或一排提示图标，不修改用户已输入内容。

**模式命令**：调用现有 durable 模式修改链路，不发模型请求。只有成功确认模式后才消耗捕获的首 token，其余正文（包括空白）逐字保留。失败保留完整草稿；等待期间用户改字、切换会话或开始 IME，旧回执不能覆盖新草稿。保持模型保存、权限、运行中、已批准计划和 pending guard；选中标记表示已确认的真实模式，不提前报成功。

**执行型命令**：接受候选即执行一次真实动作，不发送用户消息、不产生对话文本。执行结果只来自既有回执与状态投影，不提前标记成功。命令自身的 pending 期间不重复接受同一命令。

### 4.4 命令表结构（可扩展性）

命令层是一张**静态、类型化的表**，不是插件式注册平台。每条命令声明：

- `id`：稳定内部标识，用于日志与测试，不面向用户；
- `token`：规范命令字，匹配时大小写不敏感；
- `label_key` / `description_key`：i18n 键，不硬编码文案；
- `search_aliases`：固定的本地化别名，仅用于前缀匹配；
- `default_visible`：是否出现在空查询默认列表；
- `requires_empty_draft`：是否只在草稿仅含该 token 时可用；
- `availability(ctx)`：返回"可用 / 禁用并给出原因键 / 隐藏"三态；
- `execution`：本地动作，或仅补全 token；
- `consumes_token`：成功后是否消耗 token，以及消耗条件（草稿未变、非组合输入、路由仍有效）。

`ctx` 只含只读事实：backend、是否有项目、是否已持久化会话、是否运行中、既有 pending 守卫、`compactable`、容量是否已配置、分叉能力是否就绪。UI 不因此直接读写 SQLite，仍经既有事件流。

约束：

- 可见行、键盘索引与点击派发继续共用同一份投影；分区（模式 / 命令 / 上下文）由表的声明顺序决定，渲染不再各自排序。
- 新增一条命令只增加：表内一行、一个派发分支、对应 i18n 键。不改浮层结构、键盘遍历、焦点恢复和投影机制。
- 既有模式命令的语义不变；`/goal`、`/loop` 仍由自动化 parser 解析，本表只负责候选与补全。
- 可扩展性不包含：插件式或远程动态注册、第三方或 MCP 注册斜线命令、命令参数语法、模糊/语义搜索，以及把权限、模型、项目选择搬进 `/`。

## 5. `/skills`：小入口，复用既有信任与固定语义

本节是**拟重新引入的显式选择能力**，须确认 §10；不能仅凭已有未挂载接口就视为获准实施。

### 5.1 选择器与状态

- 打开后显示当前会话适用、已启用且内容已获授权的候选；名称和来源用于辨认，同名来源必须可区分。描述仅在辨认需要时展示，不把私有绝对路径或哈希常驻呈现。
- 支持列表内按名称/描述查找及键盘选择，选中标记表示"为本会话固定"。列表中选择已固定项可取消固定；不可用的既有固定项仍可识别并移除，不悄悄改选同名来源。
- 没有候选时显示真实空状态和"管理技能"入口，进入既有 Settings → Skills。来源导入、预览、授权、启用及自动触发设置都留在 Settings，不在此复制管理平台。
- 加载、提交选择、成功、失败状态来自真实投影与回执。运行中或已有选择/发送提交时沿用既有 mutation guard；可展示列表，但不能修改，相关原因可见。失败保留草稿及可重试选择，不显示虚假选中态。
- 成功选择后关闭选择器并回到输入区；仅有显式固定或草稿选择时，在输入区既有上下文区域显示紧凑的名称、来源与取消选择动作，不新增常驻底栏控件。草稿显示选择意图，已有会话显示已确认的固定；不可用项保留真实状态与移除入口，不误标为"使用中"。取消选择器不撤销此前已成功固定的选择。
- 列表只选择，不立即加载执行技能、不发送用户消息，也不提高权限。自动触发策略、当前运行的冻结快照和既有活动技能展示不变。

### 5.2 固定范围与提交边界

- 复用 `SkillComposerProjection`、`SkillComposerCandidate`、`choose_skill_candidate` 及现有 controller/service。校验 thread/project、来源身份、内容 SHA、授权 generation 与回调 owner；不能用裸技能名称或缓存列表替代授权。
- 已持久化会话：选择走现有后台 CAS 固定/取消固定，成功后才投影结果。固定会影响该会话后续运行，不包装成"一次性附件"或"仅下一条消息"。
- 新任务草稿：保持现有单个 `SkillSelectionIntent` 模型；只记录 UI 意图，不因打开或选择而创建线程。首次发送按既有 provider 就绪、线程落地、重新验证并固定的流程执行；失效时保留输入及可重试意图，不发模型请求。
- `/skills` 候选被接受时先捕获原草稿和查询 token，打开选择器但不删除正文。成功选择（草稿记录意图，或已有会话收到固定回执）后，只有草稿仍与捕获版本相同、路由仍有效且不在组合输入时，才消耗该 token，其余空白、正文和附件保留；取消或失败不消耗，迟到回执不覆盖编辑。这里只在用户接受本地候选时打开选择器；关闭候选后自行发送未消费的 `/skills` 按普通消息处理，不新增自动执行或模型侧命令语法。
- 来源变化、撤销授权、根目录消失或内容变更继续按既有 Skills 安全契约处理；不能自动接受新字节、回退到另一个同名来源、安装脚本或跳过工具审批。

## 6. 两类安全入口的迁移

### 6.1 凭据检查 → 权限菜单次级动作

在 Native 已持久化会话的权限菜单内，四种权限选项之后增加分隔及"检查本会话凭据"。它是动作，不是第五种权限，不改变选中模式、不触发权限授权。新任务草稿不展示该项，也不为检查创建会话。

- 复用 `request_privacy(PrivacyAction::Review)`、现有后台 review、定位、例外及永久清理确认流程。
- 仍按当前控制器约束等待活动回合结束；忙碌时该动作有明确原因，不把禁用状态说成"没有凭据"。无数据库、读取失败等错误保持可见并给出重试方式。
- 保留快照/会话归属检查、脱敏结果和永久清理的显式确认，不改变发送时凭据保护、日志脱敏或凭据存储位置。
- 新次级行必须可用 Tab/方向键按菜单约定到达并用 Enter/Space 激活；权限项索引及危险权限确认不能因多一行而错位。
- **只有新入口连通后，才删除「＋」里的凭据检查。** 若无法在本阶段实现，旧入口暂留，不能宣称「＋」精简已完整交付。

### 6.2 电脑接管 → 真实运行态的直接动作

扩展现有电脑控制区域：当且仅当当前任务拥有有效控制实例且处于 Running，直接提供"接管电脑"。它位于 Composer 附近的相关运行状态区域，不需要打开「＋」、搜索命令或滚动寻找历史消息；没有电脑任务时不占位。

- 沿用当前 `pause_at(epoch)` 语义及 task/thread、active message、控制实例、epoch、generation 围栏。点击是请求暂停，不能冒充已经取得系统前台或已完成交接。
- 真实进入 Pausing 后表达"正在暂停…"，避免重复请求；确认 Paused 后展示暂停状态及既有恢复入口。未得到确认不能提前显示"已接管"。
- 待授权、暂停中、已暂停、终止、失败及控制实例更换按现有生命周期处理；旧按钮或回调不能暂停新任务。暂停与 Stop 是不同动作，不改变当前单一主按钮的发送/停止规则。
- 入口支持键盘、可访问名称和可见焦点，关键状态不能只用颜色表达。
- **先让 Running 状态的新入口可用，再移除「＋」内接管项。** 中间版本宁可保留条件式旧入口，也不能出现失去接管入口的窗口。

## 7. A 类执行命令

本节三条命令都会真实改变状态，而非只补全文本。

### 7.1 `/compact`：手动压缩一次上下文

接受候选即触发一次手动上下文压缩，不发送用户消息、不产生对话正文。压缩请求本身按其既有摘要请求规则记账。

**复用链路**：`reserve_context_operation_id` → `ContextCompactionRequested { thread_id, model, request_id }` → app 侧 `start_context_compaction` 的 owner / epoch / trusted-action 围栏 → `apply_context_status` 的状态投影与运行内压缩活动呈现。不新增压缩服务、数据表、后台任务或第二套状态。

**前置条件**（由 §4.4 的 `availability` 判定）：

- 已持久化会话；新任务草稿不出现该命令，不为压缩创建会话。
- 非运行中，且无 pending 提交、队列/steering 占用。
- 无进行中的上下文操作（保存、压缩、取消 pending）。
- 无 pending 模型选择或推理保存，非已批准未开始、非 trusted action 忙碌。
- 模型上下文容量已配置（#76 之后位于 Settings → Providers 的模型策略）；未配置时给出真实原因和去处，不把缺失说成"无法压缩"。
- `compactable` 为真；否则说明没有可压缩的完整历史，不发起必然失败的请求。

**交互**：

- 只在草稿仅含该 token 时可用；有尾随空白或正文时按 §4.3 结束候选，作为普通消息提交，不触发压缩。
- 运行中不接受候选，不排队、不打断当前回合；给出原因而不是静默无反应。
- 接受后消耗 token，草稿回到空；焦点回到输入区。
- 压缩进行中显示既有进行中文案与取消入口；成功、失败、取消按既有投影呈现，失败按既有 domain 失败码给出可理解原因和下一步，不伪造百分比或预计耗时。

**与旧决定的关系**：本条取代 [模型上下文修正](76/vega-issue-76-model-context-correction.md) 第 3 条中"移除手动压缩 UI 动作、只保留自动压缩"的 UI 部分。自动压缩策略、Settings → Providers 的归属、Composer 内不出现容量/预留编辑这三项不变。

### 7.2 `/goal`、`/loop`：候选只补全

- 空查询不显示，仅在非空查询匹配时出现；已有任务继续在状态条上暂停、恢复、编辑、清除。
- 选择候选只将查询 token 补全为规范 `/goal ` 或 `/loop `，不创建任务、不发模型请求、不启动计时；已有正文和附件不丢失。
- 补全后的空白结束候选，用户下一次明确提交后才走既有解析与校验。直接提交裸命令查看状态、以及 pause/resume/clear、预算、间隔、转义和指令长度语义全部保留。
- 打开既有任务的编辑面板仍走状态条入口，不通过斜线命令新增第二条管理路径。

### 7.3 `/fork`：命令壳，依赖 #519

- 数据层 `fork_thread` 与 `clone_prefix` 已按 #518 落地，但明确为数据层 only；会话操作 UI 由 #519 消费，目前未接线。
- 本规格只定义命令壳与可用性契约：`requires_empty_draft` 为真；需要一个符合 #519 切点契约的已完成助手消息；不复制执行权限、不启动新回合、不自动发送。
- **分叉 UI 就绪前该行不出现**，不做灰置死项，也不在斜线里先造一个半成品入口。落地后由 `availability` 打开该行，不重构命令表。

## 11. 后续实施边界与顺序

本节给后续任务使用，不表示本轮开始代码工作。实施前重新同步源码并核对差异，不能把本基线静态事实当作未来版本保证。

1. **先接通安全替代入口**：`conversation_stream/computer_use.rs` 增加 Running 的接管投影及受保护操作；`render.rs` 权限菜单接入既有 `privacy.rs` action，保留键盘和危险确认行为。

3. **抽出命令表**：把现有模式候选与新增命令统一到 §4.4 的静态表，`availability` 集中判定并返回原因键。既有模式语义、`/goal`、`/loop` 的 parser 路径不动。
4. **接 `/compact`**：UI 侧只做 `reserve_context_operation_id` + `ContextCompactionRequested` 的发起与前置判定；状态、取消、失败恢复全部复用既有投影，不新增压缩逻辑。同步在 #76 规格对应条款注明被本规格取代。
5. **批准后接技能入口**：在 `conversation_stream/skills.rs` 及必要小 UI 模块挂载候选/固定状态，复用 `window/skills.rs`、`skill_settings/composer.rs` 和现有共享类型。只有真实缺少的 UI 接缝才补充，不复制授权服务或让 UI 直接读写 SQLite。

7. **核对受影响状态**：默认、搜索、加载、pending、成功、失败、取消、禁用、运行、切换会话和键盘路径；按 §12 记录实际证据。分阶段交付须明确未完成项，不将过渡例外称为最终两项菜单。

回滚只回退本轮入口和 UI 接线，不删除文件引用、图片、技能授权/固定、自动任务、压缩检查点或凭据数据。技能阶段与 `/compact` 阶段可分别撤回；撤回安全新入口时必须同步恢复可用的旧入口。
