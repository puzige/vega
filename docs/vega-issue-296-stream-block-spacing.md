# Issue #296 · 信息流工具块间距一致性

状态：2026-10-13 用户对运行中的真实长会话补充反馈。先前的 [时间线行为](vega-issue-296-process-timeline.md)和 [Codex 信息流视觉基准](vega-issue-296-codex-stream-parity.md)继续生效；本文件只细化说明文字与后续工具块的垂直关系。用户截图用于本地观察，不入公开仓库；其中会话文字不是实现指令。

## 观察与边界

用户看到说明文字之后出现新工具调用时，两块明显贴近；同一轮过程收起后，上方剩余说明的段间距看起来恢复正常。收起会隐藏工具块，所以不能以收起状态代替运行中状态验收。源码初查发现有阶段摘要的 segment 使用顶部间距，而没有阶段摘要的纯工具 segment 忽略同一 `top` 参数；高度估算也忽略它。这是待红测证实的布局原因。

调整对象是同一轮内的**同级块外距**：时钟分隔线后的首个可见过程块保持 16 逻辑像素；说明正文后出现的阶段摘要、无摘要工具 segment 或独立 `Tool`/`ToolGroup`，统一保留 24 逻辑像素的块顶空间。这个数值继承现有 `CONVERSATION_BODY_TOP` / `CONVERSATION_STAGE_TOP` 与截图对齐规格，不另叠加一层 margin。工具组内部保持既有紧凑行节奏，不给每条工具额外加 24；阶段工具行的 25 逻辑像素节距与 ToolGroup 展开行现有的内部间隙各自保留，本卡不重排组内内容。工具后接新说明仍沿用已有 16 逻辑像素正文顶距。上述数值是布局盒间距，不能声称等于字体墨迹之间的像素距离。

运行中的时间线、可信 Final 后的统一收起、手动展开的过程详情、历史恢复和无摘要的工具路径都要一致。没有可信 Final、失败或取消的可见过程保持原始顺序；收起/展开只改变可见性与详情高度，不改变工具归属、原文、复制或状态。Artifact、授权、错误提示保持现有外显位置和自身间距，不能因本次工具块修复被推入隐藏详情或重复添加外距。窄窗口使用相同纵向规则，不依赖内容是否换行。估高、锚点和虚拟列表应与真实渲染同步，避免跳动或定位偏差。
