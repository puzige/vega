# steer 续接链统一收尾

## 本轮用户裁决与边界

用户确认：整轮最终回答确认时，统一折叠 steer 续接链中的所有活动组；保留旧过程展开入口、原有消息顺序和插话气泡，不在 steer 当下自动折叠。本轮明确授权实现、PR、云端检查和完成后关闭 issue；关闭是用户指定的交付收尾，不记录为 UI 手测通过。

本章补充 #806，修订 #535 的续接段收尾：旧组仍在运行中保留原展示，但最后一段的可信 Final 必须收尾整条明确续接链。普通独立排队、停止/失败提示、计时和存储协议不变。

## 根因

`RunActivityGroup::continue_run` 仅释放旧段运行展示；`phase::apply_response_metadata` 仅对当前消息调用 `confirm_final`。旧段没有 `collapse_pending`，不会被 `settle_final_presentation` 收起，`complete` 对 continued 组直接返回。

## 最小实现

- 在 `phase.rs` 增加沿 `run_continuations.next_assistant_id` 向前回溯的收尾函数，只使用已验证的显式关系，不猜相邻行。按各组原始 message ID 收集 Assistant 过程副本，不包含用户消息或错误正文，不移动任何 entry。
- 当前组通过现有 `process_copies` 的可信 Final 校验后，同步对祖先组调用一次性 `confirm_final`。复用 `settle_final_presentation` 的焦点、选区清理和列表失效；手动再展开与重复事件保持幂等，不重新折叠。
- 历史旧页/新页装载并合入列表后，以已恢复的有效最终回答投影为种子，同样收尾续接链；页外关系可回溯，尚未加载的组不伪造，后续分页补载再恢复。历史恢复也通过 pending/settle 路径收尾，包含已显示旧段的隐藏选区清理和焦点转移；新建历史组同样在首次渲染前完成收尾，不提前绘制展开正文。历史恢复不修改已手动展开的已确认组。
- 不改停止/失败的既有可见性，不把无 Final 或无关系的组当作成功收尾，不增加产品文案、依赖、Rust 测试或存储字段。

## 验收与验证

| 场景 | 预期 |
|---|---|
| 单次或多次 steer，最新段可信 Final | 各祖先组及最新组过程折叠，Activity/终态入口可展开 |
| steer 接受但运行尚未 Final | 旧过程保留，不提前折叠 |
| 折叠后手动展开，重复元数据/分页 | 不再次强制折叠 |
| 独立排队、无显式续接关系 | 不折叠其他运行 |
| 图片插话、工具、正文混排 | 原始顺序不变；图片与用户正文不进入过程详情 |
| 旧页/新页分批加载 | 已加载续接段与 live 一致；保留原错误正文和最终回答 |
| 焦点/选择位于旧过程，live 或向后分页首次加载 Final | 通过 pending/settle 清理隐藏选区并转移焦点，保留可访问展开入口 |
