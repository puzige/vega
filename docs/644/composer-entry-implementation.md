## 实施与验收

1. Running 电脑控制区域增加可键盘激活的“接管电脑”。捕获 task/thread、active message、control 实例、epoch 和 generation；操作时重校。只请求 `pause_at`，Pausing/Paused 按真实状态显示，不报“已接管”。先接通这个入口再删除旧菜单项。
2. 「＋」仅投影项目文件引用和 Native 图片。无项目隐藏文件引用；Codex 无项目不渲染按钮及焦点目标。保留原有文件索引/图片导入、IME、草稿、附件和异步围栏。手动凭据检查直接移除 Composer 调用方，不改后台凭据保护。
3. 固定命令表统一 token、文案键、别名、默认可见性、空草稿约束、执行分类与可用性。模式、压缩、目标、定时任务、分叉共享可见行、键盘索引和点击派发。空查询的固定命令仅模式和已持久化会话压缩，其后追加当前可用技能；目标/定时/分叉非空搜索出现。大小写不敏感，中文别名只用于检索。
4. 目标/定时候选只替换查询 token、补尾随空格，不发送、不改变自动任务状态、不丢正文与附件。模式消耗 token 只在真实确认且草稿未变、非 IME 时进行。
5. 技能按产品规格 §5 实施：文本范围绑定精确身份与授权 generation，逐条提交，不写持久固定；编辑/复制/撤销与 worker 校验不得降级为名称解析或隐藏选择集合。
6. 更新相关旧规格的当前入口说明；不改历史验证证据，不宣称全部 A1–A22 已验证。

## 立即引导中的技能增量（用户确认）

本节依据用户本轮明确裁决，取代产品规格 §5 中“当前运行的冻结快照不变”对新增激活的限制；已激活技能的字节、身份、授权快照仍不可替换。同步基线为 `f7cd2aab`（完整 SHA 以交付记录为准）。

- 普通发送、排队、立即引导均携带当前文本仍绑定的精确技能意图；不按显示名重新解析，不写入会话固定。队列持久化复用现有 payload，不新增表。
- 立即引导只在当前运行的安全消费边界添加新激活，不在 provider/tool 执行途中改写状态。worker 重校来源/根目录、精确字节 SHA、启用及授权/撤销 generation、thread/run/owner；所有新增项验证成功才确认消费消息。无技能的引导行为不变。
- 相同精确身份/内容重复引用去重，已激活项沿用冻结快照；同名不同来源、不同内容或超出现有激活上限按既有安全规则明确失败，不覆盖旧激活，不放宽上限。新激活走既有 explicit_user 审计、快照和上下文预算规则，不新增权限。
- 接受的持久化边界：队列送达、下一助手消息、完整技能快照与新增激活审计必须在同一个存储事务提交；运行态替换与送达通知只在该事务成功后完成。撤权或快照/审计落库失败回滚整次接受，队列 payload 与绑定仍可恢复；不得用连续独立事件提交冒充原子接受。
- 校验或激活失败不发起该消息的模型请求，不丢弃消息与绑定；尚在 Composer 的输入保留，已进入队列的消息保留并展示可恢复的失败原因，允许修正/重试或移除。不得静默忽略技能或把失败当作接受成功。
- 提交、队列恢复、失败恢复、撤销/重做必须保持文本与绑定一致；复制粘贴、手打及跨消息历史不恢复身份。迟到结果不得覆盖新草稿、新任务或新控制实例。

必要回归：普通/排队/引导新增技能；重复精确引用；已激活技能文件变更不替换快照；新增技能 SHA/授权/根目录变更拒绝；同名冲突与激活上限；失败消息保留与可重试；owner 切换/取消迟到结果；撤销/重做及部分删除绑定；既有无技能引导不回归。

## 空查询技能列表（用户追加确认）

本节取代旧的“`$` 必须有查询字符、`/` 空查询不列技能”规则，基线 `28859f6f00b674141c6222172c8c1f1e3c18588a`。

- 单独 `$` 打开当前适用、已启用且已授权的技能列表；单独 `/` 保留既有默认命令，并在其后展示同一技能集合。
- 两种触发符均在空查询时请求现有异步技能投影。空查询匹配全部候选并保持投影顺序；继续输入使用原有前缀优先、字面子串过滤，删除查询字符恢复全部候选。
- 不扩展 Codex 能力，不改变金额、代码、路径、URL、选区、IME 排除条件，不绕过投影授权过滤、路由 generation、旧回调与草稿版本守卫。
- 候选接受仍只替换捕获范围、插入精确身份绑定并保留尾随空格；不发送、不执行、不写固定，范围外正文与附件保留。没有可用技能时 `$` 无可选列表，`/` 保留可用默认命令；不增加常驻提示。
- 必要回归：两个空查询均触发投影并显示同一稳定技能集合；过滤、退回空查询、从裸触发符接受绑定；无技能、Codex、代码/数字/路径/IME 排除及过期投影仍被拒绝。开发测试只在 Actions 执行，成功留存证据后清理，再验证最终 head。

## 已配置容量却误报未配置（用户截图反馈）

验收：有效提供方/模型容量和历史失败诊断同时存在时，上下文投影必须成功读取容量、保留失败分类；加载失败必须显示上下文读取错误，不得显示“先配置容量”。真正未知容量仍提示配置；未取得投影时不能断言未配置。

根因：`classified_failure_message_ids` 的 SELECT 只有 36 列，共用解码器读取第 37–39 列的协议/凭据分类字段，匹配到失败记录时产生列越界，整份容量投影失败。只读元数据确认截图模型已有输入 300000、输出预留 128000；其中一个相关任务存在触发记录。另一相关任务没有匹配记录，不能据此宣称其实际 UI 状态已复现。

最小修复：补齐 SELECT 尾部三列，不改变分类与归属校验；压缩可用性区分投影未加载、读取失败与已加载的未知容量。保持 fail-closed，不放宽压缩 worker 守卫、不改用户数据或配置。Actions 回归覆盖 NULL/非空分类字段、有失败记录时的真实容量投影，以及 UI 读取失败/未知容量/已配置状态。

## 有历史却禁止手动压缩（第二轮用户反馈）

本节落实 #667 A07 的既有保尾式手动压缩合同，不把已合并的容量读取修复等同于本问题已解决。单条用户请求之后的多组完整响应同样可以形成压缩前缀，不要求先发送第二条用户消息。

- 默认手动压缩的可用性与执行共用 checkpoint-aware 响应组规划：初始保留最后一组，必须存在非空摘要输入，按完整响应边界切分；不可安全切分时仍拒绝。不以消息/工具数量或最后用户位置代替规划。
- 可用性刷新不得因每个响应组都深拷贝整份历史而引入按历史字节数乘响应组数的分配。范围投影先筛选再复制所需消息片段、工具及图片，保留原有校验、UTF-8/偏移归一与输出字段语义。
- idle 手动请求保持 `source_owner_id: None`、`NoContinuation` 和来源围栏；不把历史助手伪装为活跃运行 owner，不自动恢复旧任务。保留 partial、precompute、自定义摘要要求、配对、预算/缩小、取消及原子安装检查。
- 必要回归：单用户多响应组可规划且入口可用，真实手动路径抵达摘要与安装；多 terminal owner、pending user、单组/空历史、无效配对、checkpoint 后再次规划与不继续旧任务。
- 技能空列表的当前数据前提独立记录：运行中的目录启用且根身份匹配，但批准表为空；目录内 15 个子项为符号链接，被既有安全合同拒绝。不得自动批准或放宽链接读取来制造候选；支持链接技能属于需用户明确裁决的独立安全范围。

## 链接技能审核（用户明确确认）

用户在设置截图确认全部技能均无审核入口后，明确选择继续修复受控符号链接技能支持，并排查 YAML 报错。本节取代上述对 immediate 技能目录链接的一律拒绝；不授权自动批准、修改源文件、读取凭据或扩大工具权限。

- 发现允许根目录直接子项为目录符号链接，解析真实目标，读取有界 SKILL.md 后进入现有逐项审核。审核预览显示链接入口和真实目标；确认同时批准入口/目标身份与正文 SHA，默认不自动激活。
- 持久化独立目标绑定，旧批准默认无绑定，不能自动批准链接。链接入口或目标路径、设备/inode 变化即失效，即使正文 SHA 相同；预览到提交重新校验，目录/项目/consent generation 保护不变。
- 运行时目录、正文、引用和资源读取携带同一绑定，使用无跟随描述符读取并前后重校，拒绝目标内部的符号链接、硬链接、路径穿越、非普通文件、失效或循环链接。当前已激活冻结快照不替换，不扩大脚本、MCP 或文件工具权限。
- 不放宽 YAML 格式：当前报错文件存在嵌套 metadata（合同要求字符串值）和目录/声明名称不一致；保持拒绝，不改源文件。提供准确的元数据结构诊断，避免把合法 YAML 的结构不兼容说成语法无效。
- 必要 Actions 回归：真实链接发现/预览/确认/批准重载及 Composer 可见；未批准隐藏；相同内容换目标、预览后换入口、目标身份变化、内部链接/硬链接/穿越/循环拒绝；普通目录兼容、引用/资源围栏及冻结快照不回归。开发 Rust 测试绿色留证后清理，最终 head 独立审查和 required CI；不以静态检查代替真实 UI 验收。
