# #749 侧栏重复对话入口互斥高亮

## 需求与边界

用户要求：同一对话同时出现在 Projects 与 Recents 时，仅最后点击的入口高亮，另一入口不联动选中背景。此规则同样适用于 Pinned。对话 ID、消息、运行状态、未读状态、置顶、归档及项目归属不变；不改变已有 hover/focus 样式，不增加产品文案或持久化字段。

## 根因与实现契约

`ThreadsBlock::render_row_at_height` 与被动项目行只比较 `OpenedThread.id`，导致所有投影同时选中。已有行键包含投影前缀与对话 ID，可用于区分入口。

- 在 ThreadsBlock 中保存最近成功访问的对话 ID 与入口行键，只控制选中背景。
- 点击携带行键进入原有异步访问链路。排队访问保留行键，仅最终成功且仍有效的访问提交选中入口；失败、拖拽、导航拒绝或过期访问不能提交选中态。
- 同一对话跨入口点击也必须更新行键，不能仅因对话 ID 相同而忽略。
- 所有重复投影统一通过入口行键判断选中。后台标题、运行或未读更新不重置入口。
- 未记录入口的恢复或程序导航使用唯一默认入口：组织视图优先 Pinned，否则 Recents；若设置隐藏项目对话的 Recents 投影，则项目对话使用 Projects。旧非组织视图使用原会话行。默认目标被折叠或分页隐藏时允许没有可见高亮，禁止同时高亮多处。
- 不重构导航、访问计时或列表排序，不新增依赖、测试支持或注释。

## 验收与验证

1. Projects 点击对话 A：仅 Projects/A 选中；再点击 Recents/A：仅 Recents/A 选中；反向亦成立。
2. 点击其他对话后选中背景随成功访问转移；Pinned 与项目投影的重复项同样互斥。
3. 快速连续点击时最终成功入口生效；失败或导航拦截不改变当前选中。
4. 列表刷新、流式运行状态和标题更新不引发重复高亮；恢复或非侧栏导航最多选中一处。
5. 原 hover/focus、双击重命名、拖动、行操作及运行指示不改变。

本地只做差异、格式与静态检查，不运行 Vega、不编译、不执行测试。最终版本由 GitHub Actions 执行完整 required CI，非实现者独立审查差异与受影响契约；真实交互由用户在合并后手测。此小范围 UI 状态修复不新增开发 Rust 测试；最终仍要求 no Rust tests（0 发现/0 执行）。
