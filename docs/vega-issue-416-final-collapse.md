# Issue #416 · Final 确认后统一收起过程

## 用户裁决与范围

2026-10-16，用户确认会话第一轮结束前曾上滚回看；了解旧实现会因此延后过程收起后，明确表示「不需要这个保护」。本规格据此替代 #296 的 Final 收起阅读保护：首次可信 Final 确认后，本轮过程收起一次，不再等待回到底部、选区清除、焦点移开或此前展开关闭。

跟踪：[Issue #416](https://github.com/puzige/vega/issues/416)。本卡只修改 Final 后的展示投影与相关交互，不改变 provider 协议、消息元信息、持久化格式、原始正文和工具记录。

## 当前原因

`phase::apply_response_metadata` 识别 Final 后只设置待收起状态。`settle_final_presentation` 将未跟随底部、选择焦点、过程焦点、展开详情及过程选区视为正在阅读而跳过收起；`RunActivityGroup::settle_final` 还受 `manually_expanded` 阻挡。具有完整有效 Commentary/Final 的已完成轮次因此仍可能把过程留在正文。

## 行为契约

1. 首次可信 Final 确认后，属于本轮且可由元信息完整证明的 Commentary、思考与工具统一进入一个默认关闭的过程入口；Final 留在入口外。上滚、选字、焦点、工具展开或此前手动展开都不阻挡这一次自动收起。无需等待滚动或后续输入。
2. 每轮只自动收起一次。收起后用户再次主动展开、搜索或锚点跳转可重新打开过程。重复 Final、完成事件、重绘及其他轮的事件不得再次关闭已重新展开的过程。
3. 不删除或改写正文、工具审计、顺序、复制源与持久化数据。历史重开与实时完成具有相同默认投影；原过程仍可展开、复制和定位。
4. 收起后不能保留指向隐藏过程的可见选区或隐藏焦点。仅处理本次将隐藏的过程：清理相应选区，若焦点位于将隐藏的内容则移至同轮可见过程入口；Composer、Final、其他轮或其他可见区域的焦点和选区不被无条件改变。
5. 不强制开启底部跟随。保留原有列表锚点与非底部滚动模式；若原位置属于被收起过程，允许列表按既有有界定位落到可见入口/相邻内容。旧回看状态不能自动撤销本次收起，用户主动的后续搜索/定位仍可展开。
6. 无 Final、无效/冲突/越界元信息、失败与取消继续保留有效正文；不得猜最后一段是正式答案。既有错误、权限、待处理事项与产物外显规则保持。多个用户轮次之间的内容、收起状态和身份隔离保持。
7. 不新增产品说明、开关、提示条或确认弹窗；通过实际收起和既有展开入口表达新行为。

### 云端反馈后的焦点实现细化

2026-10-16，第二轮 Actions 的 5 个焦点回归都在自动收起后的第一次 Enter 失败，过程已关闭但键盘未到达真实可见入口；其他 2731 项通过。GPUI `Window::use_keyed_state` 经 `with_global_id` 使用当前元素层级定位状态，流顶层与列表行内调用相同字符串不能保证取得同一个焦点对象。这是新增焦点迁移路径的问题，不能通过移除键盘断言解决。

FC2/FC3 补充回归：让真实工具子入口持焦后收到首次可信 Final，隐藏阶段及工具不再持焦，按 Enter 必须展开同轮可见过程入口；再次 Enter 可恢复关闭。既有过程选区、思考、阶段入口、Composer、Final、其他轮与产物焦点断言继续保留。

实现按以下顺序修订，行为契约不变：

1. 在 `RunActivityGroup` 持有稳定的过程入口 `FocusHandle`，构造时创建，`render_with_details` 与 `settle_final` 共用；不在流顶层按字符串重新创建入口焦点。
2. 删除 `settle_final` 对工具及工具组 keyed state 的字符串枚举；用实际包住隐藏阶段的 `segment.focus.contains_focused` 及既有阶段/思考句柄判定隐藏焦点。阶段容器同时包住外显产物，须排除同段产物实际持焦的情况：允许仅在 `artifact_card.rs` 增加 crate 内 `contains_focus` 查询，检查既有七个按钮句柄，不添加状态、改变渲染或扩大工具卡 API。
3. 保留真实 Enter 验证和选区/原文/跨轮断言，补齐工具子焦点回归；不修改共享 disclosure 或工具卡 API，不新增依赖或产品文案。
4. 本地仅做格式、差异和静态检查，保留前两轮失败与根因，第三轮行为结果交 Actions 验证。

第三轮 Actions 为 2735 项通过、1 项失败、5 项跳过。唯一失败是多个阅读模式共用的循环用例，未报告具体 mode；其中直接给未显示的 run details / 思考源句柄设焦点，且部分选区只改缓存，没有实际选择前置。真实拖选、阶段/工具焦点、思考源与产物按钮的独立回归均已通过，现有证据不足以认定新增生产缺口。GPUI 焦点包含查询已直接包含句柄自身，不添加重复的 `is_focused` 分支。

该循环修订只允许测试和证据变更：阶段焦点使用真实可见入口；思考源模式提供原始 ThinkingDelta 并实际展开源；过程/Final 选区通过真实选择建立。正式 Final 前断言控件确实可见且真实持焦/有选区，收起后继续保留 Enter 展开/恢复关闭、原文、选区与可见焦点隔离断言。共用焦点辅助断言增加 mode 上下文，不能靠跳过、删除模式或放宽结果换绿；若真实前置仍失败，按明确 mode 再分析生产路径。保留三轮失败，本轮生产保持不变，第四轮交 Actions 验证。
