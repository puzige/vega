# #675 · 行内排版快照与消息气泡

## 契约

用户消息 `为什么这个卡最后被拖回来了https://github.com/puzige/vega/issues/632` 在窄宽度换行后，全部行盒必须落在气泡内。保持现有字号、颜色、圆角、70% 最大宽度及内距，不裁切、不固定高度、不改写 URL。

InlineFlow 的测量可能被布局引擎多次调用，且引擎会缓存尺寸。不能将最后一次测量的可变结果当作最终结果。保留按测量宽度区分的完整 FlowLayout 快照，预绘制按最终边界选择对应快照；同一快照的片段范围、坐标、宽度用于文字元素、选择以及链接区域。快照宽高按设备像素匹配布局尺寸；不得在预绘制独立重新换行。片段继续 nowrap，图标宽度计入测量且只在链接开始出现。内容宽度保留分数逻辑像素，由 GPUI 统一按设备像素取整；不先向上取整到整个逻辑像素，以免 Retina 分数宽度下合法快照被拒绝。

气泡正文使用块级纵向自然布局，而不是 flex 列：避免 flex 在 max-width 收窄后仍将早期单行主轴高度作为已知高度传给文字叶节点。块级子节点在最终内容宽度下自然测量全部行高；普通与可选择消息路径一致修改，外层右对齐不变。

## 验证

开发期间新增临时 GPUI 回归，云端执行后固定原始源码与 SHA，合并前按仓库政策清理。覆盖两行/多行长链接、宽窄重排、多次测量后重新选择旧尺寸，以及点击区域对应完整 URL；短文本、空行、多链接与行内代码维持既有行为。最终无测试 head 再跑完整 required CI。原生像素与真实打开由用户手测，不把静态或进程内检查称为原生验收。

本地仅差异、格式和静态检查；无本地编译/运行/测试。无新生产依赖、无运行时配置/数据变更、无网络预览策略变更。开发阶段只启用已有 GPUI 的临时 test-support feature，结束时清理其独占依赖。
