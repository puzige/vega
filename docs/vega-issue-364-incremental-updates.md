# 文件级增量更新（Issue #364）

## 需求与边界

2026-10-14 用户明确要求先写规格，再实现每轮更新的文件级增量，并保留全量回退。范围仅为更新传输与安装，不做全量包瘦身、运行组件拆分、编译参数优化、二进制差分、断点续传或 Sparkle 迁移。

已发布 v0.1.112 → v0.1.113 的 199 个文件经 SHA-256 比对，196 个相同，仅主程序、Info.plist 和 INSTALL.txt 变化。全量 ZIP 为 88.20 MB，变化文件的现有压缩载荷约 18.42 MB。这是样本估算，不是新更新器实测结果或固定节省承诺。

## 更新协议

1. 保持现有全量 ZIP、SHA-256、Vega-update.json 与签名的 v1 格式和签名域不变。旧客户端的 deny_unknown_fields 必须继续兼容。首次升级到支持增量的客户端仍可能全量下载。
2. 新增独立的 Vega-delta.json 及 Vega-delta.json.sig。采用现有固定 Ed25519 公钥，以独立签名域 `Vega file delta manifest v1\n` 签名原始 JSON 字节；未知字段/版本失败关闭该增量路径。复用现有 ring、serde、sha2、zip，不新增运行时依赖。
3. 清单固定 schema=1、bundle_id=ai.vega、target=aarch64-apple-darwin、目标稳定版本，并绑定现有全量 ZIP 的 SHA-256。包含完整的目标应用普通文件清单（相对 Vega.app 的规范路径、字节大小、SHA-256、Unix mode），以及最多 5 个旧版本到本版的直接补丁描述（from_version、资产名、大小、SHA-256、变化文件路径集合）。字段命名由实现统一，但这些语义不得省略。
4. 补丁 ZIP 只包含变化/新增的目标应用文件。未变化文件按相同相对路径从当前运行的应用复制；删除文件通过按完整目标清单新建应用自然排除。不包含 INSTALL.txt 等应用外的安装说明。不修改运行中的应用、配置或用户数据。权限变化可以复制内容并设置已签名的目标权限。
5. 发布端读取最多最近 5 个较旧稳定正式 Release 的官方 ZIP，生成每个旧版本到本版的直接补丁，不串联补丁链。基线必须经现有独立签名及 ZIP 摘要验证；缺失或获取失败的基线跳过并记录原因。没有适用基线时仍发布经过签名的空补丁列表，允许全量更新。补丁不小于全量包时不发布该候选。
6. 所有生成工作在最终签名/公证/staple 后的发布包上进行，不对已签名的文件做 strip 或重新签名。CI 生成每个补丁后重建并检查完整目标文件清单、内容和权限，然后才允许发布。支持 draft 重跑、资产完整性检查和历史 Release 幂等；不得把缺少增量资产的旧版历史发布误判为损坏，也不得让新版 draft 在漏传清单/其引用补丁时发布。

## 客户端选择、验证与回退

1. 保持现有发现新版本、自动检查、下载进度、准备完成及用户确认重启的产品流程。全量签名清单始终验证；增量是额外优化，不能代替它。
2. 新客户端优先获取可选增量清单与签名，验证目标身份、版本、签名、全量摘要绑定和所有结构边界。仅选择 from_version 精确等于运行版本的补丁；无匹配时直接全量。
3. 下载前验证所有拟复用文件的哈希与长度，不仅比较版本号。复制时再次验证打开的普通文件内容，避免校验后被替换；拒绝沿任何 symlink 路径读取，不能读取应用外文件。源文件被改动即回退全量。
4. 补丁下载校验长度、摘要和允许的 GitHub 仓库资产 URL。下载大小上限沿用 512 MiB；签名清单上限 1 MiB、文件条目最多 4096、总解压字节上限沿用当前全量解压上限。限制路径长度、单文件大小、重复及大小写折叠冲突、文件/目录前缀冲突；拒绝绝对路径、空段、`.`/`..`、反斜杠、NUL、symlink、设备等特殊文件和异常权限，ZIP 中不得夹带清单外条目。
5. 在应用同目录 owner-only staging 中构造新应用。每个文件按签名清单验证内容、长度和权限；完整目标清单必须包含有效主程序及 Info.plist。验证最终应用版本、bundle identity 和现有代码签名策略后才可进入 Ready。代码签名校验不可替代独立签名和文件哈希验证。
6. 任意增量元数据缺失、不支持、不适用、源文件不匹配、下载/解压/重建/最终验证失败，丢弃本次增量候选，在同一次更新尝试中至多回退一次现有全量下载；不能递归重试或降级签名验证。全量失败保留正常可恢复错误。进度切换到实际正在下载的资产，不假称增量成功，不增加常驻实现说明。
7. 安装助手必须独立重验已签名元数据与资产，在最终替换前重新构造/验证候选，保留现有父进程、原应用 inode/device、版本和哈希检查。不能因为主进程标记 Ready 就信任可变 staging。增量准备模式必须传递到助手，但 unsigned install.json 不能授权未签名文件。
8. 为避免用户退出后才发现只能联网回退，安装准备阶段在旧应用仍运行时完成增量重验/候选准备；能恢复的增量失败先回到全量准备。最终安装阶段再验发现变化则拒绝替换、保留旧应用及恢复路径，不在退出后要求隐式联网。既有备份、替换失败恢复、启动确认、启动失败回滚与超时保留备份契约不变。

## 验收矩阵（实现前冻结）

全部自动覆盖采用进程内临时目录、合成 ZIP、确定性签名和网络/平台替身，不新增真实外部集成门禁。本地不编译、不构建、不打包；编译和 Rust 测试由现有 PR CI 执行。轻量 Python 单元测试可以本地执行。

| 用例 | 前置与操作 | 预期 | 层级 / 初始状态 |
|---|---|---|---|
| 增量正常路径 | 旧应用部分文件不变，选择对应补丁并组装 | 只请求补丁，不请求完整 ZIP；所有目标内容与权限正确 | 进程内 / 待实现 |
| 跨版本直达 | 当前版本不是上一版，但在候选表 | 直接选择对应补丁，一次完成，无补丁链 | 进程内 / 待实现 |
| 无适用补丁 | 无增量资产、空表、旧版本不在范围 | 全量一次成功，旧 v1 流程不变 | 进程内 / 待实现 |
| 源不匹配 | 版本相同，复用文件缺失或哈希不同 | 不复用错误内容，回退全量 | 进程内 / 待实现 |
| 增量失败 | 元数据签名/绑定错误、下载损坏、中断、解压/最终验证失败 | 清理部分候选，至多全量一次；全量失败暴露错误 | 进程内 / 待实现 |
| 文件变化 | 新增、修改、删除、权限改变 | 完整目标清单一致，删除项不残留 | 进程内 / 待实现 |
| 不可信结构 | traversal、symlink 父目录/叶子、重复/大小写冲突、额外项、前缀冲突、超限 | 不逃逸、不覆盖原应用、不申请无界资源 | 进程内 / 待实现 |
| 安装重验 | Ready 后篡改补丁/清单/复用文件/候选 | helper 不信任缓存，替换前拒绝或退出前回退 | 进程内 / 待实现 |
| 回滚回归 | 替换失败、新程序启动失败、启动确认超时 | 保留既有恢复行为和用户数据 | 现有 + 必要回归 / 待 CI |
| 发布生成 | 合成多版归档、缺失基线、补丁比全量大 | 最多 5 个匹配候选，重建一致，否则跳过/失败 | 进程内 / 待实现 |
| 发布完整性 | 新 draft 漏传清单/引用资产；旧正式版重跑 | 新 draft 不发布，旧版幂等仍成立 | 进程内 / 待实现 |
| 真实升级 | 支持增量的正式旧版升级下一正式版，含跳版/回退 | 下载量符合资产，重启后正确版本，可继续使用 | 用户手测 / 待合并后 |
