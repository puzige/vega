# #785 恢复单草稿与原有 UI

## 用户裁决与范围

用户要求 UI 相比多草稿引入之前不添加任何变更：删除侧栏 Drafts 区域，不以新按钮、菜单、文案、搜索结果或其他恢复入口替代。用户明确选择恢复旧版单草稿行为，不再保留多份未发送内容。静态核对旧版 R69 R4/R14 后确认：New task / Cmd+N 导航到并复用窗口唯一草稿，物化或清空后才创建下一份；不额外加入清空或强制替换行为。

本裁决取代 [#767 多草稿段落](../767/reasoning-defaults.md#用户确认保留原草稿并新建)，不撤销 #767 记住模型思考档位的修复。UI 参考为 `de2d4b26c8c69ecd72d7a38b4255c7ce07d1b420` 的父版本，实施基线为 `c3475642`。

## 最小实现

- 恢复原有侧栏、新任务事件与单草稿导航实现；移除多草稿展示和恢复入口。
- 删除窗口级多草稿容器、渲染复用、权限重置枚举及物化后的容器清理接线；单草稿的身份校验、迟到回执隔离、物化清理和权限重置保持有效。
- 不回滚 Composer 对默认思考档位的单键保存、失败反馈、重试和 catalog 防陈旧覆盖机制。
- 不迁移数据库，不读取或更改用户配置，不安装或重启远端应用，不增加依赖或 UI。

## 验收与风险

| 场景 | 期望 |
|---|---|
| 打开新任务、输入为空或非空、切到已有任务、再新建 | 不出现 Drafts 标题、模型名草稿行或新恢复入口；New task 复用唯一草稿 ID |
| 新建与 Cmd+N，切项目、设置、历史前进/后退 | 使用旧版事件/导航；已保存任务和原有文字容量保护不变 |
| 单草稿修改模型、权限、思考档位或项目，异步回执后切换 | 只更新匹配的草稿/来源 stream；不恢复已替换草稿，不污染新身份 |
| 普通发送、Codex、自动化或权限修改物化 | 匹配的单草稿清理，已保存会话可继续使用 |
| 全局权限重置 | 活动/缓存 stream 与唯一草稿仍按原权限规则刷新，不影响思考默认 |
| 在已有会话或单草稿保存模型思考档位，物化/清空后创建下一份草稿 | 新身份继承已确认的默认；返回现有唯一草稿不覆写其快照；保存失败仍提供原有真实反馈 |

单草稿回退意味着不再承诺多份未发送内容/附件的恢复；用户已明确选择该取舍，不借机清理数据库或其他资源。UI 与真实请求仍须用户手测，不以静态或 CI 代替。
