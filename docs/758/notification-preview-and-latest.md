# #758 通知预览与最新消息定位

## 目标与范围

用户反馈系统通知直接显示 Markdown 源码，要求点击通知进入对应对话后自动滚到最新消息。当前基线为 `8d86efce`。本规格补充 #481 的通知摘要与点击导航行为，不改变通知触发、终态、声音、隐私过滤或输入预测生命周期。

## 实现契约

1. 完成通知正文先用工作区已锁定、白名单内的 pulldown-cmark 解析 Markdown，再合并空白、移除控制字符、添加现有失败/中断前缀，最后按现有 160 字符上限截断。标题/粗体/斜体/删除线/代码围栏等排版标记不进入预览；保留可见文字、代码内容、链接文字与图片替代文字，不输出链接地址、原始 HTML 和脚注引用标记。段落、列表项、表格单元格与换行之间保留词边界，正文中的转义字面符号保留。纯文本、中文和 emoji 不受损；无可见文字时仍不通知。
2. 仅成功接受的通知导航产生一次目标会话尾部跟随意图；包括完成和等待回答通知。意图绑定目标会话，等其视图就绪后消费，同会话/缓存/运行中/首次异步加载均适用。该次导航跳过旧阅读锚点恢复，并使旧消息定位请求失效；失败或阻塞导航不得修改滚动状态。
3. 复用现有列表 Tail 跟随模式及后续分页能力；后续新消息保持可见，用户主动向上滚动仍可暂停跟随。普通侧边栏、搜索及历史导航继续原有阅读锚点行为。若用户在目标视图就绪前离开该会话，未消费意图随路由失效，不影响后来普通访问。
4. 不新增状态文案、依赖版本、配置或持久化字段；不修改对话正文、用户数据、通知路由校验与预测取消规则。

## 验收与验证

- 通知中 `已定位：**原因**\n\n### 发生过程\n1. 第一项` 显示可读文字，无粗体/标题标记；链接保留标题，围栏保留代码内容；失败/中断前缀、空内容抑制与截断保持。
- 当前对话停在旧消息、切走后收到完成通知、未缓存对话、已有历史定位的缓存视图：点击后显示最新消息；后续普通进入其他会话不被强制滚动。
- 等待回答通知仍进入对应对话尾部，恢复焦点及清已读行为保持；输入预测不因本次改变失效。
- 本地只做差异、格式与静态接线检查，不运行 Vega、编译或测试。不为流程增加开发 Rust 测试。非实现者只读独立审查及最终 head 完整 required Actions 为合并前提；CI 的 Rust 空集应写 `no Rust tests`（0 发现/0 执行），不冒充功能通过。系统通知与 GPUI 的真实交互由用户合并后手测。

## 风险与回滚

风险集中于异步视图就绪和旧消息定位结果竞争。以目标会话绑定的一次性意图、初始锚点恢复前检查、消息定位 generation 失效化隔离。回滚本卡差异即可恢复原行为，无数据迁移。
