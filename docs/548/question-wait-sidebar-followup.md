# 提问等待：消息列表与系统通知返工

Issue: [#548](https://github.com/puzige/vega/issues/548)

## 授权与基线

基线：`037031f3`。用户本轮澄清：“没有挂起”指消息列表仍转圈；同时要求提问时弹出操作系统通知。没有证据证明 runtime 越过未回答的问题继续执行。本轮不修改等待通道、工作计时、权限或其他任务流程。

本修订取代原规格 W3 的前台通知抑制规则，仅针对待回答通知；普通完成通知保持原行为。

## 根因

- `RunningThreads` / `sidebar/threads_block.rs` 仅判断 live worker，因此等待用户回答仍显示 Spinner。不能把 waiting 设为 worker 已结束，否则会破坏占用、安全限制与停止能力。
- `window/notifications.rs::apply_question_attention` 对前台任务提前返回，不提交系统通知。

## 验收

1. 有效提问进入待回答后，消息列表停止转圈，显示带“等待你的回答”可访问名称和就近提示的静态暂停图标；任务行可访问名称也表达等待。hover/focus 下的既有任务操作不变。
2. worker 仍存活，Stop、任务占用、项目移除保护、独立任务及提问无限等待不变。不把暂停伪装为完成或失败。
3. 回答或明确跳过后等待指示消失，仍在运行则恢复转圈；取消、完成和窗口释放清除等待投影。迟到的旧问题结束事件不得清掉新问题的等待状态。
4. 每个有效问题不分前后台向 OS 提交一次待回答通知，沿用 run/request 身份去重、点击定位、回答/停止撤回。无效问题、不存在的任务或取消中的任务不产生通知；重复绑定和切换任务不重复发送。系统通知权限、免打扰与平台投递结果由 OS 决定，不声称提交即弹出。
5. 普通完成通知、工作时钟、输入验证、单独提问批次及其他任务的状态不变。

## 最小实现

- `RunningThreads` 增加独立待回答投影，保留 `is_running` 语义；终止时统一清理。
- sidebar bridge 增加等待读写接口。行标签和 trailing 图标复用既有运行槽位，待回答用静态 Pause 图标和既有本地化等待文案，不增加常驻解释文字。
- `apply_question_attention` 在有效 Pending 后写入等待；Resolved 仅在 stream 不再有待回答问题时清除。删除待回答通知的前台提前返回，保留完成通知前台抑制。

## 验证与限制

本地仅快速 diff、格式和静态检查，不执行 Vega、不编译、不运行测试。独立审查覆盖 worker 存活不变量、等待恢复/清理、迟到事件、通知去重/路由及前台行为差异；最终 head 交完整 required Actions。按风险采用直接最小修复，不恢复历史 Rust 测试集合，不添加临时测试。CI 空集必须报告 `no Rust tests`，不冒充功能测试通过。

用户手测：提问后检查消息列表静态等待；前台/后台各一次系统通知；回答/跳过恢复转圈；连续问题、Stop、普通完成通知和其他独立任务不回归。当前桌面工具因屏幕录制权限缺失不可用，未观察实际弹窗，亦不修改系统权限或重启应用。
