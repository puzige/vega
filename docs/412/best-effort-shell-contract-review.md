# 异步 Shell V1：best-effort 合同与用户流程评审稿

版本：v1.0 · 2026-11-04 · 对应 [#412](https://github.com/puzige/vega/issues/412)。

**阶段：正式评审稿，尚未冻结实施。用户已明确接受 best-effort 的剩余风险，并授权整理合同与用户流程；本轮不改代码、不运行探针、不启动实现、不合并或启用会话能力。** 风险取舍已确定，不再要求用户重复接受同一原则；本稿的具体边界、参数及交互仍待评审确认。

## 1. 决策与证据边界

### 1.1 本次接受的合同变化

原保证是“证明所支持命令的全部后代安全收尾后，才允许工作区继续写入”。新保证拟改为：

> Vega 对自己管理的执行对象进行有界、可核验的尽力清理；没有观察到未解决异常，且必要资源与审计完成后，允许后续写入。未被发现的脱组、重挂父进程后代仍可能继续产生副作用；Vega 不承诺完整后代树终止或产物已静止。明确异常与丢失执行状态不得自动解锁。

工作区互斥是 **Vega 管理操作之间的调度约束**，不是 OS 文件锁、权限撤销或不可逃逸隔离域。`best_effort_completed` 不得继续命名或解释为 `cleanup_safe`、全部进程已结束。

保持现有 `sandbox-exec`、权限审批、危险命令检查、网络范围及凭据保护；不扩大写权限。沙箱内残留进程仍可能写入原先获准的目录，沙箱不是“取消后不再有副作用”的证据。

### 1.2 已有依据与未取得的证据

- 原冻结设计：`f28d8e2ab21869a71f30a7ed0dc959fb196d8035` 的[长命令设计](vega-long-command-waiting-design.md)。
- 未完成实现检查点：`5f2059be09ffe5a1d1df31253b9bb9f158806295`；[待完成项与原阻塞](implementation-checkpoint.md)仍需在未来实现阶段逐项处理。
- 本稿写作基线：`c00cd9cc5118dd068e29fcb8d35a9b828d4b9995`；[平台验证](platform-process-safety-validation.md)已给出直接 syscall 过滤不能覆盖 spawn 脱组、全禁 spawn 破坏普通工具链的有限反例；[可行性论证](platform-process-safety-feasibility.md)保留其他候选边界。

## 2. V1 范围

### 2.1 纳入

| 能力 | V1 合同 |
|---|---|
| 显式会话执行 | 仅 `bash.wait_ms` 为整数时启用；0–30000 ms。缺省/null 保持原阻塞协议、默认 timeout 120 秒及原输出形态，不自动转后台 |
| 已有命令的观察与取消 | `bash_wait(handle, cursor, wait_ms)`：缺省 30000 ms，0–300000 ms；`bash_cancel(handle)`：只取消原 operation；均不带新命令、scope 或 stdin |
| 运行期限 | 原 timeout 从实际启动起计时；观察、重复取消、恢复尝试均不延长它。收尾预算另计但不是继续执行许可 |
| 并发 | 每 run 最多 1 个在途 Shell、应用最多 4 个；同工作区跨 run 的可变操作互斥。只有规范化写根不重叠的工作区才可并行 |
| 只读重叠 | wait/cancel 与无需新增审批的项目内原生 read/glob/grep；读取不是快照。保留已有文件身份、读后再写及版本校验 |
| 启动资格 | 现有受支持 macOS 范围内的沙箱命令，仅项目内可写、无额外 writable roots。平台控制/身份观察接口不可用时启动前拒绝；不默默提高最低 OS 版本 |
| 用户流程 | 命令/输出/真实运行态、单命令取消、run Stop、清理异常入口、重试/手动检查/接受风险恢复；不另建任务管理器 |
| 清理 | 原组 TERM/KILL、直接 child 回收、有界后代发现和已知对象补充清理、reader/租约/临时资源收束 |
| 持久化 | 独立 operation 审计、唯一命令结果、追加清理/恢复事件、跨 run/重启工作区阻塞 |

会话模式排除 Full Access 或额外外部可写根；显式申请时启动前拒绝，不静默降级。旧阻塞命令仍走旧协议，但**同一工作区已有 busy/blocked 时，旧 bash、Full Access、write/edit 等不得绕过准入门禁**。

在途/收尾期间，同 run 的其他 bash、write/edit、其他可变工具、技能加载、桌面输入和新增动态审批继续被拒；用户 Stop、撤权及恢复所需的人类操作不受模型工具门禁阻止。跨 run 对目标工作区的可变操作同样受限。

### 2.2 不纳入

- stdin、PTY、交互登录、通用后台任务列表、自动超时转后台、跨 run/跨重启继续执行、模型自动唤醒。
- daemon、特权 helper、系统扩展、新 entitlement、提权、VM/容器或新的 OS 级隔离边界；不缩窄任意命令为文本白名单。
- 后台完整进程树追踪、无限扫描/重试、全系统模糊进程匹配、按陈旧 PID 自动绑定或终止。
- 自动 Git 回滚、文件事务、远端副作用撤回、与外部终端/应用/独立 Vega 实例之间的互斥。
- CI watcher/webhook、缩短现行五分钟查询间隔、改变构建速度或承诺性能收益。
- 新权限模式、每次取消风险弹窗、无关 UI 重设计、修改现有 CI 或新增真实外部 E2E 门禁。

## 3. 状态模型：三种事实不可合并

下列为语义字段，具体存储命名在后续实现规格中映射；不是本轮已修改的 schema。

| 维度 | 值与含义 |
|---|---|
| 执行阶段 | `prepared / awaiting_approval / running / finishing / stopping / settled` |
| 命令结果 | `exited / cancelled / timed_out / outcome_unknown`；启动前拒绝/失败单列 `not_started` |
| 真实退出观察 | 真实 exit code、signal 或未取得；取消/超时不合成 0、124、-1 作为真实退出码 |
| 清理结果 | `pending / best_effort_completed / unresolved`，附结构化原因及最近尝试 |
| 工作区处置 | `busy / blocked / open`；解锁来源区分自动满足条件或用户接受风险 |
| 输出完整性 | retained window、`output_gap / truncated / output_incomplete`，独立于命令是否已退出 |

- 仅在真实回收完成时可以确认 `cancelled / timed_out`；若直接进程状态未知，命令结果为 `outcome_unknown`。取消请求已接收不是取消完成。
- 若已知 exit 0 但清理未解决，保留 `exited(0)`，整体 operation 对外快照及 UI 是“收尾未确认”，不得显示整体 Success。对外会话 `state=outcome_unknown` 可以同时携带真实退出观察与明确清理原因。
- 只有命令退出 0、尽力清理完成、输出无读取错误且门禁可释放时，才展示命令 Success；不代表文件/远端业务结果正确或全部后代消失。正常有界截断仍可 Success，但必须保留缺口标记。
- 命令结果由唯一协调者按观察顺序一次提交。已确认自然退出先于取消决定时保留自然结果；停止决定先于退出观察时，以 cancel/timeout 等停止原因记录，仍保留真实退出观察。重复 wait/cancel 不改写已确定结果。
- 后续重试与风险恢复是追加记录：可改变当前清理/工作区投影，不覆盖原未知记录、不改写真实退出码、不制造新命令结果。历史未知的命令结果不会因“已恢复写入”变成成功。
- 收尾未解决但仍持有活 child 时继续持有其回收责任和在途容量；停止工具调用可返回异常，不丢 child、reader 或租约 owner。资源收束后可释放执行槽位，持久化工作区 blocker 必须独立保留；不能让内存保留上限淘汰 blocker 或活 owner。

## 4. 收尾与工作区互斥释放合同

### 4.1 原子停止准入与共同预算

自然退出进入 finishing；cancel、Stop、timeout、撤权、run 替换或正常关闭进入 stopping。首次进入时先关闭相应工作区的新可变准入，再收尾；原互斥无空窗转移为 busy 或 blocked。

**每次自动收尾共用 5 秒单调时间预算**，从首次进入 finishing/stopping 起算，覆盖观察、信号、回收、reader、Vega 管理的租约/代理、必要临时资源和结果提交。建议 TERM 宽限最多 300 ms、退出后输出排空最多 500 ms，均受剩余总预算约束；不逐步重置期限，也不每个 PID 另等五秒。证据齐备时立即结束，不固定睡满窗口。

五秒是有界尝试合同，不是 OS 调度/进程必然退出或界面硬实时 SLA。到期即转未解决，不据此解锁；尚活 child 保留被动回收责任，但不得靠持续后台主动重试掩盖本次失败。用户主动重试是新尝试预算，不延长原命令 timeout。

### 4.2 V1 尽力清理最小顺序

1. 合并启动时持有的身份、执行中已知关系与 TERM 前可取得的有界 PPID 后代快照，记录已知对象；不能先杀父进程，再把空父链当完整清理证据。
2. 对仍能确认属于原 operation 的原进程组发送 TERM；宽限后仍存在则 KILL。对已识别且能核验身份的脱组后代补充终止，**无论组信号是否成功**。
3. 回收直接 child，检查原组及已知对象；KILL 后最多再做一次有界后代发现。每次尝试最多保留 128 个进程身份，超过上限或发现/核验失败均记未解决，不能静默丢弃后称无残留。
4. 核验身份至少包含当前控制关系与平台可取得的进程出生身份，不能仅比较 PID、命令文本或工作目录。原组身份失去可靠关联时不向陈旧 PGID 发信号；组 ID/PID 复用或权限不足须作为未解决处理。核验仍不提供原子 kill-tree 保证。
5. 有界排空并收束 reader；撤销 Vega 管理的租约、关闭其代理，清理 Vega 拥有的临时资源；不能删除用户文件或声称已撤销传给后代的 FD、mmap、网络请求。
6. 提交唯一命令结果、清理结论与工作区处置，然后才向调度器开放写入。未取得持久化确认时保持 blocked。

PPID 发现只用于增加已知对象集；空扫描、主 child 退出、EOF、kill 成功或原 PGID 消失，单独都不能证明全后代退出。正常退出时父进程已消失、后代已 reparent 而未进入已知集，是明确接受的发现盲区；不是捏造一次“扫描成功覆盖全树”。不为发现盲区静默增加全局监控。

### 4.3 自动释放判定

以下条件须在同一 operation/工作区世代中全部满足；任一未知或失败都不能等价为 true：

| 编号 | 自动释放所需事实 |
|---|---|
| R1 | 直接 child 已真实回收，或有证据确认从未启动；已启动但未记录不属于从未启动 |
| R2 | 原进程组已观察为不存在；检查失败/无权限/归属不明不是不存在 |
| R3 | 已知执行对象无仍存活或身份待处置项，有界发现与检查无未解决错误/超限 |
| R4 | reader 正常结束；仅窗口截断可接受。强制关闭未结束 reader、读取错误另按 §5 处置 |
| R5 | Vega 管理的租约/代理及必要临时资源均已收束；撤权状态仍按原权限政策生效 |
| R6 | 命令结果、清理结论、解除本 operation 互斥理由的处置及适用世代已可靠提交，无阻止本条收束的独立安全故障；整体工作区是否开放另须检查其他 owner/blocker |

满足 R1–R6，记 `best_effort_completed`，释放本 operation 的互斥理由。并不逐一证明未观察到的后代不存在；这正是用户已接受的剩余风险。若同工作区还有其他 blocker，不得因本条完成就整体开放。

正常退出 0、非零退出、取消和超时采用相同释放门槛。run 自然结束、模型 Final、关闭窗口都不跳过门槛。已排队旧工具调用不得因解锁自动启动；有效当前 run 必须重新规划、重新读取并通过原权限/版本检查。用户 Stop 不自动恢复已停止的模型 run。

### 4.4 持久化与崩溃窗口

spawn 前可靠写入启动意图；失败则不启动。workspace gate 在运行、blocked 及恢复提交期间由同一协调域持有。终态/清理处置与 blocker 变更须以同一持久化事务或等价的崩溃一致性协议提交，收到确认后才解除内存门禁。

- spawn 后持久化失败：先尽力收尾、内存 fail-closed；不得通过重新派发修复记录。
- 最终提交失败/结果不确定：不开放写入；重开时从 durable pending 启动意图恢复为 blocked，不假装本次失败已成功保存。
- 应用启动后先扫描未确认意图、未解决 blocker、未确认解锁事务，再允许相关工作区的可变操作。存储不可读时不按“无记录”放行。
- blocker 绑定规范化工作区及世代，不受新建会话、关闭/重开项目、run 结束、路径别名或权限模式切换清除。V1 不承诺跨独立应用实例互斥。
- 正常关闭用同一预算；未解决则尝试落库。落库失败时保留已有 pending 的保守恢复含义，说明未保存确认，不能无限卡住退出或宣称退出即全部终止。

## 5. `outcome_unknown` 与不解锁规则

对外 operation 的未知结果与内部已知命令退出事实分别保留：

| 观察 | 命令事实 | 清理/工作区处置 |
|---|---|---|
| child 未回收、控制对象丢失、启动后结果丢失 | 命令 `outcome_unknown`，有何退出证据保留何证据 | unresolved / blocked；不合成退出码 |
| 已回收但原组/已知后代存活、身份不明、检查失败或发现超限 | 保留已知 exited/cancelled/timed_out | operation 收尾未确认（对外 unknown）/ blocked |
| TERM/KILL 失败且后续无法确认退出；预算耗尽 | 保留已知事实 | unresolved / blocked；不因超时转可写 |
| reader 持续不结束、必须强关或读取失败 | 已知命令结果不抹去；标 output_incomplete | unresolved / blocked；EOF 缺失不是残留证明，也不能忽略 |
| 租约/代理撤销、必要资源清理或审计失败 | 保留已知事实 | unresolved / blocked；属独立故障，不能风险跳过 |
| 崩溃/强杀/重开有未确认 operation | 未确认部分未知，handle expired | blocked；不自动恢复执行或按旧 PID 杀进程 |
| 自动解锁/用户恢复后出现可归属旧 operation 的残留证据 | 旧命令结果不重写，追加新发现 | 原子增加新 blocker，停止新可变准入；通知当前受影响 owner 进入停止流程 |

以下不单独制造未知：正常保留窗口截断、TERM 后 KILL 成功并完成检查、ESRCH 后确认对象消失、wait 观察窗口到期、理论上不能排除未发现后代。权限撤销后即使清理完成，后续仍受撤销后的权限限制。

不根据单次文件变化或模糊进程名认定“这是旧 operation 的后代”。归因不足时保留具体证据与不确定性，不误杀外部进程；可靠的新异常不得被原解锁记录覆盖。

## 6. 用户可见流程

遵守[设计守则](../vega-design-guidelines.md)及[工具块契约](../vega-tool-block-codex-parity.md)：命令/输出保持原文；工具产品标签用英文。下列只规定状态与必要动作，不新增第二套视觉组件、每行解释段或虚构进度。

### 6.1 状态、入口及反馈生命周期

| 用户场景 | 默认可见内容与动作 | 必须避免 |
|---|---|---|
| 未启用会话/普通命令 | 原有命令行、权限与阻塞反馈；不额外增加后台开关 | 自动异步化、第二次常规审批 |
| 待批准 | 沿用原批准入口，实际命令与范围；未启动不计运行时间 | 审批等待冒充命令运行 |
| 运行中 | 收起显示实际命令；展开状态 `Running command` 与真实耗时/输出；局部 `Cancel command`，全局原 `Stop` 继续存在 | 工具回执结束就显示 Success；假百分比、内部 ID 常驻 |
| 停止/收尾 | 原命令仍可识别；`Stopping command` 或自然退出的 `Finishing command`；重复取消幂等，不能启动第二套清理 | 点击取消立即变 Completed；spinner 无限替代异常 |
| 尽力清理完成 | 真实命令结果：Success/Failure、`Command cancelled`、`Command timed out`；输出保留；不叠加成功 toast | “全部进程已终止”“已安全清理”；把未知退出显示 0 |
| 未解决 | 命令附近 `Command needs attention`，工作区动作附近 `Workspace writes paused`；显示原因与 `Review recovery` | 警告只藏在已折叠过程/tooltip；把取消本身当红色失败 |
| 恢复处理中 | 原问题与写入暂停仍可见；重试清理为 `Retrying cleanup`，仅重新检查为 `Checking status`，提交风险恢复决定为 `Resuming writes`；动作防重入，只读仍可用 | 未清理却显示清理中；没收到提交确认就显示已恢复 |
| 已恢复写入 | 恢复面板关闭/局部短暂反馈；历史保留未知事实与 `Writing resumed by you` 或重试结果 | 把原未知结果改成 Success；常驻成功提示条 |

普通取消且无收尾异常不弹错误或风险确认；已知收尾异常即使起因为用户 Stop 也必须呈现。固有残留风险在会话能力的按需说明/结果详情可查，不在每个正常命令重复。用户接受风险恢复时，风险必须直接出现在确认中，不能藏入帮助。

失败文案必须说明实际问题和下一步。例如直接进程仍存活时用 `A command process is still running. Retry cleanup or stop it manually.`；存储失败时用 `Could not save the recovery state. Restore storage access, then retry.`。不向用户展示 outcome_unknown、cleanup_safe 等内部词作为唯一解释。

### 6.2 三个主要旅程

1. **运行与独立阅读**：用户提交任务 → 按原流程批准 → 命令回 running 句柄且继续执行 → Vega 可读/搜项目并分析 → wait 获取原结果 → 收尾完成后才允许后续写入。没有独立工作时正常等待，不声称加速。
2. **中途改要求**：用户 Stop 或提交替代要求 → 先停止旧 owner → 五秒预算内完成尽力清理则旧互斥理由解除；新要求在有效 run 中重新规划执行。未解决时保留输入/草稿，不悄悄丢弃，也不自动执行原排队命令；新 run 可解释/做允许的只读工作，但不能写。
3. **异常与重开**：工作区显示写入暂停 → 用户从当前会话或该工作区其他会话进入同一恢复入口 → 重试清理/手动处理/符合条件时接受风险 → 提交恢复决定后开放指定范围。退出重开依旧能找到入口，不要求复活旧 run。

收尾异常在原命令处显示具体原因；其他同工作区会话只呈现一处工作区级暂停入口，不在每个工具条目重复全文。原过程自动折叠不收起尚待处理的工作区提示。输入框仍可输入、保存草稿及进行允许的对话，写操作由实际门禁阻止，不靠禁用整个 Composer 隐藏恢复路径。

### 6.3 键盘、窄窗口与可访问性

Cancel/Stop/Review recovery 以及恢复动作均有清楚名称、Tab 可达、可见焦点；图标不能是唯一状态载体。恢复面板支持 Escape/取消返回，默认焦点不落在风险确认动作上；关闭返回触发入口。提交未确认期间禁用重复提交并可读取原因；Escape 不撤回已提交决定，也不表示恢复成功。

浅深主题、960×600 窄窗口、长命令/长错误下，主要动作与必要警告可见；完整命令和输出可展开、选择、复制。真实耗时与阶段区分，不用五秒倒计时冒充进程退出进度。不改变既有用户/模型内容、权限与阅读锚点。

## 7. 恢复流程与人类授权

### 7.1 恢复面板的内容

仅显示当前工作区、受影响命令、已知命令结果、具体未解决原因及下一步。PID、出生身份、审计世代、清理日志等诊断信息放详情；脱敏且不泄露凭据。不做全系统任务管理器，不从历史输出重建权限。

| 动作 | 条件、行为与结束状态 |
|---|---|
| `Retry cleanup` | 原 owner 仍有效时对原对象重试一次五秒有界清理；不启动原命令。R1–R6 全部满足后自动解除相应 blocker；失败仍 blocked |
| `Check again` | 无活 owner/重开后只重查可安全核验的事实及独立故障；不跨重启收养进程、发信号或恢复 handle。无法重建原控制连续性时不自动宣称清理完成 |
| `View process details` | 提供可核验身份和手动处理指引，不静默启动终端命令、不按模糊名称建议全局 kill。用户手动处理后走重新检查 |
| `Resume writes…` | 仅对残余不确定性接受风险，须满足下节条件、确认并持久化；不重试命令，不改旧结果 |
| `Not now` | 关闭面板，保留 blocker 及可再次访问入口，不自动倒计时恢复 |

### 7.2 哪些情况允许用户接受风险恢复

所有条件必须同时满足：

1. 当前没有经核验仍存活的相关执行对象，没有活跃的新 owner；已知存活则先停止/手动处理。身份无法确认不等于已知存活，可以作为明确披露的残余不确定性。
2. 独立的权限、租约/代理撤销、必要资源及存储故障已修复。不能用同意风险授予新权限、放弃凭据撤销或跳过失败审计。
3. 用户从可信应用 UI 明确确认；模型、工具调用、技能、输出、历史消息不能触发或伪造此决定。本次产品风险裁决不代替未来每次异常恢复的确认。
4. 确认绑定当前规范化工作区、指定 blocker/operation 集合和恢复世代。面板打开后若新增 blocker、发现存活对象、权限/存储变化，原确认过期；重新展示变化，不批量放行未知新问题。
5. 先可靠追加恢复记录并比较世代，再开放指定 blocker；仍有其他 blocker 则不整体解锁。记录来源为用户接受风险，绝不写成平台证明清理成功。

确认标题 `Resume workspace writes?`；正文直接说明：`Some command descendants may still be running and may change files while Vega continues. This will not rerun the command or undo earlier changes.` 主按钮 `Accept risk and resume`，取消按钮 `Keep writes paused`。若有已知活进程或独立故障，主按钮禁用并在相关位置说明原因/下一步，不能仅靠 hover。

恢复提交失败时保持面板与暂停状态；重试恢复提交必须幂等，不能重复开放或重派命令。成功后增加工作区观察世代；后续可变操作必须重新读取受影响文件并通过现有身份/版本检查，不能沿用后台运行/未知期间的陈旧读取。

重开后的未确认执行无法恢复控制连续性；即便旧 PID 已不存在，也不能自动认定全后代已退出。独立故障已修复、无已知活对象时，用户可接受风险恢复；旧 handle 始终 expired，旧命令结果仍未知。重启本身、点击“我处理好了”或时间流逝均不是解除条件。

## 8. 新增风险、缓解措施与不承诺事项

| 相比原合同新增/显化的风险 | 后果 | 保留的缓解与局限 |
|---|---|---|
| 自动放行时漏掉脱组/reparent 后代 | 与下一次 edit、Git、命令并发写入，产物在完成后变化 | 沙箱不扩大范围、版本重读、发现异常再暂停；不能消除检查后的竞态 |
| 取消并非停止全部活动 | 残留占 CPU/端口、访问已批准网络、延迟副作用 | 有界清理与已知对象处理；无全树终止保证，无远端回滚 |
| 已授予能力不能全部收回 | FD/mmap、已发网络请求或已交给后代的数据继续起作用 | 只能撤销 Vega 管理的租约/代理；不宣称能追回已授予能力或外部效果 |
| 用户在未知下恢复 | 允许后续写入与残留交错 | 限工作区/世代/问题集合、真实确认和审计；不是证明问题消失 |
| 补充枚举及信号竞态 | PID/PGID 复用、归属错误时可能误识别/误杀 | 核验出生身份、拒绝陈旧目标、不模糊扫描；不能用用户同意掩盖实现归属错误 |
| 有界清理的保守失败 | 正常命令也可能暂停写入，需要人工处理 | 一次重试与恢复入口；不为降低阻塞率吞掉真实错误 |

不以自动 Git reset/revert、删除临时文件、复制工作区或“没有新输出”代替收尾。已有文件与远端副作用不因 cancel/recovery 撤回；版本检查不是文件事务。V1 面向经权限批准的普通工具链使用，不声称是对恶意任意代码的不可逃逸 containment。
