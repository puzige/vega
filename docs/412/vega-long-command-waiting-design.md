## 1. 目标、证据与非目标

目标：显式选择会话式执行时，让长命令在短等待后返回已有运行句柄；后续等待和取消只作用于原进程，不重复派发命令。改善等待期间的响应性、独立工作的重叠和真实终态获取，不承诺缩短远端 CI 或发布本身。

本轮只新增本设计、更新卡片；不改生产代码、工具 schema、CI、数据库或用户配置，不运行 Vega、测试、构建或后台进程。实现须另获用户授权，不能由本规格自动启动。

## 3. 最小接口草案

以下为待实现合同，不是当前可用工具。名称与限制冻结用于设计评审；实现调整须先修订本规格。

| 入口 | 参数与职责 |
|---|---|
| `bash` | 原有 command/timeout/requested_scope/description 不变；增加可空 `wait_ms`。缺省/null 走原阻塞协议；整数 0–30000 显式启用会话协议，有界等待后返回当前快照 |
| `bash_wait` | `handle`, `cursor`（缺省/null 表示起点）, `wait_ms`（缺省/null 为 30000，0–300000）；只等待已有进程，不能附带命令或新 scope |
| `bash_cancel` | `handle`；请求终止已有进程组并等待有界收尾，无新授权、命令或 stdin 参数 |

`timeout` 仍为命令执行上限，null 仍为 120 秒；从实际 spawn 后按现有执行计时起点计时，不包含审批和模型生成时间。wait_ms 只限制本次观察等待，不重置或延长 timeout，不能在 bash_wait 中修改 timeout。wait 的窗口到期返回当前状态；等待调用本身被 run 取消则进入进程收尾，而不是留下后台运行。

会话协议回执至少包括：`handle`、`operation_id`、`state`、可空 `exit_code`、`output`、`next_cursor`、`retained_from`、`output_gap`、`truncated`、已知的收尾错误码。每次最多返回 16 KiB 脱敏 UTF-8 文本；这是输出字节上限而非模型 token 配额，仍受既有工具消息总预算约束。

- running 时 exit_code 为空；finishing/stopping 仅在已确认退出时可携带真实码，收尾仍在进行时不能据此称成功。
- `succeeded`：退出 0 且输出、凭据租约、临时资源收尾成功；`failed`：非零退出或已确认的执行/收尾错误，提供原因分类。
- `timed_out`/`cancelled` 仅在已确认终止及必要收尾后返回。无法确认时返回 `outcome_unknown`，不谎报取消成功；读输出失败不自动推断进程仍活着或已停止。
- 重复 cancel 查询到已有终态则返回该终态，不改写成 cancelled；观察超时与命令超时有不同字段/原因。
- 新协议 running 回执只表示“调用已接受并观察到在运行”，不是原 bash 命令成功。旧协议不强行改成 JSON 或变更非零退出的现有表示。

## 4. 状态与身份

`prepared → awaiting_approval → running → finishing → terminal`；取消/超时/撤权可由 running 转 stopping，完成收尾后进入对应 terminal。启动前拒绝、取消和 spawn 失败不产生可用 handle；finishing/stopping 都不可启动替代命令。终态采用单一协调者提交，退出、超时和取消竞争不能生成矛盾终态。

handle 是不可猜测的不透明身份，不是 PID，也不是 bearer 授权。服务端绑定：应用世代、conversation/run、规范化 workspace 身份、工具实例、原始 call/operation ID、冻结的权限上下文和取消根。每次 wait/cancel 重新确认调用者身份与原 owner，不能仅凭字符串跨会话访问。

一 run 最多 1 个在途 shell，应用最多 4 个；上限在 spawn 前原子预留，启动失败释放。内存保留的 operation（含终态）另限每 run 4 个、全应用 64 个，至 run 结束释放；满额在启动前拒绝，不以 LRU 杀死活跃命令或无声淘汰可查询结果。终态输出及句柄保留至原 run 结束；run 结束后不再接受工具调用，重开仅能查看历史审计。不存在跨重启恢复真实进程能力，也不按 PID 重新绑定。

## 5. 资源、安全和调度边界

### 5.1 同一 owner 持有整个执行寿命

运行对象统一持有 child/进程组控制、stdout/stderr reader、取消 token、总 deadline、输出缓冲、临时目录、credential lease 和收尾结果。原调用返回 running 后，这些资源不能由栈局部析构提前释放。复用现有启动前安全检查、沙箱、精确 scope 审批、网络绑定和危险命令检查；不降级到用户终端或无沙箱后台 shell。

启动审批仍独立，不与其他审批批量合并。wait/cancel 不扩大原 scope、不延长租约、不新建可执行能力；权限重置/撤销会暂停新准入并取消原进程。禁止将 lease 交给模型或写入日志。进程终止不是撤销其已造成的文件/远端副作用。

### 5.2 仅开放很窄的重叠

在途进程可能改工作区；初版不允许同一 run 再执行 bash、write/edit、其他可变工具、技能加载、桌面输入或发起新的动态审批。wait/cancel 及无需动态审批的项目内原生 read/glob/grep 可由协调器继续处理；其他调用入口在执行前拒绝并说明需先等待/取消原命令。用户主动停止、撤权、重置不受此限制，必须进入取消流程。不能只依赖提示词阻止冲突。

协调器还须按规范化 workspace 身份跨 run 互斥可变操作（含路径别名）；不能只做单 run gate。V1 会话模式只允许项目内可写、无额外 writable roots 的沙箱命令；Full Access 或申请外部 writable roots 的命令继续原阻塞协议，显式请求会话模式则启动前拒绝，不能静默降级。网络 scope 仍按原审批。多个不相交工作区可各自运行，但不承诺远端资源互斥；现有用户终端、外部应用和外部 agent 仍可改文件，版本检查不能省。

这些读取不是文件系统快照：后续修改仍必须服从现有 read-before-write、身份/版本检查；有后台写入时读取可失败，不承诺跨文件一致性。不为本卡更改只读工具并行调度。正常 run 完成前协调器必须排空进程，模型一句“完成”不能把后台所有权丢给应用。新用户输入取代 run 时先取消和排空旧 owner，再承接新 run。

### 5.3 停止与未知结果

停止、重置、正常应用关闭：关准入 → 请求终止进程组 → 回收 child 与 reader → 撤销租约 → 清理临时资源 → 记录唯一终态 → 释放 owner。清理有界，沿用现有终止/排空宽限；超出可确认边界记录错误和 outcome_unknown，不自动放行同一 workspace 的后续副作用工作。由协调器保留隔离/待处理状态，用户可见问题和恢复入口，不能静默丢所有权。

正常关闭应有有界 shutdown barrier；崩溃、强杀或逃逸进程组的后代无法仅靠内存句柄和 kill_on_drop 保证回收。重开将未确认 operation 标为 outcome_unknown/句柄 expired，不重放、不按 PID 猜测存活，也不宣称 OS 级清理已完成。实现前须验证支持平台的既有进程控制边界；若无法满足所支持命令的安全收尾，禁止开放会话模式并报告阻塞，不通过无限等待或伪造成功绕过。此卡不承诺新建 daemon/全系统进程隔离机制。

### 5.4 输出有界且可重读

每 operation 最多保留 1 MiB 脱敏后的连续输出窗口；容量满丢最旧完整 UTF-8 边界数据，reader 仍持续排空管道，不能因模型未读取而阻塞子进程。单调字节 cursor 绑定 operation 与输出世代。旧 cursor 早于 retained_from 时明确 output_gap 与缺失范围，从保留起点返回；未来/跨 operation cursor 拒绝。相同 retained 区间重复读取结果一致，不使用全局破坏性消费游标。

stdout/stderr 仅保留观测合流顺序，不保证跨流原始时间序；脱敏在暴露与落库前完成，须覆盖跨块敏感值和路径替换，并有有界尾部暂存。不能把遗漏字节数冒充完整日志；最终结果只承诺保留窗口和真实截断标记。输出预算不得按先完成的请求随机丢结果。

## 6. 审计、恢复、诊断和 UI

- 一次命令对应稳定 operation ID；bash/wait/cancel 各有独立工具 call ID。保存原启动审计关联、非权威 handle 描述、观察状态及终态；历史不携带可复用权限或凭据。
- 现有工具表的 success/failed 不能直接代替命令状态：running 工具回执完成后，独立 operation 仍在运行。最小持久化需一个追加式 schema migration（operation 状态/原调用关联/世代/脱敏终态元数据），不得靠覆盖原工具结果或让已结束 call 永远 running 来规避。
- spawn 前写入启动意图；持久化失败则不启动。spawn 后写入/运行中持久化失败则停止新工作并收尾；不重新派发以补数据库。终态可幂等提交；崩溃在“已 spawn、未确认”窗口只允许未知结果，不宣称 exactly-once 的跨崩溃执行。
- 活 handle 仅在内存 registry。重开/摘要/压缩将历史观察投影为 authority:none 的审计数据；不得从模型可见历史重建执行绑定。尚活跃 run 内压缩不得丢失 owner 与查询身份，但也不能复活已失效 handle。
- 耗时统计基于单调时间区间：模型请求、压缩、命令主动存活/观察等待、审批、未分类。按 run/attempt 合并重叠区间；模型与进程重叠分别报告且不直接相加成总墙钟。进行中不当已完成；没有远端状态证据不能仅凭 sleep 命令给整段标“CI 执行”。
- 最小 UI 复用真实运行态、已有停止入口与结果详情；仍在运行时不叠加成功文案。收尾失败/未知结果和待用户处理事项必须保持可见。调试 ID、计数、内部阶段默认进详情，不新增常驻解释段或假进度。后台仍运行时不得因工具回执返回就显示任务已完成。

## 7. 同一假定时序的对比（纸面推演，不是 benchmark）

### 7.1 本地长命令与独立工作

假定命令在 t=0 启动、t=120 秒退出，两种方式均显式设置 timeout=300 秒（避免与默认 120 秒超时竞争）；另有 30 秒独立原生只读工作，不依赖命令产物；忽略审批、模型延迟、清理成本。会话初次等待 1 秒。

| 策略 | 工具调用 | 只读工作时段 | 命令结束获知 | 全部工作结束 |
|---|---:|---|---:|---:|
| 阻塞 bash，再做只读工作 | 2 | t=120–150 | t=120 | t=150 |
| 会话 bash，做只读工作，再 bash_wait(最大 300 秒) | 3 | t=1–31 | t=120 | t=120 |
| 会话 bash，但无独立工作，立即 wait | 2 | 无 | t=120 | t=120 |

有独立工作时理想节省 30 秒，来源是重叠而非命令变快；无独立工作反而增加一次工具/模型往返。窗口结束应由退出事件尽早唤醒 wait，不无条件睡满窗口。这些数值不是此次机器或模型实测。

### 7.2 远端 CI

假定 t=0 查询未完成，远端 t=120 秒完成，查询规则仍为至少每 300 秒一次且无事件通知。两种 shell 策略最早仍在 t=300 重新查到，发现延迟 180 秒；把 sleep 放后台不改变它。若用户明确要求每分钟查，则最早可在 t=120 查询（不含请求延迟），这是查询授权变化，不是异步执行收益。

不得将 wait_ms 用于绕过 PR 五分钟查询规则；不自动改成 gh run watch 高频访问。完成事件订阅是另一个有独立权限、恢复与成本合同的能力，不纳入 V1。

## 8. 实施切片、迁移与决策

候选最小改动范围：

1. `vega_tools` 私有执行 owner：抽出进程全寿命控制与有界输出；原阻塞 bash 也走同一底层收尾，不复制两套安全逻辑。
2. `vega_runtime` 的工具定义/准备/执行：显式 wait_ms 与 wait/cancel，身份/容量/冲突准入、原 deadline、唯一终态及有界等待。
3. `vega_conversation` 的 owner/停止重置接线、独立 operation 审计、追加迁移、恢复投影和诊断；必要时在现有 UI 显示真实在途状态/未知错误，不建立第二套用户终端。
4. Actions 按矩阵验证，非写入者独立审查；用户确认系统集成后再决定默认策略。实现卡须引用本设计精确版本，不在本 Spike 偷渡代码。

兼容：缺省 bash 维持原协议；新增参数纳入真实输入与语义等价比较、审批签名和投影，不能沿用忽略 wait_ms 的旧幂等键。新工具需按 provider JSON schema 能力完整传递，旧历史不伪造参数。回退可禁用新会话准入，先收尾既有 owner；追加 schema 保留，不能回滚到不识别活跃 operation 的二进制而丢弃所有权。

设计选择：采用显式 opt-in 的运行句柄，不自动异步化全部 bash；初版无 stdin/PTY、无跨 run 后台任务。由于当前循环只理解工具终态，这不属于“一处 schema 参数”修改，必须连同 owner、审计和停止接线一起交付，否则不开放能力。
