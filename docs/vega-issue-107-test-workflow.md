## Contract
User decision 2026-09-21: reduce testing time and concurrent task conflicts without weakening regression coverage. Replaces mandatory per-push workspace-wide testing and shared-target worktree wiring.

V1. One verification entry point, scripts/verify.py. Default scope = changed workspace packages plus transitive local reverse dependencies, determined from merge-base with origin/master, tracked staged/unstaged changes and nonignored untracked files. A change in public/shared code must reach its consumers. Explicit --base accepted. Root Cargo manifests/lock/toolchain/config changes require --full (fail with explanation otherwise); unknown executable/build inputs fail closed, never silently classify as docs. --full remains available and explicit, not normal per-card default. --plan displays selected packages and commands without executing tests.
V2. Scope categories: docs-only -> diff/format checks; scripts/hooks-only -> dedicated tooling regression suite + syntax checks; Rust -> fmt, selected-package clippy --all-targets -D warnings, selected-package cargo test (including integration/doc tests). Mixed changes union scopes. Known assets/build inputs conservatively select applicable package consumers or require full. No automatic test retries or removal/ignore/relaxed assertions. Task-specific production-root regressions remain mandatory in task spec; default package suites are the safety fallback, finer filters are not introduced in v1. Package/release only at delivery when applicable, not every push; cargo test/clippy already compile selected targets, so no redundant cargo build step at every push.
V3. Successful verification evidence can be reused only for identical source content (including staged, unstaged and relevant untracked files), base identity, selected commands, verifier implementation, toolchain, relevant build/test environment. Persist exact commands, per-step elapsed times, exit codes, raw logs and hashes outside worktrees under common git dir. Failed/incomplete runs never authorize push. Check identity both before and after commands to reject edits during verification. Logs/evidence missing/tampered invalidate reuse. No evidence imported merely from a human statement. Hooks call the same runner and do not recursively invoke git push. Pre-push checks the actual pushed commit matches clean current HEAD; ref deletion needs no build, unsupported multi-ref/non-head pushes fail clearly. Task worktree content changes after verification invalidate it. Reuse is local convenience, not a cryptographic adversarial attestation.
V4. cargo-lock.sh becomes compatibility entry to a Python standard-library coordinator. fmt does not acquire build/test locks. Default managed target is unique to canonical worktree identity under git common dir; never shares mutable target across divergent worktrees. Explicit CARGO_TARGET_DIR/--target-dir honored and coordinated by canonical target identity, rejecting conflicting flags rather than silently ignoring. Canonical targets retain a worktree owner binding; a second divergent worktree cannot adopt the same target even sequentially, because serialization alone does not prevent cache identity collisions. Explicit existing nonempty unowned targets must fail with migration guidance instead of silently trusting legacy artifacts. Existing target symlinks are not changed/deleted by running tests. Global bounded capacity defaults 2 build invocations; cargo jobs bounded so two builds do not each use whole host. Existing explicit jobs honored. All cargo test invocations retain repository-wide test resource exclusion in v1 until tests using global state have been audited; independent compilation can overlap. Do not claim fully concurrent legacy tests. Same target serializes clean/build/test whole span. Exclusive test resource is acquired before scarce build permits so waiting tests don't monopolize capacity.
V5. Use OS advisory locks (macOS/Linux), kernel release on owner death; wrapper waits for child and handles signals without releasing permits while child still builds/tests. A dedicated guardian process inherits lock ownership and waits/reaps Cargo; Cargo and compiler-wrapper daemons must NOT inherit lock descriptors. Killing the outer wrapper must not free permits while the guardian/Cargo still runs. Signals terminate/reap the Cargo process group before the guardian releases ownership. Existing compiler wrappers (including sccache) are preserved, not silently disabled; daemon lifetime must not leak build permits. Same target cannot become available prematurely. Fast fail by default; --wait explicit; --status reports owners and --release never breaks live lock. Record queue wait separately from command execution. Unknown cargo subcommands conservatively locked. Preserve compatibility for xtask package and status. No busy five-second spam. Legacy cargo-share-target.sh becomes a non-destructive status/migration guidance entry; it must not reconnect worktrees or delete caches. Main checkout legacy target retained untouched; migration guidance uses coordinator target path for artifacts.
V6. Update AGENTS, exec-guide and delivery skill plus hooks together so no contradictory all-workspace/default-share instructions remain authoritative. Python 3 standard library is the only new execution requirement; no nextest/sccache/nightly dependency. Document limits (legacy test serialization, cold per-worktree cache cost, unmanaged direct cargo bypass), cleanup only task-owned inactive targets after evidence retained. No product application code or installed app modification in this tooling card. Developer-tooling Rust in xtask is in scope only to preserve packaging compatibility: rebuild_release must locate the binaries from Cargo-reported artifact paths (or the effective Cargo target directory), never the hardcoded workspace/target path. This discovered compatibility change requires xtask focused tests/clippy in addition to tooling tests; no application feature changes.

## Acceptance matrix (before implementation)
|ID|Scenario|Expected evidence|
|--|--|--|
|T1|Two temp worktrees, different source values and concurrent real cargo builds|distinct artifacts with correct values; compile commands overlap within capacity|
|T2|Same-worktree canonical target, aliases included, concurrent callers; different worktree attempts reuse|same owner serialized; fast-fail/default, --wait works; other worktree or nonempty unowned legacy target rejected|
|T3|Legacy test command competes with another test and independent build|tests exclude one another; independent build allowed; no waiter occupies capacity unnecessarily|
|T4|fmt while build/test lock held|immediate execution without build lock|
|T5|Signal/child failure/owner death|nonzero status preserved; no live child overlaps next owner; no stale permanent lock|
|T6|Changed library package with transitive consumers|scope includes consumers; docs-only no Rust tests; scripts run tooling regressions; unknown/root changes require explicit full|
|T7|Repeat identical verification then mutate source/env/base/plan/log|first run executes, repeat reuses, each mutation invalidates; failed runs never reused; edits during command rejected|
|T8|Real git push to owned bare temp repo through real hook|current verified commit succeeds without duplicate tests; non-head/uncommitted/invalid evidence cannot silently pass|
|T9|Frozen tooling source in actual Vega worktree|tooling suite + fmt + diff checks pass; plan selects no unrelated Rust suites|
|T10|Migration helper and existing symlink|no deletion/relink of existing target, no shared-target reintroduction|
|T11|xtask release artifact resolution with explicit/managed target|uses effective Cargo output, never stale legacy target binary; missing build/artifacts fail|

Tooling E2E uses owned temporary Git repositories and tiny real Cargo crates; scripted cargo fixtures only for deterministic queue/signal/failure fault injection. Product UI/real provider E2E, cargo xtask package and app install are not applicable because only developer tooling and docs change. If xtask compatibility changes, validate artifact discovery through a tiny real Cargo build and focused xtask regressions; a full app package may be used for final compatibility confirmation when warranted. Report measured timing only for executed scenarios, no unmeasured whole-project speedup promises.
