# 隔离压缩拒绝诊断

## 范围与基线

用户授权仅在隔离工作树增加无正文、无凭据的细分诊断和回归。基线 v0.1.416 / `24f1d9397215db9e3258be0a679192be183349c0`。不升级、重启、写入远端或重放工具；不改变压缩接受/拒绝规则，不宣称已复现历史失败。后续用户授权整理提交、创建 PR 并完成最终 CI；本轮停在 PR，不发布或合并。

## 验收

1. 原有规范历史仍通过；源版本/指纹冲突、工具结果/参数/偏移/分组差异仍返回原 SourceChanged。
2. 微压缩所有权拒绝、请求历史比较、准备围栏、提交围栏及数据库写入器拒绝能通过现有 run diagnostics 持久化区分。
3. 仅输出固定阶段和固定原因枚举，不输出消息正文、工具参数/输出、凭据、原始错误、路径、源指纹；不新增 UI 文案。
4. 正常路径不生成失败诊断；诊断不可用不改变业务结果；取消不伪装成源冲突。
5. 使用进程内实际源/存储/写入器验证真实冲突拒绝；provider 若被调用立即失败，不调用模型或历史工具。

## 实现计划

数据库 runtime 字段有 CHECK 白名单；增加专用 DiagnosticMetrics.compaction_rejection 固定枚举字段及递增迁移，保留旧约束；复用 ContextSummary/SourceChanged 诊断事件。以固定枚举记录校验拒绝，原错误映射保持不变。替换上一轮临时 eprintln 分支标记。对微压缩读取、prepare、共享 writer admission 与 install 拒绝分别接线。请求比较只报告首个拒绝类别，不保留差异值。

## 验证与限制

在本工作树运行必要 Rust 回归、fmt、受影响 crate Clippy；保留测试源码和日志。含真实会话的 .diagnosis 仅本机私有保存，不上传或提交。独立只读审查绑定停写内容版本。按后续授权保留可恢复的合成回归开发提交，清理 Rust 测试及独占接线后运行最终 head CI；私有现场校验源码与数据不上传。本轮不合并、不发布，不操作远端应用或数据。
