# Issue #157：Sidebar 任务行悬浮快捷操作

## 目标

任务行静止时保持简洁；鼠标悬浮后直接提供置顶与归档操作，右键仍可打开完整任务操作菜单。该卡包含 #77 的“悬浮显示归档按钮”需求，二者不重复实现。

## 行为

- 覆盖 Sidebar 的 Pinned、Recents、项目任务和已归档任务行。
- 静止时不显示三个点菜单图标。悬浮时显示两个独立、固定命中区的快捷按钮：置顶/取消置顶，以及归档/恢复。任务行文本列宽度与既有尾部状态列保持稳定，不因显隐而跳动。
- 按钮名称、图标提示及动作由当前真实任务状态决定；点击只修改该行，不打开或重命名会话，也不冒泡触发父行点击。
- 右键任务行打开既有完整操作菜单，并沿用现有菜单项、键盘导航、关闭行为和任务变更错误处理。
- 键盘聚焦时保留完整菜单的可访问入口；菜单打开期间保留当前行操作焦点语义。
- 编辑标题期间不显示悬浮快捷按钮，行右键不打断或覆盖正在编辑的内容。
- 保留正在运行指示、选中态、未读态、行点击、双击重命名与组织行菜单行为。
- 不新增依赖、持久化字段、操作种类或公开 API。

## 验收

- 定向 GPUI 测试覆盖静止/悬浮/键盘聚焦/菜单打开状态、图标的 pin/archive/restore 状态和固定布局命中区。
- 点击 pin/unpin 与 archive/restore 调用现有持久化路径；不会打开任务；每次重载后的状态与数据源一致。
- 右键打开完整菜单，鼠标与键盘继续可执行其既有操作；重复右键或外点关闭正常。
- 正在运行的状态指示、编辑态、选中态、未读态与组织菜单回归通过。
- 桌面端用 Computer Use 验证 hover、左键快捷操作、右键完整菜单以及任务名称/打开状态；对临时测试任务完成后恢复其原状态。

## 范围

本卡只改任务行交互与对应 UI 测试及文档。不改项目行、分组标题菜单和任务详情页。
