## 根因与最小实现

`prediction_environment_eligible` 同时用于新申请与已有 owner 的持续有效性，模型菜单打开使 matches 为 false，self/window 观察进而清空 prediction 并取消 token。

1. 分开新申请资格与持续有效性；新申请仍要求菜单关闭，已有申请的有效性只排除模型菜单这个临时条件，其他 fence/阻塞保持。
2. TextInput 增加不改内容/revision 的临时预测抑制态。预测读取、呈现与接受共同受抑制；主动丢弃也不得删除被菜单抑制的建议。菜单关闭仅解除抑制，不重新请求。
3. 沿 stream 的 reconcile 同步抑制态；在途响应仍经完整 matches 写入独立 prediction。窗口层继续使用同一 matches，无需另建缓存。
4. 打开菜单时聚焦模型触发器，沿用 ModelSelector 的 Enter/上下导航/Esc，Esc 关闭后恢复 Composer 焦点。GPUI 先派发 action 后派发低级 key，故根级同时捕获预测接受/丢弃 action：菜单期间接受被消费，丢弃改为关菜单；低级 Esc 兜底只关闭菜单。发送 action 也防止菜单期间透传，IME 合成优先不变。

不改 provider、重试、数据库、配置、其他菜单规则或新增界面文字。回滚走本卡合并提交 revert，保留用户草稿与数据。
