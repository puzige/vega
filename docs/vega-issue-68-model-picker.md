# Issue #68 · 无思考档位时仍可选择模型（规格与验收矩阵）

> 状态：SPEC FROZEN · 2026-09-21
> 来源：[Vega Issue #68](https://github.com/puzige/vega/issues/68) 的用户截图与标题；`docs/vega-issue-76-context-compaction-delivery.md` 记录了同一缺陷在无档位模型 `hy4` 上的复现。
> 基线：`origin/master @ 8c1d874`

## 1. 问题与范围

用户在 Composer 选中没有思考档位的模型时，点击模型触发器没有可见菜单，也无法从该入口切回其它模型。当前 `on_activate_model` 一律把关闭态切到 `ModelPickerLevel::Slider`；`render_picker_slider_layer` 对无档位模型不挂载卡片，因此状态虽为打开，屏幕却没有入口。

本卡只修复模型入口的路由。模型列表、选择后的持久化保存、思考档位能力和 wire 编码继续使用现有控制器。`ReasoningProfileProjection` 缺失、声明为空，或经 `declared_tiers` 判定没有可用档位，都属于“无可渲染档位”。不能为此虚构档位或提供方能力。

## 2. 行为契约

1. 有可渲染档位：点击/键盘激活模型触发器，先显示现有 Slider；点击 Slider 标题进入 List。保留 R59 的两级路径、卡片几何和档位选择行为。
2. 无可渲染档位且模型选项非空：激活触发器直接显示现有模型 List；不挂载空 Slider。触发器显示当前模型名，不显示“选择强度”。List 的选择、Esc、键盘上下移动与保存路径沿用现有行为。
3. 模型选项为空、模型选择正在保存或可信操作忙时，现有打开保护继续生效；不能显示空列表或发起虚假的选择。
4. 在打开 Slider 后能力投影变成无档位时，关闭已经失效的 Slider；下次激活按第 2 条打开 List。能力投影恢复后，下次激活按第 1 条打开 Slider。
5. 切换到无档位模型后，持久化确认关闭菜单；再次打开可进入 List。切回有档位模型后，再次打开进入 Slider。模型选择失败保留原模型并可重试。
6. 本卡不更改 `reasoning.toml`、模型能力声明、`ReasoningChoice`、数据库 schema、权限、provider 请求或其它 Composer 菜单。

本规格只对无档位路径取代 [R59 §3 R1](vega-r59-two-level-model-picker.md) 的“首次必进 Slider”；保留 [R57 §3.4 R12](vega-r57-composer-alignment.md) 的“不显示空滑块”。R57 对降级形态留有“普通开关或隐藏”的未决项；此处依据 Issue #68 的模型切换需求，选择直接进入现有模型列表，不新建开关。

## 4. 实现计划与回滚

1. 先在 `crates/vega_ui/src/conversation_stream/tests/model_picker_levels.rs` 用实际 `ConversationStream` 触发器写 I68-01 红测，保留失败输出；补齐 I68-02、04、05、07 的必要用例。
2. 在 `core.rs` 的触发器状态转换中，按 Slider 当前投影的 `has_tiers()` 决定首次进入 Slider 或 List；复用既有模型高亮与滚动初始化。能力投影刷新时处理已失效的 Slider。只在需要时更新 `render.rs` 的说明与旧测试断言。
3. 使用 `scripts/cargo-lock.sh` 串行执行定向测试、全量门禁和打包；以真实构建做原生走查并把证据保存到 worktree 外的持久目录。

无数据迁移。若出现回归，撤销本卡提交即可恢复原有状态；既有模型与思考偏好数据不受影响。
