## 实现计划

1. 写协调器增加命令级线程内观测scope；在队列失败时抓取协调owner类别/持有时长，保留queue/begin/commit/rollback区别，不以全局最近记录反推因果。
2. persistence actor三个命令分支在执行前建立scope，在失败后捕获有界快照。诊断文件写入发生在事务/permit释放后，沿用失败返回和取消语义；不延长超时、不自动重试业务。
3. store新增受限诊断存储：数据库同目录、descriptor锚定独立私有子目录，最多64个原子替换slot，文件0600、拒绝链接/不安全owner/模式，失败才sync；关联DB身份，读写均有界。跨进程使用私有固定锁文件的非阻塞flock；竞争时诊断返回不可用，不等待或改变原业务错误。持锁后优先使用空slot，满后替换修改时间最早的slot，不依赖进程内计数。仅使用一个固定临时文件，崩溃后在下次写入安全校验并复用，最多64个记录、1个锁文件、1个临时文件。导出加入已持久化记录，同时保留旧进程内观测字段并明确schema版本。
4. 云端回归验证真实协调器/SQLite竞争、重开读取/导出、安全路径拒绝、保留上限及原错误不变。静态调查委派准入及父事件路径；没有证据不盲修锁协议。

## 静态调查结论（基线固定，非历史归因）

- followup创建事务先提交，才返回准入成功；子执行等待父工具回执持久化后启动，没有发现这些路径的反向锁循环。
- 工具请求所属response在工具执行前已完成，因此新子任务准备不可能阻塞那个旧response的完成；可能争用的是后续父事件。
- 确认长writer暴露：`pipeline.rs` 准备事务从基线1165到1823，在锁内两次完整context-source加载（1218、1588）、投影、stage payload脱敏和目录创建（1289）。source loader在委派过滤前载入消息/工具与图片并计算指纹。它们没有10秒墙钟保证，但未取得历史耗时或持锁身份。
- 可行交错：父回执提交 → 子准备取writer → 处理历史超过10秒 → 后续父事件队列超时5/5 → 父失败取消子任务。只作为候选，不等于本次根因；不同线程队列超时5/5与外部SQLite writer的begin失败必须由新增快照区分。同线程跨连接重入返回6/6，不符合当前错误码。
- 新增诊断将Preparation/Persistence活动与thread/run绑定；队列失败保存当前内部owner类别、运行身份、持有时长及等待数，不虚构外部owner；不是全局最近记录的关联推测。
