# #868 多击选择保留末尾字符

## 目标与范围

用户报告聊天正文双击或三击后复制丢失最后一个字母，截图显示代码块文件路径的末字母没有选中。只修复只读聊天正文的多击选区；不读取截图中的私有文件，不改输入框、解析、依赖、剪贴板格式、链接或整段复制按钮。

## 根因与最小方案

基线 `4b1eb052`，`conversation_stream/selection.rs::SelectableMessage::paint` 只有在 `content_range != logical_range` 时才使用现有的局部多击范围处理；普通完整 run 交给 GPUI Base 0.6.1 的原生多击逻辑。后者在 `points_for_multi_click` 将范围转换为像素端点，Vega 的 `resolve_content_key_with` 再通过 `TextLayout::index_for_position` 转回内容索引。底层命中按字形左边界而非最近插入点解析，浮点坐标往返不保证保持原边界；回落到前一个字形时，Vega 将该索引用作半开区间终点，最后一个字符遂未被选中。此结论来自静态调用链；未本地运行复现。

最小改动：移除局部多击处理对 `content_range != logical_range` 的限制。普通正文复用现有 `multi_click_range`，直接保存逻辑正文中的 UTF-8 半开范围，同时用相同范围绘制选区及设置复制文本。保留现有 defer、投影 generation/可见内容核验、焦点与 local-selection 标志；不改变原生拖选或内容键解析器。

独立审查修订：普通完整 run 不阻断多击事件冒泡，让窗口选择层先建立原生 anchor/cursor，再由既有 defer 保存精确逻辑范围，避免后续 Shift 扩选失去锚点。下一次 Shift 单击的 capture 阶段保留原生 anchor、清除局部覆盖，继续既有窗口扩选；分片 run 仍保留原来的阻断行为，不改变其跨分片逻辑范围处理。本修订修复首次提交引入的扩选回归，不放宽验收。
