# Issue #296 · 每轮单一动态过程入口

状态：用户验收反馈后授权修复。2026-10-11。基线：`origin/master@19e4122`，保留 #304。

## 1. 需求与范围

用户反馈：运行中仍有多段工具、思考折叠行穿插正文；展开箭头常驻且紧贴标签；请求级运行图标像刷新/重置。期望每轮只有一个最大的过程折叠块，其标签随最新活动更新，展开可看本轮全部操作历史。

本轮只修改会话过程展示投影、共享过程展开控件、相关图标及测试。不改运行调度、模型调用、权限、上下文预算、存储原文或 final 判断；不动设置、Composer 分支、#291 已接受限制。用户截图作为私密验收证据，公开文档仅含合成示例。

本文件覆盖 v3 U11/U12/U16/U17/U18 中以下旧展示规则：运行中分散过程行、独立于过程头的 Thinking 行、箭头跟随标题。时长贴近标题、正文可读、可信 final、选择/焦点/回看保护继续有效。旧历史和 ACP 未知 final 仍保留全部正文。

## 2. 单一入口和正文

- 单位为一次用户提交产生的 run，沿用真实稳定身份；不按正文段落、工具循环或思考片段另起顶层过程块，不跨 run 聚合。
- 旧历史只有可靠 assistant message 归属但没有时长或 final 元信息时，可在该可靠归属内聚合已知思考/工具，时长留空、正文全留；不能以相邻位置猜跨消息 run。
- 每个有过程的 run 只有一个顶层 header 和一个展开区域。正在运行但尚无内容也显示该 header；它固定在本轮正文之前，不随着最新事件移到文末，不新增悬浮或 sticky 行。
- 运行默认收起；所有已到达的普通助手说明仍依原顺序在外展示。思考、工具调用只进入同一个过程区域，不能再作为正文间的独立折叠块。展开不重复外部正文；同一工具/思考操作在过程区域只出现一次。
- 展开后按源事件顺序查看本轮全部思考和工具历史。内部可按既有语义分组、逐项展开详情，但不新增第二个顶层入口；原文、输出、复制和状态保留。
- 可信 final 到达后，沿用 v3 的一次默认收起：有可信归属的中间正文归入同一过程区域，final 正文留外。用户已主动展开、选择、聚焦或回看时不得强制关闭。无 final、失败、取消及未知历史保留外部有效正文。
- 产物/结果卡沿用既有外显、打开和复制行为，不计作额外过程折叠入口；聚合思考/工具不能顺手隐藏产物。
- 失败/拒绝工具可在折叠 header 以紧凑状态提示存在，详细原因在历史中可追溯；消息级错误、权限卡、危险确认和待回答问题始终在外，不藏入过程区，不重复制造工具块。

合成示意（箭头仅 hover/focus 显现；两行正文仍各自保留）：

```text
检查结果表明需要补充一个字段。
```

## 3. 动态标签与状态图标

- header 的主标签来自当前真实阶段：当前思考有可信摘要则显示摘要，否则 Thinking；当前工具执行则使用易读工具动作名。并行活动工具按稳定首次出现顺序去重，最多两个动作名，更多时加“等 N 项”；完整项始终可展开。
- 优先级：待权限/回答 > 有真实正在运行的工具 > 当前思考/最新可信摘要 > 普通过渡 Thinking。终态优先于上述运行态。已结束工具不得覆盖后来开始的思考；新思考没有摘要时不得复用上一轮工具之前的旧摘要。
- 工具 proposed/PendingApproval 不能标为运行；尚待批准显示等待确认，Approved 尚未开始且无 Running 项时显示准备调用工具。存在 Running 项时只汇总真实运行集合，不把排队项当正在执行。
- 未知工具使用现有安全显示名；安全投影未提供可靠名称时允许使用通用工具分类，损坏投影仍保留异常提示，不从 raw name 补名。不得把原始参数、多行命令、敏感路径或工具输出填进主标签，不生成额外模型总结请求。
- 本轮时长是次级信息并紧贴主标签，仍使用同一时钟；更新标签、展开、切页面不重置。终态保留 Worked for / 失败 / 已取消与可靠时长，未知历史不造时长。并行子项时长不相加。
- 移除该过程 header 的 Refresh/RotateCw 图标。思考/等待模型使用共享 Bot 图标表达 AI 正在工作；单类工具使用现有类别图标，多类工具使用 Summary；待用户使用 Help/Hand；成功使用 Check，失败使用 Warning，取消使用 Close。它们不是按钮，不能产生刷新/重试动作。其他真正刷新按钮不受影响。
- Thinking/当前可信摘要沿用柔和文字 shimmer；只保留一条活动摘要。工具执行不伪装成 Thinking。待用户、终态、隐藏视图和 Reduce Motion 下停止；图标不额外旋转或闪烁。

## 4. 展开控件与阅读稳定性

- 顶层过程、内部思考行、单工具行、工具组行的展开箭头都固定在各自完整行的右侧。标题和真实时长组成左侧内容组，间距沿用 8；仅弹性空白在该组与箭头之间。
- header 沿用 28 高、16 图标、13 标签及共享颜色，保留右侧 24 宽命中槽，16 箭头居中：`(24-16)/2=4`；右侧槽始终占位，hover 不影响标题宽度、截断、行高和焦点。
- 默认不绘制箭头；指针进入该标题行或键盘焦点位于该触发器时显示。展开后若无 hover/focus 仍隐藏。整条标题可点击，键盘 Enter/Space 可展开/收起，名称与展开状态可访问。hover 不是唯一入口。
- 过程外层仍无常驻灰底。标题可以使用现有轻量 hover 反馈，只有工具输出详情允许内容底色。
- 沿用 240 高单项详情及 320 高过程列表限制与原生滚动条；短内容自然高度。当前 header 在内滚动区之外。
- 原有稳定消息/内容身份、选择/复制、锚点和视口保持契约不变。锚点进入隐藏思考/工具必须先展开所属唯一过程再定位；历史水合、流式追加、长摘要截断不能改目标身份或跳到底部。
- 更新当前标签不得重建整个历史树或每 token 重新解析全部正文；沿用已有节流、虚拟列表与缓存。
