## 真实项目与终端

在两版中分别用侧栏文件夹按钮登记同名、内容相同的独立 Git 项目，打开底部终端。在 1404 逻辑像素宽的窗口执行相同的算术输出和 `stty size`。原版与第三轮候选均输出 VEGA907_42，原版返回 11 行 143 列，候选返回 11 行 134 列。正常 shell 中候选多出整行复制/重启动作，标签与三个工具按钮挤在左侧。恢复原版的标签滚动区与固定工具区、等宽字形度量、运行/退出状态栏与光标，保留真实 PTY 输入、复制、重试、重启和 IME 输入入口。隐藏再打开时同一 shell 的状态应保留。

第三轮非作者审查还覆盖了恢复副本和设置交互。成功恢复当前副本应消费同一副本，拒绝或失败时仍可取回。更新帮助应锚定到触发钮，可经键盘查看和关闭，开关应有可见焦点。刷新按钮只呈现当前状态需要的一个提示。

## 会话复现与输入围栏

同一回环测试服务收到两个完整应用通过正常设置和 Composer 发来的请求，返回固定标题、段落、列表与 Rust 代码。第三轮候选在运行标题异步回执中 SIGABRT。加入已有的裁剪修复副本后同一操作能完成，用户气泡正文仍被挤成零宽，代码区缺原版的语言和图标。气泡应按已允许显示的正文度量，受原有最大宽度、展开/收起、复制和选区规则约束。代码标题、语言及局部复制作业应与原版匹配。

终端真实键盘聚焦还触发了 NSH 按键解析错误。原生菜单复测中，打开右键菜单时回车执行了在 shell 中预置的无害命令。菜单必须独占导航和激活事件，关闭后恢复 PTY 输入；只打开菜单不得运行、重启或写入 shell。键盘可打开菜单，复制和重启应能按名称访问。

## 空闲窗口刷新与卡顿

在同机停止输入，连续 8 次间隔 1 秒采样。第十一轮候选为 98.3%–114.2% CPU，原版隔离进程为 0.4%–2.2%。6 秒主线程采样的 444 个样本中有 415 个处于 macOS 帧回调。只给 Vega 应用层增加临时计数的构建中，稳定空窗口的一个 2 秒区间内，侧栏行重复发送 1080 个快照，收到 2160 次 AppView 通知；侧栏装饰和导航也持续发送。单个原因需要用修复后的普通生产构建同条件回测。静止时相同快照无需唤醒渲染；实际入口、权限身份、选中、焦点、主题、语言、几何、动态状态和挂载变化仍须传播。诊断计数不进入产品。

用两个独立空目录顺序启动，这一组采用两个均无诊断计数的正常 NSH 开发二进制，窗口均为初始新任务。修复前 `fdb1e37a0c60a9150cd5d5ec162f27ffda0fdf87e13bcfb5a6cb8fb9e7bd4397` 的 12 次 CPU 读数为 55.2%–62.1%，中位数 57.4%；修复后 `39cfa002575fb34200cc767977ccd6428edd6a2987bd34693e336f5b194b7ed5` 为 1.6%–8.3%，中位数 2.3%。两轮未操作窗口，间隔 1 秒，样本文件随同机证据保留。该对照只度量空闲绘制成本。

长消息仍有单独的主线程卡死。第十六轮发送后进程存活、窗口查询超时，生成测试任务但尚未产生消息。主线程 1133 个样本中 1007 个位于通知分发。展开控件曾同时使用 keyed-state 自带的子到父通知和显式的父到子订阅；普通父通知会在两者间循环。行持有可独立渲染的 Host 时，保存其元素身份即可。应保留用户操作到会话的真实修改、父级变更校验、卸载和焦点逻辑。
