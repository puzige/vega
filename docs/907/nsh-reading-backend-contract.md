# Minimal pinned body-selection backend contract

Owner: parent integration writer. This leaf does not edit dependency sources, Cargo files, shared Surface or renderer. NSH remains 0.4.0, Kit 0.7.3 and Fast 0.1.9. The user approved a minimal production selection patch, not an upgrade or a replacement renderer.

## Original evidence

Cached `nsh-platform-gpui-0.4.0/src/selectable_view.rs` owns the private document `SelectionModel` and writes the clipboard in its built-in copy path (original published source around 591–620). `src/app.rs` owns the private Surface; the public TextView event API in `nsh-base-0.4.0/src/text_view/view.rs` has links/images/code actions but no document-range callback. The published `nsh-core/src/text.rs` default geometry queries are approximate; `nsh-platform-gpui/src/text.rs` paints its private GpuiLayout. See `nsh-body-public-api-gap.md` for the traced paths. No layout geometry is reconstructed from text widths here.

## Smallest production seam requested

Expose the following through the existing GPUI AppView/Surface, backed by the same mounted selectable document that receives pointer selection. Names below specify the desired Rust contract, not an assertion that these APIs already exist.

1. In `nsh-platform-gpui/src/selectable_view.rs`, a cloneable immutable `DocumentSelectionSnapshot` containing a fresh document/mount identity, monotonically changing content revision, selection revision, anchor/focus endpoints and ordered selected spans. Each endpoint/span identifies the mounted NSH text `NodeId`, exact attributed-text revision (or retained content token), UTF-16 byte-independent range and affinity. Include code-block identity where the existing code-copy path uses a separate selection owner. A selected string alone is insufficient.
2. In `src/app.rs` (forwarded through `src/surface.rs`), register a production selection listener and pre-copy interceptor on that exact AppView. Suggested behavior: `on_document_selection(Fn(Option<DocumentSelectionSnapshot>))`; `on_document_copy(Fn(&DocumentSelectionSnapshot) -> DocumentCopyDisposition)` with `Default`, `Replace(String)`, `Cancel`. Interception must happen **before** any clipboard write, for keyboard/context/code copy, and Cancel must not fall through. A nonblocking owner capability registered in advance is also acceptable if a cross-thread callback cannot synchronously consult the controller.
3. Preserve snapshot identity when extending the same retained content, but synchronously invalidate the authority when a node, attributed text, document root, selection owner, content revision or mount changes. Do not let a stale app listener cancel or replace another Surface's copy. Publish selection cleared on detach/replacement. Copy takeover must revalidate against the current mounted snapshot at dispatch, not only when publishing selection.
4. Source binding is application data retained on the UI side: `(stream entity, thread, reading epoch, message/source identity+revision, document/mount identity, NodeId+text revision) -> retained rendered-to-source spans`. Never add raw thread data to dependency globals. UTF-16 conversion validates scalar boundaries; source mapping uses the existing Markdown/Thinking source positions, not raw Markdown as displayed text. Missing/mismatched spans fail closed for custom source copy and must cancel built-in copy rather than silently copy a different range.
5. The dependency keeps actual structured Markdown, links, native pointer drag, cross-node/bidi selection, scroll/handoff and built-in presentation. The app keeps current exact-root/modal/preview reading checks. Readonly preview permits selection/copy/links; mutation checks are separate.

## Required parent regressions

- Real production selectable document across multiple nodes, wrapped proportional text, ligatures, RTL/bidi, emoji/surrogate pairs and combining marks; snapshots refer to the actual painted text revision, never an equal-width estimator.
- Replace(node), remove/reinsert, Surface stop/error, selection clear, new mount/revision and two simultaneous documents: old snapshot/copy/interceptor cannot authorize or overwrite the new owner's clipboard.
- Pre-copy Replace writes exactly once; Cancel writes nothing; code-copy interception precedes clipboard side effects; keyboard/menu/code routes share the hook; no fallback after Cancel.
- Application mapper: Markdown link labels, list markers, code original ranges, generated localized notices, Thinking summary/raw switch, retained-source trim, preserved selection after append and rejected selection after unrelated replacement.
- Readonly child preview remains readable; wrong visible child/root, Settings/palette/delete/opening overlay and inactive window reject stale authority. Geometry/scroll/native pointer and three-platform AX acceptance remain manual validation, not engine-paint claims.

## Current stage

The resumed writer consumes the actual `ReadingRequest { intent, snapshot }`, exact `ReadingSnapshot` node/AttributedText Arc/ranges, `set_reading_handler`, `reading_snapshot(area)` and `reading_snapshot_is_current`. Each genuine body has its own Surface handler; no default copy fallback is allowed. Source conversion uses tagged nested NSH text spans, UTF-16 scalar-boundary validation, retained structured blocks and SourceTextMap. TextView's `Renderer::render` creates `Tag::View` even for a Rust inline render closure (`nsh-core/src/element/renderer.rs:122–136`); `core::collect_text` treats a non-text child as an attachment (`core/mod.rs:5669–5722`). Therefore inline `render_custom` would insert U+FFFC rather than an addressable text span. The implementation instead consumes the concrete structured Document API and constructs real NSH text/span, list, quote, table and scroll primitives under the platform's unchanged real text engine. It never embeds former GPUI text or replaces GpuiTextEngine.

### Parent selection-listener wiring (implemented, unvalidated)

The continuing writer read the parent's actual `AppView::set_reading_selection_listener(area, Option<Rc<dyn Fn(Option<ReadingSnapshot>)>>) -> bool` and wires it after the body area layout acknowledgement. Listener callbacks schedule window updates, capture the projection session, coalesce by observation serial and reject old-session/current-snapshot mismatches. Selection-only observation never writes clipboard or opens a menu. Clear checks that the current native selection is actually empty before clearing app state, avoiding an older queued clear overwriting a subsequent native install. `ReadingBinding::observe_selection` remains available to the parent; do not install a competing listener on the same area. This wiring is implementation, not compiled/native acceptance.

### Source-window selection remap (actual seam consumed; remaining boundaries)

The parent now supplies directed `ReadingSnapshot.endpoints: Option<((usize,u32),(usize,u32))>` plus `AppView::install_reading_selection(&expected, anchor, focus) -> Option<ReadingSnapshot>`. The body consumes these exact APIs: maps directed native UTF-16 endpoints through tagged fragments and SourceSpans, retains logical positions during source-continuous projection replacement, converts positions back to the new exact node/Arc snapshot and installs only after current owner/root/source/layout validation. Source identity and exact overlapping retained bytes fence continuity; an unrelated replacement or Thinking summary/raw source-domain switch clears rather than reusing equal offsets. Existing native snapshots never authorize a changed projection.

Remaining concrete seam: `reading::install` currently rejects `!expected.cross_text`; `text::reading_snapshot` publishes no directed endpoints. Single-text-only selection direction/restore therefore cannot be claimed. Expected minimal extension: supply its real directed anchor/focus and support the same current-snapshot-guarded install on that single native text, or guarantee the body emits only cross-text requests. Parent must verify mutation/listener publication ordering, reversed selection, append, trim, clear, detach, root switches and UTF-16 boundaries. The app retains no authority after a missing endpoint; it does not guess or trim away source to pass acceptance.

### Code-copy route

Public TextView supports `code_block_actions(vec![TextViewCodeAction::new("vega-copy-source")])` and reports that non-`copy` id without first writing a clipboard (`text_view/view.rs:82–89,139–149`). The concrete body renderer uses its own NSH button, so it never invokes built-in `copy`; it returns the retained binding id, checks current owner/root/revision/geometry, engine layout acknowledgment, the mounted tagged document and code SourceSpans before writing. Parent clipboard takeover remains defense in depth. The continuing app implementation adds actual GPUI transparent Tab/Shift-Tab, Enter/Space and AccessibleAction::Click targets over engine-measured native code-copy controls, with native snapshot and host geometry revalidation. Pointer/native copy still uses the same trusted source path. This is implemented but uncompiled/unverified; role alone is not claimed keyboard or native coverage.

### Exact painted text geometry still required for preview/fade and intra-block scroll

Original API evidence: `nsh-core/src/core/measure.rs::measure` rejects nodes with no `layout`; its parent walk explicitly excludes text spans/raw text from independent views. `core/mod.rs::collect_text` flattens inline text into the outer AttributedText. Consequently attaching ElementRef to a link span cannot provide painted wrapped/bidi rectangles. The existing `vega_ui::link_preview::prepaint_link_targets` requires the former GPUI TextLayout and has no pure exact-rect registration API. Reading scope remains present, but direct link opening is not preview parity. This writer does not modify that shared coordinator or manufacture a TextLayout.

Needed parent-owned geometry contract (proposed, NOT an existing method): given a current ReadingSnapshot and `(text_index, UTF16 range)`, return the exact painted visual rectangles and caret/hit endpoint from the same private GpuiLayout, in documented Surface-local coordinates, clipped to current scroll view; reject mount/content/batch/scroll/scale mismatch synchronously. App-level coordinator adapter must accept those exact rectangles, currentness callback and reading scope, retaining existing hover delay, safe link classification, cancellation, focus/AX/keyboard and scroll dismissal. The permitted app writer can consume that interface once actually provided.

### Geometry implementation acceptance

The next same-version reading increment will expose an opaque `ReadingGeometry` lease through AppView, captured only for a current native ReadingSnapshot. It retains the exact GpuiLayout/content identity and current surface generation/batch, root size/origin/scale, and ancestor mount/transform/scroll/clip state. Queries return actual layout selection rectangles and TextPosition-affinity caret/hit results in Surface-local logical points; callers convert to window coordinates using the separately validated host bounds. No measured rectangle grants copy/open authority. A currentness query must reject stale geometry after scroll, transform/clip change, content/layout replacement, reparent/detach, resize/scale/origin change, Surface retirement, and ABA where observable revision exists. Non-finite coordinates and unsupported perspective/rotation/rounded clipping must fail closed instead of approximate hit areas. Preserve un-clipped caret coordinates for source-anchor offsets separately from clipped interactive rectangles.

Development regressions must exercise actual GpuiLayout rectangle/caret/hit implementations, direction/affinity and mounted leases, plus stale scroll/resize/replacement/stop. Shaping-dependent evidence requires the actual fixed text engine and available fonts; handbuilt uniform metrics are not native shaping acceptance. Existing selection/copy/mutation tests must remain passing. Application registration accepts provided measured rectangles and a currentness predicate, retains existing hover/cancellation/scope/key/AX behavior, and rechecks before async request completion, open and retry; no stale target or new automatic action is permitted. This stays within approved core-reading capability, changes no Kit/Fast versions and does not implement wheel consumption/remainder protocol.

Block-anchor scrolling now remaps surviving logical source to a new block and restores its measured pixel inset; removed anchors clamp to first surviving mapped source. This removes the old unconditional top reset but cannot preserve a wrapped line inside a partially trimmed paragraph/code block or changed wrap width. That requires the exact caret geometry/hit contract above, not average character widths.

Streaming fade also remains incomplete: `core/mod.rs::rebuild_text` installs a new AttributedText Arc when span style/color changes, while `reading::matches` intentionally requires Arc identity. Adding per-frame color alpha would invalidate selection snapshots and can clear selection; adding opacity on an inline span does not establish text-run rendering parity. Complete fade needs selection remap coordinated with paint-only Arc changes or a parent-approved paint-only opacity path preserving trusted content identity. Existing StreamFade timing/reduced-motion policy must be reused, not replaced with whole-body fade. No renderer/backend change was made by this writer.
