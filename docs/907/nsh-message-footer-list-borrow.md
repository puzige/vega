## Minimal implementation

Footer `Mounted::prepaint` obtains `list_bounds(&self.owner, window, cx)` from the existing publication before capturing geometry. It uses that single exact value for both the clipping intersection and `Geometry::list`. If the owner or current publication is absent, geometry remains revoked; there is no fallback to ListState, previous geometry, the window viewport, or a clipped content mask.

The prepaint still clears geometry, painted geometry and displayed identity first, retains the element-state mount, intersects footer bounds with the actual content mask and exact list viewport, rejects empty visibility, records window size/scale/id and foreground height, notifies on geometry change, and prepaints its child. Paint/displayed publication is unchanged.

The action-time fence `geometry.list == stream.list.viewport_bounds()` is unchanged: after List prepaint has completed this checks the latest actual ListState against the captured current viewport. The bounds-for-item visibility fence remains unchanged too. The other footer List calls occur only in `Input::current(interactive = true)` and `Host::valid` for action validation; rendering calls `Input::current(..., false, ...)`, which short-circuits its List branch. Native request delivery uses the async request receiver; pointer/keyboard/AX validation remains in its existing event path. No other direct footer List calls need relocation for this child-prepaint defect.

No controls, visible text, NSH rendering, business actions, focus semantics, timing budgets, assertions, comments, suppression or ignore directives are changed.
