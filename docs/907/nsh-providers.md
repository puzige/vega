## Integration design

ProviderManagement owns its NSH presentation and shared draft, avoiding writes to SettingsView state. Root must sync the provider presentation on every render including hidden routes. Existing render_provider_management/render_model_basics public signatures remain. begin_edit_provider and submit_provider are root-owned and require narrow hooks specified in the final handoff. Existing legacy provider form/action renderer and bindings must be removed by main after mounting the NSH replacement.

Navigation save cannot read a masked Signal from GPUI. save_provider_draft therefore requests an explicit NSH submission intent; the live form responds with its local key exactly once after checking the displayed authority, current shared draft revision/composition and intent. The original submit_provider path remains the only form validation/save route. Navigation discard and authority bridges must bind the shared session/revision (and key-presence/revision only, never secret text). No fallback may submit stale GPUI carrier values when an NSH draft exists.

## Exact main-owned integration hooks

These are required integration work, not optional follow-up improvements. This leaf does not claim the complete settings flow safe until they are applied and verified.

1. In root `SettingsView::render`, call `self.sync_provider_presentation(cx)` on every render, including hidden sections, after route/presentation preparation and before navigation authority is projected. The method is mutable and all state is stored inside ProviderManagement; no new SettingsView field or initializer is needed.
2. At the end of `state.rs::begin_edit_provider`, after the existing nonsecret fields and empty key carrier are initialized, call `self.reset_provider_nsh_draft(cx)`. Internal Add/Edit/model entry already maintain sessions. Do not ever initialize a native masked input from `key_input` or keystore.
3. At the beginning of `state.rs::submit_provider`, before reading carriers, add `if !self.provider_nsh_submission_claimed() { self.request_provider_nsh_save(cx); return; }`. The native receiver sets this flag only while invoking the original submit path after an exact atomic claim and one-time secret payload. Do not duplicate original validation/provider_key_ref/save logic. Legacy keyboard entry then requests live NSH input rather than saving stale carriers.
4. Update the navigation provider authority bridge to include `Option<provider_management::ProviderDraftStamp>` from `self.provider_nsh_stamp()`; its composing/busy predicate must include `stamp.composing()`. These stamps contain only nonsecret text, IME flags and key presence/revision, not secret text. Exported type is `ProviderDraftStamp`; the underlying module stays private.
5. For provider navigation Save, pass the stamp actually displayed by the guard to `request_provider_nsh_save_observed(&stamp, cx)` and stop if false. For confirmed Discard, call `discard_provider_nsh_observed(&stamp, cx)` and stop navigation if false. Do not call the legacy void discard and then finish regardless of its result. Do not read a fresh stamp in the receiver to authorize an old guard. Save intent additionally captures the pending destination/close intent and controller fence: Stay/change-of-intent invalidates a delayed secret submission. The same local masked Signal services form Save and navigation Save.
6. Remove now-unused legacy `render_add_form` and provider GPUI action/field render helpers, obsolete Provider focus arrays/targets and their tab/Enter/Cmd+Enter bindings/actions once references are gone. Keep original public controller entry points needed by app/navigation; native controls already implement pointer and keyboard actions. Provider's obsolete `Command::Menu` is removed: remove that arm from `model_configuration/provider_bridge.rs::command_authority`. Main must mount that bridge module below provider_management using its existing integration plan; this leaf has not added the path attribute.
7. Extend the NSH catalog Snapshot's capacity authority with the displayed `provider_nsh_stamp()` (in addition to its existing route/generation/candidate/fence). On `Action::Capacity`, carry that observed stamp into `apply_catalog_capacity_observed(&stamp, input, value, cx)` and only show `settings.catalog.filled` when it returns true. Preserve the original matched model/value extraction and all catalog requests. The original `catalog_capacity_editable`, six-tuple `catalog_capacity_fence`, and `apply_catalog_capacity_candidate` public interfaces remain; the fence now reads freshest native nonsecret strings. The new observed hook atomically rejects an IME/newer-edit race between catalog acceptance and prefill, without replacing other native fields.
8. Native provider list/detail/forms own scrolling in full-height provider Surface. Model basics remains an intrinsically measured native Surface and is vertically composed with existing image-capability/catalog surfaces inside a GPUI layout-only scroll host. Keep section 2/3 reasoning/pricing wiring and unavailable-model route handling unchanged.

## Review corrections acceptance

- Back to list from a clean narrow Add/Edit form exits that form and retires its NSH draft; a dirty draft still requires Save/Discard/Stay before the same transition.
- Provider authority visibility requires both section 0 and actual `SettingsOpen`; even a newly synchronized current snapshot rejects operations after settings close.
- Initial provider settings focus moves from the pre-mount placeholder to the mounted Surface host exactly when that placeholder still owns focus. Subsequent `Focusable` requests and guard Stay target the mounted provider Surface. This is host focus forwarding, not proof that pinned ordinary NSH View controls support native keyboard traversal.
