# NSH Workspace scope

## Acceptance frozen before implementation

Scope: production dock headers, tabs/close/create/move/maximize/hide/commit, creation menu, terminal-open error, Environment including subagent overview, and subagent list/detail/action chrome. Only workspace.rs, subagent_panel.rs, window/nsh_workspace/** and this document are writable. Existing embedded NSH bodies, TabKey routing, PTY ownership, store/services and subagent conversation-stream ownership remain authoritative.

- Both panes preserve exact TabKey identity, ordering, selected-tab fallback, terminal identity/background execution, hide/move versus close semantics, resize geometry, narrow-window restoration and the existing 104px shell-slot reservation.
- NSH constructs every product pixel in scope. Fast may arrange surfaces/embedded entities and supply resize, event, focus, accessibility and service hosting; it must not embed legacy painted controls.
- Commands carry presentation identity and the observed route/project, exact tab/selected pane, and subagent parent/task/message/operation identity where applicable. Receiver rejects hidden, obsolete, recycled, disabled and stale actions, including accessibility activation. Engine rendering does not invoke Git, store or services.
- Real host FocusHandles provide Tab/Shift-Tab traversal, activation and visible focus. Ordinary NSH View focusable is not treated as native traversal. Selected controls reveal within bounded local scrolling; accessibility actions are active only against the current projection.
- Preserve set_subagent_preview_visible, history epochs, detail loading epochs, stop generation and related-thread checks. Presentation teardown must not stop services. Recovery explicitly replaces presentation only, never replays unknown commands.
- Keep NSH 0.4.0 / Kit 0.7.3 / Fast 0.1.9. No fork, upgrade or dependency investigation. Native composing-key shortcut limitations remain blockers where applicable, not silently accepted behavior.

## Review correction acceptance frozen before changes

This continuation corrects three independent findings without expanding ownership or changing dependencies:

- Detail chrome must use the actual laid-out panel body height, not a fixed 220px allocation. With an embedded stream, local scrollable chrome receives at most half the body (capped at its preferred 220px); the stream receives the remainder. At the 150px bottom-pane minimum minus the 40px header, the 110px body must retain at least 55px of stream; at the 272px default minus header, the 232px body retains at least 116px. Right/full-window layouts must derive the same allocation from actual host bounds, preserving narrow dual panes and every action via local chrome scrolling/reveal.
- NSH accessibility activation of a nonselected visible control must not require host keyboard focus or prior Tab selection. An independent measurement lease must bind current controller/projection/mount, current geometry generation and visible control bounds; stale, hidden, unmounted, recycled and scrolled/repositioned requests fail closed. Pointer and keyboard guards remain separate.
- A pending detail read whose optional identity changes (including None to Some during panel population, or a different message/operation) must never apply obsolete content. If its parent/epoch/selection/child still owns the selected pending request, completion must settle loading into explicit Retry recovery; a superseded request must not settle or mutate its replacement. No automatic business replay.

Development regressions must exercise the production layout-allocation, AX lease/activation and detail-completion decisions, including controllable completion order, without fabricated service IDs. All tests remain UNRUN in this stage; static arithmetic is not native layout acceptance.

## Implementation delivered for integration

- workspace.rs declares the private path module `nsh_workspace/mod.rs`; no shared registration edits. Each pane header, Environment, creation menu, terminal-open error and subagent chrome mounts a retained public Surface. Existing TabKey body routing and service methods remain owners.
- All scoped text/icons/control backgrounds, selection and focus pixels are NSH. Native code supplies layout, existing resize rails, routing, event/focus, paint-free active AX descendant and embedded migrated entities. The header retains the original shell-slot reservation; local horizontal scrolling includes tabs and actions so narrow panes do not silently hide controls. Subagent chrome uses bounded vertical scrolling. A paint-free detail layout element allocates from actual prepaint body bounds: chrome = min(body / 2, 220px), stream = body minus chrome. No guessed window padding is used. No-stream loading/error/list chrome receives the entire body.
- Uses the parent's now-public ProjectionId::new/matches and OrderedCommands::new/send. Renderers have fn(Signal, Sender) shape and local SignalEquals::Never state partitioning. No NSH keymap shortcuts are installed. Commands recheck live route/project, effective pane predicate, presentation/mount, exact tab selection/order, current enabled actions and relevant panel authority.
- Panel authority includes parent/child task, parent/message IDs, active run generation and queue operation identity. Existing related-thread lookup and generation/epoch/history ownership remain; asynchronous open/stop continuations additionally reject changed child identity or hidden/replaced preview. Pure detail reads retain optional captured message/operation identity checks. A still-selected pending read whose identity changes rejects content and settles into the existing explicit Retry UI; superseded parent/epoch/selection/child cannot settle the replacement.
- Real FocusHandles drive traversal/activation; NSH focusable is not used as a substitute. Active keyboard/AX controls require current measured visible geometry. Scroll increments a geometry generation and invalidates displayed confirmation; a measure/ack/display handshake rejects intervening scroll. Native active-descendant activation retains the keyboard focus guard. NSH AX instead admits a current request without prior keyboard focus/selection, issues a unique ProjectionId, selects/reveals that action, then activates only after current visible geometry measurement/ack/display. Request identity participates in snapshot matching; content/mount changes revoke it. Pointer activation remains direct and guarded by current controller authority.
- A failed Surface renders a separate NSH recovery Surface. Its sole enabled action replaces presentation; the original failed command is not replayed. Services remain owned by existing controllers.
