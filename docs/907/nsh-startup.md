## Independent HIGH review correction — acceptance before fix

The previous implementation incorrectly treated a snapshot captured by the native host after `Surface::publish` as rendered authority. Publication is not an engine acknowledgement: while NSH still shows loading/error A, a newly installed native host B must not Retry/Quit B.

- Add an exact structural frame identity covering startup session, mount, projection, running/error/recovery, selected control, language and appearance. Selection changes and selection round-trips require fresh identities; animation phase alone must not rebuild the structural page.
- A public pinned NSH `on_layout` callback created inside each structural dynamic run returns that exact frame over OrderedCommands. Only acknowledgement of the currently published mount/frame can establish the displayed fence. This means **NSH engine layout/render acknowledgement**, not proof of compositor presentation, native painting or pixels seen by the user. No platform/private/shared API changes are permitted.
- Pointer, Enter/Space and AX all require observed frame = engine-acknowledged displayed frame = published frame = current controller authority/selection, plus current root/mount, no engine failure, action eligibility and a one-shot dispatch claim. Native host B installation alone grants no business authority. Late acknowledgements from replaced recovery mounts cannot restore authority.
- After total recovery-engine failure, Retry/Quit remain blocked. UI-only reload may use a separate explicit failed-recovery fence requiring the current root, recovery mount, exact published/current frame, selected Reload for native activation, and one-shot consumption; this is not a claim that recovery rendered. Reload never starts a worker.
- Preserve the six original development tests. Add UNRUN regressions against the production acknowledgement/dispatch fence: delayed B ack with native host B installed yields zero Retry/Quit for pointer/key/AX; ack B permits exactly one claim; selection round-trip rejects old acknowledgements; recovery mount replacement rejects old ack; total-failure reload cannot authorize business actions.

Original product/platform acceptance remains unchanged. Build/test/app execution remains prohibited in this leaf; parent validates after writers stop.

## Implemented production contract

`StartupView::render` now enters `render_presentation`; no old GPUI product render remains. New modules are declared by explicit paths in `startup_controller.rs`, requiring no main/module integration edits. `view.rs` draws all product content; `logo.rs` records canonical paths through public NSH Painter APIs. Canvas drawing updates with the incoming phase without rebuilding the entire page every frame; the structural signal uses `signal_with(..., SignalEquals::Never)` and the exact structural frame token assigned by RenderFence rather than requiring equality on ProjectionId or ThemeColors.

`presentation.rs` owns one active Surface, its command receiver, failure subscription and production `RenderFence`. Primary error mounts a new independent recovery Surface and identity. Native handlers capture the **published**, not necessarily rendered, frame. Publication never advances the displayed fence. A public NSH `on_layout` listener created inside each structural dynamic run sends `Request::Rendered` over the same OrderedCommands queue as pointer activation. The fence accepts only the exact currently published frame token; old mount/selection/projection acknowledgements cannot advance it. Frame identity covers session, mount, projection, running/error/recovery, selection, language and appearance. Selection round-trips allocate new identities; phase-only animation updates retain identity and cannot reset a consumed claim.

`dispatch` checks the current root and uses `RenderFence::claim` for every pointer, keyboard and AX activation. Claim requires observed = published = engine-acknowledged displayed token, exact current controller state, action eligibility and no engine failure. Keyboard/AX additionally require that action to be the frame's selected control; AX retains the native focus check. A successful claim is consumed once before any action. Duplicate acknowledgements do not rearm it. Start rotates session and projection; fail rotates projection; every presentation mount rotates mount and creates a fresh fence. Recovery reload drops presentation only and never calls start. Closed command delivery has NSH-visible localized failure; both acknowledgement and pointer commands use shared OrderedCommands backpressure/order semantics.

This is **engine layout/render acknowledgement only**. It is not actual compositor presentation, native paint completion or proof that a user has seen pixels. NSH 0.4.0 public `Interactive::on_layout` is defined in registry `src/element/builder.rs:1482`; `src/core/components.rs:2775–2806` initializes a new dynamic-run listener against kept geometry even when size is unchanged; engine `src/lib.rs:2695–2714` delivers it during commit. No dependency, platform, shared Surface API or native painting changes were made.

The worker body from `let (sender, receiver) = mpsc::channel()` through its detached completion task is retained unchanged, including appearance read, updater acknowledgment, prepare_default_workspace, worker spawn/disconnect mappings, apply_appearance and open_workspace. Static body SHA-256 is `8da2615bb927da3c4f89762333927d81fc66f3e81a48a679eddc679b302de702`. Running dedupe still occurs before any startup mutation. Only presentation identity/focus bookkeeping was added around start/fail.

The fullscreen host paints nothing. It owns a real native FocusHandle and captures Tab/Shift-Tab/Enter/Space by physical key name even with character preference; held/modifier inputs are ignored by the startup policy. Retry is selected/focused on failure, NSH shows the selection border, and Tab wraps the eligible controls. There is no ordinary View.focusable shortcut. Frame scheduling checks active window, current root, nonzero viewport, reduced motion, loading state and non-recovery presentation; phase retains the original epoch across pause/resume. The existing loading_logo.rs remains available and unchanged for other callers.

Two new presentation-only strings have English/Chinese local selection via the existing language API because catalog files are outside the write boundary: the explicit Reload startup view action and the specific presentation-error/reload instruction. Existing title/error/Retry/Quit/loading and command-failure labels still use the exact catalog keys. These are necessary error/recovery instructions, not additional normal-state explanatory copy.
