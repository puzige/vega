## 当前并行实施方式

用户最新要求四路并行先完成全部实现，再集中独立审查，不在小模块交付之间插入 review。四路分别负责时间线/工具/滚动、正文阅读/渐显、原生编辑闭环、剩余生产控件/菜单；主 Agent 负责共享接线与集中编译集成。每路保持单一写入者，连续推进自己的授权范围。必要自测和编译继续用于修正实现，不视为中途独立 review。完整实现后仍执行集中非实现者独立审查、最终 required CI 与三平台验收；这次顺序调整不授权升级 Kit/Fast、扩大依赖补丁、降低功能安全验收或合并半成品。

### 共享错误文本残余迁移

Composer 控制器错误、压缩失败和回复失败提示的 `plain_error_notice` 必须使用已有 NSH 文本测量宿主，不保留 GPUI 字形绘制。原始文案、语义色、正文大小/行高、自然换行与外层间距不变；不添加操作、不改错误恢复或持久化。长 CJK/emoji 错误需产生完整 NSH 文本和自然高度回执，宽度或投影变化后拒绝旧测量。新增开发回归仍须实际执行，源码存在不算通过。

用户气泡的圆角底色亦由被动 NSH 背景绘制，保留原 accent RGB 与 conversation_bubble alpha、圆角 token、右对齐、最大宽度和全部内外边距。背景不得拦截鼠标、进入 Tab 或产生重复 AX 节点；原阅读正文和选择行为不变。

进行中的压缩提示必须由 NSH 构造原 TextSelect 图标和完整标签，保持原首行图标对齐、过程行最小高度、正文行高与换行高度。成功/取消仍零高，失败继续使用原错误提示，不改压缩状态机。独立条目与时间线子条目共用同一原生入口。

### 工作区拖拽分隔线残余迁移

右侧与底部面板分隔线的 1px 可见细线改由被动 NSH Surface 绘制，保留外层 5px 拖拽区域、横纵光标、原拖拽状态与尺寸约束。窗口根/主区域的 `bg_base`、侧栏拖拽区域的 `bg_sidebar` 以及侧栏 1px 细线也由同一被动 NSH 宿主绘制；布局、遮挡与输入仍归原宿主。各位置使用独立挂载键。浅深主题使用原语义色；无新增文字、焦点、AX 或输入目标。Surface 释放时停止，稳定投影不重复发布；实际拖拽与跨平台像素仍须后续验证。

### 权限重置全局提示残余迁移

权限重置使业务权威受阻时，主窗口保留原暂停/失败本地化提示与“返回设置”动作，改由 NSH 壳层绘制。动作只打开原通用设置，不开始、重试或确认权限清理；原 `notice_focus`、Tab/Shift-Tab、Enter/Space 与独立真实按钮 AX 范围保留。投影包含完整权限重置状态、operation 与 session 是否存在，重复相同错误的新操作不得恢复旧命令；主线程沿用壳层当前 root、owner、挂载租约、显示投影与完整可见几何校验。导航/设置/遮挡改变后拒绝过期动作。提示自然换行并按 NSH 实际高度调整，不能裁掉错误或返回入口；无新增产品文案。

## 架构与实施方案

```text
GPUI Fast 宿主/窗口/可信控制器（原有业务与后台任务所有者）
  ├── NSH Surface：有界命令队列 → 主线程控制器 → 现有服务
  └── watch 状态投影 → NSH engine thread → signal → NSH 页面
       ├── 会话与 Composer
       ├── 设置与配置
       └── 侧栏、工作区、终端与辅助面板
```

1. 主 Agent 负责全量规格、通用 `vega_ui::nsh` Surface、主题转换、依赖接线、主窗口外层和集成/提交。已有 GPUI Entity 可作为内部状态控制器保留，不能继续绘制生产内容。
2. 会话写入者负责 `conversation_stream` 与输入、消息/工具/权限/问答相关 UI，公开业务 API 与事件保持；设置写入者负责 `settings` 与配置页面；工作区写入者负责 sidebar/terminal/preview 等明确分配范围。
3. 并行写入前先固定各模块的状态/命令与文件所有权。公共 Surface 接口只由主 Agent 修改；Git/index、commit/push 与锁文件只由主 Agent 操作。未明确分配的紧耦合文件留主 Agent，不允许协作者自行扩大范围。
4. 先并行梳理并回报实际源码契约，然后以这份规范增补模块清单及实施接口；随后并行实现、集中接线、云端验证和独立审查。此为内部实现顺序，不是逐步试点/产品取舍门槛。

## 通用 Surface 契约

- 固定现有 NSH `=0.4.0`、Kit `=0.7.3`、Fast/平台 `=0.1.9`；不自动升级、不 fork。用户在获知原生 IME 分发缺口后再次明确维持此约束；命令面板 IME 验收保持阻塞，不以引擎侧组合输入守卫或异步注销绑定冒充解决，继续独立迁移范围。现阶段纯 Rust UI，不引入 TSX/QuickJS/动态下载。
- `Surface<S,C>` 持有一个 `Entity<AppView>` 和 `watch::Sender<S>`，渲染器为 `fn(Signal<S>, mpsc::Sender<C>) -> nsh_core::element::AnyElement`。`S: Clone + Send + Sync + 'static`、`C: Send + 'static`。
- `Surface::new(initial, renderer, window, cx)` 返回 `(Surface, mpsc::Receiver<C>)`；命令容量固定 64。业务所有者持有消费任务，通过 `cx.spawn_in` 与弱实体 `update_in` 回到主线程处理命令，必须保留实体身份/路由/代际与授权检查。
- `publish` 仅同步当前投影；NSH 组件按 signal 订阅，不因每帧重建引擎。页面端用异步 `send`，不以 `try_send` 静默丢弃用户操作。敏感输入不进入普通过往状态、错误与日志。
- GPUI Render 只返回 Surface 的 AppView；焦点、locale、appearance 由宿主同步。引擎关闭只结束展示任务，不拥有或取消 Agent/PTY。
- 子模块协议在 crate 内定义；跨 crate 的共享业务类型仍使用 `vega_conversation::types`，不能为本次迁移制造重复领域结构。
- 工作区生产宿主位于 `vega` crate；将既有 UI 基础设施 `ProjectionId::{new,matches}` 与 `OrderedCommands::{new,send}` 公开供其复用，仅改变可见性。字段仍封装，不新增业务类型、依赖或另一套队列；身份比较和命令顺序/失败语义保持不变。公共键盘策略暂不扩大接口，由实际叶子需求确定。

### 终端投递协议

- NSH 输入缓冲最多 64 项、总计 2 MiB（含待回执项）；容量不足立即停止键盘截获并显示失败，未进入队列的文本保留在输入控件，不清空后假装已投递。
- 每个 PTY epoch 内输入使用严格递增序号，可信控制器记录已接受序号；回执丢失后只允许以相同序号重查/重投，已接受项不得再次写入服务。明确拒绝的项保留顺序等待用户重试，epoch 更换后旧请求失效。
- 服务队列接收不等于进程已执行；不展示执行完成反馈。组合输入只投递 NSH 的已提交文本，组合期间不注册会吞掉 IME 按键的全局绑定。

### 输入桥冲突恢复

- 输入请求按序处理，待处理上限 64 项、操作文本总计 2 MiB（含待回执项）；达到上限时保留最新本地文本，冻结继续投递并给出错误恢复入口。
- 版本不匹配、投递失败或回执丢失不以可信快照覆盖本地草稿，不自动重试未知结果。冻结期间普通 watch 更新不得覆盖文本/选择；旧 generation 的后到回执不能解冻或覆盖新输入。
- 错误就近提供“复制本地草稿”和“重新载入”；重新载入需待所有在途请求排空，以最新可信快照重新同步，不提交旧请求。本地文本保存在当前编辑器恢复副本中，用户可显式“恢复本地草稿”；恢复仍经最新 revision/旧文本匹配校验，失败继续保留副本，不能直接覆盖原控制器。
- 宿主报错后由独立 NSH 恢复页提供复制与重新载入，不依赖已故障页面响应事件。本地文本与恢复副本保存在专用宿主共享恢复状态中，不随故障 owner 销毁；重新载入创建新宿主标识，旧请求与旧快捷键在可信控制器处拒绝。已经接受的操作不回滚，未知结果不重放，附件不自动重试。新宿主先载入最新权威状态，恢复副本仅由用户显式恢复。
- 正常快速输入只在最后一个请求被接受时回写可信文本，不能用前一个成功回执覆盖更晚的本地编辑；masked 输入仍不得进入普通投影。
- Composer 专用宿主保留原 TextInput entity、草稿与附件权威；NSH 编辑器及宿主共享同步屏障，任何本地修改在排队前关闭屏障，仅在请求排空、最新可信快照与本地内容/选择一致且非组合/失败时开放。发送/恢复/compact 动作必须检查屏障，不能抢在异步编辑之前提交旧草稿。其他表单尤其 masked 凭据输入不通过此入口迁移。原 FocusHandle 保留为宿主外层身份，内部输入通过显式聚焦请求获取光标；隐藏/再次挂载不清空草稿。

- 粘贴使用 NSH `PasteBehavior::Report` 的当次原始载荷，通过同一有序请求队列交回原输入控制器；不能稍后重读系统剪贴板。普通文本按原逻辑归一化 CRLF；本地文件粘贴不把路径文字插入草稿，图片与文本混合载荷保留文字。图片字节、数量、总量和本地文件 URI 在转换前限额，仍交原附件导入服务校验内容、禁止符号链接与非普通文件；不依据 MIME 声明信任图片。附件在途字节单独限额为既有单轮上限，不挤占 2 MiB 编辑文本队列预算；投递或版本失败保留本地恢复文本且不自动重试附件。

- Composer 快捷键按当前生产注册保留：Enter/平台发送组合键发送，Shift-Enter 换行；文件选择、命令选择、预测的 Enter/Tab/Escape 优先于普通发送和焦点移动。组合输入期间不注册这些截获绑定。业务快捷键带当前编辑 stamp，主线程重查同步屏障与原实体身份，陈旧快捷键不操作新草稿。输入内容高度和恢复控件高度从 NSH 回传，宿主按真实高度更新，不固定一行造成裁切；输入本体仍受原最小/最大行数限制。

### 固定 NSH 0.4 键盘能力缺口（只读调查结论）
