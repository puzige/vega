# NSH 全量桌面 UI 迁移

## 用户裁决与范围

版本 v1.3；原始基线 `d4beacac2f01d4c09af7545163393e9d43753fe9`，当前集成基线 `eec9984bab2a1cd530bef8cb21e4383aca3e05b8`。

用户要求取消渐进试点，直接制定全量迁移方案；不做性能比较。最新执行裁决：暂不使用子 Agent，由主 Agent 接手现有产物并直接实施；此前并行安排不再适用。平台裁决为 macOS、Windows、Linux，保留 GPUI Fast 桌面宿主，全部产品界面改用 NSH。此文取代本卡先前“只做预览、等待 P2 授权”的范围限制；不改变既有权限、安全、数据与功能契约。

完成定义：用户进入的生产界面由 NSH 构造，GPUI 仅承担窗口、事件循环、NSH Surface 嵌入和内部控制器实体/订阅；不得以旧 GPUI 页面嵌入 NSH、隐藏入口、只保留常用字段、静态占位或回显 Demo 冒充全量迁移。迁移期间的开发提交不代表生产交付；完整切换和必要门禁结束前不合并半成品。

## 架构与实施方案

```text
GPUI Fast 宿主/窗口/可信控制器（原有业务与后台任务所有者）
  ├── NSH Surface：有界命令队列 → 主线程控制器 → 现有服务
  └── watch 状态投影 → NSH engine thread → signal → NSH 页面
       ├── 会话与 Composer
       ├── 设置与配置
       └── 侧栏、工作区、终端与辅助面板
```

1. 主 Agent 负责全量规格、通用 `vega_ui::nsh` Surface、主题转换、依赖接线、主窗口外层和集成/提交。已有 GPUI Entity 可作为内部状态控制器保留，不能继续绘制生产内容。
2. 会话写入者负责 `conversation_stream` 与输入、消息/工具/权限/问答相关 UI，公开业务 API 与事件保持；设置写入者负责 `settings` 与配置页面；工作区写入者负责 sidebar/terminal/preview 等明确分配范围。
3. 并行写入前先固定各模块的状态/命令与文件所有权。公共 Surface 接口只由主 Agent 修改；Git/index、commit/push 与锁文件只由主 Agent 操作。未明确分配的紧耦合文件留主 Agent，不允许协作者自行扩大范围。
4. 先并行梳理并回报实际源码契约，然后以这份规范增补模块清单及实施接口；随后并行实现、集中接线、云端验证和独立审查。此为内部实现顺序，不是逐步试点/产品取舍门槛。

## 通用 Surface 契约

- 固定现有 NSH `=0.4.0`、Kit `=0.7.3`、Fast/平台 `=0.1.9`；不自动升级、不 fork。现阶段纯 Rust UI，不引入 TSX/QuickJS/动态下载。
- `Surface<S,C>` 持有一个 `Entity<AppView>` 和 `watch::Sender<S>`，渲染器为 `fn(Signal<S>, mpsc::Sender<C>) -> nsh_core::element::AnyElement`。`S: Clone + Send + Sync + 'static`、`C: Send + 'static`。
- `Surface::new(initial, renderer, window, cx)` 返回 `(Surface, mpsc::Receiver<C>)`；命令容量固定 64。业务所有者持有消费任务，通过 `cx.spawn_in` 与弱实体 `update_in` 回到主线程处理命令，必须保留实体身份/路由/代际与授权检查。
- `publish` 仅同步当前投影；NSH 组件按 signal 订阅，不因每帧重建引擎。页面端用异步 `send`，不以 `try_send` 静默丢弃用户操作。敏感输入不进入普通过往状态、错误与日志。
- GPUI Render 只返回 Surface 的 AppView；焦点、locale、appearance 由宿主同步。引擎关闭只结束展示任务，不拥有或取消 Agent/PTY。
- 子模块协议在 crate 内定义；跨 crate 的共享业务类型仍使用 `vega_conversation::types`，不能为本次迁移制造重复领域结构。

## 验证与交付

本地仅低 CPU 的格式、差异、静态 API/类型契约检查；不运行 Vega、不编译/测试/打包。所有主/子 Agent 同样适用。自动验证使用现有 Actions；不削弱断言、不修改 required check 求绿。Rust 开发测试若使用则留痕并按仓库政策在最终 head 清理；保留现有 Python 测试。

实现完成后对停写的精确版本做非实现者独立审查；最终完整 head required CI 通过才合并。未在本轮取得的 Windows/Linux 证据必须标待验证，不能以“框架支持”代替。云端发布和用户纯手测仍按既有流程。

## 风险与非目标

- 最大风险是 UI 和控制器实体混合，优先保留可信控制器并迁移显示/交互层，不能绕过原有服务与鉴权。
- 终端、虚拟列表、Markdown 原文映射和复杂表单不能按组件名称假设行为等价，需核对固定发布版实际 API。
- 不增加产品功能、不改 schema、不更换模型/工具运行时、不改变凭据策略、不删除用户文件、不迁移动端/Web。
- 不将“全量”解释为一次性去除全部 GPUI crate；用户已明确保留 Fast 宿主。

### 终端投递协议

- NSH 输入缓冲最多 64 项、总计 2 MiB（含待回执项）；容量不足立即停止键盘截获并显示失败，未进入队列的文本保留在输入控件，不清空后假装已投递。
- 每个 PTY epoch 内输入使用严格递增序号，可信控制器记录已接受序号；回执丢失后只允许以相同序号重查/重投，已接受项不得再次写入服务。明确拒绝的项保留顺序等待用户重试，epoch 更换后旧请求失效。
- 服务队列接收不等于进程已执行；不展示执行完成反馈。组合输入只投递 NSH 的已提交文本，组合期间不注册会吞掉 IME 按键的全局绑定。

### 输入桥冲突恢复

- 输入请求按序处理，待处理上限 64 项、操作文本总计 2 MiB（含待回执项）；达到上限时保留最新本地文本，冻结继续投递并给出错误恢复入口。
- 版本不匹配、投递失败或回执丢失不以可信快照覆盖本地草稿，不自动重试未知结果。冻结期间普通 watch 更新不得覆盖文本/选择；旧 generation 的后到回执不能解冻或覆盖新输入。
- 错误就近提供“复制本地草稿”和“重新载入”；重新载入需待所有在途请求排空，以最新可信快照重新同步，不提交旧请求。本地文本保存在当前编辑器恢复副本中，用户可显式“恢复本地草稿”；恢复仍经最新 revision/旧文本匹配校验，失败继续保留副本，不能直接覆盖原控制器。
- 宿主报错后由独立 NSH 恢复页提供复制与重新载入，不依赖已故障页面响应事件。本地文本与恢复副本保存在专用宿主共享恢复状态中，不随故障 owner 销毁；重新载入创建新宿主标识，旧请求与旧快捷键在可信控制器处拒绝。已经接受的操作不回滚，未知结果不重放，附件不自动重试。新宿主先载入最新权威状态，恢复副本仅由用户显式恢复。
- 正常快速输入只在最后一个请求被接受时回写可信文本，不能用前一个成功回执覆盖更晚的本地编辑；masked 输入仍不得进入普通投影。
- Composer 专用宿主保留原 TextInput entity、草稿与附件权威；NSH 编辑器及宿主共享同步屏障，任何本地修改在排队前关闭屏障，仅在请求排空、最新可信快照与本地内容/选择一致且非组合/失败时开放。发送/恢复/compact 动作必须检查屏障，不能抢在异步编辑之前提交旧草稿。其他表单尤其 masked 凭据输入不通过此入口迁移。原 FocusHandle 保留为宿主外层身份，内部输入通过显式聚焦请求获取光标；隐藏/再次挂载不清空草稿。

- 粘贴使用 NSH `PasteBehavior::Report` 的当次原始载荷，通过同一有序请求队列交回原输入控制器；不能稍后重读系统剪贴板。普通文本按原逻辑归一化 CRLF；本地文件粘贴不把路径文字插入草稿，图片与文本混合载荷保留文字。图片字节、数量、总量和本地文件 URI 在转换前限额，仍交原附件导入服务校验内容、禁止符号链接与非普通文件；不依据 MIME 声明信任图片。附件在途字节单独限额为既有单轮上限，不挤占 2 MiB 编辑文本队列预算；投递或版本失败保留本地恢复文本且不自动重试附件。

- Composer 快捷键按当前生产注册保留：Enter/平台发送组合键发送，Shift-Enter 换行；文件选择、命令选择、预测的 Enter/Tab/Escape 优先于普通发送和焦点移动。组合输入期间不注册这些截获绑定。业务快捷键带当前编辑 stamp，主线程重查同步屏障与原实体身份，陈旧快捷键不操作新草稿。输入内容高度和恢复控件高度从 NSH 回传，宿主按真实高度更新，不固定一行造成裁切；输入本体仍受原最小/最大行数限制。

### 用量面板验收

- 刷新、7/30 日筛选、UTC 标识、真实加载/失败/空态和原有累计指标全部由 NSH 绘制，保留失败时上次成功数据；数据库仍由原 app worker 读取，不在 UI 线程或 NSH 读取数据库。
- 保留年度活动热力图的每日/每周/累计语义、按模型趋势、日期点击选择及逐模型当日明细、分布环图/比例/无 token 状态和明确的未定价费用覆盖；不降级为纯文本。趋势支持聚焦后左右键/Home/End 选择日期，显示可见焦点和选中日期，不仅依赖颜色。
- 刷新仍经 `UsageReloadRequested`，刷新中不重复请求；所有动作在可信控制器重查展示身份、页面可见性、数据版本和观察到的筛选状态，陈旧图表动作不能选中新数据。NSH 实测高度回传宿主；主题/语言变化保持有效数据与筛选，挂载不重复刷新。开发回归验证失效版本拒绝、刷新去重和选择范围，实际图表/键盘行为待云端及用户手测分层核实。

### 设置外观区验收

- 主题 Light/Dark/System、English/中文与侧栏可见性全部由 NSH 绘制，用选中态与开关轨道表达当前值；保留系统字体、现有 token、Tab/Enter/Space 与可见焦点。帮助与错误不重复添加说明。
- 主题与语言继续走原 `save_preferences` 的字段级冲突校验和保存失败恢复，saving/default-permission IO 时禁用；侧栏继续发出原 ToggleSidebar 动作。命令核对页面、展示标识及观察到的当前值，陈旧选择不得覆盖更新后的状态。新投影实时反映原控制器主题/语言/侧栏状态，错误仍由原设置页展示。

### 默认权限模式区域验收

- 模式触发器、readonly/confirm/auto/full_access 四项、准备/保存/重载反馈及错误恢复由 NSH 绘制；full_access 保留明确的警示图标和颜色，选中态含非颜色标记。原授权清理 NSH Surface 保留独立状态机，不改变服务或增加执行权限。
- 选择仍经 `select_mode` → 原 prepare/save 服务，重载与取消仍使用原控制器。命令核对展示身份、设置可见性、权限版本/模式、操作阶段/编号、错误和可用性；准备/重载可取消，保存中不可取消，错误后按原规则重载。旧动作不能跨阶段、跨操作或跨页面生效，未知结果不自动重放。
- 原 Picker/Cancel/Reload 焦点意图转为 NSH 挂载后目标，Escape 保留取消准备/重载或收起选项的优先级，保存中不得绕过关闭保护；授权清理 Completed 恢复 NSH 模式触发器。页面切换不抢回焦点，原生键盘与权限行为待用户手测，不以静态检查代替。

### 默认模型选择器验收

- 默认模型触发器、展开选项与无可用模型空态由 NSH 绘制；仍使用启用提供方的模型并集，保持原始首次出现顺序并去重，不替换当前未在目录中的已保存值。模型名原样展示，选中态和焦点不只依赖颜色，Tab/Enter/Space 可操作，Escape 收起并回到触发器。
- 保存继续调用原 `select_model` / `save_preferences`；provider saving/default-permission IO 时禁用。动作重查设置页、展示身份、当前默认值和候选目录，陈旧值或已移除候选不得触发保存；保存失败保持原权威值、原错误和重试入口。权限模式选择器及其确认/清理流程不由该模型区域代替。

### 设置输入偏好验收

- 输入预测开关及运行中消息 Queue/Steer 的选择由 NSH 绘制；保留现有标签、预测说明和 Queue/Steer 按需帮助，不新增常驻实现说明。选中/开关状态及键盘焦点清晰，Enter/Space 可操作。
- 原 `toggle_composer_predictions` / `select_running_message_behavior` 继续承担字段级保存；saving/default-permission IO 期间禁用。动作核对展示身份、页面、观察值与当前保存状态，陈旧或重复操作不得翻转新值；保存失败保留原权威值及设置错误。模型/默认权限选择器不由本区域代替。

### 设置更新面板验收

- 通用设置中的更新面板全部由 NSH 绘制，保留当前/最新版本、最近检查时间、自动更新、检查/发行页面/稍后/安装、真实下载进度、错误、可展开发行说明与按需帮助；不以旧 GPUI 内容嵌入 Surface。
- Loading/Checking/Downloading/Installing 时禁用检查与自动更新；Ready 时只提供原有安装/稍后入口，不自动安装。动作携带展示身份、观察到的 phase 与 automatic 值，主线程重查最新状态；过期或重复动作拒绝，失败保留可恢复反馈。原更新控制器继续负责授权与实际服务。
- NSH 高度变化回传宿主，不裁切说明和错误；发行说明链接仍通过既有安全链接分类，不能由 Markdown 自动读取文件 URI 或远程图片。浅深色、中英文、键盘按压/Tab 与帮助/说明展开按原规范验证。

### 设置授权清理确认区验收

- 仅替换既有确认区的绘制与交互，不添加新的清理入口、不改变清理服务。Preparing/Confirming/Pausing/Stopping/Refreshing/Blocked 各状态及原提示完整保留；阻塞态的 Cancel/Inspect 仅在原投影允许时出现。
- Confirming 默认聚焦 Cancel；Tab/Shift+Tab 在 Cancel/Confirm 间循环，Escape 仅在 Preparing/Confirming 取消。Blocked 默认聚焦 Retry；Completed 恢复原默认权限选择器焦点。状态变更不得将 Enter 自动变为确认。
- 命令携带展示身份、投影 revision 和观察状态，可信控制器拒绝过期/重复/越阶段动作，再走原 PermissionResetRequested。未知结果不自动重放；原 window 控制器仍负责检查设置会话、权限权威和真实清理。

### 会话卡片协议

- 权限快照包含完整命令、安全提示、范围请求详情和实际可选决策，不能携带租约或未脱敏 Debug 输出。每次请求由原卡片实例持有不可复用的展示标识；动作回到同一卡片，核对标识、未决状态与允许选项，再走原租约 first-wins 响应。ACP 只接受请求列出的 option id；范围审批不能变成持久授权。
- 计划快照保留原文与 generated notice 的显示投影、审核状态、review note、陈旧/冲突反馈。动作包含展示标识；持久化更新或 stale 会使旧动作失效，原控制器仍检查 pending 和重复提交状态并发出原有审核事件。
- 用户问答快照和动作保留逐题选择、Other、补充备注、Skip/Back/Next/Submit，页号与会话 owner 绑定；组合输入不提交，错误保留原草稿，答复仍经 PendingUserQuestion 校验并提交。
- 工具卡片只复用现有 `ToolCardInputProjection` / `ToolCardResultProjection` 生成的安全详情；保留完整 command/output、原文复制与显示行的区别、截断/复用、真实终态/耗时、展开/滚动、图标和活动标题。NSH 动作携带卡片展示标识；打开子任务还需匹配当前 parent/agent/message 身份，不依据回收行号打开其他执行。旧 GPUI 标题元素不跨入 NSH，覆盖标题和运行态改为纯数据传递。

本轮卡片接线：计划与权限生产分支已改为 NSH Surface，原可信控制器保留。权限 Enter 保留普通允许一次、危险默认拒绝，范围/ACP 按焦点动作；审批备注只在 NSH 本地持有，决策提交时传给原控制器。布局回传触发会话列表尺寸失效。以上为实现状态，尚未取得编译/行为或云端验证结果。
