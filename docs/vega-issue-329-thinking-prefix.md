# Issue #329 · 思考阶段标题固定前缀

来源：[Issue #329](https://github.com/puzige/vega/issues/329)。2026-10-13 用户对实际会话截图反馈：灰色阶段标题虽然会随流更新，但只显示提取片段时看不出它是思考内容；希望前面始终有 `Thinking`，后面继续显示动态片段。

本规格仅覆盖 #71 的思考预览标题呈现方式和 #296 的阶段标题文案。#71 的来源优先级、增量提取、原文展示和资源上限，以及 #296 的阶段顺序、样式、折叠与最终收起规则继续适用。

## 行为契约

- 有可读片段时，阶段标题显示 `Thinking · <片段>`。片段沿用 #71 的实时提取规则：非空 summary 优先，否则取 thinking content；后续片段可以更新标题。只有 content 的模型也展示动态片段，不降级成固定文案。
- 暂无可读片段时，只显示 `Thinking`，不出现空分隔符或旧的「思考过程」占位。没有收到 thinking/summary 事件时不创建空思考块。
- 前缀和片段合计最多 96 个 Unicode 标量；长普通段落仍优先显示最新片段，Markdown 标题仍优先保留标题开头，清理规则和 UTF-8 分片处理沿用 #71。
- 会话阶段行、独立思考行、运行中 shimmer 和非运行状态使用相同文案。鼠标/键盘展开语义与可访问名称同步；展开的原文不插入此前缀，不改变复制内容。
- 不改 provider 协议、事件、存储、思考原文、正文归属、工具、计时或安全行为。历史记录里没有思考原文的轮次不制造前缀行。

## 验收矩阵

| ID | 前置与操作 | 预期 | 层级 |
|---|---|---|---|
| T1 | 只有 thinking content，跨 delta 追加普通段落和后续标题 | `Thinking ·` 始终在前，后半段实时变化 | 进程内 GPUI |
| T2 | 先 content、后 summary、再 content | 后半段切换为 summary，后续 content 不覆盖 | 进程内 GPUI |
| T3 | 空白、未完成 Markdown 标记或代码围栏内文本 | 仅 `Thinking`，没有空分隔符或伪标题 | 单元与 GPUI |
| T4 | 超长中英文段落、跨 UTF-8 delta | 整行不超过 96 标量，普通段落保留最新片段 | 单元与 GPUI |
| T5 | 阶段收起/展开、工具/正文边界、终止和历史恢复 | 文案一致，原文及交互不回退；无原文时无思考行 | 进程内 GPUI；历史恢复按现有契约 |
| T6 | 合并后使用真实模型查看流式阶段 | 前缀固定，片段更新，最终阶段仍按现有规则收起 | 用户原生手测 |
