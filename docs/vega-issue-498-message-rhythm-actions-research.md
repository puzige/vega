# #498 消息排版与复制、Fork 操作栏：调研委托 v1.0

日期：2026-10-19。代码基线：`dbb0f41d49687bef910c87f498d11020e3555887`。

本版只冻结用户已经明确的行为及只读调研范围，不是可以直接开始生产实现的规格。Codex 已审查本委托；明确委派 Vega 调研，回报后由 Codex 收口尺寸、Fork 技术方案及实施验收。关联 [Issue #498](https://github.com/puzige/vega/issues/498)。

## 1. 用户已确定的行为

- 用户消息的复制按钮平时隐藏，悬停该消息时显示；保留键盘聚焦时可见、可激活的等价路径。沿用气泡外右下位置，本次没有要求移动用户消息按钮。
- Agent 的完整最终回复在左下常显两个按钮，顺序是复制、Fork。Fork 对应 Branch in new chat，直接可发现，不藏在更多菜单。不增加朗读、点赞等按钮。
- 改善正文行间观感与复制图标比例，先核对 Codex 可观察尺寸，再决定 Vega 数值。不能把“看起来大”直接等同于全部字号或点击区域过大。
- 这次改动替代 [#477 复制规格](vega-issue-477-copy-actions.md)中 Agent 最终回复按钮仅 hover/focus 可见的部分；用户消息、原文复制、可信 Final 边界、键盘操作等其他契约保留。代码块复制按钮不在本轮调整范围内。

## 2. 既有证据与局限

以下是上述代码基线的静态事实，单位均为 GPUI logical px，不是截图中的图片像素。

| 对象 | Vega 现值/行为 | 代码入口 |
| --- | --- | --- |
| 正文字号 / 段内行高 | 13.5 / 23，行高约 1.704 倍 | `vega_theme::Typography::CONVERSATION*` |
| 普通段落额外间距 | 15.5 | `Layout::CONVERSATION_PARAGRAPH_GAP` |
| 同列表项之间的额外间距 | 6 | `Layout::MARKDOWN_LIST_ITEM_GAP` |
| 列表内段落额外间距 | 8 | `Layout::MARKDOWN_LIST_PARAGRAPH_GAP` |
| 消息复制图标槽 | 16×16，复用 GPUI Kit Copy 资产 | `icons::icon` / `Layout::ICON_SIZE` |
| 复制按钮命中框 | 24×24 | `icons::icon_button` / `Layout::COPY_ACTION_SIZE` |
| Agent 复制页脚预留 | 28，即按钮 24 + 间隔 4 | `Layout::MESSAGE_COPY_FOOTER` |
| 按钮显隐 | 用户与 Agent 均 opacity 0，group hover / focus visible 时显示 | `render_rows::message_with_copy` |
| Agent 页脚来源 | `final_copy_for_entry` 提供的可信 Final；不是所有流式片段 | `conversation_stream/render.rs` |

`render_rows::markdown_blocks` 按块加 margin，`markdown_block_gap` 根据前后块类型选择间距；普通段落、列表、标题并非同一套间距。当前代码取前后间距的最大值，尚无证据表明这里重复相加。行内代码的字形/背景高度也应单独观察，不能仅凭截图认定为行高根因。

用户提供的三张截图只在本地分析，不上传原图、真实对话或本机路径：

- Vega 图为 1620×534；Codex 正文图为 1108×328；Codex 操作栏图为 670×200。三张 PNG 的 DPI 元数据约为 144；这不能证明应用字体缩放、截图重采样和逻辑坐标一致。
- 在复制图标局部区域，以相同灰度阈值 `<210` 分离可见轮廓，Vega 包围盒约 30×30 图片像素，Codex 约 25×25。该方法受抗锯齿、灰度阈值和缩放影响，不是逻辑尺寸或按钮命中框的测量。
- 两张正文图的可见中文字形高度接近，约 25 图片像素。复制轮廓的相对大小支持用户反馈，但不能由此宣布 Codex 使用了某个精确图标 token。
- Vega 第一张图的列表前两项可见行位置相差约 58 图片像素，第三项自动折行的相邻行约 46 图片像素；这与代码中 23px 行高和 6px 列表项间隔相符，但不作为已证明的系统缩放值。
- Codex 正文参考图是两个独立段落，不能用它们之间的距离推导段内行高。当前尚未取得 Codex 逻辑字号、段内行高、图标槽或点击框的准确测量。

### 3.2 后续实施必须保留的行为边界

以下为实施规格收口的验收输入；本轮不编写或运行自动测试，不宣称 RED/GREEN。

1. 用户按钮默认隐藏，消息悬停与键盘聚焦时可见；指针移向按钮过程中不闪退。Tab、Enter、Space 可操作，图标有名称与 tooltip。
2. 每条已完成、可信的 Agent Final 只出现一组常显的复制、Fork；多片段不重复。Commentary、工具输出、流式未完成内容、空内容及缺少可信元数据的历史不能假冒完整最终回复。
3. 复制保留原始 Markdown、围栏及换行，沿用 #477 的安全投影，不回读未经批准的原始存储。选字、选区复制、代码块复制与消息右键菜单不回退。
4. 操作栏显隐、焦点与按压不改变消息高度或滚动位置。若尺寸/行距改变，真实消息 `ListState` 场景和高度缓存须一致，不能只验证普通滚动容器；避免在列表子元素绘制时重借用列表状态。
5. Fork 的建议产品语义为：以点击的最终回复为历史截止点，包含此前上下文及该回复，创建并打开独立聊天，原聊天及之后的消息不改。新聊天等待用户继续输入，不自动请求模型或重新执行历史工具；不创建 Git 分支或 worktree。该语义由 Codex 在完整技术方案中明确冻结。
6. 调研 Fork 时必须核对新会话/消息身份、历史引用、附件、工具调用与结果配对、思考/Final 来源标记、摘要/压缩截断、运行中状态、草稿、权限继承、项目/模型/后端、重启可恢复性、重复点击与失败原子性。新聊天不能共享原聊天可变的运行身份，也不能借用包含截断点之后信息的摘要。不能用“只复制可见文本到输入框”冒充上下文分支。
7. 分别记录 Native、ACP 的能力与限制；无可信截断 API 时不能直接复用完整远端 session。不要先放置无效或假成功的 Fork 按钮，支持范围须先进入实施规格。
8. 默认/hover/pressed/focus、浅深色、窄宽窗口、历史与真实列表交互都纳入后续验收；本地不能运行 Vega 的约束仍适用，自动回归只交 Actions，最终原生界面由用户手测。

## 4. 明确委派 Vega 的只读执行步骤

1. 领取本卡前核对最新交接和本版提交，记录角色、时间和基线，置 In progress；只领取本卡，不顺带处理其他队列任务。
2. 静态读取 `crates/vega_theme/src/lib.rs`、`crates/vega_ui/src/icons.rs`、`crates/vega_ui/src/conversation_stream/` 及用户消息、可信 Final、选区和列表高度相关实现。以源码中的实际 token 为准；后续修改必须同步渲染和测量，不能全局缩小其他控件。
3. 在允许访问的 Codex 可见界面上调查 R2/R3。只能用可观察界面、辅助功能公开几何或用户授权的截图；不得解包、反编译或提取 Codex 内部 CSS、组件树、token、图标资产。不读取或公开无关聊天。没有可比较样例/几何权限时明确写未知，不编造精准值，也不因此擅自运行 Vega。
4. 给出正文与消息操作栏的最小尺寸建议。可比较缩小消息图标的候选值，同时保留有利于点击的命中框；候选值不是已经批准的最终 token。本轮不改代码、不做全局字体缩放或图标替换。
5. 在 `crates/vega_conversation/`、`crates/vega_store/`、`crates/vega_runtime/`、后端适配层及会话打开/创建入口静态追踪 Fork。现有粗检未找到明确的会话 Fork API，这不证明它不存在；必须按 Native/ACP 分别查明，不把 Git 分支功能当成聊天分支能力。
6. 在 Issue #498 回报 R1–R6，列出事实、建议、未知及每项证据位置。保持 In progress，阶段“等待 Codex 收口调研”，当前执行者“待领取”，下一执行者“Codex”，停止写入。不得自行进入生产实现、开 PR、合并或关闭卡片。
