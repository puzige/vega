# 流式正文新增文本 run 渐入

## 用户修订与范围

对应 #860。原“段落/列表项/表格行整体淡入”规格粒度错误，用户要求返工为块内新追加的一小批文本 run。不是调整整段时长。只修改实时助手正文展示，不改解析、存储、真实输出时序、文本内容、选区或布局，不涉及 #804/#806 的实现，不增加依赖和界面文案。

## 实现契约

- 模型每次增量同步后登记各文本部分新追加的 UTF-8 字节范围；段落、标题、代码、列表正文/标记/复选框和表格单元格独立跟踪。一次 UI 同步合并的 delta 视为一批，不拆成逐字打字机。
- 文本部分身份为消息内 `(block_id, block_local_line_index, table_row, text_part)`；缓存前次可见文本，新 run 分配单调 segment key。同一文本部分后续追加不重建旧 run 的时间线；pending → committed、样式变化、滚动不重放。
- Markdown 重新解释导致可见文本非追加变化时，清除该部分旧动画并直接显示新投影，避免旧字符重新变透明或错配 UTF-8 范围。之后追加仍正常渐入。
- 消息级单调游标：`start = min(max(cursor, now), now + 800ms)`，`cursor = start + 24ms`。慢速流游标落后时 delay 为 0；突发新增 run 错峰，上限 800ms。不等待段落完整，不排队或延迟模型、布局、复制、选区及无障碍数据。
- 700ms、`cubic-bezier(.37,.55,.86,.88)`，仅调整新范围的文字与装饰 alpha，移除整段/整行容器 opacity。旧文字及背景几何保持不动，不新增文本布局容器。
- 完成时从当前 alpha 连续收尾至 1，取消剩余 delay，150ms 内结束；完成同步新增 run 使用 150ms。每个 run 有 2500ms 硬截止。
- settled：采样完成后移除活动动画，保留前次文本缓存作为已显示范围的记录，禁止为同一旧范围重新分配 key。减弱动态效果、窗口不活跃时立即清空活动动画并重置游标，不补播。
- 状态共享于消息 UI，非虚拟元素；仅活动 run 采样/请求帧，从 committed 最后一个块起登记可变尾部。历史、用户消息不动画。

## 用户手测验收

- 同一中文段落连续追加：每批新文字渐入，旧字符不重新变透明，不等待换段；慢速输出 delay=0。
- 突发 delta 跨多部分：24ms 单调游标/800ms 上限；持续追加不重启动画；列表标记、代码、表格单元格无整块淡入。
- 完成时连续收尾，150ms 内无残影；Markdown 强调/链接/代码重解释不让旧文字消失。
- 滚动、pending 提交、历史恢复、折叠不重播；#806 置顶无变化；复制、拖选、键盘选区、读屏内容完整且即时。
- 减弱动态效果、窗口重新激活不补播。
- >5000 字相同环境与输入对照 median/p95/max 帧时间、样本数和版本。真实数据尚未取得，CI 和静态检查不能代替性能验收。
