# 流式正文逐段淡入

## 目标与边界

对应 #860。只改变实时助手正文的不透明度，不修改 Markdown 解析、存储、复制文本、选区和无障碍内容，不改 #804 的折叠或 #806 的置顶放置，不增加依赖或界面文案。历史消息、用户消息不播放入场动画。

## 实现契约

- `stream_fade.rs` 保存消息共享的展示状态；`MessageCopy::streaming()` 仅用于实时助手构造。模型同步后登记新增段，渲染时采样，不依赖虚拟列表元素存活。
- 段标识为消息内的 `(block_id, block_local_line_index, table_row)`；同一段后续增量和 pending → committed 不重新登记。表格按行登记，列表标记与其正文使用相同 opacity。
- 每批新增段依序延迟 `min(index × 24ms, 800ms)`，使用 700ms 和 `cubic-bezier(.37,.55,.86,.88)`。只动画 opacity，不改变布局与文本。
- 完成时从当前 opacity 连续收尾，取消剩余错峰，剩余时长不超过 150ms；完成同步带入的新段使用 150ms。历史内容直接可见。
- GPUI 无 DOM animationend：渲染采样达到最后一个段的结束时刻即移除活动状态；每段另有首次出现后 2500ms 的硬截止。只在活动段仍需变化时请求动画帧，无后台常驻定时器。
- `cx.reduce_motion()` 或窗口不活跃时直接显示并清空活动动画；重新启用动态效果或重新激活窗口不重放旧段。
- 登记从上次已提交的最后一个块起扫描可变尾部和新增行，活动动画与已见标识分开保存，已完成段不逐帧重新求曲线。

## 最小修改计划

1. 新增展示状态模块，接入 `MessageCopy` 的实时构造、同步、完成路径。
2. 在可选中 Markdown 渲染中传递淡入采样，普通段和独立列表标记同步透明，表格每行独立透明。
3. 静态核对复制/选区、历史加载和布局路径；独立审查、最新 head Actions 后合并，保留用户验收。

## 验证与验收

本地只运行格式、差异及静态检查，不运行 Vega、不编译、不测试。不新增进入 master 的 Rust 测试。云端 required check 验证格式、Clippy、保留的 Python 回归及 Rust 零测试门禁。

用户真实手测矩阵：

- 中文长段追加：首次淡入，同段继续追加不重播；完成后 150ms 内收尾无残影。
- 单 delta 多段、列表、引用、表格：24ms 错峰，上限 800ms；标记不抢先出现。
- 滚出再滚回、历史恢复、折叠再展开：不重播；发送新 turn 后置顶位置不变。
- 动画期间复制、拖选、键盘选区、读屏内容保持一致。
- 系统减弱动态效果启用时直接显示，运行中切换与窗口重新激活不补播。
- 相同设备、窗口尺寸、模型/回放输入，在基线与本分支各记录 >5000 字流式场景的帧时间 median/p95/max、样本数和版本。**尚未实测，不以静态检查或 CI 代替性能验收，也不声明帧时间无劣化。**
