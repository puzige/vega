## 现场与因果证据

用户在当前版本 native 新对话中使用原生工具创建七个文件、两次编辑首个文件，结束后没有文件组。只读数据库记录确认 7 write / 2 edit 全部 success，路径与 checkpoint 归属相符，最终 Read 与磁盘内容正确，run succeeded；截图显示完成态无文件组。数据库不持久化文件产物状态，不能声称读取了捕获失败日志。

只读 Git 检查确认该仓库测试时 HEAD 为 `86963f5df55e09c2610d8980adf966fdbbfd54cb`，其跟踪文件数为 14,502；测试后用户提交新增八文件，当前为 14,510。固定 Git 可执行程序与 workspace runner 等价的只读命令返回 ls-files 约 1 MiB，无 filter 属性，未超过 8 MiB 字节预算。

本次只读核对安装包 Info.plist 为 `0.1.226`，GitHub 发布 `v0.1.226` 指向 `0fe30576d5884df6f7c2e5f75a0bb580eb883b9f`，其源码与本轮修复基线一致；未重新运行应用或宣称二进制逐字节构建证明。

基线 `0fe30576d5884df6f7c2e5f75a0bb580eb883b9f` 调用链：

1. 真实 Write/Edit 的 terminal 进入 artifact terminal worker。
2. `workspace.refresh` → `build_snapshot` → `capture_filter_identity`，对 **全仓跟踪路径**调用 `parse_nul_paths`。
3. 该 parser 使用 `PATH_LIMIT = 10_000`；此限制同时用于**变更文件**，因此在第 10,001 个跟踪路径处必定返回 `OutputTooLarge`，尚未调用 check-attr 或 capture_candidate。
4. worker 对非取消刷新失败返回 `Ok`、`captured: None`；没有文件卡，也没有原调用的错误条目。

这是源代码确定的现场触发条件，不是仅推测刷新可能失败。独立接入/归属调查另行核对是否有其他阻断；不以此替代云端行为回归或用户真实系统验收。

## 最小修复范围

- 将全仓属性扫描路径数量与变更集数量分离：全仓属性路径最多 100,000，仍受原有 8 MiB 共享保留预算、路径合法性、去重、属性白名单/过滤器拒绝与前后身份一致性校验约束。
- 变更集与产物容量保持 10,000，不提高预览、打开权限或其他安全边界；不删属性扫描、不跳过 Git 校验，不修改用户仓库配置或数据库。
- 捕获任务 workspace 刷新失败时，向上返回真实错误，由既有 `finish_artifact_terminal` 归到原调用/原消息，不能伪造卡片或成功。取消仍不新建错误。仅刷新任务对现有卡片失效/协调的语义保留。
- 不改变回合结束展示、同文件去重、六文件折叠、迟到捕获、显式 continuation、history generation 或项目/线程 fences。

## 验收与按风险验证

- 超过 10,000 且低于全仓属性上限的合法跟踪路径可通过属性解析；第 100,001 个被拒绝；不完整 NUL、重复、危险相对路径仍拒绝。
- 超过 10,000 个变更文件仍拒绝。字节预算不放宽。
- 捕获刷新失败向原回合提供真实错误，取消仍无新增错误；成功刷新仍 capture/reconcile 并允许正常终态发布。
- 可使用少量临时开发 Rust 测试验证真实 parser 决策/worker 结果边界，不恢复旧测试框架或外部 E2E。本地仅静态检查；行为测试仅 Actions。若新增测试，固定可恢复源码/完整 SHA 与实际结果后独立清理，最终 required CI 确认 no Rust tests（0 发现/0 执行）。
