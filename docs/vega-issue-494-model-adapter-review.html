把模型差异留在内部

用户选择模型和思考偏好；适配层负责把它们变成正确的请求，并完整接回模型与工具的结果。Step 的报错暴露了这两层混在一起的问题。

当前问题内部边界设置收敛本次落地依据

Chat API 相同，扩展规则由应用负责

当前

把协议能力交给用户声明

OpenAI、DeepSeek、GLM 模板同时改变思考参数、可用档位和回传策略。用户要先知道模型协议，才能让工具链继续。

Step 被设置成 standard_chat。服务返回 HTTP 200 和工具提议后，Vega 因收到思考字段而主动拒绝。

本次目标

由内部适配层处理差异

同一个 Chat Completions 入口接收统一请求。已知模型事实与服务规则在内部合成；实际返回的文本思考按所属回复保留。

Step 无需选择其他品牌模板；合法思考状态和工具结果带入下一轮，工具各执行一次。

参考 pi 的职责划分

pi 把统一模型 API 做成独立的 @earendil-works/pi-ai 包。Vega 先在现有 Rust runtime 中收拢这一职责，无需引入 Node 服务或立即迁移整个 workspace。

思考页只留下可选择的偏好

移到内部

  • 协议模板、协议类型
  • 支持范围、允许关闭、允许档位
  • 文本思考的回传策略与保留周期

同时删除隐藏快捷动作和无效焦点目标。必要错误、保存冲突和重新加载保留。

  • 旧配置与无配置的 Step 都能接入；实际收到的思考与完整工具组原样续接。
