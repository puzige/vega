# 通知跳转保留输入预测

Issue：[#727](https://github.com/puzige/vega/issues/727)。规格 v1，2026-10-28。基线 `821182b1d5664907ed595c2f47273ff4fba54229`。

## 目标与根因

用户反馈从系统消息通知进入会话后输入预测失效。静态链路为 `open_completion_notification` → `accept_palette_thread` → `Projection::apply`。后者无条件写入 `SettingsOpen(false)`；锁定依赖 GPUI 0.3.4 的 `App::set_global` 无同值比较，始终通知监听。窗口的 `SettingsOpen` 监听无条件取消全部预测，随后刷新模型目录。因此设置本就关闭时，纯导航也会丢弃正在请求或已展示的预测；普通侧边栏会话切换不写该全局。

本结论确认代码中的确定性失效路径，不冒充已运行应用复现或用户事件诊断。

## 验收与边界

- 设置关闭时，点击完成通知进入同一或其他会话，保留仍有效的预测 stream、申请和结果；其他后台会话预测不受影响，不重发请求。
- 使用相同 Projection 的命令面板、后退/前进和路由回退，同样不因 `false → false` 产生设置生命周期副作用；`true → true` 也不重复触发。
- 真正的 `false → true` / `true → false` 仍通知原设置监听；打开设置取消所有预测，关闭设置仍执行原目录失效和延迟模型刷新。
- 保持线程/项目投影、导航历史、草稿保护、访问与未读标记、通知关闭和窗口激活顺序。
- 输入/IME、附件、队列、权限、下一轮、模型/模式/后端变化、设置保存、删除和关闭窗口的失效契约不变；已取消预测不得复活。
- 不增加产品文案、依赖、数据库变更、预测重试或请求。

## 最小实现

只修改 `crates/vega/src/window/navigation.rs` 的 `Projection::apply`：保留项目和线程写入，仅当当前 `SettingsOpen.0` 与目标 `self.settings` 不同时写入该全局。不在预测取消层屏蔽设置事件，也不改变所有全局变量的通知语义。

## 验证与交付

本地只做格式、diff 和静态链路检查，不运行 Vega、不编译或测试。不恢复 Rust 测试或为此小改动建立临时测试；保留既有 CI、Python 检查和生产安全逻辑。非实现者审查停写的精确版本，最终 head 的完整 required Actions 成功后才能合并；Rust 空集必须标记 `no Rust tests`，不等于行为验证。

用户在包含集成提交的版本手测：后台会话完成后点击通知，分别覆盖预测请求中和建议已显示、当前会话和其他会话、多会话各自完成；再覆盖命令面板与历史跳转。真实设置开关、输入/IME、下一轮等仍须使旧预测失效；已失效结果不能在返回会话后重现。模型合法弃权或服务失败本就不保证有建议，不视为导航恢复失败的充分证据，可结合既有固定类别诊断区分。
