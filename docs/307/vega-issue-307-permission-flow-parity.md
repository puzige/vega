# #307 · 两段权限准备流程与横向拖拽引导

## 用户裁决、证据与替代范围

2026-10-23，用户提供 Vega 当前浮窗与参考应用权限准备页、底部拖拽面板的截图，指出效果不一致，并明确选择 **完整对齐两段流程**，不是仅缩小旧浮窗。本轮使用截图中可见的结构与操作关系作为参考，不复制第三方资产、私有 token 或原始截图；截图不上传公开仓库。

已核实基线 `b2248996cc68497ef050539fd69f05cc723e4c0a`：`card/view.rs` 使用顶部文字和居中纵向图标，`card.rs` 只有一种浮窗形态，host 在准备入口立即打开辅助功能设置。其结果符合旧紧凑规格的简化布局，但不符合本轮明确的两段目标。这是规格/验收修正，不能继续把旧审查和 CI 当作视觉对齐证据。

本规格替代 [紧凑浮层规格](vega-issue-307-compact-guide.md) 的默认 400×140 形态、纵向图标以及初次准备直接打开系统设置的安排；保留其共享检测、错误恢复、真实载荷、原任务围栏和取消/清理约束。[原生可见性修正](vega-issue-307-native-panel-visibility.md) 的非激活显示、后台可见、主线程跟随和拖拽冻结继续有效。

本轮工作分支 `feat/307-permission-flow-parity`，独立 worktree；主 checkout 的无关改动不移动、不清理。原计划由单一专职实现者写入、非写入者独立审查；本轮工具返回 `capacity_exceeded`，遗留执行取消后仍未释放。用户随后明确选择 **允许当前 Agent 直接实现并自查，交完整云端 CI**，本轮例外不要求实现委派和独立审查，不把自查称为独立审查。

| P8 | 从系统设置回来或手动重新检测 | 两项分别呈现真实静态检测状态；检测中、未检测/未知、拒绝、已开启、Busy/失败均如实区分，必要错误和重检/诊断恢复可达。允许按钮只是打开设置，不因无检测结果而伪禁用 |

## 两段界面

### 第一段：权限准备页

- 单一中心布局、Vega 正式应用图标、标题 `启用 Vega 电脑操控`。
- 用途文案服务权限判断：说明仅在用户请求电脑操控时使用。辅助功能用于访问应用界面，屏幕录制用于截图识别界面位置；不添加内部检测阶段、字段名或完成声明。
- 两张宽权限卡的结构与顺序固定：辅助功能、屏幕录制；使用仓库已有线性图标，不借用第三方权限图标资产。
- 未确认/拒绝时动作 `允许`；已静态开启时可见状态 `已开启`，仍可点 `打开设置`。Checking/Unknown 不伪造成功。显式 `重新检测` 复用现有共享会话。必要失败就近给出恢复，不把诊断表塞进权限卡。
- 关闭在顶角。只有明确任务来源时，允许保留一个次级 `返回任务` 动作，继续经过原 host 验证；不得与第二段“返回准备页”的箭头混为一谈。
- 准备页不打开设置、不请求 driver prompt 或实际屏幕抓取、不自动完成。

### 第二段：系统设置底部拖拽引导

- 单一宽矮面板，不另加大标题；左侧圆形/圆角返回控件的语义是 `返回权限准备`。
- 右侧上行使用已有 `ArrowUp` 图标，指向上方设置列表；简短说明按所选权限准确呈现。右上角可关闭。
- 下行为带清楚边界的整行拖拽区域：小型 Vega 自有正式图标在左，`Vega` 在右，横向对齐；不再使用纵向居中的大图标卡。真实应用载荷和点击/键盘 Finder 替代路径不变。
- 不实现假的系统列表 drop 高亮、不从鼠标抬起推断投递成功，不因系统开关视觉状态自动跳转下一项。用户返回后可显式重新检测，再处理另一权限。
- 沿用 #582 的安全原生面板实现；使用已存在的 `Window::resize(Size<Pixels>)` 在两阶段切换窗口内容尺寸。锁定 macOS 后端异步调整尺寸，须通过已有 `observe_window_bounds` 确认当前阶段目标内容尺寸后才调用 `move_panel`，期间暂停跟随和载荷交付；过期尺寸通知不能按旧阶段定位。定位完成只按控制器既有永久冻结状态恢复跟随，不替换原生权限/签名/驱动逻辑。
- 只使用 Vega 主题的轻表面、边界、圆角/阴影与品牌箭头，不以不确定的截图材质为由增加原生玻璃效果或新依赖。

## 几何与 token

尺寸为截图结构在 Vega 密度下的具体落地，不宣称第三方私有像素或 token。所有新几何进入 `Layout`，字体/颜色复用 `Typography`/`ThemeColors`。

| 几何项 | 值/验算（logical pt） |
|---|---|
| 准备页表面 | 600×440；每边24透明阴影余量，原生外框648×488 |
| 准备页内容宽 | 600 - 2×32 - 2×1边框 = 534 |

| 权限卡默认高 | 84；左侧图标40、文字区两行，操作按钮高32，内容居中；文字高16×1.55 + 13×1.55 = 44.95，加2×16内距和2×1边框为78.95，小于84。错误不覆盖卡内主要动作 |
| 引导表面 | 560×120；每边24阴影余量，原生外框608×168 |
| 引导内宽 | 560 - 2×16 - 2×1 = 526 |
| 引导右列宽 | 526 - 32返回槽 - 12间距 = 482 |
| 引导内高 | 120 - 2×16 - 2×1 = 86 = 32指引行 + 12间距 + 42应用行 |
| 指引行文字宽 | 482 - 32箭头 - 8间距 - 24关闭 - 8间距 = 410；实际换行/字形仍需用户验收 |
| 应用行 | 高42，图标28，与应用名横向排列；整行有效拖拽和键盘操作 |
| 默认底部定位 | 沿用 `perch`/`follow_target`，卡片可见表面右/下缘距设置窗边18，clamp到显示器可见区；新尺寸全部传入现有纯几何算法 |

430/440 为默认主体预算，错误与恢复不能被固定高度裁切。主体之后的重新检测/返回任务动作另需16间距 + 32控件 = 48；每条检测反馈另需8间距 + 13×1.55 = 28.15（单行），重启提示另需8 + 12×1.55 = 26.6（单行），均进入准备页受约束滚动内容，不伪称全部默认可见。关闭在滚动区外。引导头部、返回与关闭保持可见；正常头部32 + 间距12后，应用行有42高；异常头部可换行，后续恢复控件在独立受约束区域滚动。原生定位失败在两阶段均给出关闭后重开的具体恢复。
