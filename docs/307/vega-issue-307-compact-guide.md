## 界面契约

### 1. 紧凑浮层

- 默认可见表面 **400×140 logical pt**，外层每边24pt透明阴影余量，原生外框448×188。尺寸是本次 Vega 设计决定，不声称逐像素复制录屏。固定高度、不滚动、不出现大标题/状态表/组件行/浏览器行/抓屏行/检测结果或成排动作按钮。
- 一行任务提示：`将 Vega 拖入上方列表，然后打开开关`。以系统设置列表为指向，默认不附实现说明。
- 提示下方为明确的 Vega 应用拖拽区域：自有正式图标 `assets/logo/vega-icon-smile-light.svg`（与打包源一致），图标画布56pt、名称标签 `Vega`，含足够命中区域。不得再用Monitor图标替代应用身份。拖拽预览也使用同一自有标识，不复制第三方图标。
- 顶部尾部为24pt关闭图标按钮，提供“关闭引导”的可访问名称和键盘可达焦点；不额外占一条标题栏。设置动作、重新检测、权限状态与常规返回导航不在浮层内堆叠。
- 正常态仅上面内容。不能拖拽时，原区域替换为简短原因及“在 Finder 中显示”；不得假装可拖。真实跟随/面板保护/路径失效等直接影响当前操作的问题，允许用紧凑且可操作的本地错误替换指引或在同一区域换行，不扩张为诊断大面板。完整诊断在设置页；若需打开Vega设置恢复，可提供当前错误旁的明确入口。检测/服务/清理错误只改变简短提示并就近增加“权限与检测”，不得把它当成文件拖拽能力失效：真实 `.app`、有效路径仍须显示图标及拖拽入口；仅本地路径/面板/窗口定位问题可用阻塞替换区域。
- 默认无需常驻“在 Finder 中显示”或“返回任务”。任务侧准备入口与原会话导航仍可用；若保留浮层上的任务返回，只能在明确任务来源时用次级入口，不得新增常驻footer或改变默认尺寸。
- 使用ThemeColors、Typography、Layout。单一圆角表面、轻边框/阴影；不为模仿视频发明不可验证的玻璃材质或新原生效果。

### 2. Vega 设置页承担权限和恢复

- Agents → Native中保留电脑/浏览器开关、现有浏览器扩展安装入口（不新增浏览器流程）。把电脑操控准备的独立状态和动作归入此分组。
- 组件状态、辅助功能、屏幕录制分别呈现；“实际屏幕抓取：未验证”只陈述事实，不宣称可操控。未检查/未知/拒绝/Busy/具体失败区分，缺失组件错误必须投影到组件事实行。
- 一个明确“重新检测”动作使用已有PreparationProbe/ProbeClient适配层，重复点击不新开平行daemon；成功会话复用。设置页与浮层不能分别拥有两条竞争的准备检测链。仅打开无关设置分区不得自动占用电脑操控准备会话；普通设置呈现可被动读取最后状态，用户准备/重检动作或打开引导才可取得准备所有权。
- “辅助功能设置”“屏幕录制设置”动作仍分开。操作会派发对应URL并使紧凑浮层出现，初次开启电脑操控也可默认进入辅助功能路由；不能为检测自动弹系统权限。对已Observed且两项静态Granted的情况也不推断可自动完成。
- 设置页关闭/重建、浮层替换、任务context失效的所有权需明确：不得把旧观察无条件重新投射为本次检查结果，不自动消耗失败清理的重试。可保留最后一次状态，但必须与正在检测/未检查、原错误区分；不持久化到配置或数据库。
- 所有未解决的服务不可用/close/cleanup/inspection错误保持可查看且有实际重检或重开恢复路径。必要屏幕录制重启提示就近保留。诊断的移动不是删除安全反馈。最后所有者释放后取消客户端，但若服务仍在 Reclaiming，既有 UI 轮询仅被动等待并记录 Clear/Failed 终态后停止；不再发 RPC、取得所有权或自动重试。普通设置打开/重建可读到这份最终事实，不以重新检测来补齐已发生的清理错误。
- 从权限相关失败的持久准备入口仍能回到原会话或进入准备设置；保留原task/project/context fencing，只导航，不提交、resume、授权或重放观察。

## 实现计划与边界

1. 复用现有真实bundle解析、CardController票据、session互斥/回收管理和native几何，不重写驱动或权限架构。
2. `card/view.rs`改成上述紧凑布局；`card.rs`移除不再需要的诊断滚动和焦点接线，保留关闭、窗口生命周期、定位/跟随/冻结。图标用GPUI现有`Image::from_bytes(ImageFormat::Svg, ...)`/`img`读取内嵌自有资产，不新增依赖或资产生成步骤。
3. 最小连接设置页与已有准备状态/动作。允许新增UI内部共享model/投影模块来复用同一服务、保留独立事实与错误；不要让Settings每次render创建probe或把renderer当观察入口。既有`observe_global`/实体观察可用于状态传播，异步服务仍由已有适配层管理。
4. 按实际API调整`DesktopPreparationRequested`和host导航，使设置页权限动作派发准确路由并显示/复用紧凑浮层。旧task/context/host lifetime校验不能弱化。原生adapter默认只读；如确需改动先给具体证据。
5. 共享Layout更新width/height、图标及命中几何，不硬编码颜色/字体，不改无关主题或Composer。
6. 必要回归按最新政策按风险选择：本轮优先检查拆分后的状态与生命周期不变量。若新增进程内测试，必须调用真实生产决策，不做源码字符串/机械转发断言，不批量恢复已删历史测试；只交现有Actions执行。开发测试留痕后在合并前删除测试及独占接线，不改生产逻辑/安全断言或 Python/CI，最终 head 静态无残留且完整门禁确认 Rust 0发现/0执行。
