# Vega UI 改造方案 · 评审版

**用户已批准本方案，进入实施；本页保留为设计总览。** 2026-10-11 · 关联 [#296](https://github.com/puzige/vega/issues/296)

本次把18点反馈合成一套设计，不再逐个控件打补丁。已交付的0.1.67作为基线；以下目标已获用户批准、正在实施，尚未验收。

## 为什么看起来混乱

不是缺少圆角或更多颜色，而是同一功能有多种表达：过程被整块灰底切碎、耗时远离标题、状态与hover动作互相挤占、配置分散在不同页面。旧规范还同时保留两套设置尺寸，以及“过程无底色”和“过程统一灰底”两种要求。

[Apple HIG](https://developer.apple.com/design/human-interface-guidelines/)提供桌面平台交互原则，[GPUI Kit Design Guides](https://gpui-kit.com/docs/design-guides/)帮助检查组件组合；Vega仍需自己规定消息阶段、设置对象、状态和数据真实性。具体数值是本次Vega提案，不是从指南照搬。

## 1. 会话：运行时看进展，完成后看答案

```text
运行中                              最终答案出现后

                      用户消息                            用户消息

Working for 22s                     › Worked for 1m 18s
────────────────────               ────────────────────
已检查配置，正在验证结果……           最终答案正文
› 正在验证结果  [轻微文字扫光]         段落和列表保留舒适间距……
› 运行命令 · 5.1 秒
另一条进展说明……

                (↓)                                  (↓)
┌────── Composer ──────┐             ┌────── Composer ──────┐
```

- 工具和思考详情默认折叠，中间助手说明在运行时持续可见。
- 有摘要就替换 Thinking；只有当前真实思考/等待的文字轻微shimmer。工具执行使用真实操作名，结束、待确认和Reduce Motion时停止动效。
- 最终答案有可信阶段信号时，将此前过程收进一条可展开入口。错误、权限和待回答问题保持可见；用户正在展开回看时不强制收起。
- 所有普通过程组去掉常驻整块灰底；操作耗时紧贴名称，展开箭头属于同一组。
- 纳入最新Codex截图的层级：**活动概览 → 阶段摘要 → 单条工具 → 展开详情**。前三者是轻量无底色行；展开后的命令/输出才有浅底、细边框与圆角容器，内部显示工具类型和真实结果。长命令在摘要行省略，完整内容放详情。
- 正文先保持15px，拉开段落、标题、列表和表格节奏；展开思考由13提升到15px，长内容限高240并提供滚动条。

**关键前提：** 当前Native/ACP没有足够可靠的“最终答案开始”信号。先定义阶段契约；缺信号时保留有效正文，不能猜最后一段就是答案。最终阶段识别列为独立实现批次。

## 2. 设置：围绕提供方与模型配置

```text
通用                  服务提供方
服务提供方            ┌──────────┬───────────────────────┐
MCP                   │ 提供方列表│ 名称 · 已启用    编辑  ⋯│
Agents                │          │ 连接信息               │
Skills                │ + 添加   │ 模型       发现 / 添加 │
用量                  │          │ 模型 A          配置 ⋯ │
                      └──────────┴───────────────────────┘

                      服务提供方 / 模型 A
                      基本信息 | 思考 | 定价
                      当前分区的字段和明确控件
```

- 左侧由八项收敛到六项，用量最后；思考和定价移进模型配置，原有字段与操作都保留。
- Provider列表动作、连接设置、模型管理各归其位；删除放更多菜单，避免满页红色按钮。
- 自明说明直接删；必要解释放help。错误、授权、危险操作和安装前重启确认直接展示。
- models.dev作为元数据补齐源，支持匹配、缓存、手动覆盖，刷新不覆盖用户修改。

**关键前提：** 现有定价以模型名全局共享，不能搬进Provider后让用户误以为是提供方独立价格。先明确共享作用域；独立报价和目录接入放到数据批次，先确定迁移与历史费用规则。

## 3. 壳层与交互：紧凑、圆润、位置稳定

| 区域 | 本轮方向 |
|---|---|
| Sidebar底部设置 | 保留32高按钮及其圆角/padding，外层收紧为48高 |
| 任务运行圈 | 靠行尾固定槽；hover/focus在同一区域替换为操作，标题不跳 |
| 会话锚点 | 左侧独立gutter，紧凑短刻度居中；hover变长并预览；点击准确定位 |
| 回到底部 | 纯向下箭头，圆形32按钮；保留40高导航带避免内容抖动 |
| 所有图标 | 同一轮廓族、圆端点、光学对齐；设置图标按连接/机器人/能力/图表区分 |
| hover与动效 | 局部120ms反馈，不移动文字；少量有明确状态含义的动效 |
| 其他区域 | 标题栏、Composer、Workspace、Terminal、Environment、菜单与弹层一起检查共享规则 |

正文和Composer仍同轴同宽；底栏分支不会恢复。权限、快捷键、终端焦点、选择和历史定位均保留。

## 4. 上下文：先显示真实总量，再补分类

Composer的小环点击打开：**百分比 + 已用/配置输入上限 + 用量条**，估算明确标注。分母沿用模型配置的输入上限，不冒充供应商验证容量，也不混成本轮运行预算；当前上下文与累计账单分开。

WorkBuddy式分类条是目标，但目前没有系统/工具/对话/MCP/Skills的token分类数据。第一步展示真实总量；分类管线能对账后再显示分段，缺值不画成0，不用工具数量猜占比。

## 5. 建议分四批落实

1. **共享视觉与阅读**：侧栏、锚点、图标、去过程灰底、Markdown、时长邻接、长思考滚动、纯箭头。
2. **设置结构**：六项导航、Provider页面、模型基本/思考/定价配置，保留旧能力与共享价格语义。
3. **运行阶段**：可信final识别、请求时钟、过程自动收起、摘要shimmer，分别覆盖Native和ACP。
4. **目录与上下文数据**：models.dev、覆盖与缓存、价格身份、上下文总量及有数据后的分类。

前两批能带来直接可见的改善；后两批补足行为基础。全部18点在[详细spec](vega-issue-296-ui-redesign-v3.md)逐条映射，没有因为分批而删除。
