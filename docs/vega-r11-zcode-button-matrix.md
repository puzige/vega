## 证据与状态

- ZCode：本机原生客户端实际打开工作区、搜索、菜单和所有设置分类。下表「点验」表示已打开或执行所述安全交互；「展示」表示看到按钮及其说明，未执行会改变账户、配置、任务或远端状态的操作。看到开关不等于证明其后端成功。
- Vega：初始代码 `7b0075a` 的 production render → handler → controller 路径审查。已有功能的本轮代码审查不能替代 R9/R10 的历史验收，也不能当作新增功能已通过原生验收。
- 状态：**已有**＝已有真实入口；**部分**＝范围或行为较窄；**缺少**＝未找到对应入口/能力；**保留差异**＝用户明确决定不复刻；**本轮**＝本轮承接，验收完成前不写成已完成。
- ZCode 右栏「＋」实际为辅助对话、终端、浏览器。文件通过 Cmd+K 的文件搜索打开到右栏；本次没有观察到独立文件树或通用可编辑代码编辑器，不以推测作为参考要求。

## 本轮三张实施卡

1. **P：全局搜索与文件预览** — Astra medium 独立 worktree。四分类命令面板；真实任务搜索；当前可信项目的文件查询与受限只读预览；真实快捷动作；键盘、焦点、草稿、IME 与过期结果隔离。不得添加假 Browser/MCP 动作。
2. **T：真实交互终端** — Astra medium 独立 worktree。PTY + login shell，多标签、项目隔离、右/底栏、ANSI 屏幕、键盘/Ctrl+C、resize、滚动、关闭与进程回收。复用已有布局，不以逐行执行 Bash 工具替代。
3. **C：输入区可发现性与停止** — Astra medium 独立 worktree。运行/准备中的可见停止；现有 token 与持久化边界；「＋」→ 项目文件引用/模式；/ask、/plan、/execute 等待真实设置提交后消费前缀；不误发模型请求。

主 Agent 不并行改实现文件。T 单独拥有 `window/workspace.rs`；P 提供 FilePreview 与 typed 入口，由 T 挂接；C 仅在共同 renderer 添加约定的 Stop 订阅。主 Agent 顺序审查集成，遇到重叠仅做集成解决。
