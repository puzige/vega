# 权限菜单直接生效与 composer 精简

2026-10-28 用户明确要求：composer 更简洁，不要线程完全访问的确认弹层及其说明。此裁决取代 `permission-ui-completion.md` 和 `permission-picker-feedback.md` 中线程首次启用/重新授权仍需独立确认的展示要求。用户在权限菜单的明确选择本身即为该会话的授权操作；不再追加第二次确认。

## 验收

| 前置状态与操作 | 可观察结果 | 证据 |
|---|---|---|
| 已有受限会话或缺少授权的旧 FullAccess 会话，选择完全访问 | 一次选择即提交该精确会话的授权；无确认卡、确认按钮或长说明；提交读回后更新模式 | Actions 中应用控制器与持久化回归；用户手测 |
| 未落库草稿选择完全访问 | 校对精确草稿后原子创建线程与 thread-scoped grant；保留输入、模型、项目 | Actions 回归；用户手测 |
| 打开菜单后关闭，或重复选择当前有效授权模式 | 不写入、不轮换 grant/revision；不恢复确认卡 | 静态事件链；已有开发证据；用户手测 |
| 查看普通 composer | 权限控件只显示模式名称，不附加“需授权”或“下一轮”文字；活动运行与未来选择不同时，仅在菜单内显示实际运行模式 | 静态渲染检查；用户手测 |
| 保存/重新读取期间继续输入 | 原控件图标位置显示局部进度，阻止重复权限提交；不出现等待卡或成功卡，不抢回输入焦点 | Actions 与静态焦点链；用户手测 |
| 来源冲突、reset、不可用或未知提交结果 | 保留短错误和重新读取入口；不显示成功，不用旧来源自动重试，不产生跨线程或后来权限 | 现存服务守卫静态检查；Actions；用户手测 |

## 实现边界

1. 权限选择 controller 在同一次用户事件内准备并保存；FullAccess 的选择作为服务的显式确认输入。保留数据库身份、当前 epoch、来源/revision CAS、单写者 gate 以及提交读回，不按数据库中的模式名称自行补权。
2. 写入前校对 `change.is_draft()` 对应的窗口草稿必须与捕获 source 完全一致；无匹配来源时拒绝写入。迟到回执继续只应用到匹配 stream/route，已有运行 fence 不变。
3. 删除线程确认专用状态、按钮、事件及 controller 接线。仅保留保存、重新读取和错误状态；保存成功不转移输入焦点。未来默认、自动化与 reset 属于其他操作，本增量不改其服务契约。
   若草稿保存已提交但回执未知，重新读取先核对持久结果；读回已有线程时正确结束草稿状态，不再次生成授权。仅数据库中确实无该线程且窗口草稿与捕获来源一致时保留未落库草稿；不能把未知提交结果卡在旧草稿准备冲突中。
4. composer 保留模式名、图标和可访问名称，进度使用既有 spinner/token；活动模式差异放回权限菜单。没有新增常驻提示或 tooltip。
5. 本地只做格式、差异和静态检查，不运行、编译或测试 Vega。必要行为回归交现有 PR Check；开发 Rust 测试取得真实结果并固定可恢复源码后清理，最终 head 必须无 Rust 测试且通过 required CI。实现后由非写入者审查本次差异，合并后等用户手测。

## 开发状态

已移除线程确认 UI/事件/接线及无对应状态的取消调用，保留单次选择的准备/保存与旧权限门禁；composer 仅显示模式名称，保存/读取显示原图标槽位的 spinner，活动运行差异只在菜单内展示，成功不抢输入焦点。错误保留紧凑行和可用键盘操作的重新读取。

五项必要开发回归通过真实隔离数据库验证 controller 的持久化 worker：一次选择完成草稿/已有/legacy 会话授权，错误草稿无半成品，过期来源不覆盖新权限，受限草稿不落库，以及未知回执后按实际持久结果恢复且不重新授权。不建立新的生产公开测试 API、不恢复旧测试集合。UI 点击/键盘与像素效果通过静态调用链检查并待用户手测，不能把 worker 回归冒充原生界面验证。

本地格式、差异及中英文 TOML/键/权限引用静态检查通过；没有本地运行、编译或测试 Vega。
