# Issue #403：对话延伸至 Composer 与渐隐过渡

来源：[Issue #403](https://github.com/puzige/vega/issues/403)。用户于 2026-10-16 指定实现。关联 A2-04 / A2-11；沿用 [设计守则](vega-design-guidelines.md)、[执行总纲](vega-exec-guide.md) 和现有消息阅读保护契约。

## 需求与范围

当前会话正文、阅读导航区与 Composer 纵向排布，消息视口在 Composer 上方结束。改为消息可滚动到 Composer 后方，输入框附近以背景色渐隐，形成 Issue 两张参考图中的连续阅读面。沿用现有系统字体、主题、宽度、圆角、输入与发送行为；不新增开关、提示文案、动画循环、依赖或数据迁移。

空会话继续保持欢迎内容及新任务 utility bar 的现有布局。适用于已有消息的 Native 与 Codex 会话、浅深主题、展开的侧面板与紧凑工作区。

## 行为与视觉契约

1. 非空会话的消息视口延伸到 Composer 所在底部区域，Composer 固定在底部前景。不能仅在原本被截短的列表末尾画一块渐变。正文与 Composer 继续使用共享最大宽度和左右对齐；不改变现有气泡、代码和正文颜色。
2. Composer 上沿附近使用垂直的背景色透明度过渡：上端透明、下端与当前 `bg_base` 一致。过渡高度使用新增共享 `Layout` token，初始值 48 逻辑像素（4px 间距梯度的 12 倍）；不用逐行改变消息透明度、模糊、位图或持续计时任务。Composer 本体继续使用现有实色表面；底部及两侧不能透出不可读的消息碎片。
3. “回到底部”保持既有名称、键盘焦点与跟随语义，位于输入框上方，可与渐隐过渡所在区域共用空间。渐变是纯装饰，不拦截鼠标、滚轮或键盘；Composer 前景中的实际控件及不透明区域不能把点击交给被遮住的底层消息。
4. 列表底部余量跟随实际底部组件的布局高度，包含多行输入、附件、待发送消息、真实错误/警告和适用的隐私控制等。滚到末尾时最后一条消息及其操作必须能够完整读到并操作，不能固定藏在 Composer 后。不能只按最小输入框高度写死余量，也不能把余量实现为业务消息或破坏消息索引。
5. Composer 增高、缩小和窗口缩放时，处于底部的会话继续跟随；回看历史时保留原有阅读位置，不因底部布局变化或流式更新强制跳到底部。既有历史水合、消息锚点、选区复制和长会话虚拟化继续有效，不增加每次渲染遍历全量消息的工作。
6. 模型、权限、添加上下文、文件选择及待发送菜单继续在渐变与正文上方绘制；保持 Esc、外部点击、菜单操作、焦点返回和原有错误恢复。提交面板、计算机操作提示和其他底部必要提示必须可见且可操作。
7. 不新增产品解释文字。所有已存在的真实错误、权限、阻塞及待用户处理事项保持可见。本卡的渐隐只表示滚动区域的视觉边界，不表示消息状态或内容被删除。

本卡为用户明确要求的布局过渡，覆盖设计守则中“正文默认不加渐变”的默认规则；渐变只作用于视口与底部前景的交界，不改变正文样式或源文。

既有 `issue98_scroll_button.rs` 的 A3/A11，以及 `issue296_desktop_ui.rs` 的阅读列/恢复跟随测试，包含“按钮或导航必须在 transcript viewport 之外”的位置断言，对应旧的纵向分隔布局，由本卡的真实重叠要求取代。保留同轴、尺寸、可访问名称、焦点、绘制顺序、阅读位置、点击和 Enter 恢复跟随的断言，仅将上述旧位置条件改为按钮/导航位于前景过渡区、在 Composer 之上且不会被遮挡的生产几何条件。其他既有断言不因此放宽。

## 实现计划与归属

- 主 agent：本规格、需求边界、代码评审、集成、PR 与 CI、合并和看板状态。
- 专用实现 agent：`crates/vega_ui/src/conversation_stream/` 下布局、必要状态及生产回归测试；`crates/vega_theme/src/lib.rs` 中本卡共享几何 token；交付记录 `docs/vega-issue-403-conversation-underlay-delivery.md`。其他模块确有依赖时先向主 agent 说明。
- 顺序：先按上述矩阵补生产回归，再实现非空会话叠层、背景渐隐及动态底部余量，最后评审默认、运行、完成、失败、窄窗口与键盘路径。保留现有测试断言，不改权限、业务索引或外部调用行为。
- 本地仅允许快速差异、格式与静态检查，例如 `git diff --check`、`cargo fmt --all -- --check`。禁止本地编译、构建、打包、Clippy、test/nextest；功能点与完整测试交给现有云端 PR Check。
- 云端门禁：`cargo fmt --all -- --check`、`cargo clippy --workspace --all-targets -- -D warnings`、`cargo nextest run --workspace`；交付时记录新测试名与真实原始结果。
- PR check 通过后按仓库交付流程主动 squash 合并并置 `In review`，等待用户在云端发布的应用上手测。未收到通过结论前不关闭 Issue、不置 Done、不清理分支/worktree。回滚方式为回退本卡合并提交。
