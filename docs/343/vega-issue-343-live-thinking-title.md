# Issue #343 · 思考过程的信息层级与实时反馈

来源：[Issue #343](https://github.com/puzige/vega/issues/343)。用户看到思考详情仍持续追加，但阶段标题停在较早的短语。当前 #71 提取器一旦遇到 Markdown 小标题或整行加粗，就拒绝后续普通段落；同时已有 summary 永远优先于后来到达的 thinking。这两条规则都能造成该现象，仅凭截图不能确认实际命中哪一条。

2026-10-13 用户手测修订：PR #346 的“最近可读来源优先”会让后续原始 thinking 覆盖已收到的 summary，与期望不符。本规格改为 summary 替换模式：出现可读 summary 后，标题只由 summary 更新；常规展开内容也只展示 summary。原始 thinking 仍可接收并保存在当前块，但不主动展示。该修订取代本文旧版“较晚来源优先”及 [#71 规格](../71/vega-issue-71-reasoning-summary.md) R1–R3 中“小标题保持到下一小标题”的规则；#71 的 summary 优先原则继续适用。#329 的[前缀回退](../329/vega-issue-329-prefix-rollback.md)继续适用：不添加固定 `Thinking ·`。其余 #71 的提取安全、资源上限及 #296 的阶段布局、折叠、工具/正文归属规则不变。

2026-10-14 用户手测修订：阶段展开时外层与内层重复同一条预览。DeepSeek 流可能只有详细 thinking，GPT 流可能只有 summary；按收到的事件决定展示，不根据模型名称推断。summary 适合替换外层标题，详细 thinking 不应被截成不断跳动的外层标题。该修订取代前一日“常规展开区展示 summary”的要求；工具进度独立于思考 disclosure 保持可见，不让用户长期等待。[#296 信息流契约](../vega-desktop-ui-unification.md)中相冲突的嵌套标题与折叠默认值以此为准，其余布局和交互继续适用。

2026-10-14 用户再次手测：连续的思考与命令循环出现多组重复的 `Thinking` 和单条“已运行命令”，没有收成一个可扫读的过程。默认视图应让无可见正文隔开的循环共用一个外层阶段，并把多条命令收成一个可展开的工具组；运行、审批与错误反馈仍需及时可见。纯空白的正文增量不能单独制造视觉阶段，真正的正文仍是边界。这项修订细化下文的阶段和工具归属规则，不改变用户可见的真实正文或工具事件。

2026-10-14 用户继续手测 GPT 6：外层已有 `Thinking`，其后的查找、读取、命令、编辑和搜索失败仍逐条露在外面。用户要求这些工具记录收进同一个 `Thinking` 展开区。本次修订取代上文及 T9–T12 中“外层折叠时工具行仍可见”的展示规则：默认只显示阶段标题与简洁、真实的运行或待处理状态；打开阶段才显示按原事件顺序排列的思考和工具记录。真正需要处理的审批、阻塞及错误不能被静默掩盖，但状态提示不应把整列工具记录重新铺在外面。产物和正式正文仍保持独立可见。

2026-10-14 第四轮用户手测：`Thinking · 正在运行命令`、`Thinking · 失败 2 · 拒绝 4` 等尾缀仍然太吵；连接中断后的“正在重新连接”也不能被思考 disclosure 收起。本轮裁决取代上段“折叠标题附近显示工具状态”的设计：外层标题只表达 `Thinking` 或真实 summary，不附加工具动作、计数、失败或拒绝文案。工具级失败／拒绝是模型可能自行恢复的过程记录，仍在用户主动展开的详情中；不得把它们逐条搬到 feed 制造新噪音。需要用户处理的权限请求、连接重试、整轮失败及其他真正阻塞事项是独立 feed 记录，不能依赖 Thinking 展开状态才能看到。重试恢复后移除临时状态，终态错误保持可见或可再次访问。

2026-10-14 用户补充：独立的“正在重新连接”行使用 Wi-Fi 图标，与连接状态的含义一致；临时重试仍需清楚可见，不能被当成终态错误。

2026-10-14 第五轮用户手测：有可见正文分隔的几个无 summary 阶段仍全部写着 `Thinking`，过去的阶段看起来像一直在思考。纯思考阶段的 `Thinking` 是当前正在输出思考的状态；该阶段结束后改为 `Thought`。用户随后给出工具活动参考图：有工具的阶段应由外层一句简短的活动摘要概括已读文件、已运行命令等，原始思考和工具记录仍在展开内容里，不再把所有阶段都命名为 `Thinking`／`Thought`。同一阶段先收到可读 summary 时，标题先显示 summary；随后出现工具时，活动摘要替换该标题，此后本阶段的 summary 增量不再抢回标题。此条为当前标题优先级，取代上面第四轮“外层只表达 Thinking 或 summary”以及下列旧验收行中的冲突表述。

2026-10-14 第六轮用户补充：**一个逻辑过程条目不加聚合外壳，出现第二个才聚合。**只有一个 thinking 块时直接显示它自己的 `Thinking`／`Thought`（或可读 summary）行，一个工具时直接显示工具行；同一阶段的第二个 thinking 块或工具调用出现后，再升为一个可展开的活动摘要。重复 delta 和同一块的 summary 更新不算新条目；工具组里的每个真实调用各算一个，产物、权限提示、重连和整轮错误不计入。聚合后用第一个工具的图标，类别短语按首次出现顺序追加。若 summary 原先在单条目标题上，工具到来后由工具摘要接管，summary 只在展开详情里出现一次，避免信息消失或重复。本段取代下文旧的“一个条目也有外层阶段”表述。

2026-10-14 第七轮用户手测：同样的命令阶段有时写 `Worked on 2 commands`、有时写 `Ran 2 commands`，且数字没有帮助扫读。用户明确收窄方案：**聚合标题只显示工具种类，不显示状态动词或调用次数；种类统一用复数。**例如 `Commands`、`Read files, commands`。即使某一类只出现一次，只要阶段已由两个过程条目聚合，标题仍用复数类别名；单个过程条目继续显示原本的直接行。类别按首次出现顺序追加，图标仍取首个工具；超长时只用省略号，不显示 `+N more`。运行、成功、失败、拒绝与具体次数仍保留在展开详情，不由标题概括。本段取代下文旧版“多项显示数量”“正确单复数”和按状态选择动词的标题规则。

## 行为契约

- 同一来源内，新的可读 Markdown 小标题或普通段落都能更新预览。未完成的 Markdown 标记、空白、代码围栏内部内容不清除已有可读预览，也不抢占另一来源。
- summary 与 thinking content 各自增量提取预览。尚无可读 summary 时，thinking 的最新可读片段只用于内层思考行；一旦 summary 产生可读预览，本块进入 summary 替换模式，后续 thinking 不能再抢占。后续 summary 继续更新预览，但阶段已有工具时不再占据外层标题。空白、未完成标记或代码围栏不触发模式切换；纯思考且没有可读 summary 的外层使用 `Thinking`／`Thought` 状态标签，不把详细思考截成跳动的标题。
- 有可读 summary 且它仍是唯一条目的标题时，不在下面重复渲染该思考行；工具或第二个过程条目使外层聚合标题替换它后，在展开详情里保留该 summary 一次，不同时主动展示原始 thinking。思考块内部保留 #351 的 summary 优先来源与复制数据，后续 thinking 增量不会把原文重新放回展示。summary 尚无可读预览时使用当前 `Thinking`／`Thought` 状态，避免流式标记造成标题闪空。没有 summary 时，详情仍为原始 thinking。当前块保留真实收到的两种文本，不虚构摘要，也不改变事件归属和存储边界。
- 标题最多 96 个 Unicode 标量；长小标题保留开头，长普通段落保留最新尾部。增量处理和 UTF-8 分片规则沿用 #71，不扫描整个思考原文，不增加新的模型请求。
- 当前阶段只有一个逻辑过程条目时直接显示该条目，不另造外层聚合 disclosure：纯 thinking／summary 行标题为 `Thinking`／`Thought` 或最新可读 summary，原始 thinking 可通过该行手动展开；单个工具沿用自身工具行。第二个条目出现后，显示一个可展开的聚合标题并把两项按原顺序收进详情；若含工具，标题为工具活动摘要且后续 summary 不再抢回；若仍只有思考块，则用 `Thinking`／`Thought` 或可读 summary。纯 summary 在聚合前不生成空展开区，聚合后在详情里出现一次；产物与正式正文继续独立可见。
- 没有用户操作时，只有思考内容流式更新不会自动展开原文或聚合详情；现有运行时钟和动态状态说明仍在工作。单条目思考行的手动展开可实时看到原文；聚合后用户手动打开的详情随新事件实时更新，内部思考行仍保持自己的手动开合状态。单条目升为聚合时保留用户此前的明确开合选择与焦点，不能因新事件反复强行展开或让可见内容消失。用户手动打开的聚合区不会因思考结束而自动收起。
- thinking 与工具继续按事件顺序进入当前消息的活动阶段。工具先到且当前阶段没有 thinking 时，只有一个工具就直接显示该工具行；第二个过程条目到来时才聚合，保留原始顺序。没有可见正文隔开的多轮 thinking／工具事件共用该阶段；纯空白正文增量不单独切段，后续确有正文时仍按原内容呈现。聚合折叠时不渲染单条工具行或工具组，展开时逐条显示真实工具记录与思考行；纯工具阶段达到两项也按此聚合。只有实质正文开启后，后续活动才进入新阶段；不把跨正文的整轮过程改成一个长期折叠的总块。
- 聚合折叠时只显示一个标题：纯思考用 `Thinking`／`Thought` 或当前可读 summary，有工具时用活动摘要；不在标题后另加运行命令、失败或拒绝尾缀。可访问名称只朗读可见标题和展开操作。运行计时与真实的流式变化提供等待反馈。工具级失败、无效调用、拒绝和成功一样保留在详情及原始复制数据中，不额外生成 feed 噪音；若运行整体失败，则由已有运行错误机制在 feed 独立提示，不能只藏在阶段详情。用户手动展开后，后续事件实时加入展开区；手动收起后不会被新事件强行展开。只有 summary 的流不制造空的内层思考行；详细 thinking 的运行指示由后续工具、正文、运行终止等实际事件结束，不靠无依据的时间阈值。disclosure 的可访问名称与可见内容一致，键盘与焦点行为保持可用。
- 纯思考且无可读 summary 的外层阶段在当前思考持续产出时显示 `Thinking`；阶段转入可见正文、响应完成或整轮终止后显示 `Thought`。只依赖真实事件，不按静默时长猜测结束；重试回滚后按恢复的阶段状态重新计算。标题变化不得改变 disclosure 的手动开合、详情内容与可访问名称一致性。
- 阶段达到两个过程条目且包含工具时，外层用一条有界的工具种类摘要取代通用 `Thinking`／`Thought` 或已到达的 summary；展开区保留每个思考块与工具的真实顺序，summary 原先已在标题上时只在聚合详情里出现一次。摘要行左侧使用该阶段第一个被调用工具的分类图标，此后不因新增其他类别而跳变；同类工具合并，类别名按首次出现的顺序追加。聚合标题统一用复数类别名，例如 `Commands`、`Read files, commands`，不显示调用次数、具体文件名、状态动词、`Worked on` 或 `+N more`。摘要长度有上限，类别过多时以无数字的省略号截断。单个过程条目继续直接显示原有思考或工具行，工具的运行态与结果留在展开详情。只使用已有的安全工具分类，不把原始命令、敏感参数或完整路径放到标题。聚合阶段默认折叠，不逐条铺出命令／文件行；权限请求、连接重试和整轮错误仍在外层 feed 独立显示。
- 需要用户处理的权限请求在 feed 保持独立可操作入口，不依赖展开阶段。连接重试使用带 Wi-Fi 图标的独立 feed 状态行，阶段无论展开、收起或因重试回滚，重连信息均可见且位于阶段之外；尝试次数原位更新，恢复后消失。重试耗尽或其他整轮错误以独立的 feed 错误行展示，不在标题上拼接错误计数，也不因活动阶段折叠、Final 归档或虚拟列表复用而消失。产物与正式正文维持原有边界。
- 不改 provider 协议、事件、存储、思考原文、工具、正文或安装方式；公开证据只用合成文本。
