# 移除普通工具卡片的单命令取消入口

2026-11-16 用户反馈：消息流不应出现 Cancel command 按钮。本规格仅覆盖 #412 和 #921 的普通 Shell 卡片取消展示规则。

## 验收

| 场景与操作 | 可观察结果 | 验证 |
|---|---|---|
| 并发命令可取消，详情收起或展开 | 无 Cancel command 按钮，不留下空行或焦点入口 | 静态独审、用户手测 |
| 普通命令运行、完成、失败或取消 | 标题、详情、输出、真实终态维持现有规则 | 差异核对、用户手测 |
| 命令需要异常清理重试 | 保留 Retry cleanup、请求在途禁用/反馈及失败反馈 | 差异核对、用户手测 |
| 用户操作 Composer Stop | 沿现有路径停止本 run 的任务 | 接线核对、用户手测 |
| 恢复面板中的必要控制 | 保留原有操作与权限/恢复边界 | 差异核对 |

## 根因与实现

`ToolCard::render_with_title` 独立于详情展开态，在 `concurrent && (can_cancel || can_retry)` 时渲染卡片控制按钮。运行中命令的 `can_cancel` 来自当前 thread 的活动 operation，因此普通命令会在消息流出现常驻取消行。

将普通卡片的控制入口限制为 `concurrent && can_retry`，移除仅用于取消的标签分支。保留清理重试在途状态、事件订阅、运行状态、详情与 Composer Stop；恢复面板及 runtime/tools 的取消能力不变。无新配置、依赖、数据迁移或可见说明。

## 验证与边界

本次为删除一个 UI 入口，不添加临时 Rust 测试。执行格式、diff 检查和受影响 UI crate 严格 Clippy；独立审查绑定停写版本，最终 head 通过 required CI 后合并。空 Rust 测试集不是行为测试通过，真实系统与原生 UI 仍待用户手测。

不调查截图里的 Tool result corrupted、磁盘占用或后台命令行为，不安装/重启应用。回滚为恢复本次 UI 条件及标签分支。
