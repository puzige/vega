# Issue #78 follow-up — 双侧消息悬停复制

2026-09-22 用户复验补充：用户消息和助手回复均须在鼠标悬停时于消息下方显示复制按钮。参考仅使用用户提供截图的可见交互，不复制其正文或第三方内部实现。本契约补充既有消息气泡规格。

## 冻结行为

- 用户文字消息：复制动作位于气泡下方，靠消息列右侧；助手正文：复制动作位于回复下方，靠左。两侧均使用共享 SVG 复制图标、主题颜色和既有紧凑按钮尺寸，不新增时间戳、评价、展开等无关操作。
- 未悬停时动作隐藏；鼠标在消息或其动作区域内时显示，移动到按钮的路径不中断、不闪退。为动作保留稳定布局占位，显隐不挤动消息或滚动位置。按钮使用稳定元素 ID；键盘可聚焦并显现，具备「复制消息」可访问名称/tooltip。
- 点击复制该条消息完整源文本到系统剪贴板。保留用户换行和助手 Markdown 源文（包括代码围栏、列表和链接 URL），不从可见片段拼接丢失信息；不混入角色标签、工具、思考、错误提示、相邻消息或图片数据。
- 流式助手已有非空正文时允许复制当前已接收的正文；后续继续接收后再次复制须读取最新内容，不能复制过期快照。没有正文的空项不显示可执行复制动作。
- 历史恢复与新消息表现一致。复制只写本地剪贴板，不发送网络请求，不持久化新字段到数据库，不记录正文日志。
- 点击不提交 Composer、不触发父层其他操作；保留已有输入内容和流式/历史/滚动行为。纯图片条目不在本次文字复制范围；混合消息可复制文字部分。
- 浅深色、窄窗口均可见可用。复用既有图标/按钮语义；必要时在共享 icons 增加 Copy 映射。不得新增依赖。
