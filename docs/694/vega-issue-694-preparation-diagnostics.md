# #694 普通发送准备错误与尝试诊断

## 目标与边界

基线：`fe0fdef3880e50b1e17b8ebf3b9118ef738cf768`。保留普通发送在应用准备、会话准备、启动和首轮提交前的安全错误事实；不恢复旧现场、不修改用户配置或现有数据库内容、不重放任务，不改变准入、权限栅栏、提交与取消契约。

## 实现契约

- 准备错误保存阶段（数据库、准入、权限、工作目录、skill、会话准备）及白名单原因。可用时保存 SQLite 主/扩展码、IO 类别；不解析错误文本猜测原因。权限和工作目录链路不再先转换为字符串丢失底层类别。
- 每次 submission 的每个 attempt 独立生成 started 和终态事实（prepared/failed/cancelled/interrupted）；prepared 仅表示准备完成，不表示模型运行或任务成功。第一次具体错误优先于后续通用根 worker 失败；取消及异常 worker 仍保留原状态机的重试边界。
- 诊断绑定 submission ID 与 attempt number，不依赖消息/会话外键，覆盖未物化的新会话及重试。内存安全事实始终可查看/复制，文件数据库使用后台 writer 持久化；数据库不可写时不伪造落库成功、不覆盖主错误，保留内存回退及安全写入失败状态。
- 数据仅包含生成的标识、时间、状态、阶段、白名单原因、数值 SQLite 码和 IO 类别。正文、图片、引用、工作目录、配置路径、模型/provider 名称、原始错误、密钥等不进入诊断。不得将 Debug/Display 的原始错误插入诊断。
- 用户可见提示仅陈述已知问题并给出恢复动作；技术信息通过当前失败尝试的诊断复制入口按需获取，不增加常驻解释段落。

## 回归与交付

按用户本轮要求添加回归测试并保留，不按历史 Rust 测试清零规则删除本卡新增测试；本地仍只做格式/差异/静态检查，测试仅交 GitHub Actions。覆盖成功准备、代表性 SQLite/IO/权限失败、无消息新会话、重试隔离、首个具体错误优先、取消/worker 丢失、诊断脱敏与后台写入失败。独立非实现者审查与最新 head required CI 后合并，用户真实手测前不关 issue。
