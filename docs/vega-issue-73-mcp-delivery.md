## Proposed implementation gates and handoff

M06 requires distinct negative fixtures for DCR 4xx/invalid response, callback `state` mismatch, missing/mismatched `iss`, unapproved redirect or issuer change, expired token/refresh failure, and cross-origin credential leakage. The happy fixture must exercise registration only after the UI confirmation and must prove a genuine `tools/call` with the resulting access token. None uses an external account.

1. Freeze spec decisions before code. Check whether the existing approved HTTP/JSON/SSE/hash/base64 crates and OS CSPRNG cover implementation. If any new crate is truly required, stop under `vega-exec-guide.md` §3/§5/§6 and give the architect its exact pinned version, license, transitive dependency inventory and reason the approved stack is insufficient; obtain approval **before** editing `Cargo.toml`/`Cargo.lock`. Main agent delegates implementation to a dedicated subagent in a fresh sibling worktree. Keep #76 correction integration and shared tool-registry editing serial; do not let #73 and #74 edit the same loop/permission/persistence files concurrently.
2. Implement transport, headless OAuth and owned servers first; demonstrate the absent transport failing then focused protocol/auth tests passing through the production client. Implement the shared registry, credential persistence, permission/audit and app UI in one integration owner; prove M09–M14. Do not modify existing safety-test assertions merely to pass.
3. Under the repository-wide Cargo lock, run focused packages, `fmt --all -- --check`, strict Clippy, `test --workspace`, build/package and dependency-direction check. Capture exact commands, exit codes, pass/fail/ignored counts and raw log paths. No concurrent build/test across shared target worktrees.
4. Run M15 on the installed artifact with an existing configured real model, an owned local server, and an owned OAuth-protected remote server configured/authenticated through Settings. The real model must propose each tool call; owned servers must receive them. If no real model is configured, M15 remains blocked, not passed by M10. An external third-party MCP service may add interoperability evidence but cannot replace owned deterministic HTTP/OAuth E2E or be the only proof. Keep private captures and credentials out of the public Issue; retain screenshot hashes and a manifest outside worktrees.
5. Review against the matrix, integrate only after #76 shared-seam stabilization, rerun affected gates after integration, then follow the repo's merge, cleanup, Issue write-back and Project state protocol. A green headless test is evidence for only its slice, never an automatic pass for the full row.
