# 下一轮输入预测可靠性

Issue：[#628](https://github.com/puzige/vega/issues/628)。规格 v1.2，2026-10-26。原始基线 `410758d36e8fbe0802f816227948ece1486d8494`；独审修复同步基线 `3789bd8f3573f7aec55b233c35c57d873cfa5122`（#629 的行内重连提示，仅影响其他 UI 文件）。

## 目标与原行为修订

每个 Native 主会话的正常成功轮次，在主轮完成、终态刷新和待发送队列恢复完成后申请一次预测；不要求该会话当前被选中。每个会话独立持有任务和结果，切换到其他会话不取消，返回时复用原会话及建议，不重新请求。仅在当前应用生命周期内保留，不落库、不在打开历史或重启时补生成。

本规格取代 [#469](../469/vega-issue-469-composer-predictions.md) P1 的单次请求约束、P7 的纯线程切换取消约束、P9 的不重试约束；其他资格、权限、隐私、草稿与按键契约不变。一次逻辑预测最多 3 次 provider 单次调用：首次失败后等待 250 ms，再失败等待 500 ms；每次最长 15 秒，网络尝试及退避合计上限 45.75 秒，不含本地存储操作。不跨模型或提供方，不增加依赖或配置。

## 验收与边界

| 场景 | 要求 |
|---|---|
| 前台正常完成 | 空输入且无阻塞时生成灰色建议；不写草稿、不发送、不改主轮状态 |
| 后台正常完成 | 完成后立即独立申请，待队列恢复为空才发起；不等用户选中；返回会话能看到仍有效的建议。申请阶段允许仅队列加载 busy，保留请求及输入 fence；真正启动仍要求恢复成功、队列为空且 busy 已解除，输入/权限等阻塞仍拒绝并不复活 |
| 多会话完成/切换 | 各自拥有 stream、completed message、model/mode/backend、generation/revision 和取消令牌；互不替换或串用建议；加载保留会话时不重复执行会破坏当前预测的队列初始化 |
| 重试恢复 | 可重试的 provider/传输失败、超时、未正常结束、空/无效 JSON、超长或无效 suggestion 可再次尝试，总调用数不超过 3；成功即停止。现有 OpenAI 单次入口会因内部预算为零而将 Transport/HTTP 429、5xx 标记 `retryable: false`，预测独立预算按结构化 Transport/Http 类型识别这些临时失败，不重试 Rejected、鉴权/其他 4xx 或安全错误。流内 Protocol（含 Chat Completions 无 finish_reason 的 EOF）归入无效/未正常结束输出重试，不改 provider，不将所有错误统一重试 |
| 明确弃权/安全失败 | 合法 `suggestion: null` 直接结束；取消、权限撤销、不可重试错误、工具输出、凭据投影变化不重试；每次尝试按当前 DisplayProjection 检查收到的文本片段与累计输出，先于大小/JSON 解析/重试分类拒绝已脱敏凭据标记或投影变化，包括畸形/超长输出；保留已收到 usage；不为了显示建议捏造兜底文本 |
| 重试中失效 | 每次请求前及退避后核对取消、provider authority、持久化线程和最新完成轮次；请求后再次核对。用户输入/IME、发送、附件、队列、权限、模型/模式/后端变更沿原 UI fence 取消；输入删回空也不恢复旧结果 |
| 生命周期 | 删除线程只取消所属预测；打开/保存设置、关闭窗口取消所有所属预测；已取消的 stream 不保留为预测缓存；单纯切换会话不是取消条件 |
| 用量和隐私 | 每次实际收到 usage 的尝试单独记辅助用量，包括失败/弃权；不写主消息，不记录提示词、建议或凭据；严格解析与现有投影保护不放宽 |
| 非目标轮次 | 失败、停止、Plan、自动任务、子会话、ACP 及仅打开历史仍不触发；有下一条排队消息时优先继续主任务，不抢发预测 |

外部服务持续故障、模型明确弃权或用户操作使预测失效时，不能保证 3 次内一定出现建议；保证的是有界恢复机会、隔离和不损坏用户内容。

## 最小实现计划

1. `vega/src/window/composer_predictions.rs`：窗口 owner 改为按 thread 保存、强引用原 stream，局部取消并在失效时释放；准备/启动/回填不再依赖当前选中线程。
2. `window/{mod,agent,render}.rs`：成功轮传入明确 thread ID；选中身份变化仅使该线程的旧身份失效；渲染优先复用所属预测 stream，不重复初始化其已恢复队列；设置/窗口销毁仍全量取消。
3. `vega_conversation/src/composer_predictions.rs`：区分成功、合法弃权、可重试失败和终止失败；每次独立超时/取消、权限与轮次校验、usage 持久化。
4. `vega_ui/src/conversation_stream/composer_predictions.rs`：准备和实际启动区分暂时队列 busy，准备仍建立输入 fence，不恢复已取消申请；预测开关 setter 对相同值幂等，避免路由返回时的配置重载误广播并取消所有会话预测；真实开关变化仍立即失效。
5. 不改输入框 UI、快捷键、提供方实现、数据库结构、依赖、CI 或真实运行配置。

## v1.3 失败反馈修订（2026-10-27）

基线 `dee2009d`，分支 `feat/628-prediction-diagnostics`。本次未显示建议的根因尚未确定；辅助 usage 与预测请求一致，但不能证明返回内容或回填结果。静态确认模型列表加载会在 prepare/start 两处丢弃申请。

- 模型列表加载仅延后启动，不丢弃已符合环境资格的申请；保留原 stream/fence。当前 generation 的加载完成（含失败）后重新尝试所有保留申请，队列操作未结束继续等待原队列完成回调。过期 catalog 回调不能恢复申请。
- 输入/IME、队列内容、下一轮、模型/权限/配置变化、设置、删除或关闭仍取消；取消后不重建申请。加载结束并不绕过 authority、持久化终态或 UI fence。
- 新增独立 `composer_prediction_events` 表，避免污染主轮诊断状态。只写 thread/completed message 标识、固定事件枚举、尝试序号及时间，不保存模型响应、提示词、建议、错误正文、URL 或凭据。外键随所属消息/会话删除。
- 持久化覆盖准备拒绝、已保留、catalog 等待/恢复、启动、每次尝试及结果（弃权、格式、超时、流中断、provider、安全停止）、耗尽、取消/过期、UI 应用/拒绝。诊断通过 1024 项有界非阻塞队列交给独立线程顺序落盘，记录入队前时间；UI/请求/取消不等待诊断数据库锁。写失败、队列满或线程不可用仅固定 warn，不改变预测结果；进程退出前未落盘的尾部事件可能缺失，缺事件不能证明未触发。共享事件类型放 `vega_conversation::types`，store 字符串边界再校验固定类别；无正文 tracing。
- 增量范围为窗口预测/目录完成回调、预测 worker、store 新增迁移及事件 API；不新增依赖或界面文案。取代旧计划的无 schema 变更限制；回滚代码保留新增表，不降级或删除用户数据。
- 静态审查覆盖 catalog/queue 两种完成顺序、旧 generation、后台线程、等待期间输入取消、null 不重试、最多三次及隐私优先级。云端使用现有完整 required CI；真实时序和结果由用户安装包含合并提交的版本后复现，通过消息 ID 查询事件，不能用空 Rust 集合代表行为已验证。

## 验证与交付

本地仅差异、Rust 格式和静态边界检查，不运行 Vega、编译或测试。本轮不恢复历史 Rust 测试或为流程新增临时测试。完整 required PR Check 在 Actions 上验证 fmt、Clippy、既有 Python 检查及 Rust 清点；`no Rust tests` 不等于行为通过。停写的精确实现版本由非实现者独立审查，最新 head required CI 成功后 squash merge。

用户在集成版本手测：A/B 两个会话分别启动后切到另一个，后台完成后返回检查建议；请求期间切换与开始输入；多轮重复；下一条排队消息；关闭开关/删除线程；可控 provider 临时故障恢复及连续故障上限；确认无串线、草稿覆盖、自动发送或旧结果复活。真实 UI/服务和重试成功率尚需用户验证，不将静态检查或空集 CI 冒充手测。

回滚：关闭预测开关可停止新增请求；代码回退走本卡集成提交的 revert PR。v1.3 新增诊断表回滚时保留，不删除用户数据。合并后 Issue 保持开放、In review 等用户手测。
