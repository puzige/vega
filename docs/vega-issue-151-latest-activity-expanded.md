# Issue #151 — 默认展开当前活动（thinking / 工具调用）

关联：https://github.com/puzige/vega/issues/151 。2026-09-22 用户授权。

Status: frozen UI behavior contract. This **supersedes** exactly two resting
defaults, and nothing else:

- [Issue #61](vega-issue-61-thinking.md) §显示边界「默认折叠」——仅对**最新**的
  思考块失效；更早的思考块仍然默认折叠。
- [Issue #70](vega-issue-70-tool-activity.md) §2.1「多调用聚合行默认折叠」——
  仅对**当前**（最新）工具活动单元失效；更早的单元仍然默认折叠。

其余 #61 / #70 / R70 的边界、顺序、安全投影、fail-closed、权限卡与有界内容
契约全部保持有效。

## 观察到的缺陷

用户截图：一次运行里大量「思考过程」块和工具调用行**全部**是收起的，用户
无法在运行过程中看到模型此刻在想什么、在跑什么。需求原文：

> 现在大量的思考和工具调用都是收起来的。需要默认展开最后一个。并且出现新的
> 内容的时候自动合起来。

即：**最新的活动默认展开；出现更新的内容时，上一个自动收起。**

## 术语

**活动单元（activity unit）**：时间线上一个可展开的活动条目，恰好是下列三者
之一——

- `StreamEntry::Thinking`（一个思考块，展开=显示推理正文）；
- `StreamEntry::Tool`（单次工具调用行，展开=显示安全 detail：完整命令/输出/
  footer）；
- `StreamEntry::ToolGroup`（≥2 个相邻工具调用的聚合条目，展开=显示有序子调用
  紧凑行，语义沿用 #70）。

用户消息、正文（assistant text）、Artifact、Permission、Plan、Summary、
SkillActivation **不是**活动单元。

## 契约

### R151-1 新建活动单元默认展开

流在**实时**创建任一活动单元时，该单元初始为展开态（`expanded = true`）。

### R151-2 任意时刻至多一个「自动展开」单元

创建新的活动单元时，**先收起已存在的最新活动单元**，再展开新单元。因此自动
展开集合中任意时刻至多一个单元。

- 实现语义：在把新单元推入 `entries` 之前，收起 `entries` 中**最后**一个活动
  单元（若有）。
- 首个单元没有前驱，直接展开。
- 用户手动展开的**更早**单元不受影响（它不是「最新」单元），可以同时保持展开。

### R151-3 工具调用加入既有分组时，分组保持展开

相邻工具调用合并进既有 `ToolGroup`（或由单卡升级为分组）时，该分组即当前活动
单元：合并后分组为展开态，子调用按审计顺序可见。**不**自动展开子调用自身的
detail（#70 §3.2 的「按调用展开安全 detail」仍是手动行为）。

- 由**单卡**升级为分组时，原单卡是上一个当前单元、且刚被新内容取代：其自身
  detail 收起，以紧凑子行加入分组（`ToolCard::set_expanded(false)`），分组整体
  展开。这样展开的分组里**没有**任何子调用自带 detail，与「子调用紧凑行」一致。
- 追加到**既有分组**时，分组保持/回到展开态，不改动任何子调用自身的 detail。
- 权限卡移除后由 `merge_tool_entries_around` 合并出的分组沿用 #70 既有
  「`left_expanded || right_expanded`」语义，不额外强制展开。

### R151-4 正文开始使当前活动单元自动收起

一个 assistant 正文分段的第一条非空 `TextDelta` 到达时，收起当前活动单元。
正文是更新的内容，接手「当前」位置。

- 触发点是「新分段的第一条非空 delta」，不是每条 delta：每个分段至多一次扫描，
  不在逐 token 热路径上重复扫描 `entries`。
- 思考块之后的正文属于新分段（`append_thinking` 已有的分段收束语义），因此
  「思考 → 正文」会让思考块收起。

### R151-5 手动状态不被反复覆盖

展开状态纯 UI 内存态，不持久化、不影响审计/执行/上下文。

- 流**从不**在用户收起后主动重新展开同一单元（只在「创建新单元」时展开）。
- 自动规则（R151-2 / R151-4）在新内容到达时照常生效：若用户刚展开的就是当前
  单元，更新的内容仍会把它收起（这正是需求原文「出现新的内容的时候自动合起来」）。

### R151-6 历史水合与重开不自动展开

历史页/重开路由创建的活动单元保持默认折叠：重开后没有「当前活动」，所有单元
收起。这与 #70 §3.4「Expansion is UI-only and defaults closed on route open/
restart」一致，本条显式保留该契约。

### R151-7 边界、顺序与安全投影不变

- 活动单元的分组边界、时间线顺序、R70 正文/工具交错、权限卡生命周期、
  fail-closed（rejected/cancelled/corrupt 仍可见）、严格 write/edit 投影与
  redaction 全部不变。
- 自动展开只展示**既有安全投影**已能展示的同一份有界 detail，不引入任何新的
  原始参数、绝对路径、body、fingerprint、provider call id 或 checkpoint 引用。
- 展开只改变该单元自身高度：通过既有 `invalidate_item`（`remeasure_items`）
  路径重测量，不触碰冻结项，不改变滚动锚定语义。

### R151-8 无新增依赖 / schema / 持久化

无新依赖、无 migration、无新持久字段、无 UI 直连 SQLite（`rg -n 'rusqlite'
crates/vega_ui/src/` 保持为空）。不改变工具执行、provider 协议或权限决策。

## 非目标

- 不自动展开分组内**子调用**的 detail（#70 §3.2 保持手动）。
- 不持久化展开状态，不在重开时恢复展开。
- 不新增「显示偏好」设置项、不新增输出查看器或复制按钮。
- 不改变权限卡键盘行为、Artifact/Diff 行为、token 计价或滚动跟随。
- 不改动 #70 的聚合摘要措辞、分类图标语义与 Bash 实时耗时规则。

## 验收

测试先行矩阵与证据要求在
[`vega-issue-151-delivery.md`](vega-issue-151-delivery.md)。最低要求：

- mounted production 流测试证明：新建 thinking/单卡/分组默认展开；新单元或正文
  到达使上一个收起（至多一个自动展开）；分组加入新调用后保持展开；历史水合与
  重开不自动展开；手动收起不被重新展开；展开仅重测量自身 item。
- 既有 #70/#61 安全断言（redaction、fail-closed、权限、有界上限）保持通过。
- workspace 门禁、打包与一次真实运行的原生截图验收。
