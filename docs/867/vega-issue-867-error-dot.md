# #867 · 会话失败未读红点

## 目标与范围

复用会话列表已有未读蓝点的位置、尺寸和生命周期，将未查看的失败响应显示为主题错误红色。正常完成、等待回答、运行中、hover/键盘操作槽保持原行为。不改错误分类、通知权限、自动重试或消息内容；不新增依赖、数据库字段和迁移。

## 验收用例

| 前置与操作 | 可观察结果 | 验证方式与状态 |
|---|---|---|
| 后台会话最后一条用户/助手消息为 failed，运行终止并标为未读 | 最近任务、项目内任务、置顶/归档对应投影在原蓝点位置显示一个红点；浅深主题使用 danger token | 静态追踪 + 用户手测待执行 |
| 后台会话正常完成且未读 | 原蓝点不变 | 静态追踪 + 用户手测待执行 |
| 运行中或 Ask your question 等待回答 | 原运行/暂停提示优先，不叠加红点 | 静态追踪 + 用户手测待执行 |
| 打开失败未读会话，或前台直接发生错误 | 沿用现有已读规则，不额外保持红点；错误正文仍保留 | 静态追踪 + 用户手测待执行 |
| 失败后重试并成功，或用户主动停止 | 运行中隐藏未读点；最新消息为 done/interrupted 或新的 user 消息时不显示错误红点 | 静态追踪 + 用户手测待执行 |
| 保留未读失败后重启/重载 | 从现存消息状态恢复红点，不依赖仅内存状态 | 静态追踪 + 用户手测待执行 |
| 无消息、空会话、手动标为未读 | 无失败证据时不显示红点；手动未读仍按最新消息终态着色 | 静态追踪 + 用户手测待执行 |
| 错误点可访问语义 | 使用现有本地化 Failed 标签，不仅依赖颜色 | 静态检查 + 用户手测待执行 |

## 根因（静态事实）

`window/artifact.rs` 在 run finished 时调用 `finish_completion_attention`；后者将后台结果标为 unread 并重载 sidebar。`session_row_trailing` 只有 unread 布尔值，两个绘制入口均固定 `colors.accent`，缺少失败投影。

## 实现计划

1. `vega_store/src/threads.rs` 的共享查询列增加只读派生 `last_response_failed`：只对 unread 行，读取同线程最后一条 user/assistant 消息的 status 是否 failed，按已有唯一 `(thread_id, seq)` 索引倒序查找，空集为 false。包含 user 防止旧失败跨越新提交；不按单条工具错误推断整轮失败。
2. 经 `vega_conversation::types::Thread` 和 `thread_from_row` 传递派生布尔值，draft 初始化 false，不改可写 ThreadUpdate 或 DDL。
3. 两处现有未读点依该字段选择 `colors.danger` / `colors.accent`，失败添加现有 `ui.failed` 可访问名称；原尺寸、尾槽优先级和已读生命周期不变。

## 风险与验证

只读 SQL 增加每个未读线程一次有索引的倒序查找，不扫描正文、不额外做 UI 层数据库访问。不扩展到尚未持久化为 failed 的启动错误或非运行终态错误。没有运行终态失败的普通工具报错不触发红点。

本地只执行 diff、格式和静态检查，不运行 Vega、不编译、不执行测试。此改动不临时引入 Rust 测试；required Actions 负责 fmt、Clippy、Python 回归及 Rust 测试清点（无 Rust 测试不等于行为通过）。非实现者独立审查绑定精确提交。合并后等待用户真实场景手测，Issue 保持开放/In review。
