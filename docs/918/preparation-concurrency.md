# 运行准备与并发持久化（#918）

## 基线、事实与未决项

基线 `f3688f5ae0b7becf1f46434c7b7d732e3a3c759a`。应用 0.1.410 的发布 ref 指向 `34555cec9c0c4c4c1f7a528d739752f414e53edf`，包含 #891 的委派快照修复；发布身份不等于已校验安装二进制内容。

只读故障侧录仍指向 preparation 持有写许可超过 10 秒。现场两个阻塞者分别仅有 323 / 1 条工具记录，无 fork；不能仅以单线程历史规模归因。当前全库约 183550 条工具记录。`tool_calls::foreign_call_ids` 在最终写事务内执行 `SELECT id FROM tool_calls WHERE thread_id != ? ORDER BY id`，查询计划为按主键索引扫描并回表；一次现场只读测量取回 183554 行耗时 4.569 秒，next_seq 同次约 2.6 毫秒。该测量不是对历史 10–16 秒的完整归因，也不修改用户数据库。

现有 delegated 投影/脱敏/历史构造已经在锁外，仍需保留。工具 ID 集合是启动时的冲突预筛，不可能覆盖运行后新增的其他线程工具；真正的边界是 ToolCallProposed 的提交前身份核对与主键唯一约束，持久化回执成功后才能执行工具。

## 验收（实现前冻结，初始均待验证）

1. 暂停准备阶段的全库 ID 读取边界或投影计算时，同库另一线程必须在释放暂停之前提交消息和工具终态；不是等慢任务结束后才提交。保留 10 秒队列上限。
2. 同库父任务流式快照和至少两个子任务持久化可在准备暂停时推进；长历史/工具记录及首次启动、followup、恢复路径按风险覆盖，不调用真实模型/外部工具。
3. 同规模合成库对比完整准备耗时及 writer 持有时间；全库 180000 工具记录，当前子线程少量工具与长历史各取样。目标最终 writer p95 <250ms，且全库枚举不占 writer；记录样本、机器/工具链、原始失败和测量限制，不推算真实现场。
4. 准备快照后修改本线程依赖拒绝旧安装；不相关会话更新不使本线程快照失效。权限撤销、执行 owner/fence 改变、取消仍拒绝且不部分安装。普通可重算冲突的重试须有界，权限变化不自动获新授权。
5. 已知/准备期间/准备之后新增的跨线程重复工具 ID 均不得进入外部执行；现有工具身份和结果不得被覆盖。重复投递不重复累计用量、不重复执行工具；提交未知必须先核对，不能重放整个 Agent。
6. 排队、引擎 busy 与安全重试使用可取消的明确预算，不能无限等待或通过加大 timeout 求通过；保留 queue_timeout / queue_full / begin busy 等来源的诊断。不把权限、约束、损坏等错误作为暂态忙重试。
7. 保留 source/消息序号/脱敏偏移/checkpoint/用量的原子提交与最后 authority 校验；不把耗时准备挪入新 actor。本卡不实现 #919。

## 最小实施顺序

先添加本轮定向开发回归和完整 preparation 计时，验证全库枚举与写许可的重叠；使用合成数据库，不复制用户正文，不恢复历史全量测试集合。已有测试源码仅参考实际 API 和夹具接线。

随后将跨线程工具 ID 预筛读取移到最终写事务之外，保留提案提交端新鲜校验。根据完整 preparation 分段测量处理确实占主导的其他步骤，不凭猜测重写所有运行路径。需要时为预筛读取补覆盖索引以避免 payload 回表，DDL 仅递增迁移。

已存在的乐观 revision 校验、原子安装、来源末检和权限门禁不删除。若测量证明仍需移动某个安全检查，必须先明确依赖闭包、版本及冲突处理，再实现。重试只作用于确定尚未提交的准备/持久化单位，不覆盖外部副作用；提交结果未知按稳定身份核对，不盲重放。
