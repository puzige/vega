# #800 用户消息发送后默认渲染 Markdown

## 用户裁决与范围

已发送用户消息默认在原有右侧气泡内渲染 Markdown，不提供切换或发送前预览。替代设计守则中用户消息始终按源文换行显示的旧规则；气泡右对齐，最大宽度与圆角/内距沿用当前共享 token，不改变几何参数。当前 `CONVERSATION_USER_RATIO = 0.7`；旧设计文档的 80% 描述不是本次新增的宽度验收要求。整条复制、持久化及模型输入保留原文；选区复制可见内容，代码块复制代码。附件继续在上，文字在下，同消息间距 8px。纯图片无空气泡。

## 实现

- 用户 StreamEntry 持有完成态 Markdown 的 StreamModel，构造/历史更新/隐私投影变更时解析一次，不在 render 中解析。
- 保留原有 user lines 作为纯图片可见性、源文预览兼容数据；Markdown 显示及高度估算使用同一 model。
- 复用现有 Markdown 标题、强调、链接、列表、引用、代码块和表格渲染及选择机制；气泡内使用用户正文颜色，宽表格/代码继续复用现有横向滚动。
- 完整覆盖普通提交、即时接受、pending echo/提交、历史恢复、controller 补全、语言投影更新及 benchmark 构造。原消息身份、复制页脚、时间戳和滚动策略不变。
- 不新增依赖、产品说明文案、Rust 测试、存储字段或模型协议。

## 规格记录

独立审查指出初稿把旧设计的 80% 误记为当前宽度。核实基线 token 为 70%，本次用户只授权默认 Markdown 显示，因此修正规格事实，保持原宽度，不顺带修改布局 token；代码与此修订前一致。

## 验收与验证

用户消息中的标题、粗体/斜体、行内代码、围栏代码、列表、引用、链接和表格按现有 Markdown 能力显示。普通文本及空行遵循 Markdown 语义；纯图片没有文本气泡。窄窗、长代码/宽表格不撑破气泡；附件间距、消息复制原文、选区、代码复制、时间戳、队列提升和历史恢复保持一致。
