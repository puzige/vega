# #617 · 默认直接执行与按需委派

## 授权、基线与范围

- Issue：<https://github.com/puzige/vega/issues/617>。用户先要求整理优化卡，随后明确授权本会话接手实施。
- 规格 v1，2026-10-25，先于实现固定。已 fetch 并快进核对的基线：`76c164876542c679abe1bfb5f525f1ade2fcd2e4`；分支 `feat/617-conservative-delegation`。
- 主 Agent 为本卡唯一实现写入者；按本卡明确政策授权取消一律委派实现的旧要求，保留非实现者独立审查、最终 head required CI、用户手测与安全边界。
- 仅调整 Native 委派提示及必要工具描述、Vega 仓库现行规则；不改 Loom、其他用户项目、运行时控制流、后端、并发、权限、用量或恢复机制。

## 事实与调用链

`crates/vega/src/agent_context.rs::SYSTEM_PROMPT` 提供基础执行纪律；`crates/vega_runtime/src/agent/loop_.rs` 在 `tool_config.subagents.is_some()` 时追加委派规则；`agent/subagents.rs::definitions()` 提供 spawn/followup/resume/list/wait/cancel 契约。现有提示只笼统要求权衡成本，没有明确默认直接执行。Vega 现行 AGENTS、执行总纲、Issue 工作流、交付 skill、验证政策及设计守则变更方式同时保留强制实现委派，形成额外交接来源。基线无受版本控制的 CLAUDE.md，后续不为此创建新入口。

用户反馈使用中过于频繁是本轮优化动机；尚无控制模型、推理强度和加载规则的量化对照，不能将静态分析解释为实际效率改善。

## 验收矩阵（实现前固定）

| ID | 场景 | 要求与验证 |
| --- | --- | --- |
| A1 | 已知目标、少量调用、小修改、紧密耦合任务，无额外要求 | 提示默认当前 Agent 直接做；规模、多文件、多步骤、深入/全面措辞本身不触发委派。独立语义审查，真实遵循待用户观察。 |
| A2 | 独立并行、大量探索的上下文隔离、有理由的独立判断 | 比较收益与准备/信息损失/重复探索/等待/整合成本；允许有益委派，收益不明确不委派；不能整体外包主任务理解与综合判断。 |
| A3 | 关键路径下一步立即依赖且无其他有效工作 | 通常自己做；明确用户/项目委派或禁止要求、独立审查要求仍须遵守，不扩大权限、不增加普通调度确认。 |
| A4 | Vega 本仓实现 | 主 Agent 可为唯一实现者，不机械凑角色；由非该实现写入者独立审查已就绪停写精确版本，保留最终 head required CI。各现行入口不再要求一律委派实现。 |
| A5 | 已有子 Agent 后续工作、多个相关修复、重复 review | 续派也比较收益；合并已知同范围相关项，不为攒批拖延阻塞工作；状态使用 list/wait，不建空任务或重复无变化审查；新差异按受影响不变量增量复核并核对完整最终 head。 |
| A6 | 委派运行、等待、中断、取消、复用 | 不重复子任务、不编造结果、不提前结束主 run；保留权限、执行身份、上下文、写入权释放、未知副作用、恢复与现有等待契约。工具描述变化仅限决策提示。 |
| A7 | 规则同时加载、历史记录 | 同步 AGENTS、执行总纲、Issue 工作流、skill、验证政策；明确本卡仅取代强制实现委派及机械角色链，不批量改历史证据或降低其他门禁。 |

## 最小实现计划

1. 收敛 `loop_.rs` 的决策段落：默认直接做；列明委派例外、关键路径与理解职责；已有每个 child 成本权衡覆盖新建/续派，强调不确定时不委派。保留其余交接、审查、失败诊断、等待、恢复规则，补充不重复工作与合并相关交接。
2. `subagents.rs` 仅在 spawn/followup 描述补充默认直接做和续派非默认；不改 schema 或生命周期行为。
3. 同步上述五个政策入口及检索发现的现行设计守则。单一写入者可为主 Agent 或适当子 Agent；自主实现后仍须另一非实现者独立审查。保留 worktree、Git 协调、CI、用户验收、本地执行禁令和测试交付政策。历史 v1.4 等记录保留并注明本卡取代边界。
4. 对现行入口检索冲突；固定实现 commit，停止写入后提交非实现者语义审查，同时触发现有 Actions。合并前独立确认完整最终 head 与实际 required checks，不能用静态检查替代云端门禁。

## 验证、回滚与效果边界

本卡为提示/政策文字调整，不改变确定性运行时行为；不新增 prompt 字符串断言或伪模型测试来证明调度效率。只做低 CPU 静态检查（diff、格式、frontmatter、链接、现行规则冲突与安全契约对照）；本地不运行 Vega、编译、构建、打包或测试。现有 PR Actions 保持不变，记录原始 run/job/命令/结果和 Rust 发现/执行数；无 Rust 测试写 `no Rust tests`，不称行为验证通过。

回滚为通过 PR 一起还原本卡提示及政策修改，不动用户配置或运行数据。

用户手测/另获授权的既有评估路线：对照简单修改、紧密耦合、跨模块调查、独立并行和必要独立审查任务，记录真实 App 构建/prompt/skill、模型/推理强度、工作区/验收、规则来源，统计 spawn/followup/resume 与总子执行轮数、主子总 token、可取得费用、端到端耗时/外部等待、质量与审查完整性。未知写未知，不设硬轮数或节省百分比，不新增评估服务。静态评审、CI、合并与用户效果验收分别记录；效果未测就明确待验证。
