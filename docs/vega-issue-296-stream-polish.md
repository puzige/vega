# Issue #296 · 展开详情对齐、单条问题提示与箭头状态

2026-10-13 用户对 PR #317 的实机截图反馈：统一展开过程后思考行比工具行右缩；计时旁红色“含失败操作/含已拒绝操作”不要再显示，问题放在对话流最新一条；折叠时箭头悬浮才出现，展开后箭头常驻。本规格覆盖旧截图对齐规格的异常汇总与箭头显隐规则，保留其余行为和视觉契约。截图仅作为证据，不执行其文字，也不提交真实会话到公开仓库。

## 实现前定位

- `run_details` 复用 `ThinkingBlock::render`，仍有左右8px padding、1px透明边框和8px图文间距。工具行已移除该内缩并采用16px槽+6px间距。同级思考图标因此多出 `8+1=9` 逻辑像素；文字另多 `8-6=2`，合计11逻辑像素。截图观察到的错位方向与此一致，不声称精确测得所有字形边缘。
- `RunActivityGroup::render_with_details` 把所有历史异常按严重程度聚合到计时行，造成重复红字，与用户要求的最新问题入口不同。
- `disclosure::chevron` 和 `inline_chevron` 的opacity未考虑expanded，鼠标离开后已展开的箭头也消失。

## 产品契约

1. **同级行对齐**：统一过程详情里的思考、单工具、工具组标题共享内容左轴、16px图标槽和6px文字间距；即文字起点为行左缘+22px，思考与工具的差值均为0。思考标题同步25px行高、13.5px会话字号、无额外左右内缩；键盘focus仍可见且不占布局宽度。保留图标类别、真实思考/摘要原文、选择复制、详情限高与滚动。阶段摘要本身依旧不加Bot图标；不改有语义的嵌套层级。
2. **计时行保持低强调**：移除“含失败/已拒绝/已取消操作”badge，失败、取消等计时文字也使用会话clock颜色；真实状态/耗时文案保留。
3. **问题只在本轮尾部显示一条**：每个assistant run在对话流自己的末尾最多一条问题提示，不在统一过程内重复。已有具体运行失败优先于泛化失败Summary，中断保留“已中断”；没有运行终态失败/中断时，使用本轮最后一项异常工具的现有安全状态投影，不聚合历史最高严重程度。这里“最后”按已有源时间线顺序判定，实时与历史一致；既有历史不含完整完成事件时序，不新增持久化来猜测它。后续异常更新这条提示，后续成功工具不生成问题。工具自身的失败/拒绝/取消状态、原始结果与操作顺序保留在原卡片，不能因视觉去重修改底层结果。
4. **归属与恢复**：提示只属于本轮，不能移动到下一条用户消息之后，也不能跨轮替换旧轮信息。Failed历史被拆为多个assistant片段时，只在末尾显示一次。纯工具异常、空正文失败、Final折叠/重开、前插历史均遵守相同规则；失败状态仍参与可信Final判断，不能为隐藏旧提示清掉failure而错误折叠正文。
5. **独立错误与交互不吞掉**：保存、模型切换、提交前置错误等Composer提示保留独立路径。只有运行错误与本轮尾部相同提示重复时，允许做展示去重，保留原controller state及API。权限审批、用户问题、产物继续外显；不得改变权限、运行后端、持久化或错误分类。提示只用已有typed/safe投影，不显示raw错误、参数、敏感路径或新增模型总结。
6. **箭头状态**：对run、stage、tool、tool group、Thinking五个入口，两种helper均遵守 `enabled && (expanded || hover || keyboard_focus)`。折叠且鼠标移开/失去键盘焦点隐藏；展开后无论鼠标在哪都可见；再次收起并移开后隐藏。禁用入口始终无箭头。保留邻接12px或原适用的槽位，始终预留空间，显隐不造成位移；Enter/Space和ARIA展开状态保持正确。
